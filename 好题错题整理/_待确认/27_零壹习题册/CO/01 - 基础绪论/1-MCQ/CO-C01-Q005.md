# MCQ 第 5 题

![[_Attachments/题目识别/27_零壹习题册-题目/CO-C01-Q005_题目.png|题目]]

5. 当存放计算机指令的主存单元被读入通用寄存器中并参与 ALU 运算时，( ) .
(A) 计算机会产生异常，因为指令无法参与数据运算
(B) 指令会按照数据运算的规则正常参与运算，并产生运算结果
(C) 指令不可能被读入通用寄存器并参与 ALU 的数据运算
(D) 指令会自动拆分出操作数字段部分参与 ALU 的数据运算

---

## 答案

![[_Attachments/题目识别/27_零壹习题册-答案/CO-C01-Q005_答案.png|答案]]

## DeepSeek V4 Flash Max 解析
**答案**：B。指令和数据在存储器中都是二进制位串，ALU 不关心操作数“本来是指令还是数据”，因此指令被读入通用寄存器后，会按普通操作数参与运算并正常产生结果。

**解题切入点**：拿到题先定位到“冯·诺依曼存储程序”思想和 ALU 的功能边界。计算机不依据存储单元中的内容自动区分“指令”和“数据”，只有当 CPU 在取指/译码阶段使用它时，它才具有“指令”语义；当它被 load 指令读入通用寄存器并交给 ALU 时，它只是普通操作数。这就像算法竞赛中用一个字符串的二进制位强制转换成整数做位运算，运算器不会去判断它“原本是不是字符串”。

**推演**：

- 冯·诺依曼结构中，指令和数据以同样的二进制形式存放在主存中，主存单元本身并不记录“这个单元是指令还是数据”。
- 执行 load 类指令时，CPU 把主存单元内容读出并送入通用寄存器：
  $$R_i \leftarrow M[\text{addr}]$$
  这一步是普通的数据传送，控制逻辑不会因为该内容“恰好是一条指令”而阻止。
- 随后若执行类似 `ADD R1, R2, R3` 的指令，ALU 的两个输入来自通用寄存器。ALU 只对两个二进制位串执行指定的算术或逻辑运算，例如：
  $$R_3 \leftarrow R_1 + R_2$$
  它不会解析该位串中的“操作码字段”或“地址字段”，也不会自动拆分指令字段。
- 因此，指令位串被读入通用寄存器后参与 ALU 运算，和普通数据参与 ALU 运算没有本质区别，会按照当前 ALU 运算规则产生一个结果。
- 选项 A 错在把“执行非法指令时的异常”与“把指令当作数据处理”混为一谈；此处 ALU 不是以“指令执行”方式使用该位串。
- 选项 C 错在 load 指令完全可以读取存放指令字的主存单元；指令字只是内存中的二进制内容，可以被读入通用寄存器。
- 选项 D 错在“操作数字段拆分”是控制器指令译码阶段的工作，不是 ALU 运算时自动发生的行为。

**易错点**：

- 误选 A：以为“指令不能参与数据运算”。这是对存储程序概念的误解；指令在存储层面就是二进制数据，ALU 不识别语义。
- 误选 C：认为“指令只能进入指令寄存器 IR，不能进通用寄存器”。实际上通过 load 指令可以读取任意主存单元中的内容，包括指令字。
- 误选 D：把“指令译码时拆分操作码和地址码”错误地归给了 ALU。ALU 只负责计算，不负责解析指令格式。
- 容易忽略“异常”的产生条件：指令作为操作数参与 ALU 运算不会产生异常；但如果该位串被当作指令取指、译码，且操作码非法，才可能产生非法指令异常。

**命题规律**：本题考查“存储程序”思想下指令与数据的等价性，以及 ALU 的功能边界，属计算机组成原理基础概念题。常见变式有：给出某主存单元中的二进制内容，问它是指令还是数据；或问“程序能否修改自身指令”；或问“指令和数据的区分由什么决定”。复习时应把指令周期各阶段与数据通路联系起来理解，记住：同一二进制位串的语义由 CPU 在哪个阶段、以何种用途使用它决定；存储器和 ALU 本身不做“指令/数据”的语义判断。
