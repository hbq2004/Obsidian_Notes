# MCQ 第 24 题

![[_Attachments/题目识别/27_零壹习题册-题目/CO-C02-Q024_题目.png|题目]]

24. 在 32 位计算机中运行如下 C 语言代码，程序的输出为（）.

```c
unsigned int u = 0xffff0fff;
short s = -3940;
int i = 50000;
short temp = u + s;
int result = temp + i;
printf("%d\n", result);
```

(A) 50155
(B) $2^{32} - 15 \times 2^{12} + 46059$
(C) 49899
(D) 53940

---

## 答案

![[_Attachments/题目识别/27_零壹习题册-答案/CO-C02-Q024_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：A。`u+s` 按 32 位无符号运算，再截断成 16 位 `short` 得到 155，加 `i=50000` 后输出 50155。

**解题切入点**：  
看到 `unsigned int`、`short`、`int` 混合运算，第一反应不是直接算十进制，而是先定位“类型转换”和“位宽截断”。  
这就像算法竞赛中 debug 时先给每个变量标出类型和位宽：类型错了，后面算得再快也会错。

**推演**：  
32 位机中，`int`/`unsigned int` 为 32 位，`short` 为 16 位，按补码表示。

先看 `u + s`：

\[
u=\text{0xffff0fff}
\]

`short s = -3940`，参与运算时先整型提升为 `int`，再因为与 `unsigned int` 运算而转换为 `unsigned int`。  
于是：

\[
-3940 \equiv \text{0xfffff09c} \pmod{2^{32}}
\]

所以：

\[
u+s \equiv \text{0xffff0fff}+\text{0xfffff09c}\equiv \text{0xffff009b}\pmod{2^{32}}
\]

即完整加法为 \(\text{0x1ffff009b}\)，取低 32 位得到 \(\text{0xffff009b}\)。

然后执行：

```c
short temp = u + s;
```

`short` 是 16 位，因此截取低 16 位：

\[
\text{0xffff009b}\to \text{0x009b}
\]

\[
\text{0x009b}=155
\]

所以：

\[
temp=155
\]

接着：

```c
int result = temp + i;
```

`temp` 会整型提升为 `int`，因此：

\[
result=155+50000=50155
\]

`50155` 在 32 位 `int` 范围内，`printf("%d")` 输出：

\[
50155
\]

因此选 **A**。

**易错点**：  
1. **选 B**：忽略 `short temp` 的 16 位截断，直接把 `u+s+i` 的 32 位结果按无符号解释。  
2. **选 C**：误把 `short` 截断成 8 位；\(\text{0x9b}\) 按 `signed char` 解释为 \(-101\)，再加 50000 得 49899。  
3. **忘记整型提升**：`temp + i` 中 `temp` 会先提升为 `int`，不是在 16 位 `short` 中溢出计算。  
4. **把无符号数当有符号数算**：`u+s` 的类型是 `unsigned int`，要按模 \(2^{32}\) 理解。

**命题规律**：  
本题属于计算机组成原理中“数据的表示与运算”，核心考 C 语言隐式类型转换、无符号数运算的模 \(2^{32}\) 特性，以及赋值给更窄类型时的截断/符号扩展。  
常见变式有：把 `short` 换成 `char`，把 `int` 换成 `long long`，或要求写出 `temp` 的十六进制补码；也可能结合 `%u` 输出、有符号比较等。复习时应熟练掌握“整型提升 → 普通算术转换 → 截断/符号扩展”的完整流程。
