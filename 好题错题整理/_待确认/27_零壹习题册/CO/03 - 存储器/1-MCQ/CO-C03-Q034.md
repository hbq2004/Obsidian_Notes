# MCQ 第 34 题

![[_Attachments/题目识别/27_零壹习题册-题目/CO-C03-Q034_题目.png|题目]]

34. cache 采用全相联映射时，不会出现的 cache miss 类型是 （  ） .

(A) 必然缺失

(B) 冲突缺失

(C) 容量缺失

(D) 无效缺失

---

## 答案

![[_Attachments/题目识别/27_零壹习题册-答案/CO-C03-Q034_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：B。全相联映射允许主存任意块装入 Cache 任意行，不会因映射位置冲突而产生缺失，因此不会出现“冲突缺失”。

**解题切入点**：看到“全相联映射”与“缺失类型”，先回想 Cache 缺失的经典三分类：必然缺失、容量缺失、冲突缺失。全相联映射消除了“映射位置”的约束，自然就排除了与位置冲突相关的缺失。可以类比算法竞赛中的哈希表：如果给每个元素一个完全自由的桶，那么永远不会因为“多个元素争同一个桶”而失败，只会因为桶总数不够而失败。

**推演**：

1. 按缺失原因，Cache 缺失通常分为三类：  
   - **必然缺失（强制性缺失，Cold/Compulsory Miss）**：某块第一次被访问，Cache 中一定没有该块，因此必然发生缺失。它与映射方式无关，任何映射方式下都会发生。  
   - **容量缺失（Capacity Miss）**：程序工作集大小超过 Cache 容量，即使采用全相联映射，Cache 也无法容纳所有被访问的块，导致某些块被替换后再次访问时发生缺失。全相联映射下容量缺失依然存在，因为 Cache 总容量有限。  
   - **冲突缺失（Conflict Miss）**：由于映射规则将多个主存块映射到同一个 Cache 行（直接映射）或同一个组（组相联映射），导致即使 Cache 还有空闲位置，也因位置冲突而被迫替换，从而产生缺失。全相联映射中，主存块可以被装入任意 Cache 行，不存在“映射位置不够”或“位置冲突”的问题，因此不会发生冲突缺失。  

2. 题目选项中的“无效缺失”不是经典缺失分类中的标准术语。若将其理解为“因 Cache 行被无效化而导致的缺失”，它本质上与替换或一致性操作有关，不是映射方式直接导致的必然现象；在经典 408 考查范围内，与映射方式直接相关且能被全相联映射消除的只有冲突缺失。  

3. 因此，全相联映射可以消除的缺失类型是**冲突缺失**，答案选 B。

**易错点**：

- **误选 C（容量缺失）**：认为全相联映射“完全自由”，就以为容量缺失也不会发生。实际上全相联映射只是解决了“放哪里”的问题，不能解决“Cache 装不下”的问题。只要工作集大于 Cache 容量，容量缺失就必然存在。  
- **误选 A（必然缺失）**：必然缺失是首次访问造成的，与映射方式无关。无论全相联还是直接映射，第一次访问一个从未进入过 Cache 的块时都缺失。  
- **混淆“冲突缺失”与“容量缺失”**：冲突缺失强调“Cache 明明有空位却因映射限制无法使用”；容量缺失强调“Cache 全部被占满且没有空位”。全相联映射能让所有空位都被任意块使用，所以冲突缺失被消除，容量缺失保留。  
- **对 D 选项产生困惑**：不属于经典分类，不要强行将其与全相联映射挂钩；解题时应以标准三分类为纲。

**命题规律**：

- 考点：Cache 映射方式与缺失类型的关系，属于计算机组成原理中存储系统的重要概念。
- 常见变式：  
  1. 给出直接映射、组相联映射，问可能出现的缺失类型；  
  2. 将容量增大、组数增多等参数变化后，分析哪种缺失减少；  
  3. 结合程序访问序列，判断某次访问是哪种缺失。  
- 复习建议：熟记 Cache 缺失三分类及其与映射方式、Cache 容量、替换算法的关系。总结规律：  
  - 增大 Cache 容量 → 减少容量缺失；  
  - 增大相联度（直接映射→组相联→全相联）→ 减少冲突缺失；  
  - 预取、增大块大小 → 可减少必然缺失（但需注意块过大会增加缺失代价）。  
  做题时先判断题干中的映射方式，再逐项对照三类缺失，往往能快速锁定答案。
