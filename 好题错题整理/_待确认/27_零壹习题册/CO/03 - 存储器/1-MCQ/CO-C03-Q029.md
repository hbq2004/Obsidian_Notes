# MCQ 第 29 题

![[_Attachments/题目识别/27_零壹习题册-题目/CO-C03-Q029_题目.png|题目]]

29. 有如下 C 语言程序段：
```
for (int i = 0; i < 10; i++) {
    for (int j = 0; j < 72; j++) {
        a[j] = a[j] + 3;
    }
}
```
数组 $a$ 中都是 int 型数据。假定数组 $a$ 在主存 00000000H 处开始连续存储，其中数据 Cache 采用 4 路组相联，数据区大小为 256B，Cache 行大小为 16B，采用 LRU 替换算法，该程序执行前 Cache 为空，则该程序执行过程中访问数组 $a$ 的 Cache 缺失率为多少（  ）.【24 年零壹二模】
(A) 7.5%
(B) 25%
(C) 12.5%
(D) 15%

---

## 答案

![[_Attachments/题目识别/27_零壹习题册-答案/CO-C03-Q029_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：A（7.5%）。每次 `a[j] = a[j] + 3` 都要读一次、写一次数组元素，所以总访问数组次数为 \(10\times72\times2=1440\)；Cache 缺失共 108 次，缺失率 \(108/1440=7.5\%\)。

**解题切入点**：看到 Cache 与数组循环，先做两件事：由容量和行大小算出组数；把数组按 Cache 行分块。可以把每组看成容量为 4 的“桶”，数组块按地址模 4 分桶，桶 0、桶 1 各有 5 个块，必然发生 LRU 抖动。

**推演**：

1. 计算 Cache 参数：

\[
\text{Cache 总行数}=\frac{256B}{16B}=16
\]

4 路组相联，所以：

\[
\text{组数}=\frac{16}{4}=4
\]

一个 Cache 行可放：

\[
\frac{16B}{4B}=4\text{ 个 int}
\]

2. 数组分块：

72 个 int 占：

\[
72\times4B=288B
\]

共占 \(288/16=18\) 个主存块，块号 \(0\sim17\)。

因为数组首地址是 00000000H，所以块号按 \(块号 \bmod 4\) 映射到 4 个组：

| 组号 | 映射到的块号 |
|---|---|
| 0 | 0, 4, 8, 12, 16 |
| 1 | 1, 5, 9, 13, 17 |
| 2 | 2, 6, 10, 14 |
| 3 | 3, 7, 11, 15 |

3. 缺失情况：

第一次外层循环：18 个块都是冷不命中，共 18 次缺失。

但由于组 0 和组 1 都要容纳 5 个块，而每组只有 4 行，LRU 会换出较早进入的块：组 0 的块 0 被块 16 换出，组 1 的块 1 被块 17 换出。

之后 9 次外层循环中：

- 组 0、组 1 的访问序列长度都是 5，超过相联度 4，产生 LRU 抖动，每组每轮 5 个块都缺失；
- 组 2、组 3 恰好 4 个块，第一次调入后不会再被换出，之后全部命中。

所以缺失总数为：

\[
18+9\times(5+5)=18+90=108
\]

4. 总访存次数：

每次内层循环对数组访问两次：一次读 `a[j]`，一次写 `a[j]`。

\[
10\times72\times2=1440
\]

因此缺失率为：

\[
\frac{108}{1440}=7.5\%
\]

**易错点**：

- 最容易错的是把 `a[j] = a[j] + 3` 只算成一次数组访问；实际上它有读和写两次访存，因此分母应为 1440。若分母误用 720，会得到 \(15\%\)，即选项 D。
- 容易忘记一个 Cache 行能放 4 个 int，导致把同一行内的 4 个元素都算成缺失。应先把数组按 16B 分块。
- 容易忽略组 0、组 1 各有 5 个块而每组只有 4 行；只有它们发生抖动，组 2、组 3 后续不缺失。
- 不要混入指令访存；题目只问“访问数组 a”的数据 Cache 缺失率。

**命题规律**：本题是 Cache 地址映射与替换算法的经典综合题，核心是“组相联 + LRU + 循环数组访问”。常见变式包括：改变数组大小、Cache 容量、行大小、步长，或换成二维数组按行/按列访问。复习时建议掌握固定流程：先算组数和行内元素数，再把数组访问序列映射成块序列，最后按 LRU 逐轮统计缺失。
