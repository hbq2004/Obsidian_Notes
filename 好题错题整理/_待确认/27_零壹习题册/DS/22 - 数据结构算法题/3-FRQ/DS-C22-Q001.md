# FRQ 第 1 题

![[_Attachments/题目识别/27_零壹习题册-题目/DS-C22-Q001_题目.png|题目]]

1. 合并升序单链表
已知链表结点数据结构定义为
```c
typedef struct ListNode{
    struct ListNode* next;
    int val;
}ListNode;
```
将两个不带头结点的升序单链表 (list1, list2) 合并为一个新的升序链表并返回. 要求算法原地完成.
(1) 描述算法思想
(2) 实现代码 (即 ListNode* merge(ListNode* list1, ListNode* list2))
(3) 写出你所实现算法的时间复杂度 (此处假设 list1 长度为 m, list2 长度为 n) 和空间复杂度

## 答案

## DeepSeek V4 Flash Max 解析

**答案**：本题为代码/简答题。采用“双指针尾插法”原地合并：每次取 `list1`、`list2` 当前头结点中值较小者接到结果链表尾部，返回合并后的链表头。时间复杂度 $O(m+n)$，空间复杂度 $O(1)$。

**解题切入点**：先识别考点：有序链表合并，本质是“归并排序”的合并过程在链式存储上的实现。链表题要抓住“改指针”而不是“改值”，并且题目明确要求原地完成，因此不能新建结点、不能用数组存下再排序。可以理解为“拉链”过程：两个有序链表的头指针像两条拉链齿，每次从较小的一边取一个结点“拉”到结果链表上，直到一边拉完，再把剩余另一边整体接上。

**推演**

### （1）算法思想

设两个链表指针分别为：

$$p = list1,\quad q = list2$$

另设结果链表头指针 `head`，再设一个“尾指针” `tail`，但这里更简洁的方法是让 `tail` 始终指向结果链表最后一个结点的 `next` 域，初始时：

$$tail = \&head$$

这是因为 `head` 最终可能来自 `list1`，也可能来自 `list2`，用二级指针可以统一处理“头指针变化”的问题。

每轮比较：

- 若 `p->val <= q->val`，说明当前 `p` 是剩余所有结点中的最小值，把 `p` 接到结果尾部，然后 `p = p->next`；
- 否则把 `q` 接到结果尾部，然后 `q = q->next`；
- 更新 `tail`，使其继续指向结果链表最后一个结点的 `next` 域。

循环结束后，必有一个链表已经为空，直接把另一个链表剩余部分整体接到结果尾部即可。

### （2）实现代码

```c
ListNode* merge(ListNode* list1, ListNode* list2) {
    ListNode* head = NULL;
    ListNode** tail = &head;   // tail 指向结果链表最后一个结点的 next 域

    while (list1 != NULL && list2 != NULL) {
        if (list1->val <= list2->val) {
            *tail = list1;          // 摘下 list1 当前头结点，接到结果尾部
            list1 = list1->next;    // list1 后移
        } else {
            *tail = list2;
            list2 = list2->next;
        }
        tail = &(*tail)->next;      // tail 继续指向新尾结点的 next 域
    }

    // 剩余链表直接整体接入
    *tail = (list1 != NULL) ? list1 : list2;

    return head;
}
```

该代码没有分配任何新结点，只是不断修改原链表结点的 `next` 指针，因此满足原地要求。

### （3）时间复杂度与空间复杂度

- 时间复杂度：`while` 循环每执行一次，至少有一个结点被“摘下”并接入结果链表。两个链表一共有 $m+n$ 个结点，因此循环次数不超过 $m+n$，最后整体接入剩余链表只需 $O(1)$。所以总时间复杂度为：

$$O(m+n)$$

- 空间复杂度：只使用了 `head`、`tail` 等常数个指针变量，没有递归调用，也没有新建链表结点，因此空间复杂度为：

$$O(1)$$

**正确性说明**：两个链表分别升序，所以各自当前头结点就是各自剩余部分的最小值；每次取二者中较小者，就等价于取全体剩余结点中的最小值。因此每次接入结果链表后，结果链表仍然升序。循环结束时某一链表为空，另一链表剩余部分的所有结点值都不小于已经接入的最后一个结点，因此可以整体接入。

**易错点**：

- 忘记处理空链表。若 `list1` 或 `list2` 一开始就为空，循环不会执行，但最后一句 `*tail = list1 ? list1 : list2` 仍然能正确返回非空链表；若漏掉这一句，就会返回错误结果或发生空指针访问。
- 头指针更新错误。两个链表都不带头结点，所以合并后的头结点可能是 `list1` 的头，也可能是 `list2` 的头。用 `ListNode** tail = &head` 可以统一处理，避免单独判断 `head` 为空的特殊情况。
- 新建结点违反“原地”要求。如果使用 `malloc` 新建 $m+n$ 个结点，虽然代码逻辑也能通过，但空间复杂度变为 $O(m+n)$，不符合题意。
- 忘记更新 `tail`。如果不执行 `tail = &(*tail)->next`，下一次拼接会反复覆盖同一个 `next` 域，造成错误链接甚至循环链表。
- 使用递归实现。递归代码虽然简洁，但递归调用栈深度为 $O(m+n)$，空间复杂度不是 $O(1)$，不满足题目“原地完成”的要求。

**命题规律**：链表合并是数据结构考研 408 的高频考点，常与“原地操作、O(1) 空间”结合考查。常见变式包括：合并两个降序链表、合并 $k$ 个有序链表、链表归并排序、链表拆分与重排、判断链表回文等。复习时应重点掌握“二级指针/哨兵结点统一处理头指针变化”的方法，并注意边界条件：空链表、只有一个结点、两个链表长度不等、值相等的情况。
