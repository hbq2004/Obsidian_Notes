# FRQ 第 16 题

![[_Attachments/题目识别/WDOS-2027-FRQ/WDOS-2027-FRQ-C03-S02-Q016_题目.png|题目]]

设某计算机的逻辑地址空间和物理地址空间均为 $64KB$ ，按字节编址。若某进程最多需要 $6$ 页 ($Page$) 数据存储空间，页的大小为 $1KB$ ，操作系统采用固定分配局部置换策略为此进程分配 $4$ 个页框 ($PageFrame$)，见下表。在装入时刻 $260$ 前，该进程的访问情况也见下表 (访问位即使 用位)。当该进程执行到时刻 $260$ 时，要访问逻辑地址为 $17CAH$ 的数据。回答下列问题：

## DeepSeek V4 Flash Max 解析
**答案**：
- \(\text{17CAH}\) 对应的页号是 \(5\)，页内偏移是 \(3\text{CAH}=970\)。
- 采用 FIFO 置换算法时，物理地址为 \(\text{1FCAH}\)。
- 采用 CLOCK 置换算法时，物理地址为 \(\text{0BCAH}\)。

**解题切入点**：
地址转换第一步永远是拆地址：\(64KB=2^{16}B\)，页大小 \(1KB=2^{10}B\)，所以逻辑地址高 \(6\) 位是页号，低 \(10\) 位是页内偏移。可以把地址看作 \((page, offset)\) 二元组，类似竞赛中把区间编号和区间内偏移分开处理。  
题目访问的页是 \(5\)，而当前四个页框中只有页 \(0,1,2,3\)，所以发生缺页。固定分配局部置换意味着缺页时只能从已有 \(4\) 个页框中淘汰一页，不能额外申请页框。之后就是“选 victim”的过程：FIFO 看装入时刻，CLOCK 看访问位并循环扫描。

**推演**：
地址拆分：

\[
\text{17CAH}=0001\;0111\;1100\;1010_2
\]

高 \(6\) 位：

\[
000101_2=5
\]

低 \(10\) 位：

\[
11\;1100\;1010_2=3\text{CAH}=970
\]

所以访问的是页 \(5\)，页内偏移为 \(970\)。

FIFO 置换：

按题表，页 \(0,1,2,3\) 的装入时刻分别为 \(130,230,200,160\)。最早装入的是页 \(0\)，因此淘汰页 \(0\)。页 \(0\) 所在页框为 \(7\)，所以页 \(5\) 装入页框 \(7\)。

物理地址：

\[
7\times 1024+970=8138=\text{1FCAH}
\]

CLOCK 置换：

当前指针指向 \(2\) 号页框。CLOCK 算法中，若访问位为 \(1\)，则清 \(0\) 并继续向后扫描；若访问位为 \(0\)，则淘汰该页框中的页。  
题表中四个访问位均为 \(1\)，所以从 \(2\) 号页框开始扫一圈后，四个访问位都被清 \(0\)，指针回到 \(2\) 号页框。此时 \(2\) 号页框访问位为 \(0\)，淘汰其中的页 \(2\)，装入页 \(5\)。

页框 \(2\) 对应的物理地址：

\[
2\times 1024+970=3018=\text{0BCAH}
\]

**易错点**：
- 页内偏移不是直接取低两位十六进制：页大小是 \(1KB=2^{10}B\)，所以 \(\text{17CAH}\) 的偏移是 \(3\text{CAH}\)，而不是 \(\text{CAH}\)。
- FIFO 只看“装入时刻”，不看访问位；不要因为某页访问位为 \(1\) 就误以为它不会被淘汰。
- CLOCK 中遇到访问位为 \(1\) 时不是直接淘汰，而是先清 \(0\) 继续扫描；要等到某个页框访问位为 \(0\) 才替换。
- 计算物理地址时使用“页框号”，不是页号。例如 FIFO 淘汰的是页 \(0\)，但物理地址要用页 \(0\) 所在的页框 \(7\) 计算。

**命题规律**：
408 常把“地址变换”和“页面置换”放在同一题中，核心套路是：拆地址 → 查页表 → 判断缺页 → 按置换算法选 victim → 重新计算物理地址。这类似竞赛中写一个容量固定的在线缓存淘汰器：FIFO 是队列按入队顺序出队，CLOCK 是循环扫描加访问位标记。掌握“状态模拟”比死记结论更重要，尤其要会在指定时刻更新页表和指针状态。
