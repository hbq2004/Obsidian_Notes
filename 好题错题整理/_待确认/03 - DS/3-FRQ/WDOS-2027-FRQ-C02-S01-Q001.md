## DeepSeek V4 Flash Max 解析
**答案**：
以题干代码 `char *p = "hello"; int a; int main(){ int b; ... }` 为例：
- 指针变量 $p$：可读/写数据段（$\text{.data}$）；
- 字符串常量 `"hello"`：只读代码段 / 只读数据段；
- 未初始化全局变量 $a$：可读/写数据段（$\text{.bss}$）；
- 局部变量 $b$：用户栈；
- 若程序中出现 `malloc` 动态分配，则该内存位于运行时堆。

**解题切入点**：
按 C 语言存储类别对应虚拟地址空间区域：
- 函数外定义的全局变量 → 数据段；
- 函数内定义的普通变量 → 用户栈；
- 字符串常量 / 只读常量 → 只读区域；
- 动态分配内存 → 运行时堆。

算法竞赛视角：这相当于先判断每个变量的“生命周期”，进程启动就存在、函数结束后仍存活的对象放在静态区；函数调用期间才存在的对象放在栈中；手动申请、手动释放的对象放在堆中。

**推演**：
1. 机器指令、函数代码本身位于只读代码段。
2. `char *p = "hello";` 中：
   - $p$ 是全局指针变量，指针本身可修改，因此放在可读/写数据段；
   - `"hello"` 是字符串常量，具有静态存储期且只读，不能通过 $p$ 修改，因此放在只读代码段。
3. `int a;` 是全局未初始化变量，编译后放入 $\text{.bss}$，运行时会清零；$\text{.bss}$ 属于可读/写数据段。
4. `int b;` 是函数内局部自动变量，每次函数调用在用户栈中分配，函数返回后自动释放。
5. 图中阴影部分是未映射的虚拟地址区域，访问这些地址会产生缺页异常或段错误；堆和栈分别向中间空闲区增长，类似两个指针相向移动。

**易错点**：
- 不要把指针变量 $p$ 和它指向的字符串常量混为一谈：$p$ 可改，字符串常量不可改。
- 不要把全局未初始化变量误认为在只读代码段；它在 $\text{.bss}$，属于可读/写数据段。
- 不要把字符串常量放到运行时堆或用户栈中；它是静态存储期的只读数据。
- 注意区分“全局指针变量”和“局部指针变量”：同为指针，前者在数据段，后者在用户栈。
- 图中阴影区域是“未占用”区，不是可随意使用的空白区，访问它是非法访问。

**命题规律**：
408 常将 C 语言程序与进程虚拟地址空间布局结合，考查变量存储类别与内存区域映射关系。核心只需记住：

$$\text{全局变量/静态变量} \rightarrow \text{数据段},\qquad \text{局部变量} \rightarrow \text{栈},\qquad \text{动态分配} \rightarrow \text{堆},\qquad \text{常量} \rightarrow \text{只读区}.$$

此类题可进一步与页表、缺页中断、堆栈增长方向结合出题，是操作系统与 C 语言存储模型的交叉考点。
