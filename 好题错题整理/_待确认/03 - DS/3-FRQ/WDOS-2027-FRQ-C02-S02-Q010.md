# FRQ 第 10 题

![[_Attachments/题目识别/WDOS-2027-FRQ/WDOS-2027-FRQ-C02-S02-Q010_题目.png|题目]]

某进程调度程序采用基于优先数（priority）的调度策略，即选择优先数最小的进程运行，进程创建时由用户指定一个 nice 作为静态优先数。为了动态调整优先数，引入运行时间 $cpuTime$ 和等待时间 $waitTime$，初值均为 0。进程处于执行态时，$cpuTime$ 定时加 1，且 $waitTime$ 置 0；进程处于就绪态时，$cpuTime$ 置 0，$waitTime$ 定时加 1。请回答下列问题：
(1) 若调度程序只将 $nice$ 的值作为进程的优先数，即 $priority = nice$，则可能出现饥饿现象。为什么？
(2) 使用 $nice, cpuTime$ 和 $waitTime$ 设计一种动态优先数计算方法，以避免产生饥饿现象，并说明 $waitTime$ 的作用.

## DeepSeek V4 Flash Max 解析
**答案**：

(1) 可能饥饿。因为调度规则是选择 $\mathrm{priority}$ 最小的进程运行；而 $\mathrm{priority}=\mathrm{nice}$ 后，$\mathrm{nice}$ 是创建时指定的静态值，不再变化。若就绪队列中总存在或者不断到达 $\mathrm{nice}$ 更小的进程，则 $\mathrm{nice}$ 较大的进程每次都不是最小者，可能无限期得不到 CPU。例如：进程 $A$ 的 $\mathrm{nice}=10$，而系统中不断有 $\mathrm{nice}=1$ 的进程进入就绪队列，则 $A$ 会被无限期推迟。

(2) 一种可行的动态优先数计算方法为：
$$\mathrm{priority} = \mathrm{nice} + \mathrm{cpuTime} - \mathrm{waitTime}.$$

每个调度/计时点重新计算所有进程的 $\mathrm{priority}$，并选择 $\mathrm{priority}$ 最小者运行。

- 运行态：$\mathrm{waitTime}=0$，$\mathrm{cpuTime}$ 每加 1，$\mathrm{priority}$ 加 1，实际优先级下降；这防止进程因 $\mathrm{nice}$ 很小而长期霸占 CPU。
- 就绪态：$\mathrm{cpuTime}=0$，$\mathrm{waitTime}$ 每加 1，$\mathrm{priority}$ 减 1，实际优先级上升；等待越久越容易被调度。

$\mathrm{waitTime}$ 的作用是“老化”（aging）：使等待进程的优先数随等待时间增加而减小，即调度优先级不断提高。由于 $\mathrm{waitTime}$ 可以无限增大，任何有限 $\mathrm{nice}$ 的进程在等待足够长时间后，其 $\mathrm{priority}$ 都会成为当前最小者而被调度，从而避免饥饿。

**解题切入点**：

把调度器看成一个优先队列：每次弹出 $\mathrm{priority}$ 最小的进程。$\mathrm{priority}=\mathrm{nice}$ 时，所有进程的 key 都是固定的；如果不断有更小的 key 插入，旧元素就永远不会被弹出，这就是饥饿。

所以要避免饥饿，就要让 key 动态变化：等待进程的 key 随等待时间减小，运行进程的 key 随运行时间增大。这本质上是“构造题”：构造一个单调性正确的辅助函数，使等待者获得 aging 加成。

**推演**：

1. 静态情况下：
$$\mathrm{priority} = \mathrm{nice}.$$
若存在 $\mathrm{nice}$ 更小的进程源源不断到达，则 $\mathrm{nice}$ 较大的进程会一直排在后面，发生饥饿。

2. 动态情况下：
$$\mathrm{priority} = \mathrm{nice} + \mathrm{cpuTime} - \mathrm{waitTime}.$$

对于正在运行的进程 $p$，因为 $\mathrm{waitTime}_p = 0$，所以：
$$\mathrm{priority}_p = \mathrm{nice}_p + \mathrm{cpuTime}_p.$$
运行时间越长，$\mathrm{priority}$ 越大，越不容易继续占用 CPU。

对于就绪进程 $q$，因为 $\mathrm{cpuTime}_q = 0$，所以：
$$\mathrm{priority}_q = \mathrm{nice}_q - \mathrm{waitTime}_q.$$
等待时间越长，$\mathrm{priority}$ 越小，越容易被调度。

因此，即使某进程初始 $\mathrm{nice}$ 很大，只要它长期得不到运行，其 $\mathrm{waitTime}$ 不断增加，$\mathrm{priority}$ 不断下降，最终一定会被调度器选中。

**易错点**：

- 方向容易写反：题目是 $\mathrm{priority}$ 越小越优先，所以 $\mathrm{waitTime}$ 前应为负号，$\mathrm{cpuTime}$ 前应为正号。若写成 $\mathrm{priority} = \mathrm{nice} - \mathrm{cpuTime} + \mathrm{waitTime}$，会让运行者更优先、等待者更不优先，反而加剧饥饿。
- 注意状态重置：运行态时 $\mathrm{waitTime}=0$，就绪态时 $\mathrm{cpuTime}=0$，不能把两个时间简单都往公式里加。
- 饥饿不是死锁：饥饿进程处于就绪态，只是长期不被调度；不是阻塞或循环等待。
- $\mathrm{nice}$ 是静态优先数，动态优先数会随 $\mathrm{cpuTime}$、$\mathrm{waitTime}$ 变化；不能说“$\mathrm{nice}$ 动态调整”。

**命题规律**：

408 操作系统喜欢考“饥饿与老化”这一对概念。本题不是死记硬背调度算法，而是给出计数变量，要求自己设计动态优先数公式。核心套路是：

> 等待时间越长，调度优先级越高；运行时间越长，调度优先级越低。

这就像在优先队列中动态维护 key：等待者 key 不断减小，运行者 key 不断增大，最终保证每个进程都不会被无限期插队。这类题还经常结合抢占式调度、时间片、静态优先数 $\mathrm{nice}$ 一起考查。
