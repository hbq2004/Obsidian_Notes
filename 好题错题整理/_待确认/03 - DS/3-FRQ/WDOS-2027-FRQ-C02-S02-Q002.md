# FRQ 第 2 题

![[_Attachments/题目识别/WDOS-2027-FRQ/WDOS-2027-FRQ-C02-S02-Q002_题目.png|题目]]

有三个作业 A,B,C, 它们分别单独运行时的 CPU 和 I/O 占用时间如下图所示.

## DeepSeek V4 Flash Max 解析
**答案**：
由图中数据可得三个作业的服务时间分别为

$$
A=(10,20,10),\quad B=(10,30,20),\quad C=(20,20,20)\ \mathrm{ms}
$$

单独运行总时间：

$$
T_A=10+20+10=40,\quad T_B=10+30+20=60,\quad T_C=20+20+20=60
$$

按短作业优先调度，$A$ 最短先执行；$B,C$ 总时间相同，按常规取 $A\to B\to C$。调度完成后：

$$
C_A=50,\quad C_B=70,\quad C_C=90\ \mathrm{ms}
$$

平均周转时间：

$$
\overline{T}=\frac{50+70+90}{3}=70\ \mathrm{ms}
$$

---

**解题切入点**：
短作业优先本质上就是“按任务总耗时贪心排序”。先把每个作业的总服务时间算出来，等价于算法竞赛中按代价排序后依次处理。  
但每个作业不是不可分割的整体，而是一个状态机：

$$
\mathrm{CPU}\to \mathrm{I/O}\to \mathrm{CPU}
$$

解题时用事件驱动的方式模拟时间线：只关心当前 CPU 被谁占用、哪些作业正在 I/O、哪些作业已经就绪。这类似 BFS/DFS 中维护“状态 + 当前时间”的搜索过程。

---

**推演**：
调度表如下：

| 时间区间 | CPU | 并行 I/O |
|---|---|---|
| $0\sim10$ | $A$ 第 1 段 CPU | — |
| $10\sim20$ | $B$ 第 1 段 CPU | $A$ I/O |
| $20\sim30$ | $C$ 第 1 段 CPU | $A,B$ I/O |
| $30\sim40$ | $C$ 第 1 段 CPU | $B$ I/O |
| $40\sim50$ | $A$ 第 2 段 CPU | $B,C$ I/O |
| $50\sim60$ | $B$ 第 2 段 CPU | $C$ I/O |
| $60\sim70$ | $B$ 第 2 段 CPU | — |
| $70\sim90$ | $C$ 第 2 段 CPU | — |

因此：

$$
C_A=50,\quad C_B=70,\quad C_C=90
$$

三者同时到达，所以周转时间就是完成时间：

$$
\overline{T}=\frac{50+70+90}{3}=70\ \mathrm{ms}
$$

---

**易错点**：
1. 不要把作业看成“一次 CPU 跑完”的整块任务，必须拆成 $\mathrm{CPU}\to\mathrm{I/O}\to\mathrm{CPU}$ 三段。
2. $A$ 的最后一段 CPU 不能在 $t=30$ 立刻开始，因为 CPU 正被 $C$ 占用；CPU 是互斥资源，必须排队。
3. 计算周转时间用的是“完成时刻”，不是“最后一个 CPU 段开始时刻”。例如 $C$ 的 I/O 在 $t=60$ 结束，但还要等 $B$ 释放 CPU，所以 $C$ 最后在 $70\sim90$ 执行，完成时间是 $90$，不是 $80$。
4. 若题目额外指定“单 I/O 设备”，则 I/O 段也要互斥排队；本题按“CPU 单资源、I/O 可并行”处理。

---

**命题规律**：
408 常把调度算法放在“多道程序并发”背景下考查，不直接背定义，而是给一张 CPU/I/O 占用图，要求画 Gantt 图、算周转时间。  
解题本质是时间线模拟：先按 SJF 等策略排序，再用事件驱动方式推进。这很像算法竞赛中的“优先队列 + 事件调度”模型；如果题目再加“单 I/O 设备”条件，就等价于把 CPU 和 I/O 都当作互斥资源，变成双资源匹配问题。
