# MCQ 第 19 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C01-S02-Q019_题目.png|题目]]

下列关于多任务操作系统的叙述中，正确的是 ( ).
$(I)$ 具有并发和并行的特点
$(II)$ 需要实现对共享资源的保护
$(III)$ 需要运行在多 $CPU$ 的硬件平台上
(A) 仅 $I$
(B) 仅 $II$
(C) 仅 $I$、$II$
(D) $I$、$II$、$III$

## DeepSeek V4 Flash Max 解析
**答案**：  
B（仅 II）

**解题切入点**：  
将多任务操作系统视为一个“并发调度器”，类比算法竞赛中多线程并发编程（如使用互斥锁、条件变量管理共享资源）。核心在于区分“并发”与“并行”的概念：并发是逻辑上的同时执行（单 CPU 分时交替），并行是物理上的同时执行（多 CPU 同步）；同时注意多任务环境对共享资源保护的必然需求，这与竞赛中多线程访问全局数据时必须加锁避免数据竞争如出一辙。

**推演**：  
- (I) 并发（concurrency）指多个任务在宏观上同时运行，微观上交替调度；并行（parallelism）要求各任务严格同时执行，依赖多 CPU/多核硬件。多任务操作系统必然支持并发，但并行并非其固有特征（单 CPU 同样可运行多任务系统），故“具有并行的特点”表述不准确，因此 (I) 错误。  
- (II) 多任务下多个进程/线程共享内存、文件等资源，必须实现互斥与同步（如信号量、管程）以保证数据一致性和系统安全，这与竞赛中多线程访问共享数组需加锁才能避免竞态条件完全对应，故 (II) 正确。  
- (III) 多任务操作系统完全可以在单 CPU 平台上通过时间片轮转实现并发（如早期的 Windows 95 和 Linux 都支持单处理器多任务），因此不是必须运行在多 CPU 硬件上，故 (III) 错误。  
综上，仅叙述 (II) 正确，对应选项 B。

**易错点**：  
- 混淆“并发”与“并行”定义，误认为多任务一定需要并行（实际并发是逻辑并行，而并行是物理并行，竞赛中模拟多线程时同样要区分是否依赖多核）。  
- 忽视共享资源保护的必要性，单 CPU 下若不禁用中断或缺少同步机制，进程切换仍可能破坏共享数据，故保护是必要的（竞赛中单线程下不会出现数据竞争，但多任务调度本身就会引入抢占式切换）。  
- 认为多任务必须多 CPU（但 OS 调度从单 CPU 起步，多 CPU 只是增强并行能力而非必要条件）。

**命题规律**：  
考察操作系统基础概念的精准辨析，尤其是“并发 vs 并行”、“多任务 vs 多处理器”等易混点。此类题类似算法竞赛中的“构造题”，要求严格依据定义判断，不能凭直觉或默认“多任务 = 高性能”而掉入陷阱。命题者常将正确与错误叙述糅半真实半夸张组合，需逐条检验。
