# MCQ 第 4 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C04-S02-Q004_题目.png|题目]]

4. 有些操作系统中将文件描述信息从目录项中分离出来,这样做的好处是（ ）

(A) 减少读文件时的 I/O 信息量
(B) 减少写文件时的 I/O 信息量
(C) 减少查找文件时的 I/O 信息量
(D) 减少复制文件时的 I/O 信息量

## DeepSeek V4 Flash Max 解析
**答案**：
C。将文件描述信息（如 FCB/inode）从目录项中分离后，目录项只保留“文件名 + 指向描述信息的索引”。目录项变小，按名查找或路径解析时读入的目录块变少，因此减少查找文件时的 I/O 信息量。

**解题切入点**：
抓住“目录查找”与“文件数据读写”两个阶段。目录项本质上是文件名到文件元数据的映射项；查找文件时，系统要把目录项从磁盘读进内存并逐个比较文件名。算法竞赛类比：扫描一个大对象结构体数组的代价很高，不如先构建轻量级索引 `(key, id)`，命中后再去取完整对象。这里的“描述信息分离”就是给目录项做瘦身。

**推演**：
设目录项大小为 $s$，磁盘块大小为 $B$，目录中有 $n$ 个目录项。查找目录时读取的磁盘块数正比于

$$
\frac{n s}{B}
$$

所以 $s$ 越小，查找文件时的 I/O 量越小。分离前，$s$ 近似为“文件名 + 完整 FCB”；分离后，$s$ 近似为“文件名 + inode 编号”，是明显缩减。

选项排除：

- 读文件：`read` 在文件打开后执行，使用打开文件表和 inode 中的数据块地址，不重新扫描目录项，故 A 不是直接收益。
- 写文件：同理，`write` 访问的是已定位的数据块，不依赖目录项是否瘦身，故 B 不是。
- 查找文件：路径解析要逐级扫描目录项，目录项瘦身后每个目录块可容纳更多项，查找 I/O 减少，故 C 正确。
- 复制文件：复制的主要 I/O 是源文件数据块读取和目标文件数据块写入；目录项只在 open/create 时参与少量查询，不是核心，故 D 不是。

**易错点**：
- 混淆“读/写文件”和“打开/查找文件”。`read`/`write` 是打开后的数据读写，目录项不在主路径上。
- 把“文件描述信息”当成“文件内容”。分离影响的是元数据组织，不改变文件数据量。
- 看到“减少 I/O”就选 A/B/D；但题目问的是“从目录项中分离”的好处，收益应发生在使用目录项最多的“查找文件/目录扫描”阶段。
- 不要认为分离后多读一次 inode 就一定更慢：目录项瘦身减少的是大量目录块扫描；inode 可以按需读取并缓存，目录很大时净收益明显。

**命题规律**：
408 常以“目录项”为切入点考查文件系统的索引结构设计。类似考法：目录项由哪些部分组成、inode 分离的好处、硬链接为何能共享 inode。解题套路是把一次文件访问拆成“路径检索”和“数据读写”两段：前段看目录项，后段看数据块；凡把后段开销归因于目录项设计，多为干扰项。
