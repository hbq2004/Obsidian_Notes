# MCQ 第 3 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C04-S02-Q003_题目.png|题目]]

3. FAT32 的文件目录项不包括（ ）.
(A) 文件名
(B) 文件访问权限说明
(C) 文件控制块的物理位置
(D) 文件所在的物理位置

## DeepSeek V4 Flash Max 解析
**答案**：
C

**解题切入点**：
FAT32 中“文件目录项”本身就是该文件的 FCB，而不是“文件名 + 指向 FCB 的指针/索引”。这就像邻接表里直接把顶点信息存放在链表结点中，不会再多存一个“指向自己地址”的字段；目录项保存的是文件数据的起始簇号，而不是 FCB 自己的物理位置。

**推演**：
FAT32 目录项占 $32\text{ B}$，核心字段可抽象为：

$$
\underbrace{\text{文件名} + \text{扩展名}}_{8+3\text{ B}},\quad
\underbrace{\text{属性字段}}_{1\text{ B}},\quad
\underbrace{\text{时间字段}}_{若干\text{ B}},\quad
\underbrace{\text{首簇号（高/低）}}_{4\text{ B}},\quad
\underbrace{\text{文件大小}}_{4\text{ B}}
$$

- A 文件名：包含在文件名与扩展名字段中。
- B 文件访问权限说明：FAT32 目录项中的“属性字段”包含只读、隐藏、系统、归档等标志，题目语境下属于目录项内容。
- D 文件所在的物理位置：目录项中保存文件的“首簇号”，后续簇通过 FAT 链式查找，相当于链表头指针。
- C 文件控制块的物理位置：目录项本身就是 FCB，不需要在自身内部保存“FCB 存放在哪里的地址”。这个字段是多余的，类似链表结点里不会存放“自己这个结点的地址”。

**易错点**：
- 容易把 C 和 D 混为一谈。D 是“文件数据的物理位置”，对应 FAT 中的首簇号；C 是“FCB 自身的物理位置”，在 FAT32 中并未单独存放。
- 不要误以为 FAT32 完全没有“访问权限说明”。FAT32 没有的是 UNIX 那样完整的多用户 rwx/ACL 权限，但它有属性字段，比如只读位就是一种权限说明。
- FAT32 目录项就是 FCB，不是“文件名 + inode 号”这种间接结构；若类比图论，就是“顶点信息直接存在邻接点里，而不是存一个 vertex 编号再二次查表”。

**命题规律**：
408 喜欢在“目录项 / FCB / inode / 文件物理位置”这几个概念之间设辨析题，尤其对比 FAT 与 UNIX 的目录实现。以后遇到“某结构不包括什么”，先列字段、再找“自引用字段”；像“FCB 的物理位置”这种“自己存自己地址”的选项，往往是干扰项。
