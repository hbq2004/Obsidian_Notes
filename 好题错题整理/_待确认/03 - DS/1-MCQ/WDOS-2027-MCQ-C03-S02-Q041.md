# MCQ 第 41 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C03-S02-Q041_题目.png|题目]]

假定有一个请求分页存储管理系统,测得系统各相关设备的利用率为:CPU的利用率为 10%,磁盘交换区的利用率为 99.7%，其他 I/O 设备的利用率为 5%。下面（ ）措施将可能改进 CPU 的利用率。
$I$.增大内存的容量
$II$.增大磁盘交换区的容量
$III$.减少多道程序的度数
$IV$.增加多道程序的度数
$V$.使用更快速的磁盘交换区
$VI$.使用更快速的 CPU
(A). $I$、$II$、$III$、$IV$
(B). $I$、$III$
(C). $II$、$III$、$V$
(D). $II$、$VI$

## DeepSeek V4 Flash Max 解析
**答案**：  
B（$I$、$III$）

**解题切入点**：  
$U_{\mathrm{CPU}}=10\%$ 很低，$U_{\mathrm{swap}}=99.7\%$ 几乎饱和，$U_{\mathrm{I/O}}=5\%$ 很低。这说明系统不是普通 I/O 密集，也不是 CPU 计算密集，而是大量时间花在请求分页的换页/交换上，即典型的“抖动”（thrashing）。

缺页率 $p$ 很高时，有效访问时间  
$$
T_{\mathrm{EAT}}=(1-p)T_m+pT_{pf},\quad T_{pf}\gg T_m
$$  
会急剧增大，CPU 主要在等待页面调入。因此改进方向是降低缺页率 $p$，让每个进程的工作集尽量驻留内存。

类比算法竞赛：同时跑太多搜索分支，每个分支的工作集都超过 cache/visited 容量，导致每次状态转移都 miss。要么扩大缓存（加内存），要么减少并发搜索分支（减少多道程序度）。

**推演**：  
1. 系统状态诊断：磁盘交换区利用率高达 $99.7\%$，其他 I/O 只有 $5\%$，说明瓶颈不是普通设备，而是频繁换页；CPU 只有 $10\%$，说明有效执行被缺页打断得太厉害。

2. $I$ 增大内存容量：物理页框数增加，缺页率 $p$ 下降，$T_{\mathrm{EAT}}$ 随之下降，CPU 能有更多机会执行有效指令。可行。

3. $III$ 减少多道程序的度数：物理内存固定时，进程数 $N$ 减少，每个进程平均可得页框数 $F/N$ 增加，工作集更容易全部驻留，缺页率下降。这相当于减少同时抢占缓存的搜索分支数，可行。

4. 排除其余项：  
   - $II$ 增大磁盘交换区容量：不能增加内存页框，也不能降低缺页率；交换区容量不是当前瓶颈。  
   - $IV$ 增加多道程序的度数：总工作集超过物理内存，抖动会更严重。  
   - $V$ 使用更快速的磁盘交换区：只缩短单次换页时间，不改变缺页率；抖动时主要矛盾是“缺页太频繁”，不是“单次换页太慢”。  
   - $VI$ 使用更快速的 CPU：CPU 本来就大量空闲，更快 CPU 不能减少缺页，不能解决页框不足的问题。

**易错点**：  
- 不要把磁盘交换区的“利用率”理解为“空间使用率”。题干中的 $99.7\%$ 是设备忙碌率，不是容量快满了。  
- 不要认为多道程序度越高 CPU 利用率越高。CPU 利用率随多道程序度先升后降，超过物理内存承载能力后急剧下降。  
- 不要选“更快的磁盘”或“更快的 CPU”。它们是“卡常数”式的优化，而当前问题是“复杂度级别”的缺页风暴。  
- 注意“其他 I/O 设备利用率 $5\%$”这个信号：它排除了普通 I/O 密集场景，帮助定位到换页瓶颈。

**命题规律**：  
408 常给一组设备利用率，让考生反推系统瓶颈并选择优化措施。本质是考请求分页中的抖动与工作集模型：CPU 利用率低、换页设备利用率高、其他 I/O 利用率低，应优先选“增大内存容量”和“减少多道程序度”。这类似于先判断算法瓶颈是复杂度还是常数：加内存/减并发是降复杂度，换更快磁盘/CPU 只是优化常数。
