# MCQ 第 22 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S03-Q022_题目.png|题目]]

在使用互斥锁进行同步互斥时，下列（ ）情况会导致死锁.
(A) 一个线程对同一个互斥锁连续加锁两次
(B) 一个线程尝试对一个已加锁的互斥锁再次加锁
(C) 两个线程分别对两个不同的互斥锁先后加锁,但顺序相反
(D) 一个线程对一个互斥锁加锁后忘记解锁

## DeepSeek V4 Flash Max 解析
**答案**：
C（按 408 严格定义）。

死锁是多个执行流之间形成“循环等待”，而不是“某一线程自己卡住”或“某线程忘记释放锁”。本题中只有 C 明确构成了双向等待环。

**解题切入点**：
把问题看成图论判环：每个线程是一个节点，线程等待谁持有的锁，就画一条有向边到谁。  
这种思路和算法竞赛里的“拓扑排序判环”完全一致：若等待图中存在环，则环上的线程都在等待对方释放资源，必然死锁。

C 中：

\[
T_1 \text{ 持有 } M_A,\ T_1 \text{ 等待 } M_B
\]

\[
T_2 \text{ 持有 } M_B,\ T_2 \text{ 等待 } M_A
\]

写成等待图就是：

\[
T_1 \to T_2,\qquad T_2 \to T_1
\]

这是一个长度为 2 的有向环，满足死锁的四个必要条件：互斥、持有并等待、不可剥夺、循环等待。

**推演**：

- A：一个线程对同一个互斥锁连续加锁两次，本质是“不可重入锁”的自等待。它没有形成多个执行流之间的循环等待，按 408 严格定义不构成死锁。
- B：一个线程尝试对已加锁的互斥锁再次加锁，可能只是正常的阻塞等待；若持有者最终解锁，等待线程可以继续运行。没有环，就不是死锁的充分条件。
- C：两个线程按相反顺序加两把锁，会形成：

\[
T_1 \to T_2 \to T_1
\]

的等待环，因此必然导致死锁。

- D：加锁后忘记解锁，只是让锁一直被占用，其他线程可能永远等不到锁；但锁的持有者并没有在等待别的锁，不形成循环等待，所以不是死锁。

**易错点**：

1. 不要把“同一线程连续加锁两次”误判为 408 死锁。编程中常称 self-deadlock，但 408 的死锁判据是多个执行流之间的循环等待。
2. 不要把“ lock 阻塞”直接当成死锁。阻塞只是等待一个可能被释放的资源，而死锁必须形成环。
3. 不要把“忘记解锁”当成死锁。D 是资源未释放导致的永久阻塞，等价于“占着资源不释放”，但没有等待环。
4. 做题时优先画等待图：有环才可能死锁。这就像竞赛里用拓扑排序判环：如果环上节点永远无法被消掉，就是死锁。

**命题规律**：
408 常把“死锁”和“互斥锁/信号量”结合，考查从加锁顺序中识别循环等待。本质就是图论判环：多把锁、多个线程时，优先检查是否出现反向加锁顺序。  
掌握死锁四条件 + 画等待图，即可快速排除 A、B、D，锁定 C。
