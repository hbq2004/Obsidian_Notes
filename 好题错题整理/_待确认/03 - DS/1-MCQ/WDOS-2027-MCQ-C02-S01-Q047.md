# MCQ 第 47 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S01-Q047_题目.png|题目]]

47. 进程创建时,不需要做的是( )
(A) 填写一个该进程的进程表项
(B) 分配该进程适当的内存
(C) 将该进程插入就绪队列
(D) 为该进程分配 $CPU$

## DeepSeek V4 Flash Max 解析
**答案**：
D。进程创建时不需要分配 CPU。进程创建只是让一个进程“存在”并具备被调度的资格，真正分配 CPU 是调度器在调度阶段做的事。

**解题切入点**：
区分“创建过程”和“调度过程”。创建过程类似算法竞赛中的“构造任务”：先申请记录（$PCB$）、分配内存等资源、初始化状态，然后把它放入待处理队列；真正从队列中取出并分配 CPU 是调度器（dispatcher）的职责，不是构造阶段里的步骤。

**推演**：
进程创建的典型步骤：

1. 申请空白 $PCB$，填写进程表项。  
   对应 (A)，必须做。

2. 为该进程分配运行所需的资源，如内存、文件、设备等。  
   对应 (B)，必须做，否则进程无法加载和执行。

3. 初始化 $PCB$：设置进程标识符、程序计数器、栈指针、优先级、初始状态等。

4. 将新进程插入就绪队列，等待调度器选择。  
   对应 (C)，必须做。

5. 调度器从就绪队列中选中该进程后，才通过上下文切换把 CPU 分配给它。  
   对应 (D)，不是创建时做的，而是进程调度阶段做的。

状态转换可以表示为：

$$
\text{创建} \to \text{就绪队列} \to \text{调度选中} \to \text{运行}
$$

所以创建后进程进入的是就绪态，而不是运行态；只有被调度后才获得 CPU。

**易错点**：
- 容易误选 C，认为“创建出来的进程不一定马上插入就绪队列”。但本题按标准进程创建流程，创建完成后插入就绪队列是必要步骤；而分配 CPU 一定是调度阶段的事。
- 不要把“填写 $PCB$”和“初始化 $PCB$”混为一谈，两者都是创建时做的。
- 类比竞赛：你可以“创建”一个任务并把它 push 进优先队列，但不会在创建时立刻给这个任务分配 CPU 核心；核心分配是调度器 pop 出队之后才发生的。

**命题规律**：
408 常以概念辨析题考查进程生命周期：创建、就绪、运行、阻塞/等待、终止。核心是区分“创建态/就绪态”与“运行态”的边界，以及“创建过程”与“调度过程”的分工。遇到“何时分配 CPU”“进程何时进入运行态”，一律对应“调度器从就绪队列选中该进程并完成上下文切换之后”，而不是创建时。
