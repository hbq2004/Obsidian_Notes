# MCQ 第 49 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S03-Q049_题目.png|题目]]

有两个并发执行的进程 $P_1 和进程 $P\_2，共享初值为 $1 的变量 $x. $P_1 对 $x 加 $1，$P\_2 对 $x 减 $1. 加 $1 和减 $1 操作的指令序列分别如下：

```text
// 加 1 操作                 // 减 1 操作
load  R1,x //取 x 到寄存器 R1   load  R2,x //取 x 到寄存器 R2
inc   R1                     dec   R2
store x,R1 //将 R1 的内容存入 x  store x,R2 //将 R2 的内容存入 x
```

两个操作完成后，$x 的值( )

(A) 可能为 $-1 或 $3
(B) 只能为 $1
(C) 可能为 $0,1 或 $2
(D) 可能为 $-1,0,1 或 $2

## DeepSeek V4 Flash Max 解析
**答案**：
（C）可能为 $0,1$ 或 $2$。最终 $x$ 的取值集合为
$$
x_{\text{final}}\in\{0,1,2\}.
$$

**解题切入点**：
“加 1/减 1”不是一条原子指令，而是“读变量到寄存器、改寄存器、写回变量”三步。并发执行时，两个进程的指令可以任意交错；这相当于在两个长度为 $3$ 的指令链上做拓扑排序。因为只有 `store` 会真正改变共享变量 $x$，所以最终值取决于最后一次 `store` 写回了什么。

**推演**：
记 $P_1$ 的三条指令为 $a_1,a_2,a_3$，$P_2$ 的三条指令为 $b_1,b_2,b_3$，其中 $a_1,b_1$ 是 load，$a_2$ 是加 $1$，$b_2$ 是减 $1$，$a_3,b_3$ 是 store。

- 若最后一次 store 是 $a_3$：$a_1$ 读 $x$ 时，$P_2$ 的 store 若已发生，只能把初值 $1$ 变成 $0$；若未发生，$x$ 仍是 $1$。所以 $P_1$ 读到的 $x\in\{0,1\}$，$a_3$ 写回 $1$ 或 $2$。
- 若最后一次 store 是 $b_3$：$b_1$ 读 $x$ 时，$P_1$ 的 store 若已发生，只能把初值 $1$ 变成 $2$；若未发生，$x$ 仍是 $1$。所以 $P_2$ 读到的 $x\in\{1,2\}$，$b_3$ 写回 $0$ 或 $1$。

因此最后写者能写出的值只有
$$
\{1,2\}\cup\{0,1\}=\{0,1,2\},
$$
故 $x=-1$ 或 $x=3$ 不可能。

且三个值都能构造出来：
$$
a_1a_2b_1b_2a_3b_3 \Rightarrow x=0,\quad
a_1a_2a_3b_1b_2b_3 \Rightarrow x=1,\quad
a_1a_2b_1b_2b_3a_3 \Rightarrow x=2.
$$

**易错点**：
- 容易把“加 1/减 1”当成原子操作，认为一加一减抵消为 $1$；实际上每条机器指令之间都可以发生切换。
- 容易忽略 `store` 覆盖：例如 $P_2$ 先写 $0$，$P_1$ 后写 $2$，最终不是代数结果 $1$，而是最后一条 `store` 的结果。
- 不要把寄存器值范围想宽：$P_1$ 读不到自己尚未写出的 $2$，$P_2$ 也读不到自己尚未写出的 $0$，所以不会出现 $x=-1$ 或 $3$。
- 寄存器 $R_1,R_2$ 是各进程私有的，`inc R1` 不会影响 $R_2$。

**命题规律**：
408 常以“共享变量 + 指令级交错”考查并发与同步的必要性。核心是识别 `load-store` 不是原子操作。这类题与算法竞赛中“构造合法交错 / 状态搜索”类似：先证明不可能值，再构造可行值。若题目用锁或 `PV` 操作保护整个读改写过程，则结果唯一；不加锁就会产生 lost update 等竞态。
