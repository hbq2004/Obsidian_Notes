# MCQ 第 25 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C01-S03-Q025_题目.png|题目]]

定时器产生时钟中断后，由时钟中断服务程序更新的部分内容是( ).  
$I.$ 内核中时钟变量的值  
$II.$ 当前进程占用 $CPU$ 的时间  
$III.$ 当前进程在时间片内的剩余执行时间  

(A) 仅 $I$、$II$  
(B) 仅 $II$、$III$  
(C) 仅 $I$、$III$  
(D) $I$、$II$、$III$

## DeepSeek V4 Flash Max 解析
**答案**：  
**D**（$I$、$II$、$III$ 均更新）。

**解题切入点**：  
把内核看作一个状态机，每个进程是一个状态节点；时钟中断就是系统每个 tick 自动调用一次的 `update()`。它不做复杂搜索，只更新当前层的时间字段：全局时钟 `++`，当前进程累计 CPU 时间 `++`，当前进程剩余时间片 `--`。所以看到“定时器产生时钟中断”，应直接联想“所有以 tick 为基本单位的时间相关状态，都要在这里刷新”。

**推演**：  
时钟中断发生后，中断服务程序在核心态运行，能访问内核全局变量和当前进程的 PCB。设一个 tick 为 $\tau$，则每次时钟中断会做：

$$
\begin{cases}
T_{\text{kernel}} \gets T_{\text{kernel}} + \tau,\\
C_{\text{current}} \gets C_{\text{current}} + \tau,\\
R_{\text{current}} \gets R_{\text{current}} - \tau.
\end{cases}
$$

其中， $T_{\text{kernel}}$ 对应内核中时钟变量的值； $C_{\text{current}}$ 对应当前进程占用 CPU 的时间； $R_{\text{current}}$ 对应当前进程在时间片内的剩余执行时间。

还要注意：时间片剩余减到 0 时，时钟中断服务程序会设置“需要调度”标志或触发调度，但真正的进程切换通常发生在中断返回路径或调度程序中。无论是否发生切换，$I、II、III$ 三项的更新都发生在时钟中断服务程序内部。

**易错点**：  
- 容易漏选 $III$：以为时间片剩余执行时间只在进程切换时更新。实际上每个 tick 都要递减它，减到 0 才触发调度。
- 容易漏选 $II$：以为当前进程占用 CPU 的时间是退出或切换时结算。实际上每个 tick 都要做进程 CPU 时间记账。
- 不要把 $II$ 和 $III$ 混为同一项：$II$ 是累计“已经用了多少 CPU 时间”，$III$ 是“本次时间片还剩多少”，方向不同、用途不同。
- 不要认为时钟中断一定会引起进程切换；只有时间片耗尽或更高优先级任务需要抢占时，才会在中断返回前调度。

**命题规律**：  
408 常考“中断服务程序 vs 调度程序”的职责边界。本题本质是问：一个 tick 到达后，哪些时间字段要刷新。标准口径可总结为“一个 tick，三项更新，一次判断”：更新系统时钟、进程 CPU 时间、剩余时间片；判断剩余时间片是否为 0。后续题也可能进一步考“真正完成切换的时机”，要特别注意区分“更新状态”和“执行切换”这两个动作。
