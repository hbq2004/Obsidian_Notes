# MCQ 第 18 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C03-S01-Q018_题目.png|题目]]

多进程在主存中彼此互不干扰的环境下运行,操作系统是通过$(\quad)$来实现的.
(A) 内存分配
(B) 内存保护
(C) 内存扩充
(D) 地址映射

## DeepSeek V4 Flash Max 解析
**答案**：

B. 内存保护

**解题切入点**：

题干的关键词是“彼此互不干扰”。多进程同时驻留主存时，真正要解决的问题是：一个进程不能越界访问或修改另一个进程的内存区域。操作系统提供这种隔离能力的功能正是**内存保护**。

- 内存分配：负责把内存分给进程，但不保证进程不会越界。
- 内存映射：负责逻辑地址到物理地址的转换，不直接做越界拦截。
- 内存扩充：通过虚拟内存等手段扩大可用内存空间，与“互不干扰”无关。
- 内存保护：在每次内存访问时检查地址是否合法，防止进程间互相干扰。

因此选 B。

**推演**：

可以把主存看成一个很大的数组，多个进程是数组中被分配的多个子区间。内存分配只是告诉每个进程“你的区间是 $[l_i, r_i]$”，但如果没有保护机制，进程 $P$ 完全可以越界访问 $Q$ 的区间。这就好比 C/C++ 中数组越界不一定会被立刻发现，可能悄悄踩坏别人的数据。

内存保护相当于给每次内存访问加上一个边界检查：

$$
\text{check}(addr): \quad base \le addr < base + limit
$$

如果不满足条件，硬件抛出异常，操作系统终止该进程。于是多个进程即使物理内存相邻，也无法互相影响。

用算法竞赛的类比来说：

- 内存分配 $\approx$ 划分区间；
- 地址映射 $\approx$ 坐标离散化 / 下标重映射；
- 内存保护 $\approx$ 搜索过程中对每个状态做合法性剪枝。

只有“剪枝”才能保证状态不会跑到别人的空间里；没有保护机制，分配和映射做得再好，也挡不住一次越界访问。

**易错点**：

1. 误选 A“内存分配”：分好内存不等于隔离。分配只解决“有没有空间”的问题，不解决“能不能越界”的问题。
2. 误选 D“地址映射”：地址映射解决的是逻辑地址到物理地址的对应关系，但映射本身不检查越界。不过内存保护可以借助地址映射机制落地，比如页表项中的权限位、基址/限长寄存器。
3. 误选 C“内存扩充”：内存扩充对应虚拟内存、覆盖、交换，目的是让大作业能在小内存中运行，和进程间隔离无关。
4. 注意“内存保护”不是“数据加密保护”，而是地址空间隔离与访问控制，防止越界访问和越权操作。

**命题规律**：

这是操作系统内存管理部分的“功能对应型”选择题。命题人常把四个功能放在一起：

- 题干出现“互不干扰”“隔离”“越界”“安全” $\Rightarrow$ 内存保护；
- 题干出现“逻辑地址转物理地址” $\Rightarrow$ 地址映射；
- 题干出现“大作业在小内存运行” $\Rightarrow$ 内存扩充；
- 题干出现“分配策略”“分区”“页框分配” $\Rightarrow$ 内存分配。

408 中这种题往往不难，但容易把“地址映射”和“内存保护”混淆。本质上，地址映射是机制，内存保护是目的；做题时抓住“互不干扰”这个目的，就能快速锁定答案。
