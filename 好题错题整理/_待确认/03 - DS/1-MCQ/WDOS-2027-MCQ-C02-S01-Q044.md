# MCQ 第 44 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S01-Q044_题目.png|题目]]

44.（ ）必会引起进程切换.

(A) 一个进程创建后,进入就绪态
(B) 一个进程从运行态变为就绪态
(C) 一个进程从阻塞态变为就绪态
(D) 以上答案都不对

## DeepSeek V4 Flash Max 解析
**答案**：  
B  

**解题切入点**：  
进程状态转换可看作一个有限状态机，其中 $运行态$ 是唯一活跃执行的状态。进程切换（即上下文切换）必然发生在当前运行进程放弃 CPU 或被迫让出 CPU 的时刻。从运行态变为就绪态是唯一一个由“占用 CPU”主动或被动变为“等待 CPU”的状态转移，这要求调度程序必须从就绪队列中选取下一个进程，从而必定引起进程切换。类似在算法竞赛中，当搜索树的当前节点被标记为“待扩展”并放入队列时，必须立即从队列中取出下一个节点继续搜索，否则搜索停滞。  

**推演**：  
- 选项 A：一个进程创建后进入就绪态。这只是在就绪队列中增加一个新进程，当前运行进程可能仍在执行，不会强制切换。好比在 BFS 中向队列尾部加入一个新状态，但当前状态仍继续处理，不会立即切换。  
- 选项 B：一个进程从运行态变为就绪态。此转移通常意味着时间片用完或被更高优先级进程抢占，当前进程不再占用 CPU，必须从就绪队列中另选一个进程投入运行，因此必然发生进程切换。这类似于在 DFS 中当前节点搜索时间耗尽，必须从栈中弹出下一个节点。  
- 选项 C：一个进程从阻塞态变为就绪态。这只是进程等待的事件完成，它重新进入就绪队列，但并未立即夺取 CPU，除非采用抢占式调度且新就绪进程优先级更高，否则不一定会引起切换。好比一个先前被阻塞的线程条件满足，它只是被放入就绪队列，并不强制中断当前正在运行的任务。  
- 选项 D：显然 B 正确，故 D 错误。  

**易错点**：  
1. 误以为进程创建后必须立即执行，从而认为 A 会引起切换。实际上创建后进入就绪态，调度时机取决于当前 CPU 是否空闲或调度策略。  
2. 混淆“阻塞→就绪”与“就绪→运行”的区别，认为只要状态变化就会切换，忽略了只有“运行态”离开 CPU 才强制切换。  
3. 忽略“从运行态变为就绪态”是唯一一个主动或被动放弃 CPU 且仍可被调度的状态，其他转移均不涉及 CPU 释放。  

**命题规律**：  
本类题考察进程状态转换与进程调度、上下文切换的关系。常以“必然引起进程切换”或“可能引起进程切换”的单选题形式出现，通常正确选项是“从运行态变为就绪态”或“从运行态变为阻塞态”（后者是主动等待，也必然引起切换，但本题选项未包含）。注意在抢占式调度中，“阻塞→就绪”也可能引起切换，但并非必然，而“运行→就绪”在任何调度算法下都必然导致切换（因为 CPU 已释放）。命题者常利用“必”与“可能”的语义设置陷阱，需仔细辨析。
