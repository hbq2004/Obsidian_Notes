# MCQ 第 28 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C05-S03-Q028_题目.png|题目]]

下列选项中，不能改善磁盘设备 $I/O$ 性能的是 ( ). 
(A) 重排 $I/O$ 请求次序
(B) 在一个磁盘上设置多个分区
(C) 预读和滞后写
(D) 优化文件物理块的分布

## DeepSeek V4 Flash Max 解析
**答案**：
$$\boxed{\text{B}}$$
不能改善磁盘设备 I/O 性能的是 **在一个磁盘上设置多个分区**。  
重排 I/O 请求次序、预读和滞后写、优化文件物理块的分布，分别对应磁盘调度、磁盘缓存/缓冲、文件物理布局优化，都能直接减少磁头寻道距离、旋转延迟或 I/O 次数；分区只是逻辑划分，不是设备级性能优化手段。

**解题切入点**：
把磁盘 I/O 的耗时拆成物理瓶颈：
$$T = T_{\text{seek}} + T_{\text{rotation}} + T_{\text{transfer}}$$
凡是能降低机械臂移动距离、减少旋转等待时间、合并或缓存 I/O 的选项，都是“改善性能”。  
用算法竞赛的感觉来类比：

- 重排 I/O 请求次序 $\approx$ 把乱序访问离线排序后贪心处理；
- 预读和滞后写 $\approx$ 预计算、缓存、批量摊销；
- 优化文件物理块分布 $\approx$ 把相关数据放到连续内存里提高 cache 局部性；
- 设置多个分区 $\approx$ 只是改了 namespace/目录结构，没有改变底层计算复杂度。

所以题目等价于：哪个操作没有触及瓶颈操作本身？

**推演**：

- **(A) 重排 I/O 请求次序**  
  这是磁盘调度。比如 SCAN、C-SCAN 等让磁头按一定方向顺序处理请求，能显著减少磁头来回移动的总距离。类比算法竞赛中“按某种顺序排序后再扫描”，可以降低最坏访问开销。

- **(B) 在一个磁盘上设置多个分区**  
  分区只是把一块磁盘的地址空间切成若干逻辑区域，不改变盘片转速、磁头移动速度和单次传输效率。  
  相反，如果频繁跨分区访问，磁头往往要在相距更远的区域之间移动，可能额外增加寻道时间。它主要用于管理、隔离、多系统共存，不是磁盘 I/O 性能优化手段。

- **(C) 预读和滞后写**  
  预读把未来可能要用的块提前读入内存，提高 cache 命中率；滞后写把多次零散写操作先在缓存中合并，再统一写回磁盘，从而减少实际 I/O 次数。类比算法中的“批量处理”和“惰性更新”，能有效摊还固定开销。

- **(D) 优化文件物理块的分布**  
  让同一文件或相关文件的物理块尽量连续、靠近，例如使用连续分配、簇式分配、把目录与文件数据放在相近柱面，都能减少磁头跳跃距离。类比把稀疏邻接表重排成连续数组，增加 cache/磁盘局部性。

**易错点**：

- **不要认为“多分区 = 多磁盘并行”**。同一个磁盘上的多个分区仍共享同一套机械臂和盘片，不能并行提高带宽；真正的并行需要多个独立磁盘或 RAID。
- **不要把“分区”和“优化物理块分布”混为一谈**。分区是逻辑边界，优化物理块分布是让相关块在物理位置上靠近，前者不直接改善寻道距离。
- **注意“滞后写”虽然可能带来掉电丢数据的风险，但它确实是性能优化手段**。它把多次写合并成一次大的写操作，减少 I/O 次数。
- **不要用特殊工程场景反驳**。分区在某些 workload 下可能间接影响性能，但 408 语境下它不是教材列出的磁盘设备 I/O 性能改善方法。

**命题规律**：
408 常考“能/不能改善某种性能”的辨析题，本质上考查对操作系统经典优化机制的准确记忆。  
正确选项往往属于磁盘调度、磁盘缓存、文件物理块布局这几个核心模块；干扰项通常来自管理性功能，如分区、格式化、逻辑设备命名等。  
做题时建议先写出瓶颈公式，再逐个检查选项是否作用于瓶颈。算法竞赛类比：一个 trick 是否有效，要看它是否降低了关键路径的复杂度；如果只是改了外层组织形式，却没有优化核心循环，它大概率就是干扰项。
