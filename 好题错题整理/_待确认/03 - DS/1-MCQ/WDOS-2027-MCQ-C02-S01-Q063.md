# MCQ 第 63 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S01-Q063_题目.png|题目]]

下列选项中,会导致进程从执行态变为就绪态的事件是( ).
(A) 执行 $P(wait) 操作
(B) 申请内存失败
(C) 启动 $I/O 设备
(D) 被高优先级进程抢占

## DeepSeek V4 Flash Max 解析
**答案**：  
D（被高优先级进程抢占）

**解题切入点**：  
从进程状态转换图出发，执行态（Running）$\rightarrow$ 就绪态（Ready）意味着进程被剥夺 CPU 但未进入等待，类似于算法竞赛中状态机（State Machine）的“非阻塞式回退”。本题等价于问：哪个事件会强制进程“挂起”当前执行但保留继续运行资格？对应抢占式调度中的“被动出让 CPU”。

**推演**：  
设进程当前处于执行态，分析各选项：  
- (A) 执行 $P(wait)$ 操作：若信号量 $S \leq 0$，进程进入阻塞态（Blocked），即 Running $\rightarrow$ Blocked；若 $S > 0$ 则仍为 Running，不会转为 Ready。因此不必然导致 Running $\rightarrow$ Ready。  
- (B) 申请内存失败：通常导致进程阻塞（等待内存资源），即 Running $\rightarrow$ Blocked，也可能进入挂起态，但非 Ready。  
- (C) 启动 $I/O$ 设备：进程发出 $I/O$ 请求后需等待 $I/O$ 完成，必然进入阻塞态，即 Running $\rightarrow$ Blocked。  
- (D) 被高优先级进程抢占：在抢占式调度中，当前进程时间片未用完但被更高优先级进程抢走 CPU，此时进程已拥有除 CPU 外所有资源，只需回到就绪队列等待下次调度，即 Running $\rightarrow$ Ready。  

因此，只有事件 (D) 符合题意。

**易错点**：  
1. 混淆“阻塞”与“就绪”：阻塞是等待某资源（如 $I/O$、内存），就绪是只等 CPU。刷题时容易将 $P$ 操作、$I/O$ 等导致阻塞的事件误认为进入就绪态，类似于在 DFS 中混淆“回溯”与“剪枝”。  
2. 对 $P$ 操作的理解：认为执行 $P$ 操作一定会阻塞，实际上只有当信号量小于 $0$ 时才阻塞，否则仅进行减 $1$ 操作，进程仍运行。但在工业级 OS 中，$P$ 通常是系统调用，可能引起调度，但考研层面通常只考虑信号量不足时的阻塞行为。  
3. 忽略“被抢占”是导致 Running $\rightarrow$ Ready 的唯一典型情况（另一常见情况是时间片用完，但本题未出现）。

**命题规律**：  
- 基础题，考查进程状态转换的条件，属于 OS 必考概念，常与调度算法、信号量结合出题。  
- 在 408 中，这类题通常以“下列事件中会导致进程状态改变的是”或“从运行态变为就绪态的事件是”等形式出现，选项常包含 $P/V$ 操作、$I/O$、中断、抢占等。  
- 对于有算法竞赛背景的考生，可类比图论中的状态转移：就绪态 $\approx$ 顶点未访问但已入队，阻塞态 $\approx$ 顶点被阻塞需等待某条件，执行态 $\approx$ 当前正在访问的顶点。抢占相当于当前顶点被更高优先级的顶点替代，但原顶点仍保留在队列中。
