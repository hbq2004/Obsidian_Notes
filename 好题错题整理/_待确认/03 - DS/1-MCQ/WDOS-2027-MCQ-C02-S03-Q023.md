# MCQ 第 23 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S03-Q023_题目.png|题目]]

用来实现进程同步与互斥的 $PV$ 操作实际上是由( )过程组成的.
(A) 一个可被中断的
(B) 一个不可被中断的
(C) 两个可被中断的
(D) 两个不可被中断的

## DeepSeek V4 Flash Max 解析
**答案**：
选 D。$PV$ 操作并不是一个不可分割的“大操作”，而是 $P$、$V$ 两个原语的合称。$P$ 操作和 $V$ 操作各自都必须是对信号量的原子操作，即各自都“不可被中断”。因此 $PV$ 操作由“两个不可被中断的过程”组成。

**解题切入点**：
把题目拆成两个独立判断：

1. 数量：$PV$ 包含 $P$ 操作和 $V$ 操作，数量为 2；
2. 性质：原语（primitive）不可被中断，否则多个进程同时操作信号量会破坏互斥。

竞赛类比：并发时如果写 `if (!vis[u]) { vis[u] = true; ... }`，若不把“检查 + 标记”合并成原子操作，两个线程可能同时通过检查。$P$ 操作在信号量上做的事情与此相同，必须原子完成。

**推演**：
用信号量 $S$ 表示：

$$
P(S):\quad S = S - 1;\ \text{若 } S < 0,\ \text{则阻塞当前进程}
$$

$$
V(S):\quad S = S + 1;\ \text{若 } S \le 0,\ \text{则唤醒一个阻塞进程}
$$

$P$ 和 $V$ 都是原语，不可被中断。原因在于：

- $P$ 要同时完成“判断资源是否可用”和“分配资源 / 阻塞当前进程”两个关键步骤。若判断后、修改前被中断，另一个进程也可能判断资源可用，从而同时进入临界区，互斥失败。
- $V$ 要同时完成“释放资源”和“唤醒等待进程”两个关键步骤。若释放后、唤醒前被中断，可能发生“丢失唤醒”，导致等待进程无法及时进入临界区，甚至死锁。

所以 $P$、$V$ 各自必须原子执行；$PV$ 操作整体就是两个不可被中断的过程。

**易错点**：
- 不要把 $PV$ 当成一个过程。$PV$ 是 $P$ 操作与 $V$ 操作的合称，不是一个操作。
- 不要把“可被中断”当成允许。$P$、$V$ 若可被中断，信号量的修改和进程状态切换就会出现竞态条件。
- 不要混淆“阻塞”与“中断”。$P$ 操作中使进程阻塞是操作内部的结果，不是操作被外部打断。
- 实现上不一定全程关中断，也可能用硬件原子指令或锁机制；408 层面只需要记住原语的性质：不可被中断。

**命题规律**：
这道题考信号量 $PV$ 操作的“原语”性质。命题人常把“数量”和“原子性”放在一起设置干扰项：$A/B$ 错在数量，$C$ 错在原子性。408 喜欢用这种二二组合选项考查基本概念，记忆锚点就是：$P$ 和 $V$ 是两个不可被中断的原语过程，类似于并发编程中的 `lock/unlock` 必须各自原子实现。
