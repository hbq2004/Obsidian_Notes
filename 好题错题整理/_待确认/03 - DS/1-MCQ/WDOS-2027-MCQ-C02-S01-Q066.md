# MCQ 第 66 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S01-Q066_题目.png|题目]]

66.【2019统考真题】下列关于线程的描述中,错误的是 ( )

(A) 内核级线程的调度由操作系统完成

(B) 操作系统为每个用户级线程建立一个线程控制块

(C) 用户级线程间的切换比内核级线程间的切换效率高

(D) 用户级线程可以在不支持内核级线程的操作系统上实现

## DeepSeek V4 Flash Max 解析
**答案**：

错误的是 $\mathbf{B}$。

**解题切入点**：

抓住线程实现的“所有权”问题：用户级线程（ $ULT$ ）和内核级线程（ $KLT$ ）的本质区别在于，**线程控制块（ $TCB$ ）由谁建立、由谁管理、由谁调度**。

可用算法竞赛类比：内核级线程相当于系统给你开好的“全局状态数组”，创建、调度、回收都由操作系统负责；用户级线程相当于你自己在用户态写一个“状态机 + 队列模拟”，操作系统根本看不到你的内部线程结构，只看到一个进程。

**推演**：

- 选型 $\mathbf{A}$：内核级线程由内核管理，调度自然由操作系统完成。就像操作系统自己维护一个全局调度队列，线程切换是内核在分配 CPU 资源，正确。
- 选型 $\mathbf{B}$：操作系统不会为每个用户级线程建立线程控制块。用户级线程的上下文、栈、调度信息都由用户态线程库维护，操作系统不感知这些线程的存在。若说“用户态线程库为用户级线程建立控制块”则成立，但绝不是操作系统建立，因此 $\mathbf{B}$ 错误。
- 选型 $\mathbf{C}$：用户级线程切换不需要陷入内核，不需要用户态/内核态模式切换，只需在用户态保存和恢复寄存器、栈指针等上下文。这类似于在竞赛中直接交换数组下标或指针；而内核级线程切换要经过内核调度器，涉及模式切换，代价更大，正确。
- 选型 $\mathbf{D}$：用户级线程完全可以建立在只支持进程、不支持内核级线程的操作系统上。线程库在用户态自行完成创建、调度和切换，底层操作系统只看到一个进程。这等价于“在用户态模拟一个协作式状态机”，不要求底层提供额外原语，正确。

所以错误的是 $\mathbf{B}$。

**易错点**：

- 容易误以为所有线程都要由操作系统建立 $TCB$，实际上用户级线程的控制结构属于用户态线程库，不在内核数据区。
- 不能把“用户级线程切换效率高”误认为“用户级线程整体性能更强”。$ULT$ 切换快，但一个用户级线程阻塞可能会阻塞整个进程；$KLT$ 虽切换慢，但单个线程阻塞不影响其他内核线程。
- 不要把 $TCB$ 和 $PCB$ 混淆。用户级线程对应的“控制块”即使存在，也是运行时线程库中的私有数据结构，不是操作系统管理的内核对象。
- 对 $D$ 的判定容易犹豫，关键是理解“不支持内核级线程”不等于“不支持多线程”，因为用户级线程是纯用户态实现，不需要内核线程支持。

**命题规律**：

这是 2019 年统考对线程模型的经典考查，核心就是对比 $ULT$ 与 $KLT$ 的：

- 谁建 $TCB$
- 谁调度
- 切换代价
- 阻塞影响
- 是否支持多核并行

可以记成：**内核管 $KLT$ ，用户管 $ULT$ ；用户切换快，内核并行强**。

做题时像算法题“先明确数据由谁维护”一样，逐项问自己：这个线程的控制块在用户态还是内核态？切换要不要经过系统调用？该线程阻塞时，是整个进程停还是只有该线程停？这样就能快速锁定错误项。
