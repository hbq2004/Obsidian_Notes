# MCQ 第 22 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S02-Q022_题目.png|题目]]

关于优先权大小的论述中，正确的是（ ）
(A) 计算型作业的优先权，应高于 $I/O$ 型作业的优先权
(B) 用户进程的优先权，应高于系统进程的优先权
(C) 在动态优先权中，随着作业等待时间的增加，其优先权将随之下降
(D) 在动态优先权中，随着进程执行时间的增加，其优先权降低

## DeepSeek V4 Flash Max 解析
**答案**：
D

**解题切入点**：
将进程调度看作在线优先队列的动态键值更新。每个就绪进程是一个节点，调度器每次从队列中取“当前最优”节点运行；而“优先权”就是这个节点的比较键。和算法竞赛中 priority_queue 手动改 key 一样，状态变量（等待时间、已执行时间）变了，比较键就要变。动态优先权的核心是：等待越久越“可怜”，要提升优先权；执行越久越“贪心”，要降低优先权，从而平衡资源利用和饥饿避免。

**推演**：
A 项不对。I/O 型作业的 CPU 突发短，应优先运行，使其尽快发出 I/O 请求，让 I/O 设备与 CPU 并发工作；若计算型作业优先权高，相当于长突发任务霸占 CPU，I/O 设备只能空转，系统整体吞吐量下降。类似贪心调度中优先做“短操作”而不是“长操作”。

B 项不对。系统进程负责资源管理、调度、I/O 等核心功能，是用户进程运行的基础设施，优先权应高于用户进程。类比竞赛中“底层预处理/工具函数”的优先级应高于具体业务逻辑，不能反过来。

C 项不对。动态优先权中，等待时间增加应使优先权提高，而不是下降。这是老化（aging）思想，防止低优先权进程长期得不到 CPU 而饿死。可看成在 Dijkstra 中让一个长期未出队的节点 key 逐渐变小（如果小 key 优先），给它更多出队机会。

D 项正确。动态优先权通常可写成：
$$
P = P_0 + \alpha W - \beta S
$$
其中 $W$ 为等待时间，$S$ 为已执行时间，$\alpha,\beta > 0$，$P$ 越大优先权越高。所以 $W$ 增大会提升 $P$，$S$ 增大会降低 $P$。进程执行时间越长，说明它已经占用了较多 CPU，降低其优先权可以避免长进程垄断 CPU，给其他进程让路。这类似多级反馈队列中进程随 CPU 时间增加而被降到更低优先级队列。

**易错点**：
1. 容易把“等待时间增加”和“执行时间增加”两个方向记反。防饥饿靠提高等待者的优先权；防垄断靠降低已执行者的优先权，两者不是同向变化。
2. 注意“数值大优先”还是“数值小优先”。题目默认优先权数值越大越优先；若优先权表示越小越优先，动态公式符号会反，但“等待者更该被照顾、长执行者该让位”的本质不变。
3. 混淆作业与进程。A/C 出现在调度语境中不改变结论；无论作业调度还是进程调度，I/O 型应高于计算型、等待时间增加应提高优先权的原则一致。
4. 认为系统进程应低于用户进程。实际上系统进程是操作系统自身的进程，应具有更高优先权。

**命题规律**：
408 喜欢把一对相反关系放进同一题：I/O 型 vs 计算型、系统进程 vs 用户进程、等待时间 vs 执行时间。正确项往往来自“动态优先权调整原则”：等待时间增加优先权升高，执行时间增加优先权降低。复习时可用公式 $P = P_0 + \alpha W - \beta S$ 一条线记住，做题时先排除明显违背“防饥饿、防垄断”的选项，再锁定动态优先权选项。
