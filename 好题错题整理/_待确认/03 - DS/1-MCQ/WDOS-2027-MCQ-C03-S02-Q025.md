# MCQ 第 25 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C03-S02-Q025_题目.png|题目]]

在页面置换策略中，（ ）策略可能引起抖动.
(A) $FIFO$
(B) $LRU$
(C) 没有一种
(D) 所有

## DeepSeek V4 Flash Max 解析
**答案**：
$\boxed{D}$ 所有。

**解题切入点**：
抖动（thrashing）的本质是进程频繁缺页，导致系统开销剧增，其根本原因是进程的工作集（working set）大于实际分配的物理内存量，与具体采用的页面置换算法无关。因此，无论是 $FIFO$、$LRU$ 还是其他算法，只要分配的内存不足以容纳工作集，都可能引发抖动。这类似于算法竞赛中，当缓存大小远小于数据规模时，无论采用哪种替换策略（如 FIFO 或 LRU），都会频繁发生缓存缺失，导致性能严重下降。

**推演**：
1. 抖动的产生条件：进程的局部性失效，缺页率过高，使得 CPU 大部分时间忙于页面置换。
2. 页面置换算法只决定在缺页时选择哪个页面换出，但无法改变系统物理内存总量或进程的工作集大小。
3. 当内存分配不足时，$FIFO$ 因其“先进先出”特性可能替换掉常用页面，而 $LRU$ 虽然能保留最近使用的页面，但若工作集大小超过物理块数，必然频繁缺页。因此，$FIFO$ 和 $LRU$ 均可能引起抖动，且没有一种算法能绝对避免抖动。
4. 故选项 $A$、$B$ 不全面，$C$ 错误，正确选项为 $D$（所有）。

**易错点**：
- 混淆“Belady 异常”与“抖动”：$FIFO$ 的 Belady 异常是指物理块增加时缺页率可能上升，但抖动是系统性能的全面崩溃，二者不同。
- 误认为 $LRU$ 具有“智能”特性，能够避免抖动，但 $LRU$ 仅能优化局部性，仍无法解决内存不足的根本矛盾，如同竞赛中再精巧的缓存替换算法也无法突破物理内存上限。
- 忽略“可能引起”的含义：所有策略在特定条件下（如内存极紧张）都可能引起抖动，因此不能选“没有一种”。

**命题规律**：
- 核心考查对抖动成因的理解，常与工作集、内存分配策略、进程的局部性等概念结合。
- 避免直接记忆算法优缺点，而要从系统资源分配的高度分析，类似竞赛中分析算法瓶颈时，需区分“策略本身”与“资源约束”的影响。
- 类似题目可能变换形式：如“哪种策略可减少抖动？”此时应选择基于工作集或页面错误频率的动态调节策略，而非静态置换算法。
