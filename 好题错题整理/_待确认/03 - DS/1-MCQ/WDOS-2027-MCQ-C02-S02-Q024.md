# MCQ 第 24 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S02-Q024_题目.png|题目]]

作业是用户提交的,进程是由系统自动生成的,除此之外,两者的区别是（ ）
(A) 两者执行不同的程序段
(B) 前者以用户任务为单位,后者以操作系统控制为单位
(C) 前者是批处理的,后者是分时的
(D) 后者是可并发执行，前者则不同

## DeepSeek V4 Flash Max 解析
**答案**：
$B$（前者以用户任务为单位，后者以操作系统控制为单位）。

**解题切入点**：
题干说“作业是用户提交的，进程是系统自动生成的”，这已经把二者划到“用户侧”和“系统侧”。作业是用户视角下的完整任务单位，进程是操作系统视角下的控制、资源分配与调度单位。  
用 OJ 类比：用户交一份“代码 + 数据 + 题意要求”是一次作业（$\mathrm{Job}$），OJ 为它创建的那个评测进程是 $\mathrm{Process}$；真正在 CPU 上跑的是进程，而不是用户提交的任务本身。

**推演**：
作业 $J$ 是用户提交的任务单位，包含程序、数据和作业说明书；进程 $P$ 是程序的一次动态执行过程，是系统进行资源分配与调度的基本单位。可以看成：

$$
\text{后备队列上的作业 } J \xrightarrow{\text{作业调度}} \text{进程 } P \xrightarrow{\text{进程调度}} \text{CPU 运行}
$$

也就是说，进程是作业被系统接纳后生成的“运行实例”，并不是与作业平行的另一个程序段。

逐项排除：

- $A$ 错：同一程序段可以被多个进程共享；一个作业也可以包含多个程序段或作业步，不能说两者执行不同程序段。
- $B$ 对：作业以用户任务为单位，进程以操作系统控制/资源分配为单位。
- $C$ 错：批处理/分时是系统类型或调度方式，不是作业与进程的本质区别；分时系统也有用户任务，批处理系统也有进程。
- $D$ 错：并发执行的主体是进程；但作业不是“不能并发”的执行体，而是由 OS 创建进程后才执行。多个作业可以转成多个进程并发执行，因此这不是最本质区别。

**易错点**：
1. 把“作业”当成可运行的程序实体。作业只是任务集合，运行必须由进程承载。
2. 被“批处理/分时”迷惑。作业和进程都不与某种系统类型严格绑定。
3. 把 $D$ 绝对化：不能说“作业绝对不能并发”，只能说作业不是并发执行单位，并发调度的是进程。
4. 记混“谁创建谁”：用户提交作业，OS 接受作业后创建进程；进程不是用户直接创建的。

**命题规律**：
$408$ 爱考“概念主语”：作业是谁的单位？用户任务单位；进程是谁的单位？操作系统控制单位；线程是谁的调度单位？CPU 调度实体。  
可以把它们看作竞赛中的数据结构：

- 作业：外存/后台队列中的任务节点，由用户提交；
- 进程：内存中带 $\mathrm{PCB}$ 的调度节点，由系统创建；
- 线程：进程内的执行流，是 CPU 调度的实体。

就像算法竞赛中区分“测试数据/提交文件”和“运行时的进程实例”：数据放在那里不会自己跑，必须被评测系统读入并创建进程后才执行。遇到概念辨析题，先找“动作主体”和“单位”，答案通常就出来了。
