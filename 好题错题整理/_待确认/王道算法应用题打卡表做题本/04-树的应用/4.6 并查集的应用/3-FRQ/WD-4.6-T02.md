## DeepSeek V4 Flash Max 解析

**答案**：  
并查集用树的双亲表示法存储，$S[i]$ 表示结点 $i$ 的双亲，根结点满足 $S[i] < 0$。`Union(S, Root1, Root2)` 的基本实现为：

```c
void Union(int S[], int Root1, int Root2) {
    if (Root1 == Root2) return;   // 已在同一集合中，无需合并
    S[Root2] = Root1;             // 将 Root2 所在树的根挂在 Root1 下
}
```

该操作时间复杂度为 $O(1)$。若要求防止树退化为单链，可采用“小树并入大树”的优化版本：

```c
void Union(int S[], int Root1, int Root2) {
    if (Root1 == Root2) return;
    // S[root] 为负数，绝对值表示集合元素个数
    // S[Root2] > S[Root1] 说明 Root2 所在集合规模更小
    if (S[Root2] > S[Root1]) {
        S[Root1] += S[Root2];
        S[Root2] = Root1;
    } else {
        S[Root2] += S[Root1];
        S[Root1] = Root2;
    }
}
```

---

**解题切入点**：  
拿到题目先抓住“基于上述定义”，说明并查集的存储结构已经确定为“树的双亲表示法”。因此，`Union` 的本质不是遍历所有元素，而是把两棵树的根连接起来：一棵树的根成为另一棵树根的孩子。这就像把两棵树的根用一条边合并成一棵树，核心操作就是修改数组中的一个值。

---

**推演**：  

设并查集数组为 $S[0..n-1]$，初始时每个元素自成一个集合，即每个结点都是一棵单结点树的根：

$$
\forall i,\quad S[i] = -1
$$

其中 $S[i] = -1$ 表示结点 $i$ 为根结点，且没有双亲。

当执行 `Union(S, Root1, Root2)` 时，$Root1$ 和 $Root2$ 分别是两棵树的根结点。合并操作就是把其中一棵树的根结点变成另一棵树根结点的孩子，即执行：

$$
S[Root2] = Root1
$$

该操作只修改一个数组元素，所以时间复杂度为 $O(1)$。

但若盲目合并，例如总是把后一棵树挂到前一棵树下，连续 $n-1$ 次合并后可能形成一棵单链树，此时查找操作 $Find$ 的最坏时间复杂度退化为 $O(n)$。

优化方法是“按规模合并”：让 $S[root]$ 的绝对值表示该树中结点的个数。初始时每个根结点存储 $-1$，即集合大小为 $1$。合并时比较两棵树的规模，把规模较小的树并入规模较大的树，从而控制树高。

由于根结点存储的是负数，因此比较规模时不能直接看大小。对于两个负数 $a, b$，数值越大，绝对值越小。例如：

$$
-1 > -3,\quad |-1| = 1 < 3 = |-3|
$$

所以代码中写：

```c
if (S[Root2] > S[Root1])
```

表示 $Root2$ 的规模更小，应该把 $Root2$ 并入 $Root1$。合并后更新根结点的规模：

$$
S[Root1] = S[Root1] + S[Root2]
$$

即两个负数相加，绝对值相加。同时令：

$$
S[Root2] = Root1
$$

采用按规模合并后，任意结点向上到根的路径长度不超过 $\lfloor \log_2 n \rfloor$，因此 $Find$ 操作的时间复杂度为 $O(\log n)$，而 $Union$ 本身仍为 $O(1)$。

---

**易错点**：  

- 忘记判断 `Root1 == Root2`，导致同一个集合的根互相指向，形成环或错误结果。  
- `Union` 的参数必须是两个集合的根结点。如果传入非根结点，必须先用 `Find` 找到根，否则会破坏原有树结构。  
- 在按规模合并时，比较负数大小容易写反。`S[Root2] > S[Root1]` 表示 $Root2$ 规模更小，不能简单写成 `S[Root1] < S[Root2]` 而不交换逻辑。  
- 合并后忘记更新根结点存储的集合规模，导致后续合并规模判断错误。  
- 把根结点判定写成 `S[i] == -1`，但在按规模优化后，根结点存储的值不一定是 $-1$，而可能是更小的负数，因此根结点应判定为 `S[i] < 0`。  
- 混淆 `Union` 和 `Find` 的复杂度：`Union` 本身是 $O(1)$，不优化时退化的主要是 `Find`。
