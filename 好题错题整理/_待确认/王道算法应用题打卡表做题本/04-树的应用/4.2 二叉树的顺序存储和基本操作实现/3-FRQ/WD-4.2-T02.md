## DeepSeek V4 Flash Max 解析

**答案**：采用一维数组存储二叉树，根结点存放在数组下标 1 的位置。由于 C 数组下标从 0 开始，所以数组长度要开 `MAX_SIZE + 1`，下标 0 空置不用。定义如下：

```c
#include <stdbool.h>

#define MAX_SIZE 100

typedef int ElemType;

typedef struct {
    ElemType data[MAX_SIZE + 1]; // data[0] 不用，结点从 data[1] 开始
    bool valid[MAX_SIZE + 1];    // valid[i] 为 true 表示 data[i] 处是真实结点
    int length;                  // 当前最大下标
    int size;                    // 实际结点个数
} SeqBinaryTree;

void InitSeqBinaryTree(SeqBinaryTree *T) {
    T->length = 0;
    T->size = 0;
    for (int i = 0; i <= MAX_SIZE; ++i) {
        T->valid[i] = false;
        T->data[i] = 0;
    }
}
```

若只存储完全二叉树，可以省略 `valid` 数组，此时 `length` 既是最大下标，也是结点个数。对应下标关系为：结点 $i$ 的左孩子是 $2i$，右孩子是 $2i+1$，双亲是 $\lfloor i/2 \rfloor$。

**解题切入点**：看到“顺序存储”先定位到“数组/完全二叉树编号”；看到“下标从1开始”要立刻想到 C 数组的下标偏移：数组长度必须是 `MAX_SIZE + 1`，0 号下标空着。这就像写线段树、堆时常用 1 号下标作为根，后续左右孩子直接用 `2i`、`2i+1`，不需要做 `i-1` 的偏移。

**推演**：顺序存储二叉树的核心是“结点编号与数组下标一一对应”。设根编号为 1。按层次顺序生成结点：初始只有根，编号 1。处理完前 $i-1$ 个结点后，数组（编号空间）中已经有
$$
1+2(i-1)=2i-1
$$
个位置；因此第 $i$ 个结点的左孩子紧接其后，编号为 $2i$，右孩子编号为 $2i+1$。故：
$$
L(i)=2i,\quad R(i)=2i+1,\quad P(i)=\left\lfloor \frac{i}{2} \right\rfloor\quad (i>1)
$$
因为 $i$ 为偶数时双亲是 $i/2$，$i$ 为奇数时双亲是 $(i-1)/2$，统一写成 $\lfloor i/2 \rfloor$。数组实现时，设最多存储 $N$ 个结点，数组长度取 $N+1$，有效结点放在下标 $1\sim N$，`data[0]` 不用。对一般二叉树，空结点也要占据编号位置，否则无法通过上述公式定位孩子，所以要增加 `valid` 数组或特殊值标记空结点。

**易错点**：
- 数组长度开成 `MAX_SIZE` 而不是 `MAX_SIZE + 1`，导致访问 `data[MAX_SIZE]` 越界。
- 直接把根存到 `data[0]`，却仍用 $2i$、$2i+1$ 求孩子，造成错位。
- 一般二叉树不补空结点/不标记空结点，导致“编号空洞”被当作真实结点。
- 混淆 `length` 的实际含义：非完全二叉树时 `length` 是最大下标，不等于实际结点个数，实际结点数应单独用 `size` 记录。
- 取左/右孩子时未检查下标是否超过 `length`，或未检查 `valid` 标记，可能访问到空结点/越界。

**命题规律**：该题对应 408 中的“二叉树的存储结构”，常在选择题中考查给定数组下标求左右孩子、双亲，或者判断某数组是否表示完全二叉树/堆；在代码题中常作为堆、优先队列、线段树的底层存储。复习时要把“顺序存储、完全二叉树、堆”串起来，记住下标从 1 开始的所有公式，并动手实现初始化、插入、取孩子、取双亲等小函数。
