# 选择题 第 5 题

5. 设二叉排序树中关键字由 1 到 1000 的整数构成,现要查找关键字为 363 的结点,下述关键字序列中,不可能是在二叉排序树上查找的序列是 ( )。
(A) 2,252,401,398,330,344,397,363
(B) 924,220,911,244,898,258,362,363
(C) 925,202,911,240,912,245,363
(D) 2,399,387,219,266,382,381,278,363

## DeepSeek V4 Flash Max 解析

**答案**：选 **(C)**。序列 C 中，访问 911 后，因为 $911>363$，查找进入 911 的左子树，后续路径上的关键字都应小于 911；但序列随后出现 $912$，违反 BST 性质，因此 C 不可能是查找 363 的路径。

**解题切入点**：不要试图构造整棵树，而要把 BST 的查找路径看成“不断缩小的开区间”。查找目标 $K$ 时，每次比较都会把后续可能出现的关键字限制在一个区间内，类似于二分查找中维护上下界。若后续关键字跳出当前区间，则序列不可能。

**推演**：

设查找目标为 $K=363$，当前可能的关键字范围为 $(L,H)$。初始时因为关键字是 $1\sim 1000$，可取

$$
L=0,\quad H=1001.
$$

对路径上的每个结点关键字 $x$，若查找尚未结束，则必须满足：

$$
L<x<H.
$$

并且：

- 若 $x<K$，下一步进入 $x$ 的右子树，后续关键字都应大于 $x$，所以更新 $L\gets x$；
- 若 $x>K$，下一步进入 $x$ 的左子树，后续关键字都应小于 $x$，所以更新 $H\gets x$；
- 若 $x=K$，查找成功。

核心判断代码思路如下：

```cpp
bool check(vector<int> path, int target) {
    int L = 0, H = 1001;        // 关键字范围 [1,1000]
    for (int x : path) {
        if (x <= L || x >= H) return false;  // 越界，不可能
        if (x == target) return true;
        if (x < target) L = x;  // 进入右子树
        else H = x;             // 进入左子树
    }
    return false;
}
```

逐项检查：

- **(A)**  
  $(0,1001)\xrightarrow{2}(2,1001)\xrightarrow{252}(252,1001)\xrightarrow{401}(252,401)\xrightarrow{398}(252,398)\xrightarrow{330}(330,398)\xrightarrow{344}(344,398)\xrightarrow{397}(344,397)\xrightarrow{363}$  
  每一步都未越界，合法。

- **(B)**  
  $(0,1001)\xrightarrow{924}(0,924)\xrightarrow{220}(220,924)\xrightarrow{911}(220,911)\xrightarrow{244}(244,911)\xrightarrow{898}(244,898)\xrightarrow{258}(258,898)\xrightarrow{362}(362,898)\xrightarrow{363}$  
  每一步都未越界，合法。

- **(C)**  
  $(0,1001)\xrightarrow{925}(0,925)\xrightarrow{202}(202,925)\xrightarrow{911}(202,911)\xrightarrow{240}(240,911)$  
  此时当前区间为 $(240,911)$，但下一个关键字是 $912$，不满足 $912<911$，所以不可能。

- **(D)**  
  $(0,1001)\xrightarrow{2}(2,1001)\xrightarrow{399}(2,399)\xrightarrow{387}(2,387)\xrightarrow{219}(219,387)\xrightarrow{266}(266,387)\xrightarrow{382}(266,382)\xrightarrow{381}(266,381)\xrightarrow{278}(278,381)\xrightarrow{363}$  
  每一步都未越界，合法。

因此不可能的是 **(C)**。

**易错点**：

1. **只看相邻两项与 363 的大小关系**。例如 C 中 $240\to912$，$912>240$，单独看好像可以是 240 的右孩子；但 240 已经在 911 的左子树中，所以 912 还必须小于 911，因此不可能。
2. **更新上下界方向弄反**。当前关键字小于目标时，应更新下界；当前关键字大于目标时，应更新上界。比如 $220<363$，应令 $L=220$，而不是 $H=220$。
3. **把查找序列误当作插入序列**。查找序列是根到目标结点的路径，不是插入序列，也不是中序遍历序列。
4. **忽略当前区间的“开区间”性质**。边界值不能再出现，后来结点必须严格位于 $(L,H)$ 内。

**命题规律**：本题属于 BST 查找路径性质的应用，是 408 选择题中常见的“给序列判断是否可能为查找路径”的考法。变式包括：给出一条路径，反推被查找关键字可能属于哪个范围；或判断某序列能否成为查找失败路径。复习时应熟练掌握 BST“左小右大”的性质，并把查找过程转化为上下界收窄模型，可快速判断。
