## DeepSeek V4 Flash Max 解析

**答案**：利用后序遍历，自底向上返回每棵子树的高度并同步判断每个结点左右子树的高度差；若所有结点的 $|\text{左子树高度}-\text{右子树高度}|\le 1$，则原二叉树为平衡二叉树。时间复杂度 $O(n)$，空间复杂度 $O(h)$，其中 $h$ 为树高。

**解题切入点**：判断平衡二叉树不能只看根结点，必须看“每个结点”的左右子树高度差。而计算高度需要先知道左右子树的高度，因此应使用后序遍历；递归函数需要同时返回两个信息：“子树是否平衡”和“子树高度”。这本质上是一种树形 DP：先收集子树信息，再处理当前结点。

**推演**：

设二叉树 $T$ 为空树时高度为 $0$，且空树是平衡的。对非空结点 $v$，记其左右子树为 $T_L,T_R$，高度分别为 $h(T_L),h(T_R)$。则：

$$
h(v)=\max(h(T_L),h(T_R))+1
$$

结点 $v$ 平衡当且仅当：

$$
h(T_L)-h(T_R)\in\{-1,0,1\}
$$

并且左右子树本身也必须平衡。

因此递归函数设计为：

```c
typedef struct BiTNode {
    int data;
    struct BiTNode *lchild, *rchild;
} BiTNode, *BiTree;

// 返回 1 表示平衡，0 表示不平衡；h 返回以 T 为根的子树高度
int IsBalanced(BiTree T, int *h) {
    if (T == NULL) {
        *h = 0;          // 空树高度为 0，且平衡
        return 1;
    }

    int lh, rh;
    int leftBal  = IsBalanced(T->lchild, &lh);
    int rightBal = IsBalanced(T->rchild, &rh);

    // 后序遍历：左右子树处理完后，回到当前结点
    *h = (lh > rh ? lh : rh) + 1;

    if (leftBal && rightBal && (lh - rh <= 1 && rh - lh <= 1))
        return 1;
    return 0;
}

// 对外接口
int IsBalancedTree(BiTree T) {
    int h;
    return IsBalanced(T, &h);
}
```

正确性可由归纳法说明：

1. 递归基：空树高度为 $0$，且空树平衡，正确。
2. 对非空结点 $T$，递归调用先正确得到左右子树是否平衡以及各自高度。
3. 若左右子树中任意一棵不平衡，则 $T$ 不可能平衡；若左右子树都平衡，则 $T$ 是否平衡只取决于高度差是否不超过 $1$。
4. 当前结点的高度更新为 $\max(lh,rh)+1$，为上层结点提供了正确的高度信息。

因此算法正确。

每个结点只被访问常数次，时间复杂度为：

$$
O(n)
$$

递归栈深度等于树高，空间复杂度为：

$$
O(h)
$$

最坏情况是单支树，空间复杂度为 $O(n)$。

**易错点**：

- 只判断根结点左右子树高度差不超过 $1$，没有递归判断左右子树是否平衡。例如某棵子树内部已经不平衡，但根结点处高度差恰好不超过 $1$，会误判。
- 空树高度处理错误。若把空树高度当 $1$，则叶子结点高度会变为 $2$，导致所有平衡因子计算偏移。
- 忘记通过指针或引用把子树高度传回。若只在递归函数内部修改局部变量，上层无法获得正确高度。
- 使用先序或中序遍历思路。处理当前结点时左右子树高度尚未得到，无法正确判断平衡。
- 若题目额外要求“二叉排序树”的平衡，还需检查中序序列是否递增；本题只要求判断二叉树的高度平衡，不需要判断有序性。

**命题规律**：这是二叉树遍历应用的经典题目，核心考点是“后序遍历 + 多返回值”。408 中常见变式包括：求二叉树高度、判断完全二叉树、判断二叉排序树、求二叉树直径、输出根到叶子的路径、求最近公共祖先等。复习时应熟练掌握递归遍历模板，并习惯用引用或指针参数带回多个信息；遇到“当前结点需要子树信息才能判断”的题目，优先考虑后序遍历。
