## DeepSeek V4 Flash Max 解析

**答案**：利用二叉搜索树“左小右大”的有序性，从根结点开始按关键字比较方向下行，每下移一层层号加 1；命中目标结点时返回当前层号，走到空指针则返回 0 表示不存在。

**解题切入点**：拿到题先定位考点：二叉搜索树的查找。二叉搜索树类似于有序数组的二分查找，每次比较都能排除一棵子树；而“层号”就是从根到该结点的路径上经过的结点数。因此把“BST 查找”和“层号计数”结合起来即可，不需要遍历整棵树。

**推演**：

约定二叉搜索树结点结构为：

```c
typedef struct BTNode {
    int key;
    struct BTNode *lchild, *rchild;
} BTNode;
```

设要查找的关键字为 $k$。从根结点出发，当前层号记为 $\text{level}$。

若根结点层号为 1，则算法如下：

```c
int findLevel(BTNode *root, int k) {
    int level = 1;                 // 根结点在第 1 层
    while (root != NULL) {
        if (k == root->key)
            return level;
        if (k < root->key)
            root = root->lchild;   // 目标只可能在左子树
        else
            root = root->rchild;   // 目标只可能在右子树
        level++;                   // 下降一层，层号加 1
    }
    return 0;                      // 0 表示树中不存在关键字 k
}
```

算法正确性可由循环不变式说明：

> 每次进入循环时，若目标结点存在，则它一定在以当前 `root` 为根的子树中，且 `level` 等于当前 `root` 在原树中的层号。

初始时 `root` 为整棵 BST 的根，层号为 1，成立。  
若 $k < \text{root->key}$，由 BST 性质，左子树所有结点关键字都小于根结点，右子树所有结点关键字都大于根结点，因此目标不可能在右子树，只需进入左子树；反之则进入右子树。进入孩子后层号加 1，循环不变式保持。  
当 `root == NULL` 时，说明搜索路径上不存在该结点，返回 0。

时间复杂度：设树高为 $h$，每轮循环下降一层，最多经过 $h$ 个结点，时间为 $O(h)$。在平衡 BST 中 $h=O(\log n)$，最坏情况单支树 $h=O(n)$。迭代实现空间为 $O(1)$。

若题目给的是结点指针 $p$，可以取 $k=p\texttt{->}key$ 调用上述算法；若要求严格按结点指针匹配，则命中判断可写成 `if (root == p) return level;`，方向判断仍由 `p->key` 与 `root->key` 的大小关系决定。默认 BST 中关键字不重复。

**易错点**：

1. 层号初值容易写错。408 中通常根结点为第 1 层，因此 `level` 应初始化为 1；若题目明确根结点为第 0 层，则初始化为 0。
2. 忘记处理查找失败的情况。如果目标不在树中，应返回 0 或题目约定的哨兵值，不能返回不确定值。
3. 不使用 BST 的有序性，写成在左、右子树中同时递归查找，时间复杂度会退化为 $O(n)$，没有体现 BST 的优势。
4. 递归实现时忘记加 1。例如写成 `return findLevel(root->left, k);` 而没有把当前层加进去，结果会少 1。
5. 未判空就访问结点。循环条件必须是 `root != NULL`，否则会因空指针访问而错误。

**命题规律**：本题核心是“二叉搜索树查找”和“结点层数”的结合。408 中常见的变式有：求 BST 中指定结点的深度或路径、求查找成功时的比较次数、计算 BST 查找成功的平均查找长度 $\mathrm{ASL}=\frac{1}{n}\sum_{i=1}^{n}(\text{第 } i \text{ 个结点的层号})$、以及查找不成功的比较次数等。复习时应熟练掌握 BST 查找、插入、删除的迭代与递归写法，并理解“从根到目标结点的路径长度”与“查找代价”之间的联系。
