# 综合题 第 5 题

![[_Attachments/题目识别/27_王道408-题目/DS-C07-72-F05_题目.png|题目]]

5. 线性表中各结点的检索概率不等时，可用如下策略提高顺序检索的效率：若找到指定的结点，则将该结点和其前驱结点（若存在）交换，使得经常被检索的结点尽量位于表的前端。试设计在顺序结构和链式结构的线性表上实现上述策略的顺序检索算法。

## 答案

## DeepSeek V4 Flash Max 解析

**答案**：采用“命中后与前驱交换”的自适应顺序检索：顺序表上找到后把命中元素和它的前驱元素互换；带头结点的单链表上用三个指针找到命中结点 $p$、其前驱 $pre$ 和前前驱 $q$，通过改链完成相邻交换。单次检索最坏 $O(n)$，调整 $O(1)$，额外空间 $O(1)$。

**解题切入点**：先抓住“顺序检索 + 动态调整”两个关键词。顺序表可以用下标直接定位，找到位置 $i$ 后与 $i-1$ 交换即可；链表不能回退，交换结点 $p$ 和它的前驱 $pre$ 时，必须还要知道 $pre$ 的前驱 $q$，否则会断链。这就像调换相邻两节车厢时，必须同时握住前一节车厢之前的连接器。

**推演**：

设记录类型为 `ElemType`，含关键字 `key`；顺序表下标从 1 开始，`length` 为表长；单链表带头结点。

### 1. 顺序结构上的实现

从表头向表尾扫描，找到关键字后，若存在前驱则交换：

```c
int Search_Sq(SSTable &ST, KeyType key) {
    for (int i = 1; i <= ST.length; ++i) {
        if (ST.elem[i].key == key) {          // 查找成功
            if (i > 1) {                       // 存在前驱才交换
                ElemType tmp = ST.elem[i];
                ST.elem[i] = ST.elem[i - 1];
                ST.elem[i - 1] = tmp;
                return i - 1;                  // 命中记录已移到 i-1
            }
            return 1;                          // 首元结点无前驱，不交换
        }
    }
    return 0;                                  // 查找失败
}
```

若使用 0 基下标，则判断改为 `i > 0`，失败返回 `-1` 即可。

### 2. 链式结构上的实现

带头结点的单链表：

```c
LNode *Search_L(LinkList L, KeyType key) {
    LNode *q = L, *pre = L, *p = L->next;

    while (p != NULL && p->data.key != key) {
        q = pre;      // q 成为 pre 的前驱
        pre = p;      // pre 成为 p 的前驱
        p = p->next;
    }

    if (p == NULL)
        return NULL;  // 查找失败

    if (pre != L) {   // p 不是首元结点，存在数据前驱
        LNode *r = p->next;
        q->next = p;
        p->next = pre;
        pre->next = r;
    }

    return p;         // 交换后 p 仍指向命中结点
}
```

交换前后的局部链为：

$$
q \rightarrow pre \rightarrow p \rightarrow r
$$

变为：

$$
q \rightarrow p \rightarrow pre \rightarrow r
$$

如果没有头结点，则交换首、次结点时需要同步修改头指针；采用带头结点的单链表可以简化这一处理。

### 3. 复杂度分析

- 查找过程最坏比较 $n$ 次，时间复杂度为 $O(n)$。
- 找到后的相邻交换或指针修改均为 $O(1)$。
- 不需要额外辅助数组或链表，空间复杂度为 $O(1)$。

**易错点**：

1. **首元结点没有前驱**  
   顺序表 `i == 1` 时不能执行 `i-1` 交换；链表 `pre == L` 时不能把头结点当作数据前驱去交换。

2. **链表修改指针时断链**  
   交换前要保存 `p->next`，或者先执行 `pre->next = p->next`，再修改 `p->next`，否则会丢失原后继结点。

3. **查找方向不能搞反**  
   题意要求高频结点尽量在前端，所以顺序表应从前往后扫描。若为了用哨兵而从后往前扫描，“前端”反而最后才被比较，与题意相悖。

4. **参数传递问题**  
   顺序表算法需要修改表内容，函数参数应传引用或指针；若按值传递，交换只会在副本上生效，原表不变。

5. **查找失败不交换**  
   只有找到时才调整表；未找到时不能改变原表结构，返回失败标志即可。

**命题规律**：本题综合考查线性表的顺序存储与链式存储、顺序查找、单链表指针修改等核心内容。常见变式有：找到后移到表头而不是只前移一位、按访问频度域 `freq` 自调整、双向链表实现相邻交换、静态概率已知时按概率降序排列等。复习时应重点掌握单链表相邻结点交换的指针画图推导，并养成“先写思路、再写代码、最后写复杂度”的答题习惯。
