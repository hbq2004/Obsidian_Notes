1. 若希望循环队列中的元素都能得到利用, 则需设置一个标志域 $tag$, 并以 $tag$ 的值为 $0$ 或 $1$ 来区分队首指针 $front$ 和队尾指针 $rear$ 相同时的队列状态是“空”还是“满”。试编写与此结构相应的入队和出队算法。

## DeepSeek V4 Flash Max 解析

**答案**：为循环队列增设标志域 $tag$，每次成功入队令 $tag=1$，每次成功出队令 $tag=0$；当 $front=rear$ 时，若 $tag=1$ 则队满，若 $tag=0$ 则队空。这样不需要牺牲一个存储单元，队列最大容量可达 $MaxSize$。

**解题切入点**：循环队列的核心难点是“队首指针和队尾指针相等时，既可能空也可能满”。题目要求所有元素都能得到利用，意味着不能再用“留一个空位”的传统做法；给出的解决思路是增加一个标志域 $tag$。$tag$ 可以理解为“最后一次成功操作是入队还是出队”，类似于用一个额外比特位消除指针相遇时的二义性。

**推演**：

采用常用约定：

- $front$ 指向队头元素；
- $rear$ 指向队尾元素的下一个入队位置；
- $MaxSize$ 为队列数组长度；
- $tag=0$ 表示初始状态或最近一次成功操作是出队；
- $tag=1$ 表示最近一次成功操作是入队。

设当前队列中元素个数为 $n$。因为 $rear$ 永远等于 $(front+n)\bmod MaxSize$，所以若：

$$
front=rear
$$

则 $n$ 必须是 $MaxSize$ 的倍数。又因为 $0 \le n \le MaxSize$，所以只可能：

$$
n=0 \quad \text{或} \quad n=MaxSize
$$

也就是说，$front=rear$ 时队列只能是“空”或“满”两种状态。用 $tag$ 区分：

$$
\text{队空：}\quad front=rear \ \wedge \ tag=0
$$

$$
\text{队满：}\quad front=rear \ \wedge \ tag=1
$$

数据结构定义如下：

```c
#define MaxSize 100
typedef int ElemType;

typedef struct {
    ElemType data[MaxSize];
    int front, rear;
    int tag;   // 0：最近一次为出队/初始；1：最近一次为入队
} SqQueue;
```

初始化：

```c
void InitQueue(SqQueue &Q) {
    Q.front = Q.rear = 0;
    Q.tag = 0;   // 初始为空
}
```

入队算法：

```c
bool EnQueue(SqQueue &Q, ElemType x) {
    if (Q.front == Q.rear && Q.tag == 1)
        return false;   // 队满，入队失败

    Q.data[Q.rear] = x;
    Q.rear = (Q.rear + 1) % MaxSize;
    Q.tag = 1;          // 最近一次成功操作是入队
    return true;
}
```

出队算法：

```c
bool DeQueue(SqQueue &Q, ElemType &x) {
    if (Q.front == Q.rear && Q.tag == 0)
        return false;   // 队空，出队失败

    x = Q.data[Q.front];
    Q.front = (Q.front + 1) % MaxSize;
    Q.tag = 0;          // 最近一次成功操作是出队
    return true;
}
```

以 $MaxSize=3$ 为例验证：

- 初始：$(front,rear,tag)=(0,0,0)$，队空；
- 连续入队 $A,B,C$ 后：$(0,0,1)$，队满；
- 连续出队 $A,B,C$ 后：$(0,0,0)$，队空。

可见 $front=rear$ 时，只有 $tag$ 能区分空和满，且三个存储单元全部可以被利用。

若还需要求队列长度，可以写成：

$$
L=
\begin{cases}
0, & front=rear\land tag=0\\
MaxSize, & front=rear\land tag=1\\
(rear-front+MaxSize)\bmod MaxSize, & front\ne rear
\end{cases}
$$

**易错点**：

1. 只判断 $front==rear$，不判断 $tag$。  
   这样会把空队当成满队，或把满队当成空队，必须写成
   $front==rear\ \&\&\ tag==1$ 判满，$front==rear\ \&\&\ tag==0$ 判空。

2. 初始化时忘记设置 $tag=0$。  
   若 $tag$ 未初始化，初始时 $front=rear$ 到底是空还是满就无法确定。

3. 入队、出队后忘记更新 $tag$。  
   正确做法是：成功入队置 $tag=1$，成功出队置 $tag=0$；操作失败时不要改变 $tag$。

4. 指针移动没有取模。  
   必须写 $Q.rear=(Q.rear+1)\%MaxSize$ 和 $Q.front=(Q.front+1)\%MaxSize$，不能直接 $++$，否则会越界。

5. 和传统“牺牲一个单元”的循环队列混淆。  
   传统判满条件是 $front==(rear+1)\%MaxSize$，最大容量是 $MaxSize-1$；本题用 $tag$ 判满，最大容量是 $MaxSize$。

**命题规律**：本题属于队列顺序存储结构中的经典综合题，重点考查循环队列的判空判满、入队出队操作和容量计算。常见变式有三类：

- 用 $tag$ 域区分空满；
- 用 $size$ 计数域区分空满；
- 继续使用“牺牲一个单元”的方式，判满条件为 $front==(rear+1)\%MaxSize$。

复习时应熟练掌握 front、rear 的指针含义，能手工模拟入队出队过程；考试中即使不要求写完整代码，也要能快速写出判空判满条件。建议在草稿纸上用 $MaxSize=4$ 的循环队列手动模拟几组操作，并对比三种判满方式的异同。
