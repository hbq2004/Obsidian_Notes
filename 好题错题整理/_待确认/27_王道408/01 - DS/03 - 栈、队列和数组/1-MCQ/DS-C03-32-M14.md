# 选择题 第 14 题

14. 在用单链表实现队列时，队头设在链表的 ( ) 位置.
(A) 链头
(B) 链尾
(C) 链中
(D) 以上都可以

---

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/DS-C03-32-M14_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：选 **(A) 链头**。用单链表实现队列时，队头应设在链表头结点位置，这样出队操作可 $O(1)$ 完成；队尾则设在链尾，配合尾指针可实现 $O(1)$ 入队。

**解题切入点**：队列是“一端入队、另一端出队”的 FIFO 结构，关键看单链表擅长哪种操作。单链表天然支持 $O(1)$ 在链头插入/删除，但删除链尾需要找到前驱，代价为 $O(n)$。所以应把频繁执行“删除”的一端（队头）放在链头，把频繁执行“插入”的一端（队尾）放在链尾。可以类比生活中排队：队头的人最先离开，出口设在队伍最前端最方便。

**推演**：

设单链表结点为：

```c
typedef struct QNode {
    ElemType data;
    struct QNode *next;
} QNode;
```

用单链表实现队列时，通常设置：

- 头指针 `front` 指向队头结点；
- 尾指针 `rear` 指向队尾结点。

若队头在链头，即 `front` 就是链表头指针：

- **出队**：删除 `front` 所指结点。
  ```c
  QNode *p = front;
  front = front->next;
  free(p);
  ```
  由于 `front` 即链头，删除头结点只需修改头指针，时间复杂度 $O(1)$。
- **入队**：在链尾插入新结点。
  ```c
  rear->next = s;
  rear = s;
  ```
  若有尾指针 `rear` 指向链尾，则入队也是 $O(1)$。

若将队头设在链尾，即 `front` 指向链尾结点：

- **出队**：需要删除链尾结点。单链表删除链尾结点必须从头指针出发遍历到链尾的前驱结点，再修改其 `next` 为 `NULL`，时间复杂度 $O(n)$，完全不符合队列 $O(1)$ 出队的要求。
- 即使维护了 `front` 指向链尾，链表本身没有指向前驱的指针，也无法快速找到新的队尾。

因此，用单链表实现队列时，队头必须设在链头位置，队尾设在链尾位置。这也是链式队列的标准结构。

**易错点**：

1. **误选 B（链尾）**：有些同学把“队头”和“队尾”混为一谈，误以为队尾在链尾，队头也应在链尾。实际上队头和队尾是队列两端，队头是出队端，队尾是入队端。
2. **忽略单链表删除链尾的成本**：单链表删除头结点 $O(1)$，但删除尾结点需要找前驱，$O(n)$。若把队头设在链尾，会让出队退化为线性时间。
3. **混淆“栈顶在链头”的结论**：用单链表实现栈时，栈顶也应设在链头；但栈顶是插入/删除同一端，而队列是两端操作，不能照搬。

**命题规律**：本题属于“队列的链式存储结构”基础题，考查队列操作与单链表特点的结合。常见的变式有：

- 若用单链表实现队列，入队和出队的时间复杂度分别是多少？（答案：$O(1)$，前提是维护尾指针）
- 若只设头指针，不设尾指针，入队操作时间复杂度为 $O(n)$；
- 用循环链表实现队列时，可以只设尾指针，队头为 `rear->next`，这也是常考写法。

复习建议：熟练掌握线性表头插/头删、尾插/尾删的实现代价，理解为什么要给链式队列额外维护尾指针；同时对比栈、队列在链表上的不同设计，能快速分析“某端操作是否 $O(1)$”。这类选择题通常直接考查结论，但综合题可能要求写出链式队列的初始化和入队、出队代码。
