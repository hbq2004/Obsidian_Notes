# 选择题 第 15 题

![[_Attachments/题目识别/27_王道408-题目/DS-C03-32-M15_题目.png|题目]]

15. 用链式存储方式的队列进行删除操作时需要 (\_)。
(A). 仅修改头指针
(B). 仅修改尾指针
(C). 头尾指针都要修改
(D). 头尾指针可能都要修改

## 答案

![[_Attachments/题目识别/27_王道408-答案/DS-C03-32-M15_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：选 D。链式队列删除操作通常只需修改头指针，但当队列中仅有一个结点时，删除后队列为空，还需将尾指针置空，因此头尾指针可能都要修改。

**解题切入点**：先明确链式队列的删除位置是队头，然后立即思考“删除后队列是否为空”这一边界条件。做数据结构题和写算法题一样，不能只写通法，必须检查临界情况——这是考“链式队列删除”时最经典的陷阱。

**推演**：

设链式队列用单链表实现，队头指针为 $front$，队尾指针为 $rear$。删除操作是在队头进行的。

一般情况下，队列中至少有两个结点。设当前 $front$ 指向队头结点，$rear$ 指向队尾结点。删除队头结点：

1. 用临时指针 $p$ 保存队头结点：$p = front$；
2. 将头指针后移：$front = front \to next$；
3. 释放原队头结点：$\text{free}(p)$。

此时队列中仍有结点，队尾指针 $rear$ 无需改变，仅修改了头指针。

特殊情况：队列中只有一个结点。此时满足 $front = rear$ 且 $front \neq NULL$。若仍按上述步骤执行，删除后 $front$ 变为 $NULL$，但 $rear$ 依然指向已被释放的结点，造成“野指针”，队列状态非法。因此必须额外处理：

$$
\text{free}(front); \quad front = rear = NULL;
$$

也就是说，删除最后一个结点时，头指针和尾指针都要修改。

可写出如下关键代码思路：

```c
// 假设队列非空
if (front == rear) {          // 队列中只有一个结点
    free(front);
    front = rear = NULL;      // 头尾指针同时修改
} else {
    p = front;
    front = front->next;
    free(p);
}
```

因此，“仅修改头指针”只适用于一般情况，不能覆盖队列中只有一个结点的情形；而“头尾指针都要修改”也不是每次删除都发生。所以最准确的表述是：头尾指针可能都要修改，答案为 D。

**易错点**：

- **误选 A（仅修改头指针）**：只记住了删除队头的一般过程，忽略队列中只有一个结点的边界情况，导致尾指针悬空。
- **误选 C（头尾指针都要修改）**：把特殊情况的处理当成了每次删除的必然操作，事实上队列中多于一个结点时，尾指针不需要变化。
- **忽略带头结点的链式队列**：若队列带头结点，删除最后一个元素时同样需要将 $rear$ 指向头结点（等价于修改尾指针），结论依然是 D。平时复习时应把带头结点和不带头结点的实现都画图理解。
- **未判断队列是否为空**：删除操作默认队列非空，但仍需注意代码健壮性，在实现中可先判断 $front == NULL$。

**命题规律**：

本题属于“栈和队列”章节的基础概念题，考查链式队列的存储结构及删除操作的边界条件。命题人常用“可能”二字设置陷阱，考查考生对操作细节的掌握程度。

常见变式：

- 链式队列的入队操作是否需要修改头指针？（通常只需要修改尾指针，空队列入队时头尾指针都要修改）
- 循环队列中，入队/出队时队头队尾指针如何变化？
- 判断链式队列空/满的条件。
- 给出带头结点和不带头结点两种实现的代码填空题。

复习建议：不要死记结论，务必自己画图模拟“空队列”“单结点队列”“多结点队列”三种状态下的入队和出队过程，同时对比顺序队列与链式队列的优缺点。这类题目难度不大，但需要细心，属于必须拿分的送分题。
