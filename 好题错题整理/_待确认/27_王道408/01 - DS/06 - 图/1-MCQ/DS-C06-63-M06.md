# 选择题 第 6 题

6. 对有 $n$ 个顶点、$e$ 条边的图采用邻接矩阵表示时，进行 $DFS$ 遍历的时间复杂度为 ( )，进行 $BFS$ 遍历的时间复杂度为 ( ).  
(A) $O(n^2)$  
(B) $O(e)$  
(C) $O(n+e)$  
(D) $O(e^2)$

## 答案

![[_Attachments/题目识别/27_王道408-答案/DS-C06-63-M06_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：两个空都选 (A)；采用邻接矩阵表示时，$DFS$ 与 $BFS$ 遍历的时间复杂度均为 $O(n^2)$。

**解题切入点**：拿到题先抓“邻接矩阵”这个存储条件，不要先想 DFS/BFS 本身。邻接矩阵的规模固定是 $n\times n$，无论边数 $e$ 是多少，找邻接点时都要扫描一整行。就像在一张 $n\times n$ 的表中逐行查邻接关系，表的大小决定了开销。

**推演**：邻接矩阵 $A$ 中，顶点 $u$ 的所有邻接信息都存放在第 $u$ 行。DFS 和 BFS 每处理一个顶点，都要检查该行中的 $n$ 个元素，而每个顶点至多被处理一次，因此总时间为
$$
T_{\rm DFS}=T_{\rm BFS}=\sum_{u=0}^{n-1}O(n)=O(n^2).
$$

DFS 的代码思路如下：

```
DFS(u):
    visited[u] = true
    for j = 0 to n-1:
        if A[u][j] and !visited[j]:
            DFS(j)
```

每个顶点只会作为递归入口进入一次，因此每个顶点的行最多被完整扫描一次，共 $n$ 行，每行长度 $n$，所以是 $O(n^2)$。

BFS 的代码思路如下：

```
BFS(s):
    visited[s] = true
    queue.push(s)
    while queue not empty:
        u = queue.pop()
        for j = 0 to n-1:
            if A[u][j] and !visited[j]:
                visited[j] = true
                queue.push(j)
```

每个顶点最多入队、出队一次，每次出队扫描一行，共 $n$ 行，每行长度 $n$，所以也是 $O(n^2)$。即使图不连通，外层循环再检查 $visited$ 数组，也只需额外 $O(n)$，不会改变复杂度。

因此，本题中 $e$ 没有进入复杂度表达式，答案不是 $O(n+e)$，而是 $O(n^2)$。

**易错点**：

1. **把邻接矩阵的复杂度记成邻接表的复杂度**。邻接表才是 $O(n+e)$，因为邻接表只需扫描有效邻接点；邻接矩阵即使没有边，也要扫描整行中的 0。
2. **看到 BFS 就条件反射选 $O(n+e)$**。错。复杂度取决于存储结构，BFS 在邻接矩阵下仍是 $O(n^2)$。
3. **认为稀疏图 $e$ 很小就更快**。例如 $e=0$ 的空图，仍要把每个顶点的整行 $n$ 个元素都检查一遍，仍为 $O(n^2)$。
4. **误选 $O(e^2)$ 或 $O(e)$**。这两个选项只在某些邻接表或特殊场景下可能有关，本题邻接矩阵下不成立。

**命题规律**：这是 408 常考基础考点：图的遍历时间复杂度与存储结构的关系。常见变式有：

- 邻接表表示时，DFS 与 BFS 的时间复杂度均为 $O(n+e)$；
- 邻接矩阵表示时，DFS 与 BFS 的时间复杂度均为 $O(n^2)$；
- 还可能结合 Prim、Dijkstra 等算法，考察邻接矩阵下的时间复杂度 $O(n^2)$。

复习建议：不要只背结论，要掌握推导方式——每次处理一个顶点，就扫描该顶点在对应存储结构中的邻接信息；邻接矩阵扫整行 $O(n)$，邻接表扫链表总长 $O(e)$。这样无论题目怎样变换存储结构，都能快速判断。
