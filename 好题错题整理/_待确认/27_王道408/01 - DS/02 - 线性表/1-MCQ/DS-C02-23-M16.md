# 选择题 第 16 题

![[_Attachments/题目识别/27_王道408-题目/DS-C02-23-M16_题目.png|题目]]

16. 在双链表存储结构中，删除$p$所指的结点时必须修改指针 ( )。
A. $p \rightarrow prior \rightarrow next = p \rightarrow next; p \rightarrow next \rightarrow prior = p \rightarrow prior;$
```c
p->prior->next = p->next;
p->next->prior = p->prior;
```
B. $p \rightarrow prior = p \rightarrow prior \rightarrow prior; p \rightarrow prior \rightarrow next = p;$
```c
p->prior = p->prior->prior;
p->prior->next = p;
```
C. $p \rightarrow next \rightarrow prior = p; p \rightarrow next = p \rightarrow next \rightarrow next;$
```c
p->next->prior = p;
p->next = p->next->next;
```
D. $p \rightarrow next = p \rightarrow prior \rightarrow prior; p \rightarrow prior = p \rightarrow next \rightarrow next;$
```c
p->next = p->prior->prior;
p->prior = p->next->next;
```

## DeepSeek V4 Flash Max 解析

**答案**：选 **A**。删除双链表中的结点 $p$，核心是让 $p$ 的前驱和后继互相“绕过” $p$：  
$$p\to prior\to next = p\to next,\qquad p\to next\to prior = p\to prior.$$

**解题切入点**：看到“双链表删除结点”，马上定位到链表指针修改问题。双链表比单链表多了一个前驱指针，删除已知结点 $p$ 时可以做到 $O(1)$，关键是同时修改前后两个邻居的指针，而不是把精力放在移动数据上。打个比方：从队伍中抽走一个人，只需要让前面的人的手搭到后面的人身上，后面的人改看前面的人；被抽走的人自己的手不用管。

**推演**：

设双链表中存在相邻三个结点：
- $a = p\to prior$：$p$ 的前驱；
- $p$：要被删除的结点；
- $b = p\to next$：$p$ 的后继。

删除前有关系：
$$
a\to next = p,\qquad b\to prior = p.
$$

删除 $p$ 后，$a$ 和 $b$ 必须直接相连，即必须满足：
$$
a\to next = b,\qquad b\to prior = a.
$$

写成代码就是：

```c
p->prior->next = p->next;   // a 的后继改为 b
p->next->prior = p->prior;  // b 的前驱改为 a
free(p);                     // 释放 p
```

这正好对应 **A** 选项。

逐项排除：

- **A**：正确完成 $a\to next = b$ 和 $b\to prior = a$，删除后链表仍然完整。
- **B**：修改的是 $p$ 的前驱指针，相当于试图从 $p$ 前面“跨过”一个结点，但原来的前驱结点没有被正确摘除，链表会乱。
- **C**：只修改了 $p\to next$，没有让 $p$ 的前驱和后继互相连接，不能删除 $p$。
- **D**：两个赋值互相依赖且没有正确连接前后结点，链表被破坏。

需要补充：如果 $p$ 是尾结点，则 $p\to next$ 为空，不能直接执行 `p->next->prior = p->prior;`。实际写代码时应加判空：

```c
p->prior->next = p->next;
if (p->next != NULL)
    p->next->prior = p->prior;
free(p);
```

但本题默认常规情况，选择标准操作 **A**。

**易错点**：

1. **选成 B/C/D**：没有抓住删除的本质是“让前驱和后继互相连接”，而不是修改 $p$ 自己的指针。
2. **忘记修改后继的前驱指针**：只写 `p->prior->next = p->next;`，会导致正向遍历看似正确，但反向遍历从后继无法回到前驱。
3. **先修改 p 的指针再连接邻居**：比如先写 `p->next = p->next->next;`，会丢失原来的后继信息，导致后续指针错乱。
4. **忽略边界条件**：$p$ 是头结点或尾结点时，`p->prior` 或 `p->next` 可能为空，不判空会访问空指针。
5. **删除后忘记释放空间**：在 C/C++ 中删除结点后通常应调用 `free(p)` 或 `delete p`，防止内存泄漏。

**命题规律**：本题是 408 数据结构“线性表”部分的经典考点，常以选择题形式考查双链表的插入、删除、遍历等指针操作。常见变式包括：

- 删除 $p$ 的前驱或后继结点；
- 在 $p$ 之前或之后插入结点；
- 判断一段指针修改代码是否能完成指定操作；
- 将双链表与单链表删除已知结点的时间复杂度对比：单链表删除已知结点需要找前驱 $O(n)$，双链表可做到 $O(1)$。
