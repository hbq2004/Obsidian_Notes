# 选择题 第 12 题

![[_Attachments/题目识别/27_王道408-题目/DS-C02-22-M12_题目.png|题目]]

12. 顺序表的插入算法中，当 $n$ 个空间已满时，可再申请增加分配 $m$ 个空间，若申请失败，则说明系统没有 ( ) 可分配的存储空间.
(A) $m$ 个
(B) $m$ 个连续
(C) $n+m$ 个
(D) $n+m$ 个连续

## DeepSeek V4 Flash Max 解析

**答案**：选 D。顺序表动态扩容时，若原容量为 $n$ 且已满，再申请增加 $m$ 个空间，本质上是要求系统提供 $n+m$ 个连续存储单元；申请失败说明系统没有 $n+m$ 个连续的可分配空间。

**解题切入点**：  
看到“顺序表”立刻想到“连续存储”；看到“已满再申请增加 $m$ 个空间”立刻想到“动态扩容”；看到“申请失败”要联想到内存分配是以连续内存块为单位的。  
可以用“宿舍搬家”类比：原来一个连续宿舍住满 $n$ 人，现在要多住 $m$ 人，不能拆成两个分开放置的宿舍，必须整体搬到能容纳 $n+m$ 人的连续房间；如果找不到，就说明没有 $n+m$ 个连续床位。

**推演**：  

1. 顺序表采用顺序存储结构，逻辑相邻的元素在物理内存中也必须相邻，因此整个表必须占用一段连续的存储空间。  
2. 设当前表容量为 $n$，且已经存满。此时插入新元素，容量不足，需要扩容，常见做法是申请一个更大的连续空间，使新容量为 $n+m$。  
3. 这块新空间不仅要放下原来已有的 $n$ 个元素，还要为新增的 $m$ 个元素留出位置，所以总需求为 $n+m$ 个存储单元，并且必须是连续的。  
4. 如果系统只能找到 $m$ 个连续空间，但无法与原来的 $n$ 个空间连续拼接，则仍不能构成顺序表。因此扩容时真正向系统申请的是 $n+m$ 个连续空间。  
5. 内存分配失败，说明系统中不存在长度至少为 $n+m$ 的连续空闲区，即没有 $n+m$ 个连续可分配的存储空间。

关键代码思路如下：

```c
// 顺序表扩容：原容量为 n，扩容增量为 m
if (L.length >= L.MaxSize) {
    // 重新申请 n+m 个连续空间，或尝试原地扩展
    ElemType *newBase = (ElemType *) realloc(
        L.elem, (L.MaxSize + m) * sizeof(ElemType));
    if (newBase == NULL) {
        // 失败原因：系统没有 n+m 个连续空间
        exit(OVERFLOW);
    }
    L.elem = newBase;
    L.MaxSize += m;
}
```

因此，正确答案为 D。

**易错点**：  
- 容易误选 B（$m$ 个连续）：只看到“增加 $m$ 个空间”，忽略了新表必须同时容纳原来的 $n$ 个元素，总数应为 $n+m$。  
- 容易误选 C（$n+m$ 个）：虽然数量正确，但顺序表要求连续存储，缺少“连续”这一关键条件。  
- 容易误选 A（$m$ 个）：既没有考虑总数，也没有考虑连续性。  
- 注意“申请失败”不代表系统总剩余空间不足 $n+m$，而是没有足够大的连续空闲区，可能存在内存碎片。

**命题规律**：  
本考点属于“线性表之顺序表”的基础内容，常以选择题考查顺序表动态扩容时对连续内存的需求，也可能结合操作系统中的内存分配、碎片化出题。常见变式有：  
- 问顺序表插入时元素移动次数；  
- 比较顺序表与链表在存储空间上的利用特点；  
- 问动态扩容为什么通常成倍增加（例如翻倍），涉及均摊分析。  
复习时应重点理解顺序存储结构“占用连续空间”的本质，以及动态扩容时“重新申请、复制数据、释放旧空间”的完整过程，并与链表动态分配进行对比。
