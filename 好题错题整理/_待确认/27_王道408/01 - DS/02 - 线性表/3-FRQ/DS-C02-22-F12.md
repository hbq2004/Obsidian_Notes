# 综合题 第 12 题

![[_Attachments/题目识别/27_王道408-题目/DS-C02-22-F12_题目.png|题目]]

12.【2013统考真题】已知一个整数序列 $A = (a_0, a_1, \cdots, a_{n-1})$, 其中 $0 \leq a_i < n (0 \leq \mathrm{i} < n)$. 若存在 $a_{p_1} = a_{p_2} = \cdots = a_{p_m} = x$ 且 $m > n/2 (0 \leq p_k < n, 1 \leq k \leq m)$, 则称 $x$ 为 $A$ 的主元素. 例如 $A = (0, 5, 5, 3, 5, 7, 5, 5)$, 则 $5$ 为主元素; 又如 $A = (0, 5, 5, 3, 5, 1, 5, 7)$, 则 $A$ 中没有主元素. 假设 $A$ 中的 $n$ 个元素保存在一个一维数组中, 请设计一个尽可能高效的算法, 找出 $A$ 的主元素. 若存在主元素, 则输出该元素; 否则输出 $-1$. 要求:
1) 给出算法的基本设计思想.
2) 根据设计思想, 采用 $C$ 或 $C++$ 或 $Java$ 语言描述算法, 关键之处给出注释.
3) 说明你所设计算法的时间复杂度和空间复杂度.

## 答案

## DeepSeek V4 Flash Max 解析

**答案**：采用摩尔投票法（候选抵消法）完成两趟线性扫描：第一趟选出唯一可能的主元素候选，第二趟验证其出现次数是否大于 $n/2$；时间复杂度 $O(n)$，空间复杂度 $O(1)$。若验证通过则输出该元素，否则输出 $-1$。

**解题切入点**：
- 看到“出现次数超过一半”，应立刻定位到经典“多数元素”问题。若存在主元素，它必然唯一，因为两个不同元素的出现次数不可能都大于 $n/2$。
- “尽可能高效”意味着不要排序，因为排序至少 $O(n\log n)$；也不要用计数数组或哈希表，因为辅助空间为 $O(n)$。最佳思路是做到 $O(n)$ 时间、$O(1)$ 空间。
- 核心思想是“不同元素两两抵消”：真正的主元素数量超过其他元素总数，抵消到最后不可能被完全抵消掉；但无主元素时也可能留下某个候选者，所以必须再验证。

**推演**：

（1）基本设计思想

维护两个变量：候选元素 `cand` 和计数器 `cnt`。

第一遍扫描数组：

- 若 `cnt == 0`，说明当前候选已被全部抵消，令 `cand = A[i]`，`cnt = 1`；
- 若 `A[i] == cand`，则 `cnt++`，表示又来一个同类元素；
- 否则 `cnt--`，表示用一个不同元素抵消掉一个候选者。

这一过程等价于不断从数组中删除两个不同的元素。若主元素 $x$ 出现 $m$ 次，且 $m>n/2$，则非 $x$ 的元素共有 $n-m$ 个。因为 $m>n-m$，即使所有非 $x$ 元素都用来抵消 $x$，也最多抵消掉 $n-m$ 个 $x$，最终仍会剩下
$$
m-(n-m)=2m-n>0
$$
个 $x$ 未被抵消。因此，若存在主元素，第一遍扫描后留下的候选者一定是它；若第一遍扫描后 `cnt == 0`，则说明不可能存在主元素。

但第一遍留下的候选者不一定是真正的主元素，所以必须第二遍扫描，统计 `cand` 在原数组中的真实出现次数，若大于 $n/2$ 才输出，否则输出 $-1$。

（2）C/C++ 算法描述

```cpp
int findMain(int A[], int n) {
    int cand = -1;  // 候选元素，题中元素非负，-1 可作哨兵
    int cnt = 0;    // 当前候选未被抵消的个数

    // 第一遍：抵消不同元素，选出候选
    for (int i = 0; i < n; ++i) {
        if (cnt == 0) {     // 当前候选已被全部抵消
            cand = A[i];
            cnt = 1;
        } else if (A[i] == cand) {
            ++cnt;          // 同值，候选剩余数加 1
        } else {
            --cnt;          // 异值，抵消掉一个候选
        }
    }

    if (cnt == 0)           // 已全部抵消，不可能有主元素
        return -1;

    // 第二遍：验证候选是否真的是主元素
    cnt = 0;
    for (int i = 0; i < n; ++i) {
        if (A[i] == cand)
            ++cnt;
    }

    return cnt > n / 2 ? cand : -1;
}
```

（3）时间与空间复杂度

第一遍扫描 $n$ 个元素，第二遍扫描 $n$ 个元素，共 $2n$ 次基本操作，因此时间复杂度为
$$
O(n)
$$

算法只使用了常数个辅助变量，因此空间复杂度为
$$
O(1)
$$

**易错点**：
- 只选候选不验证。第一遍结束后 `cnt > 0` 并不能说明 `cand` 就是主元素；没有主元素时也可能留下某个候选，必须第二遍重新统计。
- 把第一遍的 `cnt` 误当成 `cand` 的真实出现次数。`cnt` 是抵消后剩余的“票数”，不是原数组中的实际出现次数。
- 判断条件写错。主元素要求 $m>n/2$，不是 $m \geqslant n/2$；当 $n$ 为偶数时，出现次数恰好等于 $n/2$ 也不能输出。
- 忽略无主元素的情况。第二遍验证不通过时要输出 $-1$。
- 使用哨兵时要注意：本题中 $0 \leqslant a_i < n$，所以用 $-1$ 作为失败标志是安全的。

**命题规律**：
- 本题是 408 中典型的“数组线性扫描 + 算法设计”综合题，考点是多数元素问题、候选抵消法、时间空间复杂度分析。
- 常见变式包括：查找出现次数超过 $n/k$ 的元素、查找数组中出现次数最多的元素、判断某个元素是否为主元素等。若推广到超过 $n/k$，需要维护 $k-1$ 个候选者。
- 复习时应把摩尔投票法当作模板熟记，重点掌握“先选候选，再验证”的两阶段结构，并能够写出清晰的设计思想、代码和复杂度分析。
