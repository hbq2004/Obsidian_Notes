# 综合题 第 10 题

![[_Attachments/题目识别/27_王道408-题目/DS-C02-23-F10_题目.png|题目]]

10. 两个整数序列 $A = a_1, a_2, a_3, \cdots, a_m$ 和 $B = b_1, b_2, b_3, \cdots, b_n$ 已经存入两个单链表中, 设计一个算法, 判断序列 $B$ 是否是序列 $A$ 的连续子序列.

## DeepSeek V4 Flash Max 解析

**答案**：采用双指针与“回溯”思想的朴素模式匹配算法，枚举链表 $A$ 中每个可能的匹配起点，依次与链表 $B$ 的结点逐位比较；若某次比较能将 $B$ 完整遍历完，则 $B$ 是 $A$ 的连续子序列。算法时间复杂度为 $O(m \times n)$，空间复杂度为 $O(1)$。

**解题切入点**：拿到题目首先明确考点是“单链表的遍历与指针操作”及“线性表的模式匹配”。连续子序列问题与字符串中匹配子串问题本质相同，但链表不支持随机访问，因此不能使用基于下标跳跃的 $O(m+n)$ 算法（如 KMP 的简化版），只能采用最直观的“固定起点 + 逐位比较”的暴力枚举法。从竞赛做题经验来看，这类似于“字符串朴素匹配”，难点在于链表的指针回退需要额外借助临时指针保存当前起点，而不是像数组那样用下标 $i-j+1$ 回溯。核心思路是“外层循环枚举起点，内层循环尝试匹配，失败则回溯到起点的下一个结点”。

**推演**：

1. **算法设计思路**  
   设两个带头结点的单链表，头结点指针分别为 $A$ 和 $B$。定义三个指针：
   - `p`：指向表 $A$ 中当前尝试匹配的起点，初始化为 `A->next`；
   - `pre`：临时指针，用于在内层比较时跟随 `p` 移动，保存当前正在比较的 $A$ 中的位置；
   - `q`：指向表 $B$ 当前待比较结点，初始化为 `B->next`。

   对于表 $A$ 中的每一个结点（以 `p` 为起点），执行以下操作：
   - 令 `pre = p`，`q = B->next`；
   - 当 `pre` 与 `q` 均非空且 `pre->data == q->data` 时，同步后移：`pre = pre->next`，`q = q->next`；
   - 若 `q` 为空，说明表 $B$ 的所有结点均已匹配成功，算法结束，返回 `true`；
   - 若 `q` 非空（说明内层比较在中途失败），则令 `p = p->next`，即尝试下一个起点，算法继续。

2. **正确性证明**  
   - **完备性**：外层循环遍历了 $A$ 中所有可能作为匹配起点的结点。若 $B$ 是 $A$ 的连续子序列，则当 `p` 指向 $B$ 在 $A$ 中首次出现位置（即 $a_k = b_1$）时，内层循环必然能完全匹配 $B$，从而返回 `true`。  
   - **可靠性**：内层循环只有在 `pre` 与 `q` 数据相等时才同步后移，一旦发现不等立即终止，因此不会出现误判。若 `q` 为空，说明 $B$ 中全部 $n$ 个结点已按序连续匹配，故结论正确。  
   - **边界情况**：若 $B$ 为空链表（$n=0$），依据空序列是任意序列的连续子序列的约定，直接返回 `true`；若 $A$ 为空且 $B$ 非空，则返回 `false`。

3. **关键代码思路（C 语言描述）**

   ```c
   typedef struct LNode {
       int data;
       struct LNode *next;
   } LNode, *LinkList;

   bool isSubSequence(LinkList A, LinkList B) {
       if (B->next == NULL) return true;          // B 为空
       LNode *p = A->next;                        // A 的工作指针
       while (p != NULL) {
           LNode *pre = p;                        // 保存当前匹配起点
           LNode *q = B->next;                    // B 的匹配指针
           while (pre != NULL && q != NULL && pre->data == q->data) {
               pre = pre->next;                   // 同步前进
               q = q->next;
           }
           if (q == NULL) return true;            // B 匹配完
           p = p->next;                           // 匹配失败，A 的起点后移
       }
       return false;                              // A 遍历完仍未匹配成功
   }
   ```

4. **复杂度分析**  
   - **时间复杂度**：外层循环最多执行 $m$ 次，内层循环每次最多执行 $n$ 次，故最坏时间复杂度为 $O(m \times n)$。当 $B$ 恰好是 $A$ 的起始连续子序列（$b_1 = a_1$ 且后续完全匹配）时，内层只需一次完整匹配，最好时间复杂度为 $O(n)$。
   - **空间复杂度**：只使用了常数个辅助指针，故为 $O(1)$。

**易错点**：

1. **指针丢失与回溯错误**：很多考生在内层匹配失败后，让 `pre` 直接后移作为新起点（即 `pre = pre->next`），这是错误的。因为 `pre` 在内层循环中已经向后移动了若干步，若以它为起点会跳过 $A$ 中很多可能的匹配位置（例如 $A = [1,2,1,2,3]$，$B=[1,2,3]$，失败后直接移动 `pre` 会漏掉第二个 1 开头的匹配）。正确做法是**必须用外层 `p` 每轮固定保存起点，失败后 `p = p->next`**。
2. **忽略头结点**：题目明确链表是带头结点的单链表，若误将 `A` 或 `B` 当作首元结点指针，则会把头结点数据参与比较，导致错误结果。必须初始化 `p = A->next`。
3. **内层循环条件缺失判空**：若不在 `inner while` 中判断 `pre != NULL`，当 `p` 接近表尾且 $B$ 比剩余部分长时，会访问空指针导致程序崩溃。条件必须是 `pre != NULL && q != NULL && pre->data == q->data`。
4. **对“连续”二字理解偏差**：连续子序列要求 $b_i$ 在 $A$ 中必须位置相邻，不能跳过任何结点。若误用“依次匹配但允许跳点”的双指针算法（即不连续子序列判断），会导致结果错误。
5. **空表边界处理**：若 $B$ 为空表，按数学定义应视为连续子序列，但部分考生未考虑直接返回 `false`，造成边界失分。

**命题规律**：

1. **考点定位**：本题属于线性表章节中“单链表基本操作”的综合应用，核心考查链表遍历、指针同步移动和边界条件控制。在 408 历年真题中，此类题常以 10~15 分综合应用题出现，难度中等，但极易因指针操作不当而失分。
2. **常见变式**：
   - **变式一**：判断 $B$ 是否为 $A$ 的**子序列（不要求连续）**。解法改为双指针常规扫描，$A$ 指针每步固定后移，$B$ 指针仅在数据相等时后移，时间复杂度降为 $O(m+n)$。
   - **变式二**：将链表改为**带头结点的循环链表**，判断循环链表中是否存在某连续子序列等于 $B$，此时外层循环需要设置计数器防止无限循环。
   - **变式三**：求两个链表的**公共后缀**起始位置，常用“双指针先对齐长度再同步走”的技巧（非朴素匹配，但思想同为指针运动）。
   - **变式四**：若题目要求“设计高效算法”，可联想到将链表转换为数组再做 KMP，但需注意额外空间开销；在 408 阅卷标准里，如果题目未要求最优解，朴素算法即为满分标准答案。
3. **复习建议**：务必熟练掌握单链表遍历的模板代码，养成“画图模拟指针移动”的习惯。复习时可将字符串的 `strstr` 朴素匹配代码与链表版对照记忆，理解“回溯”在不同存储结构下的实现差异。答题时建议分步骤书写：(1) 明确数据结构定义；(2) 画出核心代码或流程图；(3) 用文字描述正确性；(4) 给出时空复杂度。这样即使代码细节有小错，也能得到大部分步骤分。
