# 综合题 第 12 题

![[_Attachments/题目识别/27_王道408-题目/DS-C02-23-F12_题目.png|题目]]

12. 有两个循环单链表,链表头指针分别为 $h_1$ 和 $h_2$,编写一个函数将链表 $h_2$ 链接到链表 $h_1$ 之后,要求链接后的链表仍保持循环链表形式.

## DeepSeek V4 Flash Max 解析

**答案**：先分别找到两个循环单链表的尾结点 $t_1,t_2$，然后修改两条指针：$t_1\to next=h_2$，$t_2\to next=h_1$。这样就把 $h_2$ 链接到 $h_1$ 之后且仍构成单一循环链表。时间复杂度 $O(n+m)$，空间复杂度 $O(1)$。

**解题切入点**：循环单链表的标志是“尾结点的 next 指向头指针”，而不是 `NULL`。所以拿到题先找两个链表的尾结点，而不是从头到尾把所有结点重新链接一遍。可以把两个循环链表看成两个“环”，合并成一个环只需要找到两个环的接口，再改两条指针即可。

**推演**：设两个链表均不带头结点，头指针分别指向首元结点；$h_1$ 链有 $n$ 个结点，$h_2$ 链有 $m$ 个结点。链接前：

$$
h_1=a_1\to a_2\to\cdots\to a_n\to h_1
$$

$$
h_2=b_1\to b_2\to\cdots\to b_m\to h_2
$$

链接后希望得到：

$$
h_1=a_1\to a_2\to\cdots\to a_n\to b_1(=h_2)\to b_2\to\cdots\to b_m\to h_1
$$

所以关键是找到 $a_n$ 和 $b_m$，即两个链表的尾结点。代码如下：

```c
typedef struct LNode {
    int data;
    struct LNode *next;
} LNode, *LinkList;

LinkList merge(LinkList h1, LinkList h2) {
    if (h1 == NULL) return h2;
    if (h2 == NULL) return h1;

    LNode *p = h1, *q = h2;

    // 找到 h1 的尾结点
    while (p->next != h1)
        p = p->next;

    // 找到 h2 的尾结点
    while (q->next != h2)
        q = q->next;

    // 将 h1 尾结点接到 h2 首结点
    p->next = h2;

    // 将 h2 尾结点接回 h1 首结点，形成循环
    q->next = h1;

    return h1;
}
```

算法正确性在于：

1. 第一个 `while` 循环结束时，$p$ 必为 $h_1$ 链的尾结点 $a_n$，因为循环单链表中只有尾结点的 `next` 指向头指针 $h_1$。
2. 第二个 `while` 循环结束时，$q$ 必为 $h_2$ 链的尾结点 $b_m$。
3. 执行 `p->next = h2` 后，$a_n\to next=b_1$。
4. 执行 `q->next = h1` 后，$b_m\to next=a_1$，整个链表形成唯一环。

因此从 $h_1$ 出发可以遍历原来两个链表的所有结点，并且最终回到 $h_1$，满足题目要求。

**易错点**：

- 容易继续用普通单链表的 `p->next == NULL` 判断表尾。循环单链表的表尾判断应为 `p->next == h1` 或 `p->next == h2`。
- 只执行 `p->next = h2`，忘记执行 `q->next = h1`。这样 $h_2$ 原来的环没有被拆开，最终不是单一循环链表。
- 修改指针前必须分别保存两个尾结点；否则一旦断链可能丢失后半部分结点。
- 注意链接顺序：$p$ 的 next 应接 $h_2$，而不是接 $q$；$q$ 的 next 应接 $h_1$，而不是接 `NULL`。
- 若题目中的循环链表带头结点，则应连接 `p->next = h2->next`，再让 `q->next = h1`，并释放 $h_2$ 的头结点；不能把 $h_2$ 头结点作为数据结点留在链表中间。

**命题规律**：本题属于线性表链式存储中的经典指针操作题，核心是“循环单链表的遍历与尾结点定位”。408 中常与“判断链表是否有环”“寻找环入口”“两个链表合并”等考点结合考查。复习时建议通过画图模拟指针变化，熟练掌握不带头结点和带头结点两种循环链表写法，并准确分析时间复杂度与空间复杂度。
