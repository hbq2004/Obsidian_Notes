# 选择题 第 24 题

![[_Attachments/题目识别/27_王道408-题目/DS-C05-53-M24_题目.png|题目]]

24. 判断线索二叉树中 $*p$ 结点有右孩子结点的条件是 (  ) .
(A) $p != NULL$
(B) $p \rightarrow rchild != NULL$
(C) $p \rightarrow rtag == 0$
(D) $p \rightarrow rtag == 1$

---

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/DS-C05-53-M24_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：选 C。线索二叉树中，$*p$ 有右孩子当且仅当 $p\to rtag == 0$，即 $p\to rchild$ 字段表示真正的右孩子。

**解题切入点**：看到“线索二叉树”就要立刻想到：$rchild$ 字段被复用了，它既可以指向右孩子，也可以指向中序（或对应遍历序）后继。因此不能一看到 `rchild != NULL` 就认为有右孩子，先看标志位 `rtag`。这就像读一个联合体变量时，必须先看类型标记字段才能解释数据。

**推演**：

线索二叉树结点一般定义为：

```c
typedef struct ThreadNode {
    ElemType data;
    struct ThreadNode *lchild, *rchild;
    int ltag, rtag;   // 0 表示孩子，1 表示线索
} ThreadNode;
```

标志位的含义是：

$$
rchild=
\begin{cases}
右孩子, & rtag=0 \\
后继线索, & rtag=1
\end{cases}
$$

同理：

$$
lchild=
\begin{cases}
左孩子, & ltag=0 \\
前驱线索, & ltag=1
\end{cases}
$$

所以，“$*p$ 有右孩子”与“$p\to rchild$ 是否为空”没有直接关系，关键在于 $rtag$ 的值：

- 若 $p\to rtag == 0$，则 $p\to rchild$ 指向右孩子，因此有右孩子。
- 若 $p\to rtag == 1$，则 $p\to rchild$ 指向后继线索，不是右孩子，因此无右孩子。

逐项判断：

- A：$p != NULL$。这只能说明 $p$ 是合法结点，不能说明它有右孩子。
- B：$p\to rchild != NULL$。线索化后，即使没有右孩子，$rchild$ 也可能指向中序后继，因此不能作为“有右孩子”的判据。
- C：$p\to rtag == 0$。标志位为 0，表示 $rchild$ 是真正的右孩子，正确。
- D：$p\to rtag == 1$。标志位为 1，表示 $rchild$ 是后继线索，说明没有右孩子，错误。

关键判断代码思路如下：

```c
if (p->rtag == 0) {
    // p 有右孩子
} else {
    // p 没有右孩子，p->rchild 是后继线索
}
```

**易错点**：

1. 误选 B：把 `rchild != NULL` 当成“有右孩子”。线索化后 `rchild` 可能存放后继线索，即使没有右孩子也可能非空。
2. 混淆 `ltag` 和 `rtag`：判断右孩子要看 `rtag`，判断左孩子要看 `ltag`。
3. 忽略标志位的优先性：在线索二叉树中，必须用 `rtag` 来判断 `rchild` 的含义，而不是直接判断指针值。
4. 将 A 当作充分条件：`p != NULL` 只是访问前提，不是“有右孩子”的条件。

**命题规律**：

本题属于“线索二叉树存储结构”的基础概念题。考查重点是线索二叉树中标志位的含义。常见变式有：

- 判断 $*p$ 有无左孩子：条件是 $p\to ltag==0$。
- 在中序线索二叉树中求某结点的后继：若 $p\to rtag==1$，则 `rchild` 直接是后继；若 $p\to rtag==0$，则后继是右子树中最左下结点。
- 考查线索化过程中空指针如何改为线索，以及前序、中序、后序线索树中找前驱/后继的区别。

复习建议：牢记“0 孩子，1 线索”。自己画一棵二叉树，手工完成中序线索化，并逐个结点判断左/右孩子、前驱/后继，就能彻底掌握该类题。
