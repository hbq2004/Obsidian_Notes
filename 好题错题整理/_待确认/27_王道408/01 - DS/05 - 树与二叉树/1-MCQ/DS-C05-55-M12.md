12. 下列关于并查集的说法中，正确的是 ( )(注，本题涉及图的考点).

(A) 并查集不能检测图中是否存在环路的问题

(B) 通过路径优化后的并查集在最坏情况下的高度仍是 $O(n)$

(C) $Find$ 操作返回集合中元素个数的相反数，它用来作为某个集合的标志

(D) $Union$ 操作时可根据当前集合的规模，将小集合合并到大集合中

## DeepSeek V4 Flash Max 解析

**答案**：选 D。并查集可以用于检测无向图中的环路；$Union$ 操作按集合规模把小集合并入大集合是一种正确的优化策略。

**解题切入点**：看到并查集先想两件事：$Find$ 找“代表元素”，$Union$ 合并两个集合。再结合图的 Kruskal 算法：判断一条边是否会形成环路，就是看它的两个端点是否已经在同一个集合中。选项 A 考判环，B、D 考优化，C 考并查集数组的存储方式。

**推演**：

并查集常用“双亲表示法”存储：

- 每个集合用一棵树表示；
- 根结点可以作为集合的代表元素；
- $Find(x)$ 沿父指针找到根；
- $Union(x,y)$ 先找两个根，若根相同则无需合并，否则把一个根挂到另一个根下。

### 逐个选项分析

**A 错误。**  
并查集可以检测无向图中的环路。例如在 Kruskal 算法中，对每条边 $(u,v)$：

```c
ru = Find(u);
rv = Find(v);
if (ru == rv) {
    // 说明 u 和 v 已经连通，再连这条边就形成环
} else {
    Union(ru, rv);
}
```

因此“并查集不能检测图中是否存在环路”的说法是错误的。需要注意：它通常直接适用于**无向图**；有向图判环一般用拓扑排序或 DFS。

**B 不是本题应选项。**  
如果只做“路径压缩”而不做“按规模/按秩合并”，最坏情况下树的高度确实仍可能达到 $O(n)$。例如不断把当前根挂到新结点上，并且不触发对深层结点的查找，路径压缩就不会改善高度。  
但 408 常规语境中，优化后的并查集通常指“路径压缩 + 按规模/按秩合并”，此时最坏树高为 $O(\log n)$，均摊时间复杂度接近 $O(1)$。因此 B 的表述有歧义，不是本题要选的最无争议正确项。

**C 错误。**  
$Find$ 操作返回的是集合的**根结点/代表元素**，不是集合元素个数的相反数。  
若采用根结点存负数表示集合大小的写法：

```c
int Find(int S[], int x) {
    while (S[x] >= 0) x = S[x];
    return x;
}
```

根结点处可能存储负数，例如 `S[root] = -size`，但 $Find$ 仍然返回 `root`，而不是返回 `-size`。负数值只是用来表示“当前结点是根，并且集合大小为 $size$”。

**D 正确。**  
$Union$ 时可以采用“按规模合并”：把小集合的根挂到大集合的根上。这样每个结点的深度增加时，它所在集合的大小至少翻倍，因此每个结点深度至多为 $O(\log n)$，树高为 $O(\log n)$。

关键思想：

```c
int root1 = Find(x);
int root2 = Find(y);
if (root1 == root2) return;

// 假设 size[root1] >= size[root2]
parent[root2] = root1;
size[root1] += size[root2];
```

**易错点**：

1. 误以为并查集不能判环。实际上 Kruskal 算法就用并查集判断无向图是否形成环。
2. 混淆“根结点存负数”和“$Find$ 返回负数”。$Find$ 返回根下标，而不是负的集合大小。
3. 只记忆“路径压缩”而忽略“按规模/按秩合并”。单独路径压缩最坏高度仍可能为 $O(n)$；配合按规模合并后高度为 $O(\log n)$。
4. 判环时要注意图是**无向图**；有向图判环不能简单用并查集。

**命题规律**：

并查集在 408 中常结合图出题，尤其是：

- Kruskal 最小生成树中的判环；
- 判断无向图的连通分量个数；
- 并查集 $Find$、$Union$ 操作的复杂度分析；
- 路径压缩与按规模/按秩合并的优化效果。

复习时应熟练掌握并查集的数组实现，并能手写：

```c
Find(x);
Union(x, y);
```

同时理解“路径压缩”和“按规模合并”各自的作用，以及它们对树高的影响。
