## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C06-Q03_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：  
Web 服务器的 IP 地址是 $64.170.98.32$；该主机的默认网关 MAC 地址是 $00\text{-}21\text{-}27\text{-}21\text{-}51\text{-}ee$。构造图 2 数据帧时用 ARP 确定目的 MAC 地址，ARP 请求帧的目的 MAC 地址为广播地址 $\text{FF-FF-FF-FF-FF-FF}$；从发出该 HTTP 请求算起，持续非流水线方式下共需 $6$ 个 RTT；路由器 R 转发该 IP 分组时，需修改源 IP 地址、TTL、IP 首部校验和。

**解题切入点**：  
拿到题目先不要看 HTTP 内容，而要做“抓包式”逐层拆解：以太网帧头 $14$ B，接着是 IP 首部 $20$ B，再接着是 TCP 首部。先看二层目的 MAC 是谁，判断是否发给默认网关；再看三层源/目的 IP，判断 Web 服务器地址和 NAT；最后看四层目的端口是否为 $80$，确认是 HTTP 请求。HTTP 部分只需数对象个数，并结合“持续非流水线”判断 RTT 数量。

**推演**：

### 1. 以太网帧解析：确定 Web 服务器 IP 和默认网关 MAC

以太网帧头为 $14$ B：

- 目的 MAC：前 $6$ B 为 `00 21 27 21 51 ee`；
- 源 MAC：第 $7\sim 12$ B 为 `00 15 c5 c1 5e 28`，正是该主机的 MAC；
- 类型：第 $13\sim 14$ B 为 `08 00`，表示上层是 IPv4。

因此，该以太网帧是主机发出的、目的 MAC 不是 Web 服务器 MAC，而是路由器 R 的 MAC。因为目的 IP 不在本局域网中，主机必须把 IP 分组交给默认网关转发，所以该帧的目的 MAC 就是默认网关的 MAC：

$$
\text{默认网关 MAC}=00\text{-}21\text{-}27\text{-}21\text{-}51\text{-}ee
$$

继续解析 IP 首部：

- `45`：IPv4，首部长度 $5\times 4=20$ B；
- 源 IP：`0a 02 80 64`，即 $10.2.128.100$；
- 目的 IP：`40 aa 62 20`，即 $64.170.98.32$。

因为这是主机发往 Web 服务器的 IP 分组，所以 Web 服务器 IP 地址就是：

$$
64.170.98.32
$$

### 2. ARP 协议：确定目的 MAC 地址的方式

主机知道 Web 服务器的 IP 地址，但不知道默认网关的 MAC 地址。由于目的 IP 不在同一局域网内，主机不会对 Web 服务器做 ARP，而是对默认网关的 IP 地址做 ARP，以获得网关 MAC 地址。

ARP 请求是广播报文，因此封装 ARP 请求的以太网帧目的 MAC 地址是广播地址：

$$
\text{FF-FF-FF-FF-FF-FF}
$$

ARP 应答则是单播给请求主机。图 2 的以太网帧目的 MAC 为 `00-21-27-21-51-ee`，说明此时 ARP 已经完成。

### 3. HTTP/1.1 持续非流水线方式下的 RTT 数量

图 2 中 TCP 目的端口为 `00 50`，即 $80$，且载荷以 `GET /rfc.html` 开头，说明这是浏览器请求主页 `rfc.html`。

HTTP/1.1 采用持续连接，且非流水线方式工作：

- 浏览器先请求 `rfc.html`，需要 $1$ 个 RTT；
- 收到 HTML 后，浏览器解析出其中引用的 $5$ 幅 JPEG 小图像；
- 非流水线方式下，浏览器必须收到前一个响应后才能发送下一个请求，因此每幅图像需要 $1$ 个 RTT。

所以总 RTT 数为：

$$
1 + 5 = 6\ \text{RTT}
$$

注意：题目问“从发出图 2 中的 Web 请求开始”，因此不另计 TCP 连接建立过程。

### 4. 路由器 R 转发时 IP 分组头需要修改的字段

该 IP 分组的源 IP 是私有地址 $10.2.128.100$，目的 IP 是公网地址 $64.170.98.32$。主机通过路由器 R 访问公网时，R 需要做 NAT，将私有源 IP 改写为公网 IP。因此 IP 分组头中至少需要修改：

1. 源 IP 地址：由私有地址改写为公网地址；
2. TTL：每经过一个路由器，TTL 减 $1$；
3. IP 首部校验和：由于 IP 首部字段发生变化，必须重新计算。

目的 IP 地址不变。若题目限定 R 只做普通路由而不做 NAT，则只需修改 TTL 和 IP 首部校验和；但本题强调源 IP 为私有地址，因此应包含 NAT 对源 IP 的修改。

**易错点**：

- 容易把图 2 中的目的 MAC 误认为 Web 服务器的 MAC。实际上，主机访问外网时，以太网帧的目的 MAC 是默认网关的 MAC，IP 分组的目的 IP 才是 Web 服务器 IP。
- 容易把 ARP 请求的目的 MAC 答成默认网关的 MAC。ARP 请求发出时还不知道网关 MAC，所以必须广播，目的 MAC 为全 F。
- HTTP RTT 数容易漏算 `rfc.html` 本身，只数 $5$ 幅图片，得到 $5$ RTT；本题应是 $1+5=6$ RTT。
- 容易忽略 NAT：源 IP 是私有地址，经过边界路由器 R 时必须改写源 IP 地址，不能只答 TTL 和校验和。
- 注意区分 IP 首部校验和与 TCP 校验和。路由器每转发一个 IP 分组都要重新计算 IP 首部校验和；而 NAT 改变源 IP 后，TCP 校验和也会因伪首部变化而需要更新，但本题问的是 IP 分组头。

**命题规律**：  
本题是典型的“协议栈综合题”，把以太网帧、IP 数据报、ARP、HTTP、NAT 串在一起考查，要求能从十六进制帧中准确剥离各层首部。常见变式包括：改问 TCP 连接建立过程的 RTT 数、IP 分片字段变化、ARP 攻击/代理 ARP、NAT 转换表等。复习时应熟练掌握以太网帧头格式、IPv4 基本首部格式、TCP 首部格式，并会从给定十六进制数据中定位关键字段；HTTP 部分要区分持续/非持续、流水线/非流水线，最好会画时间图辅助计数。

> 03.【解答】
> 1）以太网帧的数据部分是 IP 数据报，只要数出相应字段所在的字节即可。由图 3 可知以太网帧首部有 $6 + 6 + 2 = 14\text{B}$，由图 4 可知 IP 数据报首部的目的 IP 地址字段前有 $4 \times 4 = 16\text{B}$，从图 2 的帧第 1 字节开始数 $14 + 16 = 30\text{B}$，得到目的 IP 地址为 40.aa.62.20（十六进制数），转换成十进制数为 64.170.98.32。由图 2 可知以太网帧的前 6 字节 00-21-27-21-51-ee 是目的 MAC 地址，即为主机的默认网关 10.2.128.1 端口的 MAC 地址。
> 2）ARP 用于解决 IP 地址到 MAC 地址的映射问题。主机的 ARP 进程在本以太网以广播形式发送 ARP 请求分组，在以太网上广播时，以太网帧的目的地址为全 1，即 FF-FF-FF-FF-FF-FF。
> 3）HTTP/1.1 协议以持续的非流水线方式工作时，服务器发送响应后仍在一段时间内保持这段连接，客户在收到前一个请求的响应后才能发出下一个请求。注意题目说的是从发出 Web 请求开始，所以此时 TCP 连接已经建立。第 1 个 RTT 用于请求 Web 页面，客户收到第一个请求的响应后（还有 5 个请求未发送），每访问一次对象就用去 1RTT。因此共需 $1 + 5 = 6\text{RTT}$ 后浏览器收到全部内容。
> 4）私有地址和 Internet 上的主机通信时，须由 NAT 路由器进行网络地址转换，把 IP 数据报的源 IP 地址（本题为私有地址 10.2.128.100）转换为 NAT 路由器的一个全球 IP 地址（本题为 101.12.123.15）。因此，源 IP 地址字段 0a 02 80 64 变为 65 0c 7b 0f。IP 数据报每经过一个路由器，TTL 值就减 1，并重新计算首部检验和。若 IP 分组的长度超过输出链路的 MTU，则总长度字段、标志字段、片偏移字段也会发生变化。
