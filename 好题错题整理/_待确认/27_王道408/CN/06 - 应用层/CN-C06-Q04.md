# 综合题 第 4 题

![[_Attachments/题目识别/27_王道408-题目/CN-C06-Q04_题目.png|题目]]

04. 【2021 统考真题】某网络拓扑如下图所示，以太网交换机 S 通过路由器 R 与 Internet 互连。路由器部分接口、本地域名服务器、H1、H2 的 IP 地址和 MAC 地址如图中所示。在 $t_0$ 时刻 H1 的 ARP 表和 S 的交换表均为空，H1 在此刻利用浏览器通过域名 www.abc.com 请求访问 Web 服务器，在 $t_1$ 时刻 ($t_1 > t_0$) S 第一次收到了封装 HTTP 请求报文的以太网帧，假设从 $t_0$ 到 $t_1$ 期间网络未发生任何与此次 Web 访问无关的网络通信。

【图：网络拓扑结构如下：路由器 R 接口 (IP: 192.168.1.1/25, MAC: 00-11-22-33-44-aa) 连接交换机 S 端口 2；本地域名服务器 (IP: 192.168.1.126/25, MAC: 00-11-22-33-44-bb) 连接 S 端口 1；主机 H2 (IP: 192.168.1.3/25, MAC: 00-11-22-33-44-dd) 连接 S 端口 3；主机 H1 (IP: 192.168.1.2/25, MAC: 00-11-22-33-44-cc) 连接 S 端口 4。Web 服务器 (www.abc.com) 通过 Internet 连接路由器 R。】

请回答下列问题。
1）从 $t_0$ 到 $t_1$ 期间，H1 除了 HTTP，还运行了哪个应用层协议？从应用层到数据链路层，该应用层协议报文是通过哪些协议进行逐层封装的？
2）若 S 的交换表结构为 $<\text{MAC 地址，端口}>$，则 $t_1$ 时刻 S 交换表的内容是什么？
3）从 $t_0$ 到 $t_1$ 期间，H2 至少接收到几个与此次 Web 访问相关的帧？接收的是什么帧？帧的目的 MAC 地址是什么？

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C06-Q04_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：  
H1 还需运行 DNS 客户进程；DNS 报文按“DNS → UDP → IP → 以太网帧”逐层封装；$t_1$ 时刻 S 的交换表中有 H1、DNS 服务器、路由器 R 三个表项；H2 至少收到 2 个 ARP 请求广播帧，目的 MAC 地址均为 $\texttt{FF-FF-FF-FF-FF-FF}$。

**解题切入点**：  
看到“通过域名访问 Web 服务器”，应立刻想到“先 DNS 解析域名”；看到“H1 的 ARP 表为空、S 的交换表为空”，应想到“发送 IP 分组前必须先 ARP 解析下一跳 MAC 地址”。交换机只根据收到的帧的源 MAC 地址和到达端口进行自学习，所以问 S 交换表内容时，只需梳理 $t_0\to t_1$ 期间所有进入 S 的帧。H2 能否收到某个帧，关键是看它是不是广播帧，或交换机是否明确把该帧转发到 H2 所在端口。

**推演**：  

1. H1 请求 `www.abc.com`，首先要向本地 DNS 服务器 192.168.1.126 查询域名对应的 IP。  
   DNS 报文封装过程为：
   $$
   \text{DNS 报文}\to \text{UDP 数据报}\to \text{IP 数据报}\to \text{以太网帧}
   $$
   DNS 查询一般使用 UDP，端口号为 53。ARP 是发送前获取目的 MAC 地址的辅助协议，不属于 DNS 报文的逐层封装过程。

2. 因为 H1 的 ARP 表为空，H1 必须先发送 ARP 请求解析 DNS 服务器 192.168.1.126 的 MAC 地址。这个 ARP 请求是以太网广播帧，S 会将其从除 H1 所在端口外的其他端口转发出去，因此 H2 会收到该帧。

3. DNS 服务器收到 ARP 请求后，向 H1 单播回复 ARP 应答。S 从端口 1 收到该帧，学习到 DNS 服务器 MAC 对应端口 1，再把 ARP 应答转发给 H1。

4. H1 发送 DNS 查询帧，目的 MAC 为 DNS 服务器的 MAC。S 查表后只向端口 1 转发，H2 收不到该帧。DNS 服务器随后向 H1 返回 DNS 响应，H2 也收不到。

5. H1 得到 `www.abc.com` 的 IP 后，发现该 IP 不在本地子网 192.168.1.0/25 内，因此要将 HTTP 请求发送给默认网关 R，即 192.168.1.1。H1 的 ARP 表中还没有 R 的 MAC 地址，于是再次发送 ARP 请求解析 R 的 MAC 地址。这个 ARP 请求同样是广播帧，H2 会收到。

6. R 向 H1 单播回复 ARP 应答。S 从端口 2 收到该帧，学习到路由器 R 的 MAC 对应端口 2。之后 H1 与 Web 服务器还需先完成 TCP 连接建立，再发送 HTTP 请求；这些帧都是 H1 与 R 之间的单播帧，H2 收不到。

因此：

1）H1 除 HTTP 外还运行了 **DNS**。  
其报文封装为：
$$
\text{DNS 报文}\to \text{UDP 数据报}\to \text{IP 数据报}\to \text{以太网帧}
$$

2）$t_1$ 时刻 S 的交换表内容为：
$$
\langle 00\text{-}11\text{-}22\text{-}33\text{-}44\text{-}cc,4\rangle,\quad
\langle 00\text{-}11\text{-}22\text{-}33\text{-}44\text{-}bb,1\rangle,\quad
\langle 00\text{-}11\text{-}22\text{-}33\text{-}44\text{-}aa,2\rangle
$$
即 H1 对应端口 4，DNS 服务器对应端口 1，路由器 R 对应端口 2。H2 没有发送过帧，所以交换表中没有 H2 的表项。

3）H2 至少收到 2 个与此次 Web 访问相关的帧，分别是：  
- H1 为解析 DNS 服务器 MAC 地址发送的 ARP 请求；  
- H1 为解析默认网关 R 的 MAC 地址发送的 ARP 请求。  

这两个帧的目的 MAC 地址均为广播地址：
$$
\texttt{FF-FF-FF-FF-FF-FF}
$$

注：题干未说明本地 DNS 服务器是否有缓存；若 DNS 服务器需要递归查询 Internet 上的域名服务器，中间还可能出现 DNS 服务器与 R 之间的额外帧，因此题目问“至少”。但上述两个 H1 发出的 ARP 广播请求是必然出现的。

**易错点**：  
- 把 DNS 的传输层封装误写成 TCP。DNS 查询通常使用 UDP，不是 TCP。  
- 把 ARP 误认为 DNS 报文的封装层次。ARP 是地址解析协议，DNS 报文的封装链是 DNS → UDP → IP → 以太网帧。  
- 误以为 H2 会收到 DNS 查询帧或 HTTP 请求帧。实际上这些帧是单播帧，且在此之前交换机已经学习到 DNS 服务器和路由器的 MAC 地址，因此不会向 H2 所在端口转发。  
- 误认为交换表会记录广播地址。交换机只学习源 MAC 地址，不会把广播地址写入交换表。  
- 忘记 HTTP 请求发送前还需要 TCP 三次握手。但 TCP 握手帧不是 HTTP 帧，也不影响 H2 收到的帧数。

**命题规律**：  
本题综合考查 DNS、ARP、交换机自学习、以太网帧封装。常见变式包括：改变 H1 或交换机的初始表状态，问某主机能否收到某类帧；问交换表新增了哪些表项；结合路由器分隔广播域、VLAN 等知识点。复习时应把“DNS 解析 → ARP 解析 → 封装发送 → 交换机转发”的完整流程画成时序图，并牢记：交换机不隔离广播域，ARP 请求是广播帧，ARP 应答是单播帧。

> 04.【解答】
> 1） 从 $t_0$ 到 $t_1$ 期间，除了 HTTP，H1 运行了 DNS 应用层协议，以将域名转换为 IP 地址。
> DNS 运行在 UDP 之上，UDP 将应用层交付的 DNS 报文添加首部后，向下交付给 IP 层，IP 层使用 IP 数据报进行封装，封装好后，向下交付给数据链路层，数据链路层使用 CSMA/CD 帧进行封装。因此，逐层封装关系如下：DNS 报文→UDP 数据报→IP 数据报→CSMA/CD 帧。
> 传统以太网在数据链路层采用 CSMA/CD 协议，因此使用 CSMA/CD 帧进行封装。
> 提示：在数据链路层对该报文的封装解释为以太网 V2 帧（或以太网帧）会更合适，标准答案给出的 CSMA/CD 帧相对而言并不算特别合适。CSMA/CD 协议更多地用在以传统集线器互连的以太网中。交换机可工作于全双工方式，通常不采用 CSMA/CD 协议。
>
> 2） $t_0$ 时刻，H1 的 ARP 表和 S 的交换表为空。H1 利用浏览器通过域名请求访问 Web 服务器。
> 因为要先解析域名，查询该域名对应的 IP 地址，所以要先向本地域名服务器发送 DNS 查询报文。ARP 表为空，因此需要先发送 ARP 请求分组，查询本地域名服务器对应的 MAC 地址，这个帧的目的 MAC 地址是 FF-FF-FF-FF-FF-FF。S 接收到这个帧，在交换表中记录 MAC 地址为 00-11-22-33-44-cc，位于端口 4，然后广播该帧。当本地域名服务器收到 ARP 请求后，向 H1 发送 ARP 响应分组。S 接收到这个帧，在交换表中记录 MAC 地址为 00-11-22-33-44-bb，位于端口 1，然后将该帧从端口 4 发送出去。
> 得到了域名对应的 IP 地址，发现不在本局域网中，需要通过路由表转发。
> H1 的 ARP 表中没有路由器对应的 MAC 地址，因此需要先发送 ARP 请求分组，查询路由器对应的 MAC 地址，这个帧的目的 MAC 地址是 FF-FF-FF-FF-FF-FF。S 接收到这个帧，广播该帧。当路由器收到 ARP 请求后，向 H1 发送 ARP 响应分组。S 接收到这个帧，在交换表中记录 MAC 地址为 00-11-22-33-44-aa，位于端口 2，然后将该帧从端口 4 发送出去。现在，H1 就能发送 HTTP 请求。在整个过程中，并没有涉及 H2，H2 没有主动发送数据，因此 S 不会记录 H2 的 MAC 地址和端口，$t_1$ 时刻 S 的交换表如下所示。
>
> | MAC 地址       | 端 口 |
> |----------------|-------|
> | 00-11-22-33-44-cc | 4     |
> | 00-11-22-33-44-bb | 1     |
> | 00-11-22-33-44-aa | 2     |
>
> 3） 由步骤 2）的分析可知，H2 至少会接收到 2 个和此次 Web 访问相关的帧。接收到的均是封装 ARP 查询报文的以太网帧；这些帧的目的 MAC 地址均是 FF-FF-FF-FF-FF-FF。
