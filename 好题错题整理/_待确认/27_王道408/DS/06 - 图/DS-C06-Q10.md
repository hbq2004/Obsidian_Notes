## DeepSeek V4 Flash Max 解析

**答案**：该网络可抽象为“带权无向图（网）”；可用图的邻接表/带 `linkHead` 与 `netHead` 的 LSI 链表保存；按 Dijkstra 算法，R1 到各子网的最短费用依次为：$192.1.1.0/24$ 为 $1$，$192.1.5.0/24$ 为 $3$，$192.1.6.0/24$ 为 $4$，$192.1.7.0/24$ 为 $8$。

**解题切入点**：看到“路由器 + 链路费用 + 网络拓扑”，应立刻把网络抽象成图：路由器、子网是顶点，链路是边，`Metric` 是边权。OSPF 是链路状态协议，本质就是用 Dijkstra 算法求最短路径树。第二问要求“链式存储”，自然想到邻接表或带多条链的 LSI 链表；第三问直接手算 Dijkstra，注意每个子网本身还有一条费用为 $1$ 的直连边。

**推演**：

### 1. 逻辑结构

设路由器顶点为

$$
R_1=10.1.1.1,\quad R_2=10.1.1.2,\quad R_3=10.1.1.5,\quad R_4=10.1.1.6
$$

子网顶点为

$$
N_1=192.1.1.0/24,\quad N_5=192.1.5.0/24,\quad N_6=192.1.6.0/24,\quad N_7=192.1.7.0/24
$$

由题表和拓扑图，路由器间边为：

$$
(R_1,R_2;3),\quad (R_1,R_3;2),\quad (R_2,R_4;4),\quad (R_3,R_4;6)
$$

每个路由器还分别连接一个子网，费用为 $1$。

因为存在环，例如 $R_1\to R_2\to R_4\to R_3\to R_1$，所以不是线性结构也不是树，而是**带权无向图**，即“网”。

---

### 2. 链式存储结构设计

可以采用“LSI 记录结点 + 链路结点 + 子网结点”的链式结构。

```c
typedef struct LinkArc {   // 链路结点：连接另一台路由器
    int neighborID;        // 所连路由器的 Router ID
    int localIP;           // 本端接口 IP
    int metric;            // 链路费用
    struct LinkArc *next;  // 指向下一条链路
} LinkArc;

typedef struct NetArc {    // 子网结点：直连网络
    int prefix;            // 网络前缀，如 192.1.1.0
    int prefixLen;         // 前缀长度，如 24
    int metric;            // 到达该直连网络的费用
    struct NetArc *next;   // 指向下一个直连网络
} NetArc;

typedef struct LSI {       // 一台路由器的 LSI 记录
    int routerID;          // 本路由器 Router ID
    LinkArc *linkHead;     // 指向 Link1、Link2 等链路结点链
    NetArc *netHead;       // 指向直连子网结点链
    struct LSI *next;      // 指向下一台路由器的 LSI
} LSI;
```

对应链式存储示意图可简化为：

```text
LSIList: [R1:10.1.1.1] -> [R2:10.1.1.2] -> [R3:10.1.1.5] -> [R4:10.1.1.6] -> ∧

R1.linkHead: [10.1.1.2 | 3] -> [10.1.1.5 | 2] -> ∧
R1.netHead : [192.1.1.0/24 | 1] -> ∧

R2.linkHead: [10.1.1.1 | 3] -> [10.1.1.6 | 4] -> ∧
R2.netHead : [192.1.6.0/24 | 1] -> ∧

R3.linkHead: [10.1.1.6 | 6] -> [10.1.1.1 | 2] -> ∧
R3.netHead : [192.1.5.0/24 | 1] -> ∧

R4.linkHead: [10.1.1.5 | 6] -> [10.1.1.2 | 4] -> ∧
R4.netHead : [192.1.7.0/24 | 1] -> ∧
```

其中 `[x | y]` 表示链式结点，`x` 为对端 ID，`y` 为费用，`∧` 表示空指针。实际保存时还应保留 `localIP`、`prefixLen` 等字段。

---

### 3. Dijkstra 算法求解

Dijkstra 算法关键思路：

```text
dist[源点] = 0，其余 dist = ∞，pre 记录前驱。
每次从未确定顶点中选出 dist 最小的顶点 u；
标记 u 确定；
遍历 u 的所有出边 (u, v, w)：
    若 dist[v] > dist[u] + w，则更新 dist[v] 和 pre[v]。
```

本题中每条路由链路和直连子网边权都为正，因此 Dijkstra 有效。

从 $R_1$ 出发，Dijkstra 距离变化过程如下：

| 已确定顶点 | $d(R_2)$ | $d(R_3)$ | $d(R_4)$ | $d(N_1)$ | $d(N_5)$ | $d(N_6)$ | $d(N_7)$ |
|---|---:|---:|---:|---:|---:|---:|---:|
| 初始（从 $R_1$ 松弛） | 3 | 2 | $\infty$ | 1 | $\infty$ | $\infty$ | $\infty$ |
| $N_1$ | 3 | 2 | $\infty$ | 1 | $\infty$ | $\infty$ | $\infty$ |
| $R_3$ | 3 | 2 | 8 | 1 | 3 | $\infty$ | $\infty$ |
| $R_2$ | 3 | 2 | 7 | 1 | 3 | 4 | $\infty$ |
| $N_5$ | 3 | 2 | 7 | 1 | 3 | 4 | $\infty$ |
| $N_6$ | 3 | 2 | 7 | 1 | 3 | 4 | $\infty$ |
| $R_4$ | 3 | 2 | 7 | 1 | 3 | 4 | 8 |
| $N_7$ | 3 | 2 | 7 | 1 | 3 | 4 | 8 |

同距离顶点可任选一个先确定，不影响最终结果。

因此按 Dijkstra 算法确定目标子网的顺序，R1 到各子网的最短路径及费用为：

| 顺序 | 目标子网 | 最短路径 | 费用 |
|---|---|---|---|
| 1 | $192.1.1.0/24$ | $R_1 \to 192.1.1.0/24$ | $1$ |
| 2 | $192.1.5.0/24$ | $R_1 \to R_3 \to 192.1.5.0/24$ | $2+1=3$ |
| 3 | $192.1.6.0/24$ | $R_1 \to R_2 \to 192.1.6.0/24$ | $3+1=4$ |
| 4 | $192.1.7.0/24$ | $R_1 \to R_2 \to R_4 \to 192.1.7.0/24$ | $3+4+1=8$ |

注意：到 $192.1.7.0/24$ 若走 $R_1\to R_3\to R_4$，费用为 $2+6+1=9$，大于走 $R_1\to R_2\to R_4$ 的 $8$，所以后者才是最短路径。

**易错点**：

- 把网络误判为树或线性结构。存在环，且任意结点可有多个邻接点，因此是图。
- 链式存储只存路由器间链路，忘记保存直连子网信息和费用。子网也必须作为边/顶点保存。
- Dijkstra 计算中漏加子网直连费用 $1$。例如到 $192.1.7.0/24$，不能只算到 $R_4$ 的费用 $7$，还要加 $1$。
- 到 $R_4$ 的最短路径容易误选 $R_1\to R_3\to R_4$。虽然 $R_1\to R_3$ 较短，但 $R_3\to R_4$ 费用为 $6$，总体不如 $R_1\to R_2\to R_4$。
- Dijkstra 不能处理负权边，本题边权均为正，可以直接使用。

**命题规律**：本题将《数据结构》中的图和 Dijkstra 算法与《计算机网络》中的 OSPF 协议结合，属于跨章节综合题。常见变式包括：要求画出邻接矩阵或邻接表、求 R1 的完整路由表、某条链路断开后重新计算、比较 OSPF 与 RIP 所使用的算法等。复习时应重点掌握无向带权图的建模、邻接表存储定义、Dijkstra 手算表和路径回溯，并注意把“Metric”翻译为图论中的“权值”。
