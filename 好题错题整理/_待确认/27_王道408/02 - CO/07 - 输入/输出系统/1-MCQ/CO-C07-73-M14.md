# 选择题 第 14 题

![[_Attachments/题目识别/27_王道408-题目/CO-C07-73-M14_题目.png|题目]]

14. 在 $I/O$ 接口中设置中断触发器保存外设发出的中断请求,是因为 ( )  
(A) 中断不需要立即处理  
(B) 中断设备的处理速度比 $CPU$ 快  
(C) $CPU$无法对发生的中断请求立即进行处理  
(D) 可能有多个中断同时发生

## 答案

![[_Attachments/题目识别/27_王道408-答案/CO-C07-73-M14_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：C。在 I/O 接口中设置中断触发器，是为了把外设发出的异步中断请求锁存起来，因为 CPU 无法对发生的中断请求立即进行处理。

**解题切入点**：  
看到“中断触发器”“保存请求”，就要立刻想到“异步信号需要暂存/锁存”。外设发出中断请求时，CPU 可能正在执行当前指令，不可能马上响应；就像程序里用全局 flag 记录外部事件，主循环忙完手头工作后再轮询 flag。因此本题考点是“CPU 响应中断的时机”与“接口中的中断请求锁存电路”。

**推演**：  

外设的中断请求是异步事件，CPU 只能按照自己的指令周期工作，不能在任何微操作中都去响应中断。CPU 响应中断通常需要满足两个基本条件：

1. 当前指令执行结束；
2. CPU 处于开中断状态，且没有更高优先级的中断或 DMA 请求等。

也就是说，外设发出请求的瞬间，CPU 往往不能立即响应。如果接口中不设置中断请求触发器，外设发出的请求信号可能持续时间很短，CPU 事后查询时请求已经消失，就会造成中断丢失。

设置中断触发器后，外设发出中断请求时，把该触发器置为“1”，表示“有中断请求等待处理”。CPU 在合适时刻检测到这个触发器为“1”，便进入中断响应周期；响应后，再将该触发器清除。

对比其他选项：

- A 错：中断需要及时处理，只是 CPU 不能“立即”响应，不等于“不需要立即处理”。
- B 错：不是外设处理速度比 CPU 快，而是 CPU 响应中断有时间上的延迟。
- C 对：由于 CPU 无法立即处理中断请求，所以需要触发器保存请求。
- D 错：多个中断同时发生需要的是中断排队和优先级判优机制；单设备设置中断请求触发器，主要是为了把请求锁存住，防止丢失。

**易错点**：

1. 误选 D。  
   看到“多个中断同时发生”容易误选，但多中断同时出现需要解决的是“先响应谁、后响应谁”的判优排队问题；题目问的是“保存请求”的原因，核心是 CPU 不能立即响应，所以需要用触发器锁存。

2. 误选 A。  
   “中断不需要立即处理”与“CPU 无法立即处理”不同。中断本身要求及时处理，只是 CPU 响应时存在延迟，不能把“延迟响应”理解为“可以不及时处理”。

3. 混淆中断请求触发器和中断屏蔽触发器。  
   中断请求触发器用来保存外设的中断请求；中断屏蔽触发器用来屏蔽某些中断请求，使其不能参与中断判优。两者作用不同。

4. 忽略 CPU 响应中断的时机。  
   CPU 一般只在当前指令执行结束后才能响应中断，因此外设请求信号必须被保持到 CPU 能够识别时，否则会丢失。

**命题规律**：  
本题属于“I/O 接口与中断方式”的基础考点，考查中断请求触发器存在的硬件原因。常见变式包括：CPU 响应中断的时机、中断请求触发器和中断屏蔽触发器的区别、多中断的响应优先级与处理优先级。复习时应抓住“外设请求异步、CPU 响应延迟、接口需要锁存请求”这条主线，并理解中断请求的建立、保持与清除过程。
