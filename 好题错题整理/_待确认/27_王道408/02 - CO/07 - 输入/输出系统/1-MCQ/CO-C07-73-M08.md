# 选择题 第 8 题

![[_Attachments/题目识别/27_王道408-题目/CO-C07-73-M08_题目.png|题目]]

8. 在下列情况下,可能不发生中断请求的是 ( )

(A) $DMA$ 操作结束
(B) 一条指令执行完毕
(C) 机器出现故障
(D) 执行“软中断”指令

---

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CO-C07-73-M08_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：B。一条指令执行完毕只是 CPU 检测中断请求的时机，它本身不是中断源，不会主动发出中断请求。

**解题切入点**：先区分“中断请求”和“中断响应”。题目问“可能不发生中断请求”，就要看哪个选项不是由硬件/指令主动产生的中断源信号，而只是 CPU 正常工作中的一个时间点。类似竞赛中“事件触发”和“轮询时机”的区别：轮询时刻本身不产生事件。

**推演**：

中断请求是指中断源（如 I/O 设备、硬件故障、程序中的软中断指令等）向 CPU 发出的要求中断的信号。可逐项分析：

- (A) DMA 操作结束：DMA 控制器在完成一批数据传送后，通常需要向 CPU 报告，以便 CPU 进行后续处理（如检查传送结果、释放总线等），因此会发出中断请求。  
- (B) 一条指令执行完毕：这是 CPU 执行指令的正常步骤之一。CPU 只在指令执行完毕后的特定时刻（如指令结束、取下一条指令前）检查是否有中断请求，但该时刻本身并不会产生中断请求。若没有中断源提出请求，则完全不会发生中断。  
- (C) 机器出现故障：例如电源故障、校验错等，属于硬件故障类中断源，会立即发出中断请求，要求 CPU 处理。  
- (D) 执行“软中断”指令：如 $\text{INT } n$ 指令，执行时会主动产生一个中断请求，属于程序性中断。

因此，唯一“可能不发生中断请求”的情况是一条指令执行完毕。

若从中断处理流程来看，CPU 在每条指令执行结束后都会去检测中断请求信号：

$$
\text{指令执行完毕} \rightarrow \text{检测中断请求信号} \rightarrow \begin{cases}
\text{有请求：响应中断}\\
\text{无请求：继续执行下一条指令}
\end{cases}
$$

所以“一条指令执行完毕”只是检测窗口，不是中断源。

**易错点**：

1. 误选 A：认为 DMA 结束可以不中断。实际上 DMA 结束后通常需要中断 CPU 来进行后处理，尤其是非块传输方式下的收尾工作。DMA 结束本身是一个典型的中断源。  
2. 误选 D：软中断指令是程序主动产生的，必然产生中断请求。  
3. 混淆“中断请求”与“中断响应”：指令执行完毕是响应中断的时机，而不是请求中断的原因。  
4. 忽略“可能”二字：题目问的是“可能不发生”，不是“一定不发生”。指令执行完毕后若无中断请求，自然不发生中断。

**命题规律**：本题考查中断的基本概念，属于中断系统的基础题。常见的变式有：  
- 问“CPU 响应中断的时机” → 通常是一条指令执行完毕（或指令执行结束、异常时）。  
- 问“下列哪个不是中断源” → 类似地排除指令执行完毕。  
- 结合 DMA：DMA 结束中断是高频考点。  
复习时应理清中断源、中断请求、中断响应、中断服务程序的区别，并牢记各类中断源（I/O、时钟、故障、软中断、DMA 结束）和 CPU 响应中断的时机。
