# 选择题 第 28 题

![[_Attachments/题目识别/27_王道408-题目/CO-C07-73-M28_题目.png|题目]]

28. 在$DMA$方式传送数据的过程中,由于没有破坏(   )的内容,所以$CPU$可以正常工作(访存除外).
(A) 程序计数器
(B) 程序计数器和寄存器
(C) 指令寄存器
(D) 堆栈寄存器

---

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CO-C07-73-M28_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：B。DMA 传送由 DMA 控制器直接控制主存与 I/O 设备之间的数据交换，不打断 CPU 正在执行的程序，也没有破坏 CPU 的程序计数器和寄存器的内容，因此 CPU 除访存可能被“挪用”外，可以继续正常工作。

**解题切入点**：拿到题目先判断这是 I/O 方式中的 DMA 方式，核心是与“中断方式”对比。中断方式会让 CPU 跳去执行中断服务程序，必须保存“断点”和“现场”；而 DMA 方式不靠 CPU 执行程序来传数据，所以不需要破坏 PC 和寄存器。可以类比竞赛中的“异步任务”：如果异步任务不会修改当前栈帧和局部变量，那么主流程就可以不受影响地继续运行。

**推演**：

- 在程序查询方式和中断方式中，CPU 需要参与 I/O 操作：
  - 程序查询方式：CPU 不断检测设备状态，占据 CPU；
  - 中断方式：CPU 响应中断后，要转去执行中断服务程序，硬件会自动保存程序计数器 $PC$（断点），必要时还要由软件保存通用寄存器等内容（现场），处理完后再恢复现场、返回断点。
- 而在 DMA 方式中：
  - DMA 控制器直接接管主存与设备之间的数据传送，数据不经过 CPU 内部寄存器；
  - CPU 只是在 DMA 传送期间可能因“周期挪用”或“停止访存”而暂时无法访问主存；
  - 但 CPU 内部的 $PC$ 仍然指向下一条待执行指令，通用寄存器的值也保持不变；
  - 因此 DMA 传送结束后，CPU 可以继续原来的程序执行，不需要像中断那样“恢复现场”。

所以题目中“没有破坏”的内容应指程序计数器和寄存器，即 CPU 的“执行现场”没有被破坏。选项 A 只提到程序计数器，不够完整；C 的指令寄存器、D 的堆栈寄存器都不是关键考查对象。故答案为 B。

**易错点**：

1. 只选 A：只想到“断点”是 $PC$，忽略了通用寄存器的现场也未被破坏。题目强调“CPU 可以正常工作”，需要 $PC$ 和寄存器都保持原值，B 更完整。
2. 误选 C：$IR$（指令寄存器）保存的是当前正在执行的指令，DMA 不会破坏它，但这不是 CPU 能继续正常工作的主要原因。
3. 与中断方式混淆：中断方式需要保护断点和现场，而 DMA 不需要，因为 DMA 传送不是靠执行软件程序完成的。
4. 忽略“访存除外”：DMA 可能挪用总线导致 CPU 访存暂停，这不属于破坏 CPU 内部状态，不能因此认为 DMA 会影响程序正常运行。

**命题规律**：本题属于“I/O 方式”中的高频考点，考查 DMA 与中断的本质区别。常见变式有：
- DMA 传送过程中是否需要保护断点和现场？（不需要）
- 中断方式中自动保存什么？（断点，即 $PC$，有的机器还保存程序状态字）
- DMA 传送期间 CPU 为什么不能访存？（因为 DMA 控制器占用存储总线）

复习建议：将三种 I/O 控制方式（程序查询、中断、DMA）对比记忆，重点抓住“谁控制传送”“CPU 是否被打断”“是否需要保护现场”三个维度。做题时看到“CPU 正常工作（访存除外）”这类描述，应立即定位到 DMA。
