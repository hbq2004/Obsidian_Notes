# 选择题 第 5 题

![[_Attachments/题目识别/27_王道408-题目/CO-C03-35-M05_题目.png|题目]]

5.在不同的情况下,需要采用适合的 $Cache$ 写策略。对于下面两种情况:①主要运行访问密集型应用,其中包含写操作;②安全性要求很高,不允许有任何数据不一致的情况发生。适合它们的写策略分别是 ( )

A. 回写法,全写法
B. 全写法,回写法
C. 回写法,回写法
D. 全写法,全写法

## 答案

![[_Attachments/题目识别/27_王道408-答案/CO-C03-35-M05_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：A。回写法适合访问密集型（含写操作）场景，因为能减少写主存次数；全写法适合高安全性场景，因为它能随时保持 Cache 与主存一致。

**解题切入点**：  
拿到题先想：Cache 写策略核心区别是“何时把数据写到主存”。题目给了两个场景：①强调性能（访问密集、写操作多）；②强调安全（不允许不一致）。这等价于比较“回写法：延迟写、快但可能不一致”和“全写法：立即写、慢但一致”。像做算法题一样，先抓关键词：出现“写操作多”优先考虑减少主存访问；出现“一致性/安全”优先考虑同步写主存。

**推演**：  
首先明确两种 Cache 写策略：

- 全写法（write-through）：CPU 写 Cache 命中时，同时更新 Cache 和主存。因此主存始终与 Cache 一致，但每次写操作都要访问主存，写操作耗时长。
- 回写法（write-back）：CPU 写 Cache 命中时只更新 Cache，并将该块标记为脏（dirty）；当该块被替换时，才把整块写回主存。因此主存访问次数少，但脏块未写回前，主存数据与 Cache 不一致。

对于情况①：主要运行访问密集型应用，且包含写操作。这类应用访存频率高，写操作也多。若用全写法，每次写 Cache 都要同时写主存，会产生大量主存写流量，性能下降明显。回写法先把写操作记录在 Cache 中，延迟到块被替换时再写回主存。例如：某个 Cache 块在驻留期间被写 $k$ 次，全写法需要向主存写 $k$ 次，而回写法最多只需在该块被替换时写 $1$ 次，因此能显著减少写主存次数，提高执行效率。故情况①适合回写法。

对于情况②：安全性要求很高，不允许有任何数据不一致的情况发生。回写法在脏块写回之前，主存中仍是旧数据，而 Cache 中是新数据，两者不一致，存在一个“不一致窗口”。一旦系统出错或其它部件需要读取主存，就可能得到过期数据。全写法在每次写 Cache 的同时也更新主存，因此 Cache 与主存始终一致，不存在不一致窗口，满足高安全性要求。故情况②适合全写法。

因此，两种情况分别为“回写法、全写法”，选择 A。

**易错点**：  
- 容易把“访问密集型”误认为需要保证数据一致而选全写法。但题目并未提出一致性要求，强调的只是性能，故应选回写法。
- 容易把两种策略名称记反：全写法 = 写直达 / 写穿（write-through）；回写法 = 写回（write-back）。注意“回”表示“先放着，以后再写回”。
- 容易忽略回写法的“脏位”机制，导致不理解为什么不一致。脏数据未写回主存前，主存数据是过期的。
- 题目是两种情况分别选策略，不要误选 B（全写、回写），那是完全反向的选择。

**命题规律**：  
考点常设在 Cache 写策略的特点与适用场景：全写法一致性高、速度慢；回写法速度快、但可能不一致。常见变式有：

1. 给具体场景选择写策略；
2. 结合 Cache 命中率、缺失代价计算平均访存时间；
3. 考察写分配 / 非写分配、脏位、写缓冲等概念；
4. 在多处理机 Cache 一致性中考查全写法与回写法对一致性协议的影响。

复习建议：先建立“写回 = 延迟写、省主存带宽；写直达 = 立即写、保一致”的底层逻辑，再记忆写缓冲、脏位等细节。做题时先找“性能”还是“一致性”关键词，再套用对应策略。
