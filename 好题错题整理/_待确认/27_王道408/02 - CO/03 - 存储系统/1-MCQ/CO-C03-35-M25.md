# 选择题 第 25 题

![[_Attachments/题目识别/27_王道408-题目/CO-C03-35-M25_题目.png|题目]]

25. 下列关于 Cache 替换算法的叙述中,错误的是 ( )
(A) 组相联映射和全相联映射都必须考虑如何进行替换
(B) 先进先出算法无须对每个 Cache 行记录替换信息
(C) 直接映射是多对一的映射,无须考虑替换问题
(D) LRU算法需要对每个 Cache 行记录替换信息

## 答案

![[_Attachments/题目识别/27_王道408-答案/CO-C03-35-M25_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：B。FIFO 算法同样需要知道“最早装入的是哪一行”，因此必须记录装入/替换顺序信息；“无须对每个 Cache 行记录替换信息”说法错误。A、C、D 均正确。

**解题切入点**：  
拿到本题先抓住核心问题：替换算法解决的是“当 Cache 满了，多个候选行中选哪一个被替换”。所以先看每种映射方式下候选 Cache 行数：

- 直接映射：候选行唯一，无需“选择”；
- 组相联：候选行是组内若干行，需要选择；
- 全相联：候选行是所有 Cache 行，需要选择。

然后再区分 FIFO 和 LRU 要记录的信息：FIFO 记录“装入顺序”，LRU 记录“最近访问顺序”。不要以为 FIFO 实现简单就完全不需要记录信息。

**推演**：  
设某个主存块可进入的候选 Cache 行集合为 $S$。

1. 直接映射  
   主存块号 $B$ 只能映射到固定的 Cache 行，例如行号为  
   $$B \bmod N$$  
   其中 $N$ 是 Cache 行数。这时 $|S|=1$，发生冲突时只有唯一一个 Cache 行可替换，因此不需要“替换算法”。  
   所以 C 项说“直接映射是多对一的映射，无须考虑替换问题”是正确的。这里的“替换问题”应理解为“替换策略选择问题”，不是说永远不会覆盖旧行。

2. 组相联映射与全相联映射  
   组相联映射中，一个主存块可以放入所属组内的任意一个 Cache 行，即 $|S|=k$，其中 $k$ 为组内行数。  
   全相联映射中，一个主存块可以放入任意一个 Cache 行，即 $|S|=N$。  
   当这些候选行都已被占用时，必须决定淘汰哪一行，所以 A 项正确。

3. FIFO 算法  
   FIFO 选择“最早装入”的 Cache 行替换。为了判断最早装入的是哪一行，至少需要记录装入顺序。例如可用装入序号 $T_{\text{load}}$，替换时选择  
   $$v = \arg\min_{l \in S} T_{\text{load}}(l)$$  
   也就是选择装入时间最早的行。  
   因此 FIFO 算法并非完全不需要记录替换信息，至少需要记录各行的装入顺序或维护组内 FIFO 队列。命中时虽然不更新这个顺序，但替换时仍需要利用它。  
   所以 B 项“无须对每个 Cache 行记录替换信息”是错误的。

4. LRU 算法  
   LRU 选择“最近最久未被访问”的行替换。它需要记录每个 Cache 行最近一次被访问的时刻或访问先后顺序，每次命中时还要更新这些信息。例如  
   $$v = \arg\min_{l \in S} T_{\text{access}}(l)$$  
   其中 $T_{\text{access}}(l)$ 表示行 $l$ 最近一次被访问的时刻。  
   所以 D 项“LRU算法需要对每个 Cache 行记录替换信息”正确。

综上，错误的是 B。

**易错点**：  
- 容易误选 C：直接映射也会发生“覆盖旧行”，但那不是“替换算法选择”，因为候选行唯一。不要把“会发生替换”和“需要替换算法”混为一谈。  
- 容易误认为 FIFO 与随机算法一样无需记录信息。随机算法可以完全随机选择，而 FIFO 必须知道“谁最先来”，因此需要记录顺序。  
- 容易混淆 FIFO 和 LRU：FIFO 记录“装入顺序”，命中不改变顺序；LRU 记录“访问顺序”，每次命中都要更新。  
- 组相联/全相联在有空闲行时先装入空闲行，只有候选行全满时才真正执行替换，但这不影响“必须考虑替换算法”的结论。

**命题规律**：  
本题是 Cache 替换算法的基础概念题。常见变式有：给定访问序列和 Cache 映射方式，用 LRU/FIFO 模拟替换过程求命中率；或者比较随机、FIFO、LRU 算法的硬件开销。复习时要把“映射方式决定候选行数”“替换算法决定候选行中选择规则”这两条主线结合起来，再通过画表模拟替换过程巩固。
