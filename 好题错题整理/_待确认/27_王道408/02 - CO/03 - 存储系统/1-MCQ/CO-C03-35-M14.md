# 选择题 第 14 题

![[_Attachments/题目识别/27_王道408-题目/CO-C03-35-M14_题目.png|题目]]

14. 某存储系统中，主存容量是 $Cache$ 容量的 4096 倍，$Cache$ 被分为 64 个块，采用直接映射方式、随机替换算法和全写法，则标记阵列（所有标记信息）的大小应为（）.
A. $6 \times 4097bit$
B. $64 \times 12bit$
C. $6 \times 4096bit$
D. $64 \times 13bit$

---

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CO-C03-35-M14_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：D。直接映射下 Cache 有 64 行，每行标记项需 12 位 tag 加 1 位有效位，且全写法无需脏位，所以标记阵列总大小为 $64\times(12+1)=64\times13\text{ bit}$。

**解题切入点**：拿到题先定位“标记阵列大小”这个考点：Cache 行数决定标记阵列行数，主存容量与 Cache 容量之比决定 tag 位数；“全写法”用来判断是否需要 dirty 位。可以类比算法题中的哈希表：Cache 行是桶，tag 是桶内需要比较的“高位键”，有效位表示桶是否初始化，而替换算法不改变存储结构。

**推演**：

设 Cache 块大小为 $2^b$ 字节。Cache 有 64 个块，即 $2^6$ 块，因此 Cache 容量为：

$$
2^{6+b}
$$

主存容量是 Cache 容量的 $4096=2^{12}$ 倍，所以主存容量为：

$$
2^{12}\times 2^{6+b}=2^{18+b}
$$

主存被划分成与 Cache 块大小相同的主存块，因此主存块数为：

$$
\frac{2^{18+b}}{2^b}=2^{18}
$$

直接映射下，每个 Cache 块可能对应：

$$
\frac{2^{18}}{2^6}=2^{12}
$$

个主存块，因此每个 Cache 块的 tag 位数为 12 位。

地址划分也可验证：

- 块内偏移：$b$ 位；
- Cache 块索引：$\log_2 64=6$ 位；
- 主存地址总位数：$18+b$ 位；
- tag 位数：$(18+b)-b-6=12$ 位。

标记阵列每个表项至少需要：

$$
12\text{ 位 tag} + 1\text{ 位有效位}=13\text{ bit}
$$

采用全写法时，Cache 和主存同时更新，没有脏数据，因此不需要 dirty 位。随机替换算法在直接映射下不改变候选行，因此也不影响标记阵列大小。

Cache 有 64 个块，所以标记阵列总大小为：

$$
64\times 13\text{ bit}
$$

因此选 D。

**易错点**：

1. 容易把 Cache 索引位数 6 误认为 tag 位数。本题主存与 Cache 容量比为 $2^{12}$，所以 tag 位数是 12，不是 6。  
2. 容易只算 tag 字段得到 $64\times12\text{ bit}$，漏掉每个 Cache 行必须有的有效位。题目强调“所有标记信息”，因此要加 1 位有效位。  
3. 容易误加脏位。全写法不需要 dirty 位；如果是写回法，每个 Cache 行才需要额外加 1 位脏位。  
4. 随机替换算法对标记阵列大小无影响，直接映射下替换位置固定，不需要考虑替换算法。

**命题规律**：本题属于 Cache 地址映射与标记阵列计算的常考题型。核心是 “主存地址 = tag + index + offset”，标记阵列大小 = Cache 行数 ×（tag 位数 + 有效位 + 可能的脏位）。常见变式有组相联映射、全相联映射、写回法、给出主存地址位数求标记阵列容量，或反向求 Cache 容量。复习时应熟练掌握直接映射、组相联映射下 index 和 tag 的计算方法，并区分“有效位”“脏位”在不同写策略下是否出现。
