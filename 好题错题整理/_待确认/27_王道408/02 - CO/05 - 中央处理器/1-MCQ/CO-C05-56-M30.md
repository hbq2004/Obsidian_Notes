# 选择题 第 30 题

![[_Attachments/题目识别/27_王道408-题目/CO-C05-56-M30_题目.png|题目]]

30.【2023统考真题】在采用“取指、译码/取数、执行、访存、写回”5段流水线的 RISC 处理器中，执行如下指令序列(第一列为指令序号)，其中 $s0$、$s1$、$s2$、$s3$ 和 $t2$ 表示寄存器编号。

```text
I1:    add s2, s1, s0      // R[s2] ← R[s1] + R[s0]
I2:    load s3, 0(s2)      // R[s3] ← M[R[s2] + 0]
I3:    beq t2, s3, L1      // if R[t2] = R[s3]  jump to L1
I4:    addi t2, t2, 20     // R[t2] ← R[t2] + 20
I5:    L1:  ...
```

若采用转发(旁路)技术处理数据冒险,采用硬件阻塞方式处理控制冒险,则在指令 $I1 \sim I4$ 的执行过程中,发生流水线阻塞的指令有( )

A. 仅 I3
B. 仅 I2、I4
C. 仅 I3、I4
D. 仅 I2、I3、I4

---

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CO-C05-56-M30_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：C（仅 I3、I4）。  
**解题切入点**：先识别指令间的数据依赖与控制依赖，再结合转发与硬件阻塞的冒险处理策略，判定哪些指令在流水线中会停顿。  
**推演**：  
- 流水线为 5 段：IF、ID、EX、MEM、WB。  
- 数据冒险：转发可解决大部分 RAW，但 load‑use 需插入一个 stall（加载指令在 MEM 阶段末才得到数据，后续指令的 EX 阶段若紧邻则无法在开始时获得）。  
- 控制冒险：采用硬件阻塞，即分支指令在 EX 阶段确定结果后，后续指令的 IF 才允许进行，相当于在分支指令后插入一个 stall。  

指令序列及依赖：  
I1: `add s2, s1, s0` → 写 s2。  
I2: `load s3, 0(s2)` → 读 s2（基址），写 s3。  
I3: `beq t2, s3, L1` → 读 t2 和 s3。  
I4: `addi t2, t2, 20` → 读 t2，写 t2。  

- I1 → I2：I2 的 EX 阶段需 s2，I1 的 EX 结果可通过转发从 MEM 或 EX 送至 I2 的 EX，无 stall。  
- I2 → I3：I3 的 EX 阶段需 s3，I2 的 MEM 阶段末才产生 s3，紧邻的 I3 的 EX 在 I2 的 MEM 之后一周期开始，因此需在 I2 的 MEM 阶段插入一个 stall，使 I3 的 ID 保持一个周期，I3 因此阻塞。  
- I3 是分支指令，其后 I4 的 IF 因硬件阻塞需等待 I3 的 EX 结束，故 I4 的 IF 被延迟一个周期，I4 因此阻塞。  
- I1 和 I2 无 stall。  

综上，发生阻塞的指令是 I3 和 I4。  

**易错点**：  
1. 误以为 I2 也因读 s2 而阻塞，实际转发可消除该冒险。  
2. 忽略控制冒险对 I4 的影响，认为仅 I3 有阻塞。  
3. 混淆 load‑use 的 stall 位置（应是 load 后紧接着的指令，而非 load 本身）。  

**命题规律**：  
- 常考 5 段流水线中数据冒险（转发、load‑use stall）与控制冒险（分支预测、硬件阻塞）的组合分析。  
- 变式：改变指令顺序、增加转发路径、使用分支预测而非硬件阻塞。  
- 复习建议：熟练掌握流水线时空图，手动模拟各周期状态，理解转发与阻塞的硬件实现。
