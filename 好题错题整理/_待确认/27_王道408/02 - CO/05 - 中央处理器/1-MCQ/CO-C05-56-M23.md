# 选择题 第 23 题

![[_Attachments/题目识别/27_王道408-题目/CO-C05-56-M23_题目.png|题目]]

23.【2014统考真题】采用指令 $Cache$ 与数据 $Cache$ 分离的主要目的是 ( )

A. 降低 $Cache$ 的缺失损失  
B. 提高 $Cache$ 的命中率  
C. 降低 $CPU$ 平均访存时间  
D. 减少指令流水线资源冲突

---

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CO-C05-56-M23_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：D。指令 Cache 与数据 Cache 分离后，取指和访数可并行进行，主要目的是减少指令流水线中的资源冲突。

**解题切入点**：拿到题目先明确 Cache 分离改变的是“硬件结构”，而不是“替换算法”或“容量大小”。可以把流水线想象成一条生产线：取指令和取数据都需要访问存储部件，若只有一个存储口，就像一条流水线上两道工序抢同一台机器，必然排队；分成两个 Cache 后，相当于给两道工序各配一台机器，并行度提高。这种结构优化主要针对“资源冲突”，而不是直接针对命中率或缺失损失。

**推演**：

1. 指令 Cache 与数据 Cache 分离，本质上是将原来统一的 Cache 分成两个独立的存储部件：一个专门存放指令，一个专门存放数据。这样，CPU 在取指阶段访问指令 Cache，在执行阶段访问数据 Cache，两者可以同时进行。

2. 在指令流水线中，各个阶段（取指 IF、译码 ID、执行 EX、访存 MEM、写回 WB）需要同时工作。若指令和数据共用一个 Cache，那么当某条指令需要取指、而另一条指令需要访存时，两者会争用同一个 Cache 端口，造成结构冲突（资源冲突），流水线必须停顿。

3. 分离后，取指访问指令 Cache，访存访问数据 Cache，二者互不干扰，从而消除了这类结构冲突。因此主要目的是减少指令流水线资源冲突，对应选项 D。

4. 其他选项分析：
   - A. 降低 Cache 的缺失损失：缺失损失主要取决于缺失后的主存访问时间、缺失处理机制等，分离 Cache 并不直接改变缺失代价。
   - B. 提高 Cache 的命中率：分离后每个 Cache 容量相对减小，可能反而使命中率略微下降；即使因局部性更好而有所改善，也不是分离的主要目的。
   - C. 降低 CPU 平均访存时间：平均访存时间与命中率、缺失率、缺失损失有关。分离 Cache 可能因减少冲突而间接改善性能，但其直接目的不是降低平均访存时间，而是消除流水线中的资源争用。
   - D. 减少指令流水线资源冲突：这正是分离设计的目标。

5. 补充说明：指令 Cache 与数据 Cache 分离还可以支持不同的优化策略（如指令 Cache 只读，数据 Cache 需要支持写回/写直达），但在 2014 年这道选择题中，最直接、最主要的目的是减少流水线资源冲突。

**易错点**：

- 误选 B：认为“指令和数据分开存放，互不干扰，所以命中率提高”。实际上，在总容量相同的情况下，分离后每个 Cache 容量减小，可能增加冲突缺失；即使局部性有所改善，命中率也不一定是提高的，且这不是设计的主要目的。
- 误选 C：分离 Cache 确实可能减少平均访存时间（因为减少了流水线停顿），但这是结果而非“主要目的”。题目问“主要目的”，应抓住结构冲突这一本质。
- 误选 A：分离 Cache 与缺失损失无关，缺失损失主要指 Cache 不命中后访问主存的时间开销，与是否分离没有直接关系。
- 区分“资源冲突”与“数据冲突”“控制冲突”：流水线中数据冲突靠转发/停顿解决，控制冲突靠分支预测等解决，而指令与数据访存争用 Cache 属于资源冲突，靠分离 Cache 解决。

**命题规律**：

- 考点定位：指令流水线中的结构冲突（资源冲突）及 Cache 组织结构。属于计算机组成原理中“存储系统”与“指令流水线”交叉知识点。
- 常见变式：
  1. 问“指令 Cache 与数据 Cache 分离的优点有哪些？”（多选，可能包含减少资源冲突、支持并行取指和访存等）。
  2. 问“哈佛结构与冯·诺依曼结构的区别”，其中指令/数据分离是哈佛结构的重要特征。
  3. 结合流水线时空图，判断某条指令在访存时是否与另一条指令取指冲突。
  4. 问“分离 Cache 的缺点”，如总容量相同时每个 Cache 容量变小、灵活性差等。
- 复习建议：牢记流水线三类冲突（结构、数据、控制）及其典型解决办法；理解 Cache 分离的根本动机是解决取指与访存的资源争用，而不是直接优化命中率或缺失损失。同时注意将 Cache 结构与处理器设计思想（如哈佛结构）联系起来记忆。
