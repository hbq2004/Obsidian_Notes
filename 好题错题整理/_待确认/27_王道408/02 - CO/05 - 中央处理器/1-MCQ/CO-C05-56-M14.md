# 选择题 第 14 题

![[_Attachments/题目识别/27_王道408-题目/CO-C05-56-M14_题目.png|题目]]

14. 下面有关控制冒险的描述中,错误的是( )
$I$. 无条件转移指令不会发生控制冒险 \quad $II$. 在分支指令加入若干空操作可以避免控制冒险
$III$. 采用转发(旁路)技术,可以解决部分控制冒险
$IV$. 中断或异常也会引起控制冒险 \quad $V$. 流水段的数量与控制冒险引发的开销无关
(A) $I$、$IV$、$V$
(B) $III$、$V$
(C) $I$、$III$、$IV$
(D) $I$、$III$、$V$

## 答案

![[_Attachments/题目识别/27_王道408-答案/CO-C05-56-M14_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：D（$I$、$III$、$V$ 错误）。一句话理由：无条件转移指令同样会改变 $PC$ 并可能取错后续指令，转发/旁路主要解决数据冒险，流水段数量会影响控制冒险开销；而 $II$、$IV$ 正确。

**解题切入点**：先抓住“控制冒险”的本质：只要指令改变 $PC$，或使后续本该按顺序取入的指令作废，就属于控制冒险。判断时把五个命题分成三类：是否由控制流改变引起、是否属于控制冒险的解决手段、控制冒险开销与流水线结构是否有关。选项差异主要在 $I$ 和 $III$ 是否错误。

**推演**：

控制冒险的本质是：当执行转移、跳转、异常或中断时，真实下一条指令地址不是原来的 $PC+4$，而是某个目标地址；但流水线在目标地址确定前可能已经取入了若干条后续指令，这些指令必须被作废或冲刷。

逐一判断：

1. **$I$ 错误**：无条件转移指令也会发生控制冒险。  
   例如在经典五段流水线中，无条件转移指令在 ID 段译码并计算目标地址；但 ID 阶段进行的同时，IF 阶段已经取入了该转移指令的下一条顺序指令。当转移指令进入 EX 段时，这条顺序指令是错误指令，需要被清除。因此“无条件转移不会发生控制冒险”是错误的。

2. **$II$ 正确**：在分支指令后加入若干空操作（NOP）可以避免控制冒险。  
   若空操作数量足够，使分支的目标地址或转移条件确定之前，后续有用指令尚未进入流水线，则流水线不会执行错误的“有用”指令。NOP 不改变寄存器或存储器状态，即使被取入也可安全丢弃。这只是以牺牲若干时钟周期为代价来保证正确性。

3. **$III$ 错误**：转发（旁路）技术主要用于解决数据冒险。  
   例如：
   $$
   \text{ADD } R1,R2,R3;\quad \text{SUB } R4,R1,R5
   $$
   可通过把 ALU 结果直接从 EX/MEM 段转发到 EX 段，避免等待写回。转发不会改变 $PC$，也不能解决“取错分支后指令”的问题，因此不是控制冒险的解决手段。

4. **$IV$ 正确**：中断或异常会迫使处理器转向中断/异常处理程序，改变正常指令执行顺序，并清空流水线中已取入的指令，因此也会引起控制冒险。

5. **$V$ 错误**：流水段数量与控制冒险开销有关。  
   若分支在流水线第 $s$ 段才确定目标地址/是否跳转，则在无分支预测、无延迟槽时，已经取入的错误指令数为 $s-1$，分支损失为：
   $$
   \text{分支损失} = s-1 \text{ 个时钟周期}
   $$
   $s$ 越大，通常需要冲刷的指令越多，控制冒险开销越大。因此不能说“流水段数量与控制冒险引发的开销无关”。

综上，错误的是 $I、III、V$，正确选项为 D。

**易错点**：

- 误认为“无条件转移”没有条件判断，所以不会发生控制冒险。实际上它仍会改变 $PC$，仍可能取入错误指令。
- 误认为转发技术能解决控制冒险。转发解决的是数据冒险中的 RAW 相关，不是控制冒险。
- 误认为插入空操作完全消除控制冒险。插入空操作本质是用“停顿/气泡”换取正确性，仍会产生性能开销。
- 忽略中断/异常对流水线的清空作用。它们也会引起控制流改变，属于控制冒险。
- 误认为流水段数与分支开销无关。分支判定位置越深，需要冲刷的指令越多，控制冒险开销越大。

**命题规律**：本题是典型的“冒险类型辨析”选择题，考查控制冒险的成因、解决手段和开销。常见变式包括：给出五段流水线，求分支指令在 ID 或 EX 段判定时的分支损失；结合分支预测成功率计算 $CPI$；区分“转发/旁路”与“分支预测/延迟槽/冲刷”分别解决哪类冒险。复习时应通过画流水线时空图，熟练掌握控制冒险的判定级数与分支开销之间的关系，并牢记：转发解决数据冒险，控制冒险主要靠分支预测、延迟槽、提前计算目标地址、插入空操作/冲刷来解决。
