# 选择题 第 1 题

![[_Attachments/题目识别/27_王道408-题目/CO-C05-55-M01_题目.png|题目]]

1. 以下关于“自陷”(*Trap*)异常的叙述中,错误的是( )

(A) “自陷”是人为预先设定的一种特定处理事件

(B) 可由访管指令或自陷指令的执行进入“自陷”

(C) 一定是出现某种异常情况才会发生“自陷”

(D) “自陷”发生后 $CPU$ 将进入操作系统内核程序执行

---

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CO-C05-55-M01_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：C。  
“自陷”（Trap）是程序主动、有意安排的异常，例如通过访管指令或自陷指令请求操作系统服务，不一定是因为出现了“异常情况”才发生。

**解题切入点**：  
看到“自陷”应立即联想到“主动”“有意”“系统调用”。它类似算法竞赛中主动调用系统 API 或抛出受控信号，而不是程序崩溃或硬件出错。题目中（C）出现“一定是”这种绝对化表述，通常就是考点：自陷并不等于故障或错误。

**推演**：  
在计算机组成原理中，中断/异常通常分为两大类：

- 外部中断：由 CPU 外部设备等异步事件引起；
- 内部异常：由 CPU 内部指令执行产生，其中又包括：
  - 故障（Fault）：如缺页、除零等，通常由某种错误或异常状态引起；
  - 自陷（Trap）：由程序主动执行特定指令引起，如访管指令、自陷指令；
  - 终止（Abort）：严重硬件错误，系统无法继续执行。

自陷的本质特征是：程序在执行到某条指令时，主动请求进入操作系统内核程序，常见用途是系统调用。例如用户程序执行 `syscall` 或访管指令后，CPU 会保存现场，然后进入内核态，并跳转到对应的处理程序：

$$
I_{\text{trap}} \Rightarrow \text{保存现场},\ M \leftarrow 0,\ PC \leftarrow \text{自陷处理程序入口}.
$$

其中 $M$ 表示 CPU 的工作模式，$M \leftarrow 0$ 表示切换到内核态。

逐项判断：

- （A）正确。“自陷”是人为预先设定、有意安排的一种处理事件，不是随机发生的错误；
- （B）正确。访管指令或自陷指令的执行可以触发“自陷”；
- （C）错误。“自陷”并不一定是出现某种异常情况才发生。系统调用就是正常请求服务，不属于“异常情况”；
- （D）正确。“自陷”发生后，CPU 会进入操作系统内核程序执行，实现从用户态到内核态的切换。

因此错误的是（C）。

**易错点**：  
1. 混淆“异常”与“出错”。自陷属于异常的一种，但不代表系统出错；  
2. 把自陷误认为外部中断。自陷由 CPU 内部指令主动触发，是同步事件；外部设备引起的是中断；  
3. 忽略返回地址差异。自陷处理完后一般返回下一条指令；故障处理完后可能重新执行当前指令；终止则通常不能恢复。题目虽未直接考返回地址，但这是常见变式。

**命题规律**：  
考点定位在“中断与异常分类”，重点是自陷与故障、终止、外部中断的区别。常见变式包括：

- 给出一组事件，如除零、缺页、自陷、时钟中断、I/O 中断，要求分类；
- 问自陷返回地址是下一条指令还是当前指令；
- 问自陷发生后 CPU 是否进入内核态。

复习建议：用表格整理“中断、故障、自陷、终止”的触发源、同步/异步、是否主动、返回地址。看到“访管指令”“自陷指令”“系统调用”就应锁定自陷。
