# 选择题 第 34 题

![[_Attachments/题目识别/27_王道408-题目/CO-C02-21-M34_题目.png|题目]]

34.【2025统考真题】在32位计算机上执行下列$C$语言代码段后,$ui$的值是( )
```c
short si = -32767;
unsigned int ui = si;
```
A. $2^{15} - 1$
B. $2^{15} + 1$
C. $2^{32} - 2^{15} - 1$
D. $2^{32} - 2^{15} + 1$

---

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CO-C02-21-M34_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：D。  
`short si = -32767;` 中 `si` 的数值是 $-32767$，赋给 `unsigned int` 时按无符号数模 $2^{32}$ 转换，得到：
$$ui=2^{32}-32767=2^{32}-2^{15}+1$$

**解题切入点**：  
看到“有符号 `short` 赋给 `unsigned int`”，要立刻定位到 C 语言中的整数提升和有符号转无符号规则。这不是简单地把 16 位二进制位复制到 32 位，而是“数值转换”。可以类比竞赛中的负数取模：结果是负数值加上模数，使其落入无符号数范围。

本题还有一个关键数字：$-32767=-(2^{15}-1)$，不是 $-2^{15}$，也不是 $2^{15}+1$。

**推演**：  

在 32 位计算机上，按常见 C 语言实现：
- `short` 为 16 位有符号整数；
- `unsigned int` 为 32 位无符号整数。

初始化：
$$si=-32767=-(2^{15}-1)$$

这个值在 `short` 的表示范围内，所以 `si` 保存的数值就是 $-32767$。

执行：
```c
unsigned int ui = si;
```

赋值时，将 `short` 类型的数值 $-32767$ 转换为 `unsigned int` 类型。  
C 语言规定：有符号整数转换为无符号整数时，如果值不能表示，则对 $2^{32}$ 取模，使结果落在 $[0,2^{32}-1]$ 内。

因此：
$$ui = -32767 + 2^{32} = 2^{32} - 32767$$

又因为：
$$32767 = 2^{15}-1$$

所以：
$$ui = 2^{32} - (2^{15}-1) = 2^{32} - 2^{15} + 1$$

故选 **D**。

从补码角度看也能验证：  
$-32767$ 的 16 位补码是 `1000 0000 0000 0001`，即 `0x8001`；  
符号扩展为 32 位后是 `0xFFFF8001`。  
将其按 `unsigned int` 理解：
$$0xFFFF8001 = 2^{32} - 0x7FFF = 2^{32} - 32767$$

同样得到 D 选项。

**易错点**：  

1. **误选 B**：把 `short` 的位模式直接“零扩展”成 32 位，即把 `0x8001` 变成 `0x00008001`，得到 $2^{15}+1$。  
   这是把“数值转换”错当成“按位拷贝”。

2. **误选 A**：忽略符号，直接取绝对值 $32767=2^{15}-1$。

3. **符号理解错误**：把 $-32767$ 误当成 $-2^{15}$。实际上：
   $$2^{15}=32768,\quad 2^{15}-1=32767$$

4. **转换规则不熟**：有符号转无符号是明确定义的模运算，不是未定义行为。

**命题规律**：  
本题是典型的 C 语言整数类型转换与补码表示结合题。命题角度常包括：

- `short`/`char` 转 `unsigned int`；
- 有符号数与无符号数比较大小，如 `-1 > 0U` 为真；
- 溢出与截断问题，如 `unsigned short` 转 `int`；
- 补码扩展：符号扩展 vs 零扩展。

复习时要熟练掌握：
$$2^n,\quad 2^n-1,\quad -2^n$$
之间的换算关系，并理解 C 语言“有符号转无符号按模转换”的本质，而不是死记选项。
