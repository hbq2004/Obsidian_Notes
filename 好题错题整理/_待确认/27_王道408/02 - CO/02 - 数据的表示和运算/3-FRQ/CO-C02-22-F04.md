# 综合题 第 4 题

![[_Attachments/题目识别/27_王道408-题目/CO-C02-22-F04_题目.png|题目]]

4.【2020统考真题】有实现 $x \times y$ 的两个 C 语言函数如下：
```c
unsigned umul(unsigned x, unsigned y){ return x*y; }
int imul(int x, int y) { return x*y; }
```
假定某计算机 $M$ 中的 $ALU$ 只能进行加减运算和逻辑运算。请回答下列问题。
(1)若 $M$ 的指令系统中没有乘法指令，但有加法、减法和位移等指令，则在 $M$ 上也能实现上述两个函数中的乘法运算,为什么?
(2)若 $M$ 的指令系统中有乘法指令，则基于 $ALU$、位移器、寄存器及相应控制逻辑实现乘法指令时，控制逻辑的作用是什么?
(3)针对以下三种情况:①没有乘法指令；②有使用 $ALU$ 和位移器实现的乘法指令；③有使用阵列乘法器实现的乘法指令，函数 $umul()$ 在哪种情况下执行的时间最长？在哪种情况下执行的时间最短？说明理由.
(4)$n$ 位整数乘法指令可保存 $2n$ 位乘积,当只取低 $n$ 位作为乘积时,其结果可能会发生溢出。当 $n=32, x=2^{31}-1, y=2$ 时,有符号整数乘法指令和无符号整数乘法指令得到的 $x \times y$ 的 $2n$ 位乘积分别是什么 (用十六进制表示)?此时函数 $umul()$ 和 $imul()$ 的返回结果是否溢出?对于无符号整数乘法运算,当仅取乘积的低 $n$ 位作为乘法结果时,如何用 $2n$ 位乘积进行溢出判断?

## DeepSeek V4 Flash Max 解析

**答案**：本题为综合题。结论要点：①没有乘法指令时，也可用“移位＋加减”的二进制乘法算法实现；②乘法指令中的控制逻辑负责按算法产生各节拍的微操作控制信号；③`umul()` 执行时间最长的是①，最短的是③；④$x \times y$ 的 $2n$ 位乘积为 `0x00000000FFFFFFFE`，`umul()` 不溢出，`imul()` 溢出；无符号乘法溢出可用高 $n$ 位是否全零判断。

**解题切入点**：看到“ALU 只能加减和逻辑运算、没有乘法指令”时，应立刻想到二进制乘法就是“竖式乘法”：乘数每一位决定是否把被乘数移位后相加。硬件乘法指令相当于把软件循环“固化”到硬件控制逻辑中；阵列乘法器则是用组合逻辑直接并行完成。溢出判断则要从 $2n$ 位乘积的高 $n$ 位入手。

**推演**：

(1) 无乘法指令也能实现乘法。

二进制乘法可写成
$$
X \times Y=\sum_{i=0}^{n-1} y_i\,X\,2^i,
$$
其中 $y_i$ 是乘数 $Y$ 的第 $i$ 位。$X2^i$ 可以通过移位得到，各项再用加法器累加。因此“移位”和“加法”指令已经足够。

对于补码有符号数，不能简单套用无符号乘法，但可用 Booth 算法：根据乘数相邻两位决定加被乘数、减被乘数或不加，然后做一次算术右移。因此还需要减法指令。题目中已有减法指令，所以 `imul()` 也可实现。

故没有乘法指令时，编译器或运行库可以把 `x*y` 展开为“移位、加/减、判断乘数位”的指令序列，因此两个函数都能在 $M$ 上实现。

(2) 乘法指令中控制逻辑的作用是：把乘法算法转换成一系列有序的微操作控制信号，指挥数据通路中的 ALU、移位器和寄存器协同工作。

具体包括：

- 将乘数和被乘数送入相应寄存器；
- 清零或初始化部分积寄存器；
- 每一拍根据乘数的当前位，控制 ALU 做加法、减法或直通；
- 控制移位器对部分积或被乘数进行移位；
- 控制迭代计数器递减；
- 当迭代完成后，控制把结果写回目的寄存器并结束该指令。

因此，控制逻辑相当于一个“硬件状态机”，负责决定每个时钟周期各个部件做什么。

(3) 三种情况下，`umul()` 执行时间最长的是①，最短的是③。

理由：

- ① 没有乘法指令：乘法用软件循环完成，每一步移位、加法、判断乘数位、循环跳转都要取指令、译码并执行，指令开销很大，所以最慢。
- ② 有使用 ALU 和移位器实现的乘法指令：乘法指令内部仍按“移位相加”方式迭代，需要多个时钟周期，但省去了软件循环中反复取指、译码和跳转的开销，所以比①快。
- ③ 有阵列乘法器实现的乘法指令：阵列乘法器用组合逻辑直接产生并累加所有部分积，基本可在单周期或极短延迟内完成，所以最快。

因此执行时间：①最长，③最短，②居中。

(4) 已知
$$
x=2^{31}-1=0x7FFFFFFF,\qquad y=2=0x00000002,
$$
所以
$$
x \times y=(2^{31}-1)\times 2=2^{32}-2=0x00000000FFFFFFFE.
$$

由于这里两个操作数都是正数，有符号解释和无符号解释的位模式相同，因此有符号整数乘法指令和无符号整数乘法指令得到的 $2n=64$ 位乘积都是
$$
0x00000000FFFFFFFE.
$$

其低 $32$ 位为 `0xFFFFFFFE`。

对于 `umul()`：返回类型是 `unsigned`，低 $32$ 位 `0xFFFFFFFE` 解释为无符号数是 $2^{32}-2$，正好等于真实乘积，因此不溢出。

对于 `imul()`：返回类型是 `int`，低 $32$ 位 `0xFFFFFFFE` 解释为有符号数是 $-2$，但真实乘积是 $2^{32}-2$，超出 `int` 可表示范围，因此发生溢出。从 $64$ 位乘积看，低 $32$ 位符号位为 $1$，高 $32$ 位应为 `0xFFFFFFFF` 才是符号扩展，但实际高 $32$ 位是 `0x00000000`，所以带符号溢出。（严格按 C 标准，带符号整数溢出属于未定义行为，但按机器级乘法指令判定为溢出。）

无符号整数乘法的溢出判断方法：设 $2n$ 位乘积为
$$
P=H\cdot 2^n+L,
$$
其中 $H$ 是高 $n$ 位，$L$ 是低 $n$ 位。若高 $n$ 位全为 $0$，则 $P=L<2^n$，低 $n$ 位可以表示真实乘积，无溢出；只要高 $n$ 位不全为 $0$，则 $P\ge 2^n$，低 $n$ 位不足以表示真实乘积，发生溢出。

所以无符号乘法溢出判断为：
$$
\text{溢出} \iff \text{乘积的高 } n \text{ 位不全为 } 0。
$$

**易错点**：

- 误以为没有乘法指令就不能实现乘法；实际上“移位相加”或 Booth 算法即可。
- 误以为用 ALU 和移位器实现的乘法指令与软件实现速度差不多；硬件指令省去反复取指、译码和跳转，仍明显更快。
- 把无符号溢出的判断方法套用到有符号乘法；有符号乘法应检查高 $n$ 位是否为低 $n$ 位的符号扩展。
- 看到 `0xFFFFFFFE` 的最高位为 $1$，就认为 `umul()` 溢出；这是错误的，无符号数 `0xFFFFFFFE` 是合法且可表示的。
- 在 C 语言中 `imul()` 的带符号溢出是未定义行为，但本题按机器级乘法指令判定溢出。

**命题规律**：本题是 2020 年统考真题，考查定点乘法实现、数据通路中控制逻辑的作用、软件乘法与硬件乘法的性能差异，以及乘法结果溢出的判断。常见变式包括：补码一位乘（Booth 算法）、原码一位乘、阵列乘法器、无符号/有符号乘法溢出判断等。复习时应重点掌握“乘法竖式”的移位相加思想，理解硬件控制器与软件程序的本质区别，并能根据 $2n$ 位乘积的高 $n$ 位判断无符号乘法溢出。
