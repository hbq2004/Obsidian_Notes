# 综合题 第 2 题

![[_Attachments/题目识别/27_王道408-题目/CO-C07-Q02_题目.png|题目]]

02. 假定某I/O设备向CPU传送信息的最高频率为4万次/秒，而相应中断处理程序的执行时间为40$\mu$s，则该I/O设备是否可采用中断方式工作？为什么？

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CO-C07-Q02_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：不能。该设备最高传送频率对应的请求间隔为 \(25\mu s\)，小于中断处理程序的执行时间 \(40\mu s\)，CPU 来不及处理下一次传送，会导致信息丢失，因此不能采用中断方式工作。

**解题切入点**：把设备“请求传送”看成每隔一定时间“来一个任务”，把“执行一次中断处理程序”看成“处理一个任务”。中断方式可行的核心条件是：处理一个任务的时间不能大于相邻两次任务到达的间隔。所以拿到题目先要把“最高频率 \(4\times 10^4\) 次/秒”换算成“每两次传送的间隔时间”，再和中断处理时间比较。

**推演**：

已知设备最高传送频率

\[
f=4\times 10^4\text{ 次/s}
\]

则相邻两次传送的间隔为

\[
T=\frac{1}{f}
=\frac{1}{4\times 10^4}\text{ s}
=25\mu\text{s}
\]

也就是说，设备以最高频率工作时，每 \(25\mu\text{s}\) 就会向 CPU 请求传送一次信息。

而中断方式下，每次传送都需要 CPU 执行一次中断处理程序，耗时

\[
t_{\text{int}}=40\mu\text{s}
\]

比较两者：

\[
t_{\text{int}}=40\mu\text{s} > T=25\mu\text{s}
\]

等价地，CPU 每秒最多能处理的中断次数为

\[
\frac{1}{40\mu\text{s}}=2.5\times 10^4\text{ 次/s}
\]

但设备请求频率为

\[
4\times 10^4\text{ 次/s}
\]

显然

\[
2.5\times 10^4 < 4\times 10^4
\]

即使忽略中断响应、现场保护与恢复等额外开销，CPU 的处理能力也不足。若按一秒计算，设备请求 \(4\times 10^4\) 次，CPU 需要花费

\[
4\times 10^4 \times 40\mu\text{s}=1.6\text{ s}
\]

超过 1 秒，因此必然无法及时处理所有中断请求，会丢失信息。

所以，该设备按题设最高频率工作时，不能采用中断方式；可采用 DMA 等方式，或要求设备的实际请求频率降低到中断处理能力范围以内。

**易错点**：

1. **单位不统一**  
   不能直接把“\(40000\) 次/秒”和“\(40\mu\text{s}\)”比较，应先把频率换算成周期：

   \[
   40000\text{ 次/s} \Rightarrow 25\mu\text{s/次}
   \]

   或者在统一单位后比较。

2. **忽略“最高频率”这一条件**  
   判断能否采用中断方式，应满足最高频率下的最坏情况。不能只根据平均频率或假设设备不会连续满速工作。

3. **忽略中断响应、现场保护与恢复开销**  
   本题只给了中断处理程序执行时间，实际还要有关中断、响应、保存/恢复现场等额外开销。如果把这些算上，结论仍然是“不能”。

4. **误以为中断排队可以解决**  
   中断排队只能缓冲短时突发请求。如果输入速率长期大于 CPU 处理能力，队列会不断增长或溢出，最终仍会丢失数据。

**命题规律**：本题属于计算机组成原理中“I/O 方式”部分的典型计算题，核心考点是中断方式的适用条件。常见变式有：

- 给定设备传送频率和中断处理时间，判断能否采用中断方式；
- 计算 CPU 因处理中断而占用的时间比例；
- 给出中断响应时间，求设备最高允许传送频率；
- 与 DMA 方式结合，比较中断方式和 DMA 方式下的 CPU 开销。

复习时应牢记判据：

\[
t_{\text{处理}} \le \frac{1}{f_{\max}}
\]

即每次中断处理的 CPU 时间不能超过设备请求的间隔时间。同时注意单位换算，理解“中断方式适合低速设备，DMA 适合高速设备”的基本规律。

> 02. 【解答】
> I/O 设备传送一个数据的时间为 $1 \div (4 \times 10^4) \text{s} = 25\mu\text{s}$，所以请求中断的周期为 $25\mu\text{s}$，而相应中断处理程序的执行时间为 $40\mu\text{s}$，大于请求中断的周期，会丢失数据（单位时间内 I/O 请求数量比中断处理的多，自然会丢失数据），所以不能采用中断方式。
