# MCQ 第 21 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C05-S01-Q021_题目.png|题目]]

当一个进程请求 I/O 操作时,该进程将被挂起,直到 I/O 设备完成 I/O 操作后,设备控制器便向 CPU 发送一个中断请求,CPU 响应后便转向中断处理程序,下列关于中断处理程序的说法中,错误的是( ).
(A) 中断处理程序将设备控制器中的数据传送到内存的缓冲区(读入),或将要输出的数据传送到设备控制器(输出)
(B) 对于不同的设备,有不同的中断处理程序
(C) 中断处理结束后,需要恢复 CPU 现场,此时一定会返回到被中断的进程
(D) I/O 操作完成后,驱动程序必须检查本次 I/O 操作中是否发生了错误

## DeepSeek V4 Flash Max 解析
**答案**：
选 $C$ 。$A$、$B$、$D$ 都是中断处理/驱动程序的正常职责；$C$ 的“一定”错。

**解题切入点**：
题眼是“恢复现场”和“返回到被中断的进程”是否等价。恢复现场只是恢复寄存器等 CPU 状态，返回哪个进程由调度器决定。算法竞赛视角：中断处理程序像一个 `handle_irq()` 回调，回调结束不一定 `return` 到原来的调用点，返回前可能先 `schedule()`，相当于在状态搜索中不回溯，而是从就绪队列里选一个新状态继续。

**推演**：
设 $P$ 为请求 I/O 并阻塞的进程，$Q$ 为中断发生时正在运行的进程。

- 设备完成后，控制器发中断，CPU 保存 $Q$ 的现场并转入中断处理程序。
- 中断处理程序中：
  - 读状态寄存器、检查错误位：对应 $D$；
  - 读操作：设备控制器 $\rightarrow$ 内存缓冲区；写操作：内存缓冲区 $\rightarrow$ 设备控制器：对应 $A$；
  - 不同设备由不同中断向量/设备驱动对应不同处理程序：对应 $B$。
- 中断返回前，如果调度器把 CPU 分配给 $P$ 或更高优先级进程 $R$，那么恢复的是 $R$ 的现场，中断返回到 $R$ 的执行流；只有未发生调度时才返回 $Q$。

所以：

$$
\text{中断返回目标}=
\begin{cases}
Q, & \text{返回前不调度}\\
R, & \text{返回前已调度到 } R
\end{cases}
$$

因此“一定会返回到被中断的进程”不成立。

**易错点**：
- “恢复现场”不等于“回到原进程”。中断返回前可以有调度时机，这是最常见错因。
- 不要把“等待 I/O 的进程”和“被中断的进程”当成同一个。前者已经阻塞，后者是中断发生时刻 CPU 上的当前进程。
- 如果联想到 DMA，注意本题按典型中断驱动 I/O 模型判断：$A$ 说的是由中断处理程序完成一次与设备控制器的数据交换；题目未引入 DMA 时不据此判错。

**命题规律**：
408 常在中断、异常、系统调用、进程切换的边界设题。选项中一旦出现“一定/必须/总是”这类绝对化词，优先怀疑。核心规律是：中断处理之后的返回目标由调度器决定，不由中断机制决定。算法竞赛中可类比为：`interrupt_handler` 只是一个事件回调，事件处理完后是 `return` 还是 `yield` 给另一个任务，取决于调度状态机，而不是回调自身的返回语句。掌握“中断向量表 $\approx$ 函数指针表、现场恢复 $\approx$ 状态快照、调度 $\approx$ 状态切换”即可快速解题。
