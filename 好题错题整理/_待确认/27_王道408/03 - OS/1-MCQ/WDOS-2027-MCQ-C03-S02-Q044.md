# MCQ 第 44 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C03-S02-Q044_题目.png|题目]]

当系统发生抖动时，可以采取的有效措施是( )
$I$.撤销部分进程
$II$.增加磁盘交换区的容量
$III$.提高用户进程的优先级
(A) 仅 $I$
(B) 仅 $II$
(C) 仅 $III$
(D) 仅 $I$、$II$

## DeepSeek V4 Flash Max 解析
**答案**：A（仅 $I$）

**解题切入点**：抖动本质是 内存过载 导致频繁缺页，类似算法竞赛中“内存超限”或“缓存未命中”引发的性能崩溃。解决核心是 降低多道程序度，即减少并发进程数，如同在复杂搜索中通过剪枝控制递归深度。

**推演**：
- 抖动（thrashing）发生时，系统频繁进行页面置换，CPU 利用率急剧下降。实质是 进程的工作集 无法全部装入内存，造成缺页率过高。
- 措施 $I$：撤销部分进程 → 直接减少并发进程数量，释放内存空间，使剩余进程拥有足够的工作集内存，降低缺页率。这类似于算法竞赛中，当递归深度过大导致栈溢出时，剪枝或减少搜索分支。
- 措施 $II$：增加磁盘交换区的容量 → 交换区容量增大仅允许更多页面被换出，但无法增加物理内存，反而可能使系统维持更多进程，加剧内存竞争。如同在算法中，扩大外部存储并不能解决内部缓存不足导致的频繁 I/O，反而因允许更多数据溢写而增加 I/O 次数。
- 措施 $III$：提高用户进程的优先级 → 仅影响 CPU 调度顺序，不改变内存分配量，无法缓解缺页问题。如同在算法竞赛中，提高线程优先级不能解决内存不足引起的 “Time Limit Exceeded”。
因此，只有 $I$ 有效。

**易错点**：
- 误认为增加交换区容量可以缓解抖动，实际上交换区容量并不影响缺页率，反而可能助长多道程序度过高。
- 混淆 “优先级” 与 “内存分配” 的关系，认为提高优先级能获得更多内存资源，但优先级仅影响 CPU 调度，不涉及内存分配。
- 忽略抖动产生的根本原因是 “并发进程过多导致内存不足”，而非交换区大小或 CPU 调度策略。

**命题规律**：
- 常考抖动定义、原因及解决方案，需区分 “有效” 与 “无效” 措施。
- 常与 “工作集模型”、“页面置换算法” 结合出题，考察对内存管理整体理解。
- 类似算法竞赛中 “资源分配” 类问题，需要识别瓶颈所在（内存 vs CPU vs I/O），并选择针对性优化策略。
