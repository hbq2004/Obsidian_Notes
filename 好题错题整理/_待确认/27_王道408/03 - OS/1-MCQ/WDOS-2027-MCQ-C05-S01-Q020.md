# MCQ 第 20 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C05-S01-Q020_题目.png|题目]]

下列 $I/O 方式中，会导致用户进程进入阻塞态的是( )
$I.程序直接控制
$II.中断方式
$III.DMA 方式
(A) $II
(B) $I、III
(C) $II、III
(D) $I、II、III

## DeepSeek V4 Flash Max 解析
**答案**：
$\boxed{C}$（$\mathrm{II}$、$\mathrm{III}$）。

**解题切入点**：
抓住进程状态转移的触发条件：阻塞态要求进程让出 CPU，进入等待队列，等待后续事件唤醒。程序直接控制方式下，进程不是“让出 CPU 等待”，而是“占着 CPU 轮询”，所以不阻塞；中断方式与 DMA 方式则把“等待 I/O 完成”从忙等变成了“阻塞 + 中断唤醒”。

**推演**：
设用户进程 $P$ 发起一次 I/O 操作，要求数据到达 $P$ 的缓冲区。

- $\mathrm{I}$ 程序直接控制：$P$（在内核态）反复执行测试指令检查设备状态寄存器，等价于  
  $$
  \text{while (设备未就绪) ;}
  $$
  $P$ 没有进入等待队列，仍占用 CPU，状态是运行态而非阻塞态。故 $\mathrm{I}$ 不选。

- $\mathrm{II}$ 中断方式：CPU 发出 I/O 启动命令后，不需要再轮询设备。$P$ 可进入阻塞态，CPU 转去执行其他进程；设备完成一次数据准备/传送后发出中断，中断处理程序将 $P$ 唤醒。故 $\mathrm{II}$ 选。

- $\mathrm{III}$ DMA 方式：CPU 初始化 DMA 控制器（内存地址、传送字节数、方向等）后，由 DMA 控制器完成数据块在内存与外设之间的搬运。在此期间 $P$ 可进入阻塞态，传送完成后 DMA 发中断唤醒 $P$。故 $\mathrm{III}$ 选。

状态迁移可概括为：
$$
\text{程序直接控制：}\ P:\ \mathrm{Running} \to \text{忙等（仍占用 CPU）}
$$
$$
\text{中断/DMA：}\ P:\ \mathrm{Running} \to \mathrm{Blocked} \xrightarrow{\text{完成中断}} \mathrm{Ready} \to \mathrm{Running}
$$

**易错点**：
1. 误以为“等待 I/O”就一定阻塞。程序直接控制是忙等，不阻塞；只有进入等待队列让出 CPU 才叫阻塞。
2. 误以为中断方式中“CPU 不等待，设备完成后通知”，所以用户进程不会阻塞。实际上发起 I/O 的用户进程若不阻塞，就无法获得所需数据，它通常被阻塞；被换下 CPU 的正是该进程。
3. 误以为 DMA“不需要 CPU 参与数据搬运”，所以用户进程不阻塞。DMA 只是不占用 CPU 搬运数据，用户进程仍要等“整块数据传送完成”这一事件，因此可以阻塞。
4. 注意“中断处理程序运行”不等于“用户进程运行”；中断只能完成 $Blocked \to Ready$，进程还要重新参与调度才回到运行态。

**命题规律**：
408 常把 I/O 控制方式与进程状态、CPU 利用率结合考查，本质是“是否让出 CPU”的辨析。可以把三种方式类比为算法竞赛中的同步机制：
- 程序直接控制 = 自旋锁/轮询 `while (!flag);`
- 中断方式 = 注册事件回调挂起任务，事件到来再唤醒
- DMA 方式 = 把传输任务交给协处理器/GPU，主任务阻塞在 `future` 上，完成中断使其就绪

复习时抓住两条线：一是 CPU 在 I/O 过程中的参与程度；二是用户进程是“忙等”还是“阻塞等待”。这类题常用组合选项，排除掉“程序直接控制”即可锁定 $\mathrm{C}$。
