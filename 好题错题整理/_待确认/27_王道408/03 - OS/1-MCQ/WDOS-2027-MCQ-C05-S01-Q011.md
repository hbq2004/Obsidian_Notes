# MCQ 第 11 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C05-S01-Q011_题目.png|题目]]

11. $DMA$ 传输前需要进行预处理,传输后需要进行后处理,则下列说法中正确的是( ).
(A) 预处理程序运行在用户态,后处理程序运行在内核态
(B) 负责预处理和后处理程序的进程都是请求 $I/O$ 的进程
(C) 预处理阶段不需要 $CPU$ 参与,后处理阶段需要 $CPU$ 参与
(D) 预处理阶段请求 $I/O$ 的进程处于运行态,后处理阶段处于阻塞态

## DeepSeek V4 Flash Max 解析
**答案**：D

**解题切入点**：

把 DMA 看成“异步批量搬运”：

- 预处理 = CPU 向 DMA 控制器提交参数；
- 数据传送 = DMA 控制器自己搬数据，CPU 不逐字节参与；
- 后处理 = DMA 发中断，CPU 做收尾。

所以关键在于：CPU 在预处理和后处理阶段都要参与，而真正“不占 CPU”的只是中间的数据搬运阶段。这就像在算法竞赛里开一个异步任务：先构造好参数并提交，再等待结果；提交前和回调收尾都要主线程参与，但批量计算本身是“硬件协处理器”完成的。

**推演**：

A 错：真正的 DMA 预处理是 CPU 在内核态设置 DMA 控制器，不是用户态程序；后处理是中断处理程序，也在内核态。

B 错：预处理可以发生在请求 $I/O$ 的进程上下文里，但后处理是中断处理程序完成的，运行在中断上下文，不是请求 $I/O$ 的进程。不能把“后处理者”等同于“请求者”。

C 错：预处理阶段需要 CPU 参与，因为 CPU 要设置设备地址、内存地址、传送方向和传送长度；后处理阶段也需要 CPU 参与，因为 CPU 要响应中断、检查状态并唤醒进程。

D 对：预处理阶段请求 $I/O$ 的进程处于运行态；DMA 开始后，该进程等待 $I/O$ 完成，进入阻塞态；后处理阶段中，请求进程仍处于阻塞态，直到中断处理程序将其唤醒后进入就绪态。

$$
\text{运行态} \xrightarrow{\text{启动 DMA 后等待}} \text{阻塞态} \xrightarrow{\text{后处理唤醒}} \text{就绪态} \xrightarrow{\text{调度}} \text{运行态}
$$

**易错点**：

- 不要误以为“DMA 方式全程不需要 CPU”。DMA 只是让 CPU 从数据搬运中解放出来，但预处理和后处理都必须由 CPU 完成。
- 不要把中断处理程序当成请求 $I/O$ 的进程。后处理是内核中断上下文，类似异步回调；请求进程还在等待队列里阻塞。
- 不要把“运行态”和“用户态”混为一谈。进程在内核态执行驱动代码时，仍然处于运行态。
- 后处理唤醒进程后，进程先进入就绪态，而不是直接回到运行态；是否运行还要由调度器决定。

**命题规律**：

408 常考 DMA 三阶段：预处理、数据传送、后处理，重点考察 CPU 参与程度和请求进程的状态变化。这本质上是一道“状态机”题：把 CPU、DMA、请求进程三个角色按时间轴标出来，谁在运行、谁在等待、谁在传输，一目了然。复习时可以和程序直接控制方式、中断驱动方式对比，DMA 的“前后要 CPU、中间不占 CPU”是高频考点。
