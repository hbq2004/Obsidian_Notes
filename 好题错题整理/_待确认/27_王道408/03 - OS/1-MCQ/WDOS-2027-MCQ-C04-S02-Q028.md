# MCQ 第 28 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C04-S02-Q028_题目.png|题目]]

某文件系统采用显式链接分配方式组织文件, 磁盘块大小为 $4KB, 一个簇包含两个磁盘块, 操作系统以簇为单位进行盘块分配。已知系统支持的最大文件长度为 $512MB, 若 $FAT 的每个表项仅存放簇号, 则 $FAT 表占用的空间大约是 ( ) .
(A) $64KB
(B) $128KB
(C) $512KB
(D) $1024KB

## DeepSeek V4 Flash Max 解析
**答案**：B. $128KB$

**解题切入点**：
FAT 表就是一张全局 `nxt[]` 数组：以簇号为下标，表项存放下一簇簇号。竞赛中若结点编号上限为 $65536$ ，用 `unsigned short` 存 `next` 即可；这里先由“最大文件长度 / 簇大小”得到簇号范围，再由簇号范围确定表项字节数，最后由表项数乘表项大小得到 FAT 大小。

**推演**：
1. 簇大小：
$$2 \times 4KB = 8KB = 2^{13}B.$$
2. 最大文件长度：
$$512MB = 512 \times 2^{20}B = 2^{29}B.$$
3. 可寻址簇数：
$$N = \frac{2^{29}B}{2^{13}B} = 2^{16} = 65536.$$
4. 每个 FAT 表项只存放簇号，所以表项位宽：
$$\lceil \log_2 65536 \rceil = 16\ bit = 2B.$$
5. FAT 表项数等于可寻址簇数，因此：
$$65536 \times 2B = 131072B = 128KB.$$

所以选 B。

**易错点**：
- 分配单位是簇，不能拿磁盘块 $4KB$ 直接去除 $512MB$ ；必须先得簇大小 $8KB$ 。
- 表项位宽由簇号最大值决定：$65536$ 个簇号需要 $16$ 位，即 $2B$ ；误用 $1B$ 会得 $64KB$ ，误用 $4B$ 则偏离选项。
- FAT 表项数是按整个簇号空间设置的，不是只按一个文件当前链上的簇数动态设置；这如同开 `nxt` 数组要开到值域大小，而不是开到当前链表长度。

**命题规律**：
- 本质是单位换算链：先求簇数 $N=\frac{512MB}{8KB}=2^{16}$ ，再求表项位宽 $\lceil \log_2 N \rceil=16bit$ ，最后乘 $N$ 得到 FAT 大小。
- 显式链接分配 / FAT 题常把“块、簇、最大文件长度”包装在一起，核心是识别出 `nxt[]` 数组的长度和下标位宽。
- 竞赛类比：本题等价于“用 `short nxt[65536]` 还是 `int nxt[131072]`”的选择题；先看值域，再算数组空间，就能避免单位干扰。
