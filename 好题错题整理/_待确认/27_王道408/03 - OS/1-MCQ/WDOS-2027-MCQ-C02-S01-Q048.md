# MCQ 第 48 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S01-Q048_题目.png|题目]]

48. 下面关于用户级线程和内核级线程的描述中,错误的是 ( )

(A) 采用轮转调度算法,进程中设置内核级线程和用户级线程的效果完全不同
(B) 跨进程的用户级线程调度也不需要内核参与,控制简单
(C) 用户级线程可以在任何操作系统中运行
(D) 若系统中只有用户级线程,则 CPU 的调度对象是进程

## DeepSeek V4 Flash Max 解析
**答案**：$\text{B}$

**解题切入点**：  
看到“用户级/内核级线程”，先想两件事：线程由谁管理？调度对象是什么？  
用户级线程是“用户态库管理的轻量执行流”，内核不知道它的存在；内核级线程是“内核知道的执行流”。  
可以把每个进程看成一个状态机：用户级线程的切换只是状态机内部的状态转移；跨进程的线程调度相当于从一个状态机跳转到另一个状态机，这必须由内核完成。类似算法竞赛中跨连通块必须经过“桥”，不能靠本地 DFS/BFS 直接跳过去。

**推演**：  
- A 项正确。采用轮转调度时，设时间片为 $q$，某进程有 $n$ 个用户级线程，则内核只把该进程看成一个调度实体，先给进程 $q$，再由用户线程库在内部给各线程分配；若有 $n$ 个内核级线程，内核就绪队列中直接有 $n$ 个该进程的调度实体。因此二者在调度粒度和 CPU 时间分配上效果不同。
- B 项错误。用户级线程的切换不进入内核，但仅限于同一进程内。跨进程切换需要切换地址空间、页表、处理器上下文等，这些是特权操作，必须由内核完成。跨进程时，内核先调度到某个进程，用户线程库再在进程内选择线程，不能说完全不需要内核参与。
- C 项正确。用户级线程只需要用户态线程库，内核无需感知线程，因此任何支持进程的操作系统都能运行用户级线程。
- D 项正确。只有用户级线程时，内核的调度对象是进程；线程的具体选择由用户态线程库完成。

**易错点**：  
- 把“同进程用户级线程切换不陷入内核”扩大成“所有线程调度都不需要内核”。  
- 看到 A 中“完全不同”就认为是绝对化错误。实际上 A 在 408 语境下是对的，核心差异在于“线程是否为内核调度单位”。  
- 混淆“CPU 调度对象”和“实际执行流”：只有用户级线程时，CPU 调度对象仍然是进程，不是线程。  
- 忽略用户级线程中一个线程阻塞系统调用会阻塞整个进程，这也是它与内核级线程的重要区别。

**命题规律**：  
408 喜欢用“概念错位”命题：把“用户态”与“不需要内核”绑定，把“线程”与“调度单位”绑定。解题时抓住“谁管理、谁调度、调度单位是谁”三问即可。  
从算法竞赛视角看：用户级线程相当于局部优化/本地搜索，内核级线程相当于全局调度/全局协调；跨进程操作必然走内核这条“全局边”。这类题不难，关键是不要凭“用户态切换快”的局部印象推出“跨进程也不需要内核”的错误结论。
