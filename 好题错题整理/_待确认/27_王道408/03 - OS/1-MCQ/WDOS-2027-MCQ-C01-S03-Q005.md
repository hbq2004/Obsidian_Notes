# MCQ 第 5 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C01-S03-Q005_题目.png|题目]]

5. CPU 执行的指令被分为两类,其中有一类称为特权指令,它只允许 ( ) 使用.
(A). 管理员
(B). 联机用户
(C). 目标程序
(D). 操作系统

## DeepSeek V4 Flash Max 解析
**答案**：  
D. 操作系统。特权指令只能由操作系统（内核）在核心态/管态下执行，用户程序无权直接执行。

**解题切入点**：  
CPU 指令集按权限可划分为特权指令与非特权指令。核心问题是：谁运行在核心态？答案是操作系统内核。可以类比算法竞赛中“只有 root 权限的评测进程能执行底层系统调用”，而普通提交程序只能通过 `syscall` 请求系统服务，不能直接碰底层资源。

**推演**：  
设CPU状态集合为 $S=\{\text{核心态},\ \text{用户态}\}$，则特权指令集合 $I_p$ 只能在核心态下执行。  
- A. 管理员：管理员是用户账户身份，管理员进程仍然运行在用户态，不能直接执行 $I_p$；它只能通过系统调用请求操作系统代为执行。  
- B. 联机用户：普通用户进程，同样处于用户态，排除。  
- C. 目标程序：即用户目标程序，运行在用户态，禁止执行 $I_p$，排除。  
- D. 操作系统：操作系统内核运行在核心态，负责管理硬件和资源，因此 $I_p$ 只允许操作系统使用。

在实现上，用户程序一旦执行特权指令，CPU 会产生异常，相当于“非法操作”被强制终止。这就像 DFS/BFS 中访问未授权的状态节点，直接触发 `vis` 检查失败。

**易错点**：  
容易误选 A“管理员”。管理员只是用户层面的高权限账户，不是 CPU 状态层面的权限拥有者；其执行普通程序时依然处于用户态，不能直接使用特权指令。  
另一个误区是把“系统调用”和“特权指令”混为一谈。用户程序通过非特权指令（如访管指令/trap）进入内核态，由操作系统执行特权指令，但这并不意味着用户程序“使用”了特权指令。

**命题规律**：  
属于 408 操作系统基础概念题，常与“用户态/核心态切换”“中断/异常”“系统调用”结合考查。本质上是一个状态机模型：特权指令的合法状态集合为 $\{\text{核心态}\}$，用户态不在其中，因此不能执行。后续真题中若出现“访管指令是否特权指令”“系统调用如何进入核心态”等变体，核心依旧是这一状态权限映射。
