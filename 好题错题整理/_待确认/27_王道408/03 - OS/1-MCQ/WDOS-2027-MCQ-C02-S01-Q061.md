# MCQ 第 61 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S01-Q061_题目.png|题目]]

一个进程的读磁盘操作完成后，操作系统针对该进程必做的是( ).
(A) 修改进程状态为就绪态
(B) 降低进程优先级
(C) 给进程分配用户内存空间
(D) 增加进程时间片大小

## DeepSeek V4 Flash Max 解析
**答案**：
A（修改进程状态为就绪态）。

**解题切入点**：
题目问的是 I/O 完成后的“必做”操作，等价于问：在进程状态机中，磁盘读完成这个事件触发哪条唯一的状态转移边。进程发出读磁盘请求后，通常因等待该 I/O 事件进入阻塞态；I/O 完成意味着等待条件消失，操作系统必须把进程从阻塞态改为就绪态，并放入就绪队列。

$$
\text{运行} \xrightarrow{\text{请求 I/O}} \text{阻塞} \xrightarrow{\text{I/O 完成}} \text{就绪} \xrightarrow{\text{调度}} \text{运行}
$$

这就像 BFS 中，一个节点正在等待外部事件；事件到达后，只能按状态转移表进入唯一后继状态，不能直接“继续运行”。

**推演**：
- A 正确。I/O 完成前，进程因等待该事件而阻塞；完成后阻塞原因消除，OS 必须修改 PCB 状态： $\mathrm{PCB.status} \leftarrow \text{就绪}$ ，并将 PCB 移入就绪队列。
- B 错误。优先级是否改变取决于调度算法，不是 I/O 完成的必然结果。
- C 错误。用户内存空间应在发起读操作之前已分配好；I/O 完成只是把磁盘数据写入已分配的内存区域，不是临时再分配内存。
- D 错误。时间片大小由调度策略决定，I/O 完成事件不会自动增加进程时间片。

因此只有 A 是“必做”。

**易错点**：
1. 把“唤醒”和“调度”混淆。I/O 完成后进程进入就绪态，不是运行态；它还要等待 CPU 调度。
2. 认为读磁盘完成需要分配内存。实际上读请求的目标缓冲区在读操作开始前就已存在；I/O 完成中断处理主要做状态更新与唤醒进程。
3. 看到“优先级”“时间片”就误以为与 I/O 相关，但它们是调度策略问题，不是状态转移的必然操作。
4. 在算法竞赛思维中，容易把 I/O 完成当作“可直接继续执行的回调”；在 OS 进程模型里，它只是把节点从等待队列放入就绪队列，相当于 BFS 中从“等待事件”变成“可被调度”。

**命题规律**：
408 常以“I/O 完成、时间片到、等待的事件发生”等具体事件考查进程状态转换。解题时采用“状态机法”：先确定进程当前状态，再由事件找唯一合法转移边。干扰项通常来自内存管理、处理机调度，要求考生区分进程管理与调度策略。把五状态模型画成一张状态转移图，像维护 DFS/BFS 搜索状态一样记清每条边，即可快速定位答案。
