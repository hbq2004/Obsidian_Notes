# MCQ 第 33 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S02-Q033_题目.png|题目]]

33. 多级反馈队列调度算法不具备的特性是( ).
A. 资源利用率高
B. 响应速度快
C. 系统开销小
D. 并行度高

## DeepSeek V4 Flash Max 解析
**答案**：
C. 系统开销小

多级反馈队列调度算法（$\text{MLFQ}$）通过“多级队列 + 进程降级/升级”来兼顾短作业和长作业，因此具有响应速度快、资源利用率高等优点；但该机制本身需要维护多个就绪队列，并在时间片到期时做队列迁移和重新选择，调度与切换开销较大，所以不能说它“系统开销小”。

**解题切入点**：
把 $\text{MLFQ}$ 建模成状态机。每个进程状态为 $(level,\ used)$，其中 $level$ 是所在队列编号，$used$ 是当前时间片已用时间。调度器每次从优先级别最高的非空队列取出一个进程运行；时间片到则 $level \leftarrow level+1$。这就像竞赛中用“分层桶”做 BFS/动态维护：检索最优状态的策略很好，但每个状态的入桶、出桶、降级都是额外操作。题目要你判断的，正是这个机制的代价而不是它带来的好处。

**推演**：
设系统有 $n$ 级队列：
$$
P(Q_1)>P(Q_2)>\cdots>P(Q_n),\qquad q_1\le q_2\le\cdots\le q_n.
$$
新到进程进入 $Q_1$。在 $Q_i$ 运行了 $q_i$ 仍未结束，则降入 $Q_{i+1}$；若进程因 I/O 阻塞，则唤醒后回到原队列或按规则升级。于是：

1. 短进程/交互式进程在 $Q_1$ 很快完成，响应快，对应 B。
2. 长进程下移后使用较长的时间片，减少无谓切换；I/O 密集与 CPU 密集进程能交错占用资源，资源利用率高，对应 A。
3. 但每级队列的维护、时间片到期的中断处理、进程的降级/升级以及从多队列中查找最高优先级非空队列，都会产生额外开销。因此 C 与机制冲突。
4. D“并行度高”并不是调度算法本身的直接评价指标；并行度取决于 CPU 核心等硬件结构。本题的确定性排除项是 C。

**易错点**：
- 看到“多级队列”就联想到“多核并行”。其实多级反馈队列是优先级分层，不是把进程同时放到多个 CPU 上执行。
- 把“算法性能好”等同于“系统开销小”。$\text{MLFQ}$ 性能确实较综合，但性能好来自多级反馈机制，而机制本身需要付出额外调度/切换代价。
- 竞赛类比：功能越强的高级数据结构，常数不一定小。用 `std::set` 做动态最值很好写，但每次操作有 $O(\log n)$ 代价；$\text{MLFQ}$ 的“多级维护”也有类似常数代价。

**命题规律**：
408 喜欢把进程调度算法放在一起做特性辨析：FCFS 公平但平均周转慢；SJF 平均周转快但长作业可能饥饿；RR 响应快但切换频繁；$\text{MLFQ}$ 综合长短作业，但调度/切换开销偏大。复习时把每个算法画成状态转移图，标出“什么事件触发调度、切换代价来自哪里、会不会饥饿”，即可应对这类概念题。
