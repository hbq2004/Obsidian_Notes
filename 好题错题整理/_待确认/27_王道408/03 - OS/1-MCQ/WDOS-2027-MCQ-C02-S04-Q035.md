# MCQ 第 35 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S04-Q035_题目.png|题目]]

某时刻进程的资源使用情况见下表，此时的安全序列是（ ）.

| 进程名 | 已分配资源 $R_1 | 已分配资源 $$R_2 |$ 已分配资源 $R_3 | 尚需分配 $$R_1 |$ 尚需分配 $R_2 | 尚需分配 $$R_3 |$ 可用资源 $R_1 | 可用资源 $$R_2 |$ 可用资源 $R_3 |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| $$P_1 | 2 | 0 | 0 | 0 | 0 | 1 | | | |
|$ $P_2 | 1 | 2 | 0 | 1 | 3 | 2 | | | |
| $$P_3 | 0 | 1 | 1 | 1 | 3 | 1 | | | |
|$ $P_4 | 0 | 0 | 1 | 2 | 0 | 0 | | | |
| 可用资源 | | | | | | | 0 | 2 | 1 |

(A) $$P_1,P_2,P_3,P_4
(B)$ $P_1,P_3,P_2,P_4
(C) $$P_1,P_4,P_3,P_2
(D)$ 不存在

## DeepSeek V4 Flash Max 解析
**答案**：
D（不存在安全序列）。

**解题切入点**：
银行家算法求安全序列，本质上是在资源状态图上做“可行执行顺序”的判定，类似拓扑排序中的 Kahn 算法。令 $W$ 为当前可用资源向量，$Need$ 为进程尚需资源向量。每次找一个未完成进程满足 $Need_i\le W$ ，则它可执行完；执行完后归还其已分配资源，即 $W\leftarrow W+Alloc_i$ 。因为 $W$ 只会单调不减，所以不需要像 DFS 枚举全排列那样回溯；每步能选就选，选不动就说明不存在安全序列。

**推演**：
由表得：
$$
Alloc=
\begin{pmatrix}
2&0&0\\
1&2&0\\
0&1&1\\
0&0&1
\end{pmatrix},\qquad
Need=
\begin{pmatrix}
0&0&1\\
1&3&2\\
1&3&1\\
2&0&0
\end{pmatrix},\qquad
W_0=(0,2,1).
$$

初始检查：

$$
Need_{P_1}=(0,0,1)\le(0,2,1)=W_0.
$$

因此唯一能先执行的是 $P_1$ 。执行后：

$$
W=W_0+Alloc_{P_1}=(0,2,1)+(2,0,0)=(2,2,1).
$$

此时检查剩余进程：

$$
Need_{P_2}=(1,3,2)\not\le(2,2,1),
$$

$$
Need_{P_3}=(1,3,1)\not\le(2,2,1),
$$

$$
Need_{P_4}=(2,0,0)\le(2,2,1).
$$

所以第二步只能是 $P_4$ 。执行后：

$$
W=(2,2,1)+(0,0,1)=(2,2,2).
$$

再检查剩余进程：

$$
Need_{P_2}=(1,3,2)\not\le(2,2,2),
$$

$$
Need_{P_3}=(1,3,1)\not\le(2,2,2).
$$

没有任何进程可继续执行，安全序列不存在。

因此 A、B 在第二步就矛盾，C 在第三步矛盾，答案选 D。

**易错点**：
- 注意“尚需分配”已经是 $Need$ ，不是最大需求；若题目给最大需求，才需要算 $Need=Max-Alloc$ 。
- $P_i$ 执行完后，$W$ 增加的是 $Alloc_i$ ，不是 $Need_i$ 。例如 $P_1$ 完成后增加的是 $(2,0,0)$ 。
- 比较 $Need_i\le W$ 必须三个资源分量都满足。$P_2$、$P_3$ 都卡在 $R_2$ 不足，不能只看 $R_1,R_3$ 满足就认为可执行。
- 找不到安全序列表示当前状态不安全，但不等于死锁已经发生。

**命题规律**：
408 常给一张多进程多资源表，构造“第一步唯一、第二步唯一、最后卡死”的陷阱，答案会落在“不存在安全序列”。这类题本质是资源约束下的可行性判断，等价于拓扑排序：每次删除一个当前可满足的进程，删不完则无解。若表中给的是最大需求，则必须先转换为尚需需求再比较。
