# MCQ 第 10 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C03-S01-Q010_题目.png|题目]]

10. 下列关于程序装入的动态重定位方式的描述中,错误的是 ( \\_ )  
(A) 系统将程序装入内存后,程序在内存中的位置可能发生移动  
(B) 系统为每个进程分配一个重定位寄存器  
(C) 被访问单元的物理地址 $=$ 逻辑地址 $+$ 重定位寄存器的值  
(D) 逻辑地址到物理地址的映射过程在进程执行时发生

## DeepSeek V4 Flash Max 解析
**答案**：
B。动态重定位需要的是 CPU/MMU 中一个（组）重定位寄存器，而不是为每个进程各分配一个物理寄存器；每个进程只需把自己的基址值保存在 PCB 中，进程切换时载入或恢复该寄存器。

**解题切入点**：
抓住“动态”的本质：地址映射推迟到进程执行时进行。可以把动态重定位看成维护一个全局 `base` 变量：

$$ \text{物理地址} = \text{逻辑地址} + \text{重定位寄存器值} $$

这就像竞赛中所有访问都写成 `base + offset`，移动对象时只更新 `base`，而不是把所有 `offset` 绝对地址都改一遍。重定位寄存器是容量为 1 的全局硬件资源，不是按进程数量分配的数组资源；进程切换相当于保存现场、恢复现场。

**推演**：
- A 正确：动态重定位支持进程在内存中移动，移动后只需修改重定位寄存器。
- B 错误：硬件重定位寄存器只有一个（或每个 CPU 一套），同一时刻只保存当前运行进程的基址；每个进程自己的基址值保存在 PCB 中，而不是真正“分配”一个寄存器。
- C 正确：访存时由硬件完成：
  $$ \text{物理地址} = \text{逻辑地址} + \text{重定位寄存器值} $$
- D 正确：动态重定位的地址映射发生在进程执行过程中的每次访存时刻，而不是在装入时刻。

**易错点**：
- 容易把“每个进程有一个基址值”误说成“每个进程分配一个寄存器”。前者是 PCB 中保存的状态，后者是物理硬件资源，二者不能混同。
- 容易混淆静态重定位与动态重定位：静态重定位在装入时一次性修改逻辑地址，之后程序不能移动；动态重定位在执行时计算地址，程序可以移动。
- 容易忽略上下文切换：若切换进程后不恢复重定位寄存器，当前进程会访问到上一进程的物理地址，就像 DFS 回溯时忘记恢复全局状态一样。

**命题规律**：
408 常以“错误的是”考查概念细节，尤其喜欢把“硬件寄存器”和“每进程数据结构”互换制造陷阱。动态重定位常与内存紧凑、交换、分区分配、页式/段式地址变换联合考查。解题时抓两条主线：地址映射发生在何时、基址信息由谁保存和恢复。
