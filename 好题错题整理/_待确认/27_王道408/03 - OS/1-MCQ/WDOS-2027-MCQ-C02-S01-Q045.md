# MCQ 第 45 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S01-Q045_题目.png|题目]]

45. 进程处于（ ）时，它处于非阻塞态。  
(A) 等待从键盘输入数据  
(B) 等待协作进程的一个信号  
(C) 等待操作系统分配 CPU 时间  
(D) 等待网络数据进入内存

## DeepSeek V4 Flash Max 解析
**答案**：  
C。对应进程的**就绪态**，也就是非阻塞态。

**解题切入点**：  
先明确三态模型：$S=\{\text{运行},\text{就绪},\text{阻塞}\}$ 。阻塞态的本质是：进程在等待某个“外部事件/除 CPU 外的条件”，即使把 CPU 分给它，它也无法继续执行；非阻塞态则是“只要拿到 CPU 就能跑”。四个选项都在描述“等待”，所以关键是判断题中等待的是“外部事件”还是“ CPU 资源”。

**推演**：  
把进程状态看成一个状态机，核心转移为  
$$
\text{运行} \xrightarrow[\text{时间片/抢占}]{\text{调度}} \text{就绪},\quad
\text{运行} \xrightarrow[\text{I/O、信号等事件}]{\text{等待}} \text{阻塞},\quad
\text{阻塞} \xrightarrow[\text{事件到达}]{\text{唤醒}} \text{就绪}.
$$

- A 等待键盘输入、D 等待网络数据进入内存：都是在等待外部 I/O 事件，属于阻塞态。类似算法竞赛中调用了阻塞式 `read`，数据不到，当前这路 DFS 就挂起。
- B 等待协作进程的信号：属于同步/通信事件未到达，类似 `sem_wait`、`thread.join()` 或 channel receive，当前流程无法继续，也是阻塞态。
- C 等待操作系统分配 CPU 时间：进程已在就绪队列中，除 CPU 外万事俱备，只差调度器选中它。这就像并行计算中任务已经在任务队列里排队，只等空闲线程来取，不是等待外部数据或事件。所以它是就绪态，非阻塞。

**易错点**：  
1. 看到“等待”就选阻塞。应区分等待对象：等待键盘/网络/协作信号是等外部事件；等待 CPU 是等调度资源。
2. 把“非阻塞态”等同于“运行态”。实际上运行态和就绪态都是非阻塞态；本题中的 C 是就绪态。
3. 对“协作进程信号”理解成普通异步信号。在进程同步语境下，收不到该信号进程无法继续，是阻塞等待；不是 CPU 分配问题。
4. 分不清“即使给 CPU 也不能运行”和“给 CPU 就能运行”。前者阻塞，后者就绪/非阻塞。

**命题规律**：  
408 喜欢用小场景考进程三态模型，本质是状态机判型。设问形式常为“进程处于哪种状态/非阻塞态/可能发生状态转移的事件”。备考时把各状态转换的触发事件整理成一张表：时间片到、事件等待、事件完成、调度选中。结合 I/O 和同步机制出题时，记住口诀：等 CPU 是就绪，等事件是阻塞。这与算法竞赛中“等资源/等状态”的调度问题类似，核心就是判断当前任务是否能继续推进。
