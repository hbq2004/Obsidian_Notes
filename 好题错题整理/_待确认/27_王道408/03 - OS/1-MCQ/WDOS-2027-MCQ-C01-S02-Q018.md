# MCQ 第 18 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C01-S02-Q018_题目.png|题目]]

与单道程序系统相比, 多道程序系统的优点是()。

$I$. CPU 利用率高
$II$. 系统开销小
$III$. 系统吞吐量大
$IV$. I/O 设备利用率高

(A) 仅 $I$、$III$
(B) 仅 $I$、$IV$
(C) 仅 $II$、$III$
(D) 仅 $I$、$III$、$IV$

## DeepSeek V4 Flash Max 解析
**答案**：
$$\boxed{D}$$
即“仅 $\mathrm{I}$、$\mathrm{III}$、$\mathrm{IV}$”。

**解题切入点**：
多道程序系统的核心是“并发切换”：当一道程序因 $\mathrm{I/O}$ 阻塞时，CPU 转而执行另一道程序，使 CPU 与 $\mathrm{I/O}$ 设备尽可能重叠工作。这就像算法竞赛里把 CPU 和 $\mathrm{I/O}$ 看作两个 worker：单道程序是串行执行，一个 worker 等数据时另一个只能闲着；多道程序是维护一个就绪队列，谁就绪谁上。所以它提高资源利用率和吞吐量，但必然引入调度、切换、内存保护等额外开销。看到“系统开销小”就该立刻排除。

**推演**：
可以把每个进程看成一个状态机，多道程序系统就是在多个状态机之间做调度；调度器是“谁就绪谁运行”，相当于在 DFS/BFS 搜索中不断选择下一个可扩展结点，而不是一条路径走到底。

- 单道：一个程序占用全部资源，若它等待 $\mathrm{I/O}$，CPU 空闲；若它计算，$\mathrm{I/O}$ 设备可能空闲。资源串行，利用率低。
- 多道：程序 A 计算时，程序 B 可以等 $\mathrm{I/O}$；程序 A 等 $\mathrm{I/O}$ 时，程序 B 可以上 CPU。CPU 和 $\mathrm{I/O}$ 尽量并行，因此资源利用率提高。

逐项判断：

- $\mathrm{I}$ 正确：CPU 空闲时间减少，CPU 利用率高。
- $\mathrm{II}$ 错误：多道需要进程调度、上下文切换、内存保护等，系统开销变大。
- $\mathrm{III}$ 正确：单位时间完成的作业数增加，系统吞吐量大。
- $\mathrm{IV}$ 正确：多道程序的 $\mathrm{I/O}$ 请求可重叠，$\mathrm{I/O}$ 设备空闲时间减少，利用率高。

故正确组合是 $\mathrm{I}$、$\mathrm{III}$、$\mathrm{IV}$，选 D。

**易错点**：
- 把“多道程序”理解成“多核并行”。多道程序在单 CPU 上也能实现，本质是并发/交替，不是同一时刻执行多条 CPU 指令；只是 CPU 和 $\mathrm{I/O}$ 设备可以并行。这就像状态搜索中多路分支不等于多线程并行。
- 误把“吞吐量大”和“响应快”混为一谈。多道程序可能让单个作业排队更久，平均周转时间不一定缩短；所以不能选“响应快/交互性好”等选项。
- 漏掉 $\mathrm{III}$。系统吞吐量大是 408 教材明确列出的多道程序优点，不能因为它是“结果”就不选。
- 被 $\mathrm{II}$ 迷惑：利用率高不等于系统开销小。多道程序的调度与切换是额外常数开销，正如并发程序比单线程多出同步成本。

**命题规律**：
本题属于操作系统概述中“操作系统发展历程/多道程序设计技术”的常考点。命题方式多为“下列哪些是多道程序的优点/特点”或组合选项。核心判断依据是：多道程序设计是为了让 CPU 和 $\mathrm{I/O}$ 设备尽量不空闲，因此提高资源利用率、提高系统吞吐量；代价是系统开销大，且不提供交互、平均周转时间可能变长。遇到类似题，优先把“系统开销小”“交互性好”“实时性强”作为错误项排除。
