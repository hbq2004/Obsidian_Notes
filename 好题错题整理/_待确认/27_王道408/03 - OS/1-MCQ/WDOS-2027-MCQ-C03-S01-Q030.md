# MCQ 第 30 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C03-S01-Q030_题目.png|题目]]

在页式存储管理中，页表的始地址存放在( )中.
(A) 物理内存
(B) 页表
(C) 快表($TLB$)
(D) 页表寄存器

## DeepSeek V4 Flash Max 解析
**答案**：
D. 页表寄存器（更准确地说是页表基址寄存器，PTBR）。

**解题切入点**：
题目问的是“页表这个数组的首地址在哪里”，不是在问“页表数组存在哪里”。用算法竞赛的话说，页表就像一张邻接表或一个 `vector<int>`：它的元素在物理内存里，但是要访问这个数组，必须先拿到它的首地址指针 `&pt[0]`。这个指针不能放在数组自己里面（否则先有鸡还是先有蛋），也不能放在快表里；快表只是 `(page, frame)` 映射的缓存。当前进程的页表首地址由 CPU 中的页表寄存器保存，所以选 D。

**推演**：
设逻辑地址为 $(p, d)$，页表基址为 $B$，页表项大小为 $s$，页大小为 $P$。地址转换过程是：
1. MMU 取得页表基址 $B$，$B$ 来自页表寄存器。
2. 页表项地址为 $B + p \times s$。
3. 从该地址读出页框号 $f$，若对应页不在内存则触发缺页异常。
4. 拼接物理地址：
$$ \text{物理地址} = f \times P + d $$

整个过程的关键是第一步：CPU 必须知道 $B$。这个 $B$ 就是“页表的始地址”，它存放在页表寄存器中。类比 ICPC 里 `head[u]` 存的是链首下标，但 DFS 要获取某个点的邻接表，必须先通过 `head` 数组；这里的页表寄存器就是“当前进程页表数组的 `head` 指针”。进程切换时，旧进程的页表基址保存在 PCB 中，新进程的页表基址被加载进页表寄存器。

**易错点**：
1. 误选“物理内存”：页表本身存放在物理内存中，但“页表的始地址”是一个指针值，存放在寄存器中；不要混淆“数组存哪”和“数组名/首地址存哪”。
2. 误选“快表”：TLB 保存的是最近用到的页表项，例如 $p \to f$ 映射，是访问页表的高速缓存，不是页表基地址。TLB 相当于 `unordered_map` 缓存，页表寄存器才是指向原始数组的基址指针。
3. 忽略“当前运行进程”这一语境：严格说，页表基址在进程控制块中也有备份，但 CPU 当前用于地址转换的是页表寄存器；如果题目选项有“PCB”，那是另一个考点。
4. 多级页表中，上级页表项确实保存下级页表的起始地址，但本题目没有特别说明，考的是最基础的页式管理模型，仍应选页表寄存器。

**命题规律**：
这是 408 操作系统“内存管理”部分的经典概念题，通常以 1~2 分选择题出现。命题人喜欢把“页表放哪”“页表首地址放哪”“TLB 放什么”“页表项放什么”混在一起考。解题时抓住“谁保存谁的地址”：
- 页表 → 物理内存；
- 页表始址 → 页表寄存器（PTBR）；
- 页表长度 → 页表长度寄存器；
- TLB → 缓存页表项；
- 多级页表 → 页目录基址由页表寄存器/页目录基址寄存器给出，目录项存下级页表基址。

这类题送分但易错，复习时把“地址转换流水线”画一遍即可。
