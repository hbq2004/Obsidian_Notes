# MCQ 第 35 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C05-S02-Q035_题目.png|题目]]

printf( ) 是 C 语言中进行格式化输出的库函数,该函数最终会转到内核态执行相应的系统调用服务例程，进程是通过执行 $\＿$ 从用户态进入内核态的.
(A) 陷入指令
(B) 关中断指令
(C) 无条件跳转指令
(D) 输出指令

## DeepSeek V4 Flash Max 解析
**答案**： $\boxed{\text{A 陷入指令}}$ 。  

**解题切入点**：  
题目考的是“用户态如何切换到内核态”，而不是 `printf` 的格式化功能。`printf` 只是 C 库函数，真正进入内核是因为它最终触发系统调用。可以把用户态和内核态看成状态机中的两个状态：普通函数调用只是状态内部的转移，而用户态到内核态必须经过唯一的“转移边”——陷入指令。竞赛里写 DFS 时，从当前状态到下一状态要显式写转移；这里库函数再复杂，也不能自己完成特权级切换，必须借助陷入指令。  

**推演**：  
- `printf` 先在用户态完成格式化，然后需要向标准输出写入数据，这属于内核管理的设备资源。  
- 于是库函数调用系统调用 $write$ 请求内核代做输出。  
- 用户态进程不能直接执行特权指令，也不能直接访问设备，因此必须执行一条陷入指令（也称访管指令，x86 上对应 `int 0x80` / `syscall`）来触发 CPU 模式切换。  
- 陷入指令执行后，CPU 保存用户态现场，切换到内核态，跳转到系统调用服务例程。可表示为：
$$\text{printf} \xrightarrow{\text{用户态库函数调用}} \text{write} \xrightarrow{\text{陷入指令}} \text{内核系统调用服务例程}$$
- 这就像竞赛中不能直接修改评测机后台，只能通过评测接口提交请求；陷入指令就是这个“提交请求”的入口。  

**易错点**：  
- 不能选 C：无条件跳转指令只能改变 PC，不能改变 CPU 特权级，相当于 DFS 里的普通递归转移，不会跨状态。  
- 不能选 D：看到输出就选输出指令是常见误判；输出指令是 I/O 操作，不是用户态到内核态的切换机制。  
- 不能选 B：关中断指令是内核态使用的特权指令，常用于临界区保护，不是用户进程进入内核的入口。  
- 注意区分库函数与系统调用：`printf` 是库函数，不是系统调用；库函数内部通过陷入指令触发系统调用，不能把二者混为一谈。  

**命题规律**：  
408 中本题属于“中断、异常、系统调用”的基础概念题，常与用户态/内核态切换、特权指令、访管指令结合考查。干扰项通常设置为普通跳转指令、I/O 指令和特权指令。核心结论是：系统调用是进程主动请求内核服务，对应的模式切换指令是陷入指令；外部中断和异常虽然也能进入内核态，但不是本题系统调用的主动路径。用竞赛思维总结，CPU 模式是两个状态，普通指令是状态内部的自环，陷入指令才是连接用户态与内核态的那条“关键有向边”。
