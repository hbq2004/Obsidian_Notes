# FRQ 第 5 题

![[_Attachments/题目识别/WDOS-2027-FRQ/WDOS-2027-FRQ-C02-S03-Q005_题目.png|题目]]

某寺庙有小和尚、老和尚若干,有一水缸,由小和尚提水入缸供老和尚饮用. 水缸可容 10 桶水,水取自同一井中. 水井径窄,每次只能容一个桶取水. 水桶总数为 3 个. 每次入缸取水仅为 1 桶水,且不可同时进行. 试给出有关从缸取水、入水的算法描述.

## DeepSeek V4 Flash Max 解析
**答案**：

设信号量：$S_{\text{empty}}$ 表示缸中还能容纳的空桶位，$S_{\text{full}}$ 表示缸中已有水的桶数，$S_{\text{pail}}$ 表示空闲水桶数，$S_{\text{well}}$ 表示井口互斥，$S_{\text{vat}}$ 表示水缸操作互斥。

$$
S_{\text{empty}}=10,\quad S_{\text{full}}=0,\quad S_{\text{pail}}=3,\quad S_{\text{well}}=1,\quad S_{\text{vat}}=1
$$

按空缸初态；若初始缸中有 $k$ 桶水，则令 $S_{\text{full}}=k,\ S_{\text{empty}}=10-k$。

小和尚进程（生产者）：

```c
while (true) {
    P(S_empty);      // 申请一个空位，缸满则等待
    P(S_pail);       // 申请一个水桶
    P(S_well);       // 独占井口
    从井中打水;
    V(S_well);       // 释放井口

    P(S_vat);        // 独占水缸
    倒水入缸;
    V(S_vat);        // 释放水缸

    V(S_pail);       // 归还水桶
    V(S_full);       // 缸中水 +1
}
```

老和尚进程（消费者）：

```c
while (true) {
    P(S_full);       // 等缸中有水，没水则等待
    P(S_pail);       // 申请一个水桶
    P(S_vat);        // 独占水缸
    从缸中取水;
    V(S_vat);        // 释放水缸

    V(S_pail);       // 归还水桶
    V(S_empty);      // 空位 +1
}
```

**解题切入点**：

把问题抽象成「有界缓冲区 + 多资源互斥」的生产者-消费者模型：

- 水缸容量 $10$ 对应有界缓冲区；
- 井口、水缸分别是两个不同的临界资源；
- 水桶总数 $3$ 是共享资源池；
- 小和尚是生产者，老和尚是消费者。

用算法竞赛的话说，每个和尚就是一条状态机：  
小和尚状态链为：等空位 → 拿桶 → 等井口 → 打水 → 等缸口 → 倒水 → 还桶；  
老和尚状态链为：等水 → 拿桶 → 等缸口 → 取水 → 还桶。  
信号量就是状态转移条件。判断死锁就像判断资源等待图是否有环，必须保证申请资源的顺序不会成环。

**推演**：

小和尚必须先 $P(S_{\text{empty}})$，再 $P(S_{\text{pail}})$。  
如果先拿桶再等空位，极端情况下 3 个桶全被小和尚拿着等空位，老和尚没有桶就无法取水，也就无法释放空位，形成死锁。

同理，老和尚必须先 $P(S_{\text{full}})$，再 $P(S_{\text{pail}})$。  
如果先拿桶再等水，3 个老和尚可能各拿一桶等水，小和尚没有桶无法打水入缸，也形成死锁。

申请到水桶后：

- 小和尚打水时需要独占井口，所以 $P(S_{\text{well}})$；
- 打完水立刻 $V(S_{\text{well}})$，不能占着井口去等水缸；
- 倒水入缸时需要独占水缸，所以 $P(S_{\text{vat}})$；
- 老和尚从缸中取水也需要独占水缸，所以同样 $P(S_{\text{vat}})$。

这样保证了“入缸”和“取水”不会同时进行。  
每次 $P(S_{\text{pail}})$ 都有对应的 $V(S_{\text{pail}})$，所以水桶数不会泄漏；每次 $P(S_{\text{empty}})$ 最终由老和尚 $V(S_{\text{empty}})$ 归还，每次 $P(S_{\text{full}})$ 最终由小和尚 $V(S_{\text{full}})$ 产生。

由于所有进程都按  
$$
S_{\text{empty}}/S_{\text{full}} \rightarrow S_{\text{pail}} \rightarrow S_{\text{well}}/S_{\text{vat}}
$$
的顺序申请资源，且没有人持有井口等水缸、没有人持有水缸等水桶，因此资源等待图无环，不会死锁。

**易错点**：

1. 把 $P(S_{\text{pail}})$ 放在 $P(S_{\text{empty}})$ 或 $P(S_{\text{full}})$ 前面，会导致“拿着桶等容量/等水”的死锁。
2. 井口和水缸不能共用同一把锁。虽然合并可能仍然正确，但会不必要地让打水、倒水、取水全部串行，并发度太低。
3. 小和尚打完水后，必须先 $V(S_{\text{well}})$ 再 $P(S_{\text{vat}})$。如果占着井口等水缸，可能出现持锁等待的坏局面。
4. 老和尚取水后不要忘记 $V(S_{\text{pail}})$ 和 $V(S_{\text{empty}})$；小和尚倒水后不要忘记 $V(S_{\text{pail}})$ 和 $V(S_{\text{full}})$。漏掉一个 $V$ 就像算法竞赛里忘释放标记一样，会让资源永久丢失。
5. $S_{\text{empty}}$ 和 $S_{\text{full}}$ 的 $P/V$ 位置不能写反：小和尚生产水，所以 $V(S_{\text{full}})$；老和尚消费水，所以 $V(S_{\text{empty}})$。

**命题规律**：

这是 408 进程同步中非常典型的 PV 操作题，本质是“生产者-消费者 + 多类资源互斥”。命题人喜欢给一个生活场景，要求识别临界资源、资源数量、容量限制，然后写出 $P/V$ 算法。

和算法竞赛对比：不需要优化复杂度，但需要像判断图是否有环一样分析死锁。重点永远是：

- 信号量初值是否正确；
- $P/V$ 是否成对出现；
- 多资源申请顺序是否可能形成等待环；
- 临界区是否被正确互斥。

变式通常是把水缸容量、水桶数改成参数，或者增加多个水缸/水井，核心仍是这几类信号量的组合。
