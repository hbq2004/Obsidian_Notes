# FRQ 第 7 题

![[_Attachments/题目识别/WDOS-2027-FRQ/WDOS-2027-FRQ-C02-S03-Q007_题目.png|题目]]

有桥如下图所示。车流方向如箭头所示。回答如下问题：

## DeepSeek V4 Flash Max 解析
**答案**：
按经典两小问处理。记两个行车方向为 $A$、$B$。

1. 每次仅一辆车过桥时，桥是一把普通互斥锁：
$$
\begin{aligned}
&\text{semaphore } bridge=1;\\
&\text{任意方向的车：}\quad P(bridge);\ \text{过桥};\ V(bridge).
\end{aligned}
$$

2. 同向可多辆、异向互斥时：
$$
\begin{aligned}
&\text{semaphore } mutexA=1,\ mutexB=1,\ bridge=1;\\
&\text{int } countA=0,\ countB=0;\\[2mm]
&\text{方向 } A \text{ 的车：}\\
&\quad P(mutexA);\\
&\quad \textbf{if } countA == 0 \textbf{ then } P(bridge);\\
&\quad countA++;\\
&\quad V(mutexA);\\
&\quad 过桥;\\
&\quad P(mutexA);\\
&\quad countA--;\\
&\quad \textbf{if } countA == 0 \textbf{ then } V(bridge);\\
&\quad V(mutexA);\\[2mm]
&\text{方向 } B \text{ 的车：把 } A,B \text{ 对调即可。}
\end{aligned}
$$

注意：$P(bridge)$ 必须在该方向的 $mutex$ 保护内执行；若阻塞，则本方向后续车会在该 $mutex$ 上排队，不能抢跑。

**解题切入点**：
桥是临界资源。第一问是纯互斥；第二问同向可以并发，因此不是普通互斥锁，而是“方向级”的读写锁。把 $A$、$B$ 看成两类进程，需要一个计数器记录本方向是否已经有人占用桥。第一辆车是代表，负责 $P(bridge)$；最后一辆车是代表，负责 $V(bridge)$。这类似算法竞赛中批量数据的懒标记：第一个操作打标记，最后一个操作清标记。

**推演**：
第一问中，$bridge$ 是二值信号量，初值为 $1$。每辆车都执行一次 $P$ 和一次 $V$，因此任意时刻桥上至多一辆车。

第二问中，$bridge$ 是方向间的互斥信号量。$countA$ 表示 $A$ 方向当前在桥上的车辆数；若 $countA == 0$，说明 $A$ 方向还没有车在桥上，必须先 $P(bridge)$ 占用桥；若 $countA > 0$，说明 $A$ 方向已经拥有桥权，后续 $A$ 方向车直接上桥即可，从而实现同向多辆并发。

出口对称处理：$countA--$ 减到 $0$ 时，说明 $A$ 方向的车已全部离桥，此时 $V(bridge)$ 释放桥权。$B$ 方向完全同理。

用 $mutexA$、$mutexB$ 分别保护两个计数器，是为了防止“等待桥的一方锁住另一个方向的出口”。若共用一个全局 $mutex$，当 $A$ 的第一辆车在 $P(bridge)$ 上阻塞且持有该全局 $mutex$ 时，$B$ 的最后一辆车无法进入出口修改 $countB$ 并 $V(bridge)$，会死锁。

**易错点**：
- 常见错误：把 $V(mutexA)$ 提到 $P(bridge)$ 之前。这样后续同向车在第一辆车尚未获得桥时，就会看到 $countA > 0$ 而直接上桥，破坏互斥。
- 常见错误：用一个全局 $mutex$ 保护两个方向的计数器。这会导致等待桥的一方阻塞时，另一方无法释放桥，形成死锁。
- 常见错误：每辆车过桥后都执行 $V(bridge)$。同向多车时桥会被提前释放，异向车辆可能进入，违反“异向互斥”。
- 常见错误：忘记“最后一辆车才释放桥”。若第一辆车释放，第二辆车还在桥上时异向车已可进入，不安全。
- 该算法不保证方向公平；若题目额外要求避免饥饿，需要再加门闩/轮转信号量。

**命题规律**：
408 喜欢把读者—写者模型包装成桥、路口、仓库等实际场景。本题本质是：同向 = 读者，异向 = 写者。核心考点是信号量初值、$P/V$ 位置、以及“第一辆车申请、最后一辆车释放”的计数模式。复习时要把这种 `first/last` 批量互斥模式练熟，并理解为什么计数器要分方向保护。
