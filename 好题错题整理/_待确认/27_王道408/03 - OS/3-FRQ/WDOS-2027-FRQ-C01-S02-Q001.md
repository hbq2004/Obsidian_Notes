# FRQ 第 1 题

![[_Attachments/题目识别/WDOS-2027-FRQ/WDOS-2027-FRQ-C01-S02-Q001_题目.png|题目]]

有两个程序,程序 $A$ 依次使用 $CPU$ 计 $10s$、设备甲计 $5s$、$CPU$ 计 $5s$、设备乙计 $10s$、$CPU$ 计 $10s$; 程序 $B$ 依次使用设备甲计 $10s$、$CPU$ 计 $10s$、设备乙计 $5s$、$CPU$ 计 $5s$、设备乙计 $10s$. 在单道程序环境下先执行程序 $A$ 再执行程序 $B$,$CPU$ 的利用率是多少?在多道程序环境下,$CPU$ 利用率是多少?

## DeepSeek V4 Flash Max 解析
**答案**：单道：$\frac{1}{2}$（$50\%$）；多道：$\frac{8}{9}$（约$88.89\%$）。

**解题切入点**：单道程序环境无资源重叠，直接累加执行时间即可。多道程序环境允许 CPU 与 I/O 设备并行工作，需分析资源冲突，通过事件驱动模拟（类似算法竞赛中“状态机”或“贪心调度”）构造时间线，在满足资源互斥和顺序约束的前提下最小化总执行时间，从而计算 CPU 利用率。

**推演**：程序 A 的 CPU 时间 $10+5+10=25$ s，I/O 时间 $5+10=15$ s，总时间 $40$ s；程序 B 的 CPU 时间 $10+5=15$ s，I/O 时间 $10+5+10=25$ s，总时间 $40$ s。

- 单道：先执行 A 再执行 B，总时间 $40+40=80$ s，CPU 总时间 $25+15=40$ s，利用率 $\displaystyle \frac{40}{80}=\frac{1}{2}$。
- 多道：从 $t=0$ 开始并发执行 A、B，模拟如下：
  - $t=0$：A 占 CPU（$10$ s），B 占设备甲（$10$ s）。
  - $t=10$：A 转设备甲（$5$ s），B 转 CPU（$10$ s）。
  - $t=15$：A 请求 CPU，但 B 仍用 CPU 至 $t=20$，A 等待。
  - $t=20$：B 释放 CPU，A 获 CPU（$5$ s），B 开始设备乙（$5$ s）。
  - $t=25$：A 转设备乙（$10$ s），B 转 CPU（$5$ s）。
  - $t=30$：B 请求设备乙，但 A 占用设备乙至 $t=35$，B 等待。
  - $t=35$：A 释放设备乙并请求 CPU，B 获设备乙（$10$ s），A 获 CPU（$10$ s）。
  - $t=45$：A、B 同时结束。
  总时间 $45$ s，CPU 使用时间段为 $0-10$、$10-20$、$20-25$、$25-30$、$35-45$，共 $40$ s，利用率 $\displaystyle \frac{40}{45}=\frac{8}{9}$。

**易错点**：① 单道环境下误认为程序内部 CPU 与 I/O 可重叠（实际不可）；② 多道环境下忽略 I/O 设备互斥，导致冲突时间计算错误；③ 模拟时关键时间点（如 $t=15$、$t=30$ 的等待）遗漏或错位；④ 认为多道总时间等于两程序总时间之和，未考虑重叠；⑤ 误将设备甲、乙视为同一设备，或忽略不同设备可并行。

**命题规律**：本类题是操作系统“并发与资源管理”的经典题型，常以两个程序的多段资源使用序列给出，要求计算单道与多道下的 CPU 利用率。解题核心是绘制甘特图（或事件模拟），理清资源占用与等待关系。在 408 历年真题中多次出现，考生需熟练掌握时间重叠分析与资源互斥约束，类似算法竞赛中的“调度”问题，需细心模拟。
