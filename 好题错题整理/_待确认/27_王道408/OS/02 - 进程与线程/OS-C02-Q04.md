# 综合题 第 4 题

![[_Attachments/题目识别/27_王道408-题目/OS-C02-Q04_题目.png|题目]]

04. 考虑某个系统在下表时刻的状态。

| 进程名 | Allocation (A B C D) | Max (A B C D) | Available (A B C D) |
| :--- | :--- | :--- | :--- |
| $P_0$ | 0 0 1 2 | 0 0 1 2 | 1 5 2 0 |
| $P_1$ | 1 0 0 0 | 1 7 5 0 | 1 5 2 0 |
| $P_2$ | 1 3 5 4 | 2 3 5 6 | 1 5 2 0 |
| $P_3$ | 0 0 1 4 | 0 6 5 6 | 1 5 2 0 |

使用银行家算法回答下面的问题：
1） Need 矩阵是怎样的？
2）系统是否处于安全状态？如安全，请给出一个安全序列。
3）若从进程 $P_1$ 发来一个请求 $(0, 4, 2, 0)$，这个请求能否立刻被满足？如安全，请给出一个安全序列。

## 答案

![[_Attachments/题目识别/27_王道408-答案/OS-C02-Q04_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：系统当前处于安全状态，安全序列为 $P_0 \rightarrow P_2 \rightarrow P_1 \rightarrow P_3$（或 $P_0 \rightarrow P_2 \rightarrow P_3 \rightarrow P_1$）；若 $P_1$ 发出请求 $(0,4,2,0)$，满足条件后可立即分配，系统仍安全，安全序列同上。

**解题切入点**：银行家算法是死锁避免的经典方法，核心在于判断系统是否处于安全状态。拿到题目首先计算每个进程的 Need 矩阵（最大需求减已分配），然后利用安全性算法（类似资源分配图上的拓扑排序）检查是否存在一个安全序列。本题属于典型的多资源银行家算法题，只需按部就班计算、比较、模拟即可。

**推演**：

1. **计算 Need 矩阵**  
   $Need = Max - Allocation$，各进程 $Need$ 向量为：
   - $P_0$：$(0,0,1,2) - (0,0,1,2) = (0,0,0,0)$  
   - $P_1$：$(1,7,5,0) - (1,0,0,0) = (0,7,5,0)$  
   - $P_2$：$(2,3,5,6) - (1,3,5,4) = (1,0,0,2)$  
   - $P_3$：$(0,6,5,6) - (0,0,1,4) = (0,6,4,2)$  

   故 Need 矩阵（行进程，列资源）为：
   $$
   \begin{array}{c|cccc}
   \text{进程} & A & B & C & D \\ \hline
   P_0 & 0 & 0 & 0 & 0 \\
   P_1 & 0 & 7 & 5 & 0 \\
   P_2 & 1 & 0 & 0 & 2 \\
   P_3 & 0 & 6 & 4 & 2 \\
   \end{array}
   $$

2. **判断当前状态是否安全**  
   初始 Available = $(1,5,2,0)$。  
   - 检查 $P_0$：$Need_0 = (0,0,0,0) \le (1,5,2,0)$，满足。  
     分配后 $P_0$ 释放资源，Available 更新为 $(1,5,2,0)+(0,0,1,2)=(1,5,3,2)$。  
   - 检查 $P_2$：$Need_2 = (1,0,0,2) \le (1,5,3,2)$，满足。  
     分配后 $P_2$ 释放资源，Available 更新为 $(1,5,3,2)+(1,3,5,4)=(2,8,8,6)$。  
   - 检查 $P_1$：$Need_1 = (0,7,5,0) \le (2,8,8,6)$，满足。  
     分配后 $P_1$ 释放资源，Available 更新为 $(2,8,8,6)+(1,0,0,0)=(3,8,8,6)$。  
   - 检查 $P_3$：$Need_3 = (0,6,4,2) \le (3,8,8,6)$，满足。  
     分配后 $P_3$ 释放资源，Available 更新为 $(3,8,8,6)+(0,0,1,4)=(3,8,9,10)$。  
   所有进程均能完成，因此系统处于安全状态，安全序列为 $P_0 \rightarrow P_2 \rightarrow P_1 \rightarrow P_3$（$P_1$ 与 $P_3$ 顺序可互换）。

3. **处理 $P_1$ 的请求 $(0,4,2,0)$**  
   - 合法性检查：  
     $Request_1 = (0,4,2,0) \le Need_1 = (0,7,5,0)$，且 $Request_1 \le Available = (1,5,2,0)$，满足条件，进行试分配。  
   - 试分配后新状态：  
     $Available' = (1,5,2,0) - (0,4,2,0) = (1,1,0,0)$；  
     $Allocation_1' = (1,0,0,0) + (0,4,2,0) = (1,4,2,0)$；  
     $Need_1' = (0,7,5,0) - (0,4,2,0) = (0,3,3,0)$；  
     其他进程不变。  
   - 对新状态进行安全性检查：  
     - 初始 Available = $(1,1,0,0)$。  
     - $P_0$：$Need_0 = (0,0,0,0) \le (1,1,0,0)$，满足，释放后 Available 为 $(1,1,0,0)+(0,0,1,2)=(1,1,1,2)$。  
     - $P_2$：$Need_2 = (1,0,0,2) \le (1,1,1,2)$，满足，释放后 Available 为 $(1,1,1,2)+(1,3,5,4)=(2,4,6,6)$。  
     - $P_1$：$Need_1' = (0,3,3,0) \le (2,4,6,6)$，满足，释放后 Available 为 $(2,4,6,6)+(1,4,2,0)=(3,8,8,6)$。  
     - $P_3$：$Need_3 = (0,6,4,2) \le (3,8,8,6)$，满足，释放后 Available 为 $(3,8,8,6)+(0,0,1,4)=(3,8,9,10)$。  
     所有进程均能完成，系统仍安全，安全序列为 $P_0 \rightarrow P_2 \rightarrow P_1 \rightarrow P_3$（或 $P_0 \rightarrow P_2 \rightarrow P_3 \rightarrow P_1$）。  
   - 因此，该请求可以立刻满足。

**易错点**：  
- 计算 Need 时易混淆 $Max - Allocation$ 与 $Allocation - Max$，注意维度对应。  
- 安全性检查时，必须每次比较全部未完成进程的 Need 与当前 Available，且释放资源后应立即更新 Available。  
- 请求分配时，需先检查 $Request \le Need$ 和 $Request \le Available$，再试分配并做安全性检查，不能跳过。  
- 安全序列可能不唯一，但必须保证序列中每个进程的 Need 都能在对应时刻被满足；若只有一种顺序，则需严格写出。

**命题规律**：  
银行家算法是操作系统考研常考重点，常结合资源分配表考查 Need 计算、安全性判断及请求处理。变式包括：增加/删除进程、修改资源数量、多个请求并发、单独考察“不安全状态”判定等。复习时应熟练掌握银行家算法的数据结构与流程，多练习多资源类型的向量比较，并注意区分“安全状态”与“死锁”的关系。
