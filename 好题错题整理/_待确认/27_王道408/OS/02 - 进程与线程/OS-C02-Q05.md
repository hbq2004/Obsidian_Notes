# 综合题 第 5 题

![[_Attachments/题目识别/27_王道408-题目/OS-C02-Q05_题目.png|题目]]

05. 假设具有 5 个进程的进程集合 P = {P₀, P₁, P₂, P₃, P₄}，系统中有三类资源 A, B, C，假设在某时刻有如下状态：

| 进程名 | Allocation | Max | Available |
| :---: | :---: | :---: | :---: |
| | A  B  C | A  B  C | A  B  C |
| P₀ | 0  0  3 | 0  0  4 | |
| P₁ | 1  0  0 | 1  7  5 | |
| P₂ | 1  3  5 | 2  3  5 | 1  4  0 |
| P₃ | 0  0  2 | 0  6  4 | |
| P₄ | 0  0  1 | 0  6  5 | |

当前系统是否处于安全状态？若系统中的可利用资源 Available 为(0, 6, 2)，系统是否安全？若系统处在安全状态，请给出安全序列；若系统处在非安全状态，简要说明原因.

01. C
引起死锁的 4 个必要条件是：互斥、占有并等待、非剥夺和循环等待. 本题中，出现了循环等待的现象，意味着可能导致死锁. 进程释放资源不会导致死锁，进程自己进入死循环只能产生"饥饿"，不涉及其他进程. 共享型设备允许多个进程申请使用，因此不会造成死锁. 再次提醒，死锁一定要有两个或两个以上的进程才会导致，而饥饿可能由一个进程导致.

02. C
信号量机制能确保临界资源的互斥访问，不能完全避免死锁，选项 A 错误. 同时检查两支筷子是否可用的方法可以预防死锁，但是会导致资源浪费，因为可能有一些空闲的筷子无法使用，但拿到筷子的哲学家用完餐后，释放筷子，其他哲学家就可以正常用餐，因此不会导致饥饿现象，选项 B 错误. 若限制允许拿起筷子的哲学家数量，则不被允许的哲学家左边的哲学家一定可以拿到两边的筷子，从而破坏"循环等待"条件，选项 C 正确. 对哲学家顺序编号，奇数号哲学家先拿左筷子，然后拿右筷子，而偶数号哲学家刚好相反，则相邻的哲学家总有一个可以拿起两边的筷子，但这破坏的是"循环等待"条件，而不是"互斥条件"，选项 D 错误.

03. C
进程的执行优先级并不能破坏死锁的四个必要条件. 即使有高优先级和低优先级的进程，若它们都请求或占有了不可抢占的资源，且形成了环路等待，则死锁仍可能发生. 选项 A 可以破坏请求并保持条件，选项 B 可以破坏互斥条件，选项 D 可以破坏循环等待条件.

04. B
发生死锁的 4 个必要条件：互斥、占有并请求、非剥夺和循环等待. 一次分配所有资源的方法是当进程需要资源时，一次性提出所有的请求，若请求的所有资源均满足，则分配，只要有一项不满足，就不分配任何资源，该进程阻塞，直到所有的资源空闲后，满足进程的所有需求时再分配. 这种分配方式不会部分地占有资源，因此打破了死锁的 4 个必要条件之一，实现了对死锁的预防.

## 答案

## DeepSeek V4 Flash Max 解析

**答案**：题表所示 $Available=(1,4,0)$ 时系统处于安全状态，一个安全序列为 $P_2,P_0,P_1,P_3,P_4$；若 $Available=(0,6,2)$，则系统处于非安全状态。

**解题切入点**：
银行家算法本质上是一个“资源约束下的消去过程”，类似拓扑排序或贪心：先计算每个进程还需要的资源 $Need=Max-Allocation$，再维护当前可分配资源 $Work$，每次找一个 $Need\le Work$ 的未完成进程，让它运行完并归还其 $Allocation$。若所有进程都能被消去，则存在安全序列；若某一步找不到可消去进程，则系统处于非安全状态。

**推演**：

先计算 Need 矩阵：

$$
\begin{array}{c|ccc}
\text{进程} & A & B & C\\ \hline
P_0 & 0 & 0 & 1\\
P_1 & 0 & 7 & 5\\
P_2 & 1 & 0 & 0\\
P_3 & 0 & 6 & 2\\
P_4 & 0 & 6 & 4
\end{array}
$$

其中 $Need=Max-Allocation$，以下向量比较均为各分量同时满足。

### 1. 当 $Available=(1,4,0)$ 时

令 $Work=(1,4,0)$，按银行家算法检查：

- $P_2:(1,0,0)\le(1,4,0)$，可完成；$Work=(1,4,0)+(1,3,5)=(2,7,5)$；
- $P_0:(0,0,1)\le(2,7,5)$，可完成；$Work=(2,7,5)+(0,0,3)=(2,7,8)$；
- $P_1:(0,7,5)\le(2,7,8)$，可完成；$Work=(2,7,8)+(1,0,0)=(3,7,8)$；
- $P_3:(0,6,2)\le(3,7,8)$，可完成；$Work=(3,7,8)+(0,0,2)=(3,7,10)$；
- $P_4:(0,6,4)\le(3,7,10)$，可完成；$Work=(3,7,10)+(0,0,1)=(3,7,11)$。

所有进程均能完成，因此系统处于安全状态。一个安全序列为：

$$
P_2,P_0,P_1,P_3,P_4
$$

安全序列不唯一。

### 2. 当 $Available=(0,6,2)$ 时

令 $Work=(0,6,2)$。此时可先让 $P_0$ 运行：

- $P_0:(0,0,1)\le(0,6,2)$，$Work=(0,6,5)$；
- $P_3:(0,6,2)\le(0,6,5)$，$Work=(0,6,7)$；
- $P_4:(0,6,4)\le(0,6,7)$，$Work=(0,6,8)$。

但此时剩余进程：

- $P_1$ 需要 $(0,7,5)$，其中 $B$ 类资源 $7>6$，不满足；
- $P_2$ 需要 $(1,0,0)$，其中 $A$ 类资源 $1>0$，不满足。

因此找不到安全序列，系统处于非安全状态。

原因简要说明：$P_2$ 还缺 1 个 $A$ 类资源，而该资源被 $P_1$ 占有；$P_1$ 还缺 7 个 $B$ 类资源，而当前可用的 $B$ 类资源不足，$P_2$ 又因缺 $A$ 类资源无法完成并释放其占有的资源，形成循环等待式的资源僵局，银行家算法无法保证所有进程最终完成。

**易错点**：

1. **把 Max 当成 Need**：必须用 $Max-Allocation$。例如 $P_2$ 的 Need 是 $(1,0,0)$，不是 $(2,3,5)$。
2. **归还资源时只加 Need**：进程运行完应归还其全部 $Allocation$。例如 $P_2$ 完成后 $Work$ 要加 $(1,3,5)$，而不是加 $(1,0,0)$。
3. **认为非安全状态等于死锁**：非安全状态只是“不能保证所有进程最终完成”，不一定已经死锁；但继续分配可能引发死锁。
4. **忽略 Available 是全局资源向量**：Available 不是某个进程单独可用的资源，比较时三维向量必须同时满足。
5. **安全序列不唯一**：只要按推进顺序能使所有进程完成，都是合法安全序列。

**命题规律**：
银行家算法属于“死锁避免”的核心内容，是 408 高频考点。常见命题形式有：给出 Allocation 和 Max，判断系统是否安全并给出安全序列；给出某进程的请求向量，判断能否立即分配；或由资源总量和 Allocation 反推 Available。复习时应熟练掌握安全算法流程：先求 Need，再维护 Work，循环查找可完成进程；同时注意与死锁的四个必要条件、死锁预防/避免/检测/解除等概念区分。

> 05.【解答】
> 1）根据 Need 矩阵可知，初始 Work 等于 Available 为$(1, 4, 0)$，可以满足进程 $P_2$ 的需求；进程 $P_2$ 结束后释放资源，Work 为$(2, 7, 5)$，可以满足 $P_0, P_1, P_3$ 和 $P_4$ 中任意一个进程的需求，所以系统不会出现死锁，当前处于安全状态。
