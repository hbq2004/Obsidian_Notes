# 综合题 第 12 题

![[_Attachments/题目识别/27_王道408-题目/OS-C03-Q12_题目.png|题目]]

12. 有一个矩阵 int A[100,100]以行优先方式进行存储。计算机采用虚拟存储系统，物理内存共有三页，其中一页用来存放程序，其余两页用于存放数据。假设程序已在内存中占一页，其余两页空闲。若每页可存放 200 个整数，则程序 1、程序 2 执行的过程中各会发生多少次缺页？每页只能存放 100 个整数时，会发生多少次缺页？以上结果说明了什么问题?

程序 1:
```c
for (i=0; i<100; i++)
    for (j=0; j<100; j++)
        A[i,j]=0;
```

程序 2:
```c
for (j=0; j<100; j++)
    for (i=0; i<100; i++)
        A[i,j]=0;
```

## 答案

![[_Attachments/题目识别/27_王道408-答案/OS-C03-Q12_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：当每页可存放$200$个整数时，程序$1$发生$50$次缺页，程序$2$发生$5000$次缺页；当每页只能存放$100$个整数时，程序$1$发生$100$次缺页，程序$2$发生$10000$次缺页。结果表明，程序$1$（行优先访问）具有良好的空间局部性，缺页次数远少于程序$2$（列优先访问）；增大页面容量可减少总缺页次数，但无法改变两者因访问模式差异导致的巨大差距。

**解题切入点**：首先明确矩阵的行优先存储方式，将矩阵元素按页划分（每页可容纳的整数个数决定页大小和总页数）。然后根据程序访问顺序（行优先或列优先）生成页面访问序列，结合物理内存仅有两页数据页且初始空闲的条件，模拟置换过程（常用LRU或FIFO）计算缺页次数。核心考点是程序局部性对缺页次数的影响，类似于缓存中的命中率分析。

**推演**：

1. 基本参数
  矩阵总元素数 $N = 100 \times 100 = 10000$。
  物理内存可用于数据页的页框数 $M = 2$，初始为空。
  置换算法采用LRU（或FIFO，本题中两者结果相同）。

2. 页大小 $P = 200$ 整数
  总页数 $S = \frac{N}{P} = \frac{10000}{200} = 50$。
  每页可存放连续两行（因为每行$100$整数，$200$整数对应两行），页号$0$对应行$0$~$1$，页$1$对应行$2$~$3$，…，页$49$对应行$98$~$99$。

  - 程序1（行优先访问）
    访问顺序：按行$i$从$0$到$99$，每行内按列$j$从$0$到$99$。由于存储顺序与访问顺序一致，页面访问序列为连续的页$0$（$200$次）、页$1$（$200$次）、…、页$49$（$200$次）。每个页面在被首次访问时缺页，之后该页内所有元素连续访问，不会再次产生缺页；且后续页面不再重复访问前面页面，因此缺页次数等于总页数$S=50$次。

  - 程序2（列优先访问）
    访问顺序：按列$j$从$0$到$99$，每列内按行$i$从$0$到$99$。对于固定列，页面访问序列为：页$0$（两次，对应行$0,1$）、页$1$（两次，对应行$2,3$）、…、页$49$（两次，对应行$98,99$）。模拟LRU（或FIFO）过程：
    - 第一列：初始内存空。访问页$0$第一次，缺页，调入页$0$；第二次访问页$0$，不缺页。访问页$1$第一次，缺页，调入页$1$；第二次访问页$1$，不缺页。此时内存已满（页$0$、页$1$）。访问页$2$第一次，缺页，LRU置换最久未使用的页$0$，调入页$2$；第二次访问页$2$，不缺页。依此类推，每页第一次访问均缺页，第二次访问均不缺页，直到页$49$：第一次访问缺页（置换页$47$），第二次访问不缺页。第一列共缺页$50$次（每页一次）。第一列结束时内存中为页$48$和页$49$（最近访问顺序页$49$、$48$）。
    - 第二列：开始内存为页$48$、$49$。访问页$0$第一次，缺页（置换页$48$）；第二次不缺页。访问页$1$第一次，缺页（置换页$49$）；第二次不缺页。之后每页第一次访问均缺页，第二次均不缺页，又缺页$50$次。第二列结束时内存恢复为页$48$、$49$。
    - 后续每一列重复上述过程，每列均缺页$50$次。总列数$100$，故总缺页次数$100 \times 50 = 5000$次。

3. 页大小 $P = 100$ 整数
  总页数 $S = \frac{10000}{100} = 100$。
  每页对应一行，页号$i$对应行$i$。

  - 程序1（行优先访问）
    页面访问序列为连续的页$0$、页$1$、…、页$99$，每个页面仅被访问一次。缺页次数等于总页数$S=100$次。

  - 程序2（列优先访问）
    对于固定列，页面访问序列为页$0$、页$1$、…、页$99$（每个页一次）。模拟LRU：
    - 第一列：初始内存空。访问页$0$，缺页，调入；页$1$，缺页，调入；内存满。访问页$2$，缺页，置换页$0$；页$3$，缺页，置换页$1$；…；页$99$，缺页，置换页$97$。第一列共缺页$100$次（每页一次）。第一列结束时内存为页$98$、$99$。
    - 第二列：开始内存页$98$、$99$。访问页$0$，缺页，置换页$98$；页$1$，缺页，置换页$99$；页$2$，缺页，置换页$0$；…；页$99$，缺页，置换页$97$。第二列共缺页$100$次。
    - 后续每一列均缺页$100$次。总列数$100$，故总缺页次数$100 \times 100 = 10000$次。

4. 结果说明
  程序1的访问顺序与存储顺序一致，页面内连续访问，空间局部性好，缺页次数仅等于页数；程序2的访问顺序跨行跨列，每次访问几乎都落在不同的页面，空间局部性差，缺页次数为页数与列数的乘积。增大页面容量可减少页数，从而降低两种程序的缺页次数，但程序2的缺页次数始终是程序1的$100$倍（列数），说明访问模式对缺页次数的影响起决定性作用。

**易错点**：
- 忽略程序2中同一页面在一列内的连续两次访问，错误地认为每列缺页次数为$100$（页大小为$200$时），导致多算缺页。
- 认为程序1也会因内存只有两页而在顺序访问中产生额外缺页（如认为缺页次数为$100$或$50$加上置换次数），实际上顺序访问时每个页面仅被访问一次，缺页次数恰好等于页数。
- 混淆“页大小”与“行大小”，误以为每页只能存放$100$整数时每页仍可放两行，导致页数计算错误。
- 未明确置换算法，但若采用FIFO，在页大小为$100$时，第一列结束后内存及后续行为与LRU相同，故结果一致；若采用OPT，则程序2可能会有更少的缺页次数（但题目未指定，通常默认LRU或FIFO）。

**命题规律**：本题是操作系统虚拟存储管理中关于缺页次数计算的经典例题，重点考查局部性原理对程序性能的影响。常见变式有：改变矩阵大小（如$1024\times 1024$）、页大小、内存页框数、置换算法（如LRU/FIFO/OPT），或要求计算缺页率并分析优化策略。复习时需熟练掌握页面访问序列的生成方法，能够手动模拟常见置换算法的缺页过程，并理解存储顺序与访问顺序对局部性的影响。建议通过对比不同访问模式（行优先、列优先）的缺页次数，加深对空间局部性的理解，同时注意页面大小对系统性能的影响。在408考试中，此类题目常以综合题形式出现，需要结合计算与原理分析，答题时需分点清晰，计算准确。

> 12. 【解答】
> 程序1按行优先的顺序访问数组元素，与数组在内存中存放的顺序一致，每个内存页面可存放200个数组元素。这样，程序1每访问两行数组元素就产生一次缺页中断，所以程序1的执行过程会发生50次缺页。
>
> 程序2按列优先的顺序访问数组元素，每个内存页面存放两行数组元素，因此程序2每访问两个数组元素就产生一次缺页中断，整个执行过程会发生5000次缺页。
>
> 若每页只能存放100个整数，则每页仅能存放一行数组元素，同理可以计算出：程序1的执行过程产生100次缺页；程序2的执行过程产生10000次缺页。
>
> 以上说明缺页的次数与内存中数据存放的方式及程序执行的顺序有很大关系；同时说明，当缺页中断次数不多时，减小页面大小影响并不大，但缺页中断次数很多时，减小页面大小会带来很严重的影响。
