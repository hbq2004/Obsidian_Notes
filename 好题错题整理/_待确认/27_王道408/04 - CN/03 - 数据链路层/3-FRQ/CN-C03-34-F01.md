# 综合题 第 1 题

![[_Attachments/题目识别/27_王道408-题目/CN-C03-34-F01_题目.png|题目]]

1.在选择重传协议中，设序号用3比特编号，发送窗口 $W_T=6$，接收窗口 $W_R=3$。试找出一种情况，使得在此情况下协议不能正常工作.

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C03-34-F01_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：该配置不能正常工作。一种典型失效情况是：发送方发送 0～5 号帧，接收方按序全部收到后，接收窗口已滑动为 $\{6,7,0\}$；若 0 号帧的 ACK 丢失，发送方超时重传 0 号帧，此时重传的旧 0 号帧落在接收窗口内，被误认为新一轮的 0 号帧，造成重复交付。根本原因是 $W_T+W_R=6+3=9>2^3=8$，不满足选择重传协议的窗口约束。

**解题切入点**：拿到题目先看“序号位数 + 发送窗口 + 接收窗口”，立刻应定位到选择重传协议（SR）的窗口约束：$W_T+W_R\le 2^n$。可以把模 $2^n$ 的序号空间理解成大小为 $8$ 的循环数组/循环缓冲区；$W_T+W_R$ 就是“尚未彻底区分新旧”的序号个数。超过容量 8，就像哈希表装载因子超过 1，必然出现“新旧碰撞”。构造 ACK 丢失、超时重传的用例，就是为了让新旧帧在同一个序号上碰撞。

**推演**：
1. 序号用 3 比特编号，所以序号空间大小为  
$$N=2^3=8,$$  
序号按模 8 使用：$0,1,2,3,4,5,6,7,0,1,\dots$

2. 选择重传协议正常工作的必要条件是  
$$W_T+W_R\le 2^n.$$  
本例  
$$W_T+W_R=6+3=9>8,$$  
因此一定存在导致协议失败的情况。

3. 构造坏例：
   - 初始发送窗口可发送序号 $0,1,2,3,4,5$；初始接收窗口为 $\{0,1,2\}$。
   - 发送方发送 0～5 号帧，接收方按序收到全部帧：
     - 收到 0、1、2 号帧后，接收窗口滑动为 $\{3,4,5\}$；
     - 收到 3、4、5 号帧后，接收窗口滑动为 $\{6,7,0\}$。
   - 此时 0～5 号帧已经全部交给上层。
   - 假设 0 号帧的 ACK 丢失（ACK1～ACK5 即使到达也不行，因为 SR 的确认不累积，且 0 号未确认时发送窗口基址不能越过 0）。
   - 发送方因收不到 ACK0，定时器超时，重传 0 号帧。
   - 接收方当前窗口为 $\{6,7,0\}$，重传的旧 0 号帧落在窗口内，被当作新的一轮 0 号帧缓存并最终再次上交，造成重复交付，协议无法正常工作。

**易错点**：
- 误以为只要 $W_T\le 2^n$ 或 $W_R\le 2^n$ 就安全；实际上 SR 要求的是 $W_T+W_R\le 2^n$。
- 误用 $W_T=W_R\le 2^{n-1}$ 这一特例；本题 $W_T\ne W_R$，应使用一般约束。
- 把 SR 和 GBN 混淆：GBN 接收窗口为 1，确认具有累积性；SR 接收窗口可以大于 1，确认是逐帧独立的。
- 构造反例时，要让接收窗口已经回绕并包含旧序号；如果接收方还没收到足够多的帧就重传，旧帧可能不在接收窗口内，不能说明协议失效。

**命题规律**：考点是数据链路层选择重传协议中的“序号空间与窗口大小关系”。常见变式有：给定位数、$W_T$、$W_R$，判断协议能否正常工作；或反过来求最大允许窗口；或与 GBN、停-等协议比较。复习时应熟记核心不等式 $W_T+W_R\le 2^n$，并理解其意义：序号空间必须能区分“发送方尚未确认的帧”和“接收方当前可接收的帧”，否则重传帧会被误认为新帧。
