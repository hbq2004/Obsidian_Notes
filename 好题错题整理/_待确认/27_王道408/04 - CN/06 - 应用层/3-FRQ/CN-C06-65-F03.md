## DeepSeek V4 Flash Max 解析

**答案**  
(1) Web 服务器的 IP 地址是 $64.170.98.32$，该主机的默认网关的 MAC 地址是 $00-21-27-21-51-ee$。  
(2) 使用 ARP 协议；封装该协议请求报文的以太网帧的目的 MAC 地址是广播地址 $FF-FF-FF-FF-FF-FF$。  
(3) 需要 $6$ 个 RTT。  
(4) 需要修改 IP 分组头中的源 IP 地址、TTL 和首部检验和。

**解题切入点**  
首先从数据帧中提取 IP 分组头，确定源 IP 和目的 IP。主机 IP 是私有地址，目的 IP 是公网地址，因此默认网关必须进行 NAT。类似地，在算法竞赛中，构造辅助函数相当于封装协议，分层处理；分治策略相当于协议栈的分层协作。本题定位考点：以太网帧结构、IP 分组头、ARP 协议、HTTP 持续连接、路由器转发与 NAT。

**推演**  
(1) 以太网帧前 6 B 为目的 MAC，接着 6 B 为源 MAC，再 2 B 为类型。由十六进制转储：  
- 目的 MAC：$00\ 21\ 27\ 21\ 51\ ee$ → $00-21-27-21-51-ee$。  
- 源 MAC：$00\ 15\ c5\ c1\ 5e\ 28$ → $00-15-C5-C1-5E-28$（与主机 MAC 一致）。  
- 类型：$08\ 00$，表示 IPv4。  
IP 分组头从第 15 字节开始（帧头 14 B）。IP 头前 20 B：  
- 版本/首部长度：$45$ → 版本 4，首部长度 $5\times4=20$ B。  
- 总长度：$01\ ef$ → $0x01EF=495$ B。  
- 标识：$11\ 3b$。  
- 标志/片偏移：$40\ 00$ → DF=1，MF=0，片偏移 0。  
- TTL：$80$ → $128$。  
- 协议：$06$ → TCP。  
- 首部检验和：$ba\ 9d$。  
- 源 IP：$0a\ 02\ 80\ 64$ → $10.2.128.100$。  
- 目的 IP：$40\ aa\ 62\ 20$ → $64.170.98.32$。  
因此 Web 服务器 IP 为 $64.170.98.32$。主机默认网关为路由器 R 左侧接口 $10.2.128.1$，主机发送帧时目的 MAC 即网关 MAC，故默认网关 MAC 为 $00-21-27-21-51-ee$。

(2) 主机需将 IP 分组发送给网关，但不知道网关 MAC 地址。使用 ARP 协议获取网关 MAC。ARP 请求以太网帧的目的 MAC 地址为广播地址 $FF-FF-FF-FF-FF-FF$。

(3) HTTP/1.1 持续非流水线：客户端先请求 rfc.html，经 1 个 RTT 收到 HTML；解析后发现有 5 幅 JPEG 图像，然后依次请求每个图像，每请求一个需要 1 个 RTT，共 5 个 RTT。总计 $1+5=6$ 个 RTT。注意：TCP 连接已在图 2 的请求前建立，故不计入。

(4) 该 IP 分组经过路由器 R 转发时，需进行 NAT（因为源 IP 为私有地址），将源 IP 地址由 $10.2.128.100$ 改为路由器右侧接口的公网 IP $101.12.123.15$；同时 TTL 减 1（由 $128$ 变为 $127$）；IP 头检验和需重新计算（因源 IP 和 TTL 改变）。分组长度 $495$ B $< \text{MTU}=1500$ B，故不分片，无需修改标识、标志、片偏移。

**易错点**  
- 误将源 MAC 当作网关 MAC，或混淆 IP 地址与 MAC 地址。  
- 忽略 ARP 请求是广播，认为目的 MAC 是网关 MAC。  
- 在 HTTP 持续非流水线中，忘记解析 HTML 所需的 RTT，或误认为每个图像可并行请求（流水线方式）。  
- 忽略 NAT，认为只需修改 TTL 和检验和；或误认为需修改目的 IP。

**命题规律**  
- 考点：以太网帧结构、IP 分组头解析、ARP 协议、HTTP 持续连接、路由器转发与 NAT。  
- 常见变式：改为 UDP 协议、不同 HTTP 版本（流水线/非流水线）、引入分片计算、DNS 解析等。  
- 复习建议：熟练掌握帧结构、IP 头字段、ARP 原理、HTTP 请求方式、路由器转发过程（包括 NAT）。多做真题，注意细节。
