# 综合题 第 2 题

![[_Attachments/题目识别/27_王道408-题目/CN-C06-65-F02_题目.png|题目]]

2.在如下条件下,计算使用非持续方式和持续方式请求一个 $Web$ 页面所需的时间:
(1)测试的 $RTT$ 的平均值为 $150ms$,一个 $gif$ 对象的平均发送时延为 $35ms$.
(2)一个 $Web$ 页面中有 $10$ 幅 $gif$ 图片, $Web$ 页面的基本 $HTML$ 文件、$HTTP$ 请求报文、$TCP$ 握手报文大小忽略不计.
(3)$TCP$ 三次握手的第三步中捎带一个 $HTTP$ 请求.
(4)使用非流水线方式.

## 答案

## DeepSeek V4 Flash Max 解析

**答案**：本题为计算题，无选项。按默认“对象串行请求、无并行 TCP 连接”计算：

- 非持续方式：$3650\ \mathrm{ms}=3.65\ \mathrm{s}$
- 持续方式（非流水线）：$2150\ \mathrm{ms}=2.15\ \mathrm{s}$

结论要点：新建立一个 TCP 连接取一个对象需要 $2RTT+T_{\text{对象}}$；持续非流水线只有初始 HTML 需要 $2RTT$，之后每个 gif 在同一条连接上只需 $RTT+T_{\text{gif}}$。

---

**解题切入点**：

先抓“页面请求顺序”：先取基本 HTML，再取其中引用的 10 个 gif。题目核心是区分“非持续”和“持续”两种连接管理方式。

可以类比算法竞赛中的“每次查询都重新初始化数据结构”和“复用同一个数据结构”：

- 非持续方式：每个对象都新建一次 TCP 连接，相当于每次请求都重新建图、重新初始化；
- 持续方式：所有对象复用一个 TCP 连接，相当于只初始化一次数据结构，之后反复查询；
- 非流水线：相当于 for 循环中每次都必须等当前请求返回后才能发下一个请求，不能批量预取。

---

**推演**：

设  
$$R=150\ \mathrm{ms},\qquad T_g=35\ \mathrm{ms}$$

### 1. 新建立 TCP 连接取一个对象所需时间

TCP 三次握手第三次步捎带 HTTP 请求，所以：

- TCP 握手需要 $1$ 个 RTT；
- 第三次握手捎带 HTTP 请求后，服务器回送对象，客户端收到该对象还需要约 $1$ 个 RTT 加上对象发送时延。

因此，在一个新 TCP 连接上取得一个对象的时间为：

$$
2RTT+T_{\text{对象}}
$$

### 2. 非持续方式

基本 HTML 文件大小忽略不计，但仍需要请求它一次，所以基本 HTML 时间为：

$$
2RTT+0=2R=300\ \mathrm{ms}
$$

10 个 gif 每个都需要建立新的 TCP 连接，每个时间为：

$$
2RTT+T_g=300+35=335\ \mathrm{ms}
$$

因此非持续方式总时间为：

$$
T_{\text{非持续}}
=2RTT+10(2RTT+T_g)
$$

代入数值：

$$
T_{\text{非持续}}
=300+10(300+35)
=300+3350
=3650\ \mathrm{ms}
=3.65\ \mathrm{s}
$$

### 3. 持续方式（非流水线）

持续方式只建立一次 TCP 连接，初始请求基本 HTML：

$$
2RTT=300\ \mathrm{ms}
$$

之后 10 个 gif 在同一条 TCP 连接上依次请求，非流水线表示每次必须等前一个 gif 收到后再发下一个请求。每个 gif 的时间为：

$$
RTT+T_g=150+35=185\ \mathrm{ms}
$$

因此持续方式总时间为：

$$
T_{\text{持续}}
=2RTT+10(RTT+T_g)
$$

代入数值：

$$
T_{\text{持续}}
=300+10(150+35)
=300+1850
=2150\ \mathrm{ms}
=2.15\ \mathrm{s}
$$

对比可知，持续方式比非持续方式节省了 10 次 TCP 握手的 RTT，共节省：

$$
10RTT=1500\ \mathrm{ms}
$$

---

**易错点**：

- 容易漏掉基本 HTML 请求。题目说 HTML 文件大小忽略不计，只表示它的发送时延为 $0$，但请求 HTML 仍然需要经历 RTT。
- 持续方式下不要把每个 gif 都算成 $2RTT+T_g$。同一条连接上后续对象不再需要 TCP 握手，每个 gif 只需 $RTT+T_g$。
- 不要把“报文大小忽略”误解为“RTT 也不需要算”。忽略的是发送时延，RTT 是传播/往返时延，必须计入。
- 题目没有说明并行连接数，应默认串行请求；如果允许多条并行 TCP 连接，结果会改变。

---

**命题规律**：

这是应用层 HTTP 与传输层 TCP 结合的经典 RTT 计算题，408 中常考的点包括：

- 非持续 HTTP 与持续 HTTP 的时间差；
- TCP 三次握手与 HTTP 请求的时序关系；
- 非流水线与流水线的区别。

常见变式：

- 增加 DNS 解析时延；
- 增加 TLS/HTTPS 握手时延；
- 改为持续流水线方式；
- 允许有限条并行 TCP 连接。

复习建议：画时间轴，标出 SYN、SYN+ACK、ACK+HTTP 请求、服务器发送对象这几步，熟练记住三类公式：

- 非持续：每个对象 $2RTT+T$
- 持续非流水线：首个对象 $2RTT+T$，后续对象 $RTT+T$
- 持续流水线：首个对象 $2RTT+T$，后续所有对象基本只需 $1RTT+\sum T$
