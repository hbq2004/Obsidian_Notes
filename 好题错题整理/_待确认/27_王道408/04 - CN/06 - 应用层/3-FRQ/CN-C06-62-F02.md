## DeepSeek V4 Flash Max 解析

**题目 2（域名概念与解析）**

**答案**：引入域名是为了解决 IP 地址难记、不便于用户使用和层次化管理的问题；域名转换即域名解析，是将域名映射为 IP 地址，典型过程是“本地缓存 → 本地域名服务器 → 根/顶级/权威域名服务器”逐级查询；域名服务器中的高速缓存用于存放解析结果，减少重复查询的延迟与服务器负载，并通过 TTL（生存时间）保证缓存一致性。

**解题切入点**：拿到题目先抓两条主线：一是“为什么需要域名”，二是“域名如何变成 IP 地址”。从算法竞赛角度，可以把域名系统看成一棵巨大的“字典树”：每次解析域名就像从根到叶子走一遍；而高速缓存就像记忆化搜索中的缓存表，先查缓存再查树，命中就避免重复递归。

**推演**：

1. 引入域名的原因：
   - IP 地址是 32 位二进制或点分十进制，难记且没有语义；域名如 `www.example.com` 采用层次化命名，便于人记忆与组织管理。
   - 需在域名与 IP 地址之间建立映射关系，这项任务由 DNS（域名系统）完成。

2. 域名转换过程（以递归+迭代混合查询为例）：
   - 用户主机向本地域名服务器发送解析 `www.example.com` 的请求，这是递归查询：本地服务器要替用户“问到底”。
   - 若本地服务器缓存未命中，则 向根域名服务器发起迭代查询；根服务器返回 `com` 顶级域名服务器的 IP 地址。
   - 本地服务器再向 `com` 顶级域名服务器查询，得到 `example.com` 权威域名服务器的 IP 地址。
   - 本地服务器继续向 `example.com` 权威服务器查询，得到 `www.example.com` 的 IP 地址。
   - 最后本地服务器把结果返回给用户主机，并将该“域名→IP”映射存入缓存。

3. 高速缓存的作用：
   - 命中后直接应答，避免重复走完整的查询链。
   - 减少访问根、顶级、权威服务器的流量，降低网络延迟和服务器压力。
   - 缓存条目有 TTL，例如 $TTL=86400$ 秒；到期后自动删除，保证域名 IP 变更后能获得新结果。

**易错点**：
- 混淆递归查询与迭代查询：递归是“我替你问到底”，迭代是“我给你下一个地址，你自己问”。
- 忽略缓存必须有过期机制：缓存不是永久的，不能只写“缓存结果”而不提 TTL。
- 查询顺序写错：应先是本地域名服务器，再根域名服务器，再顶级域，再权威域，不能颠倒。
- 把“域名解析”误写成“域名服务器之间的互相转换”，注意实际是查表得 IP。

**命题规律**：考点集中在 DNS 的层次结构、递归/迭代查询方式、缓存作用；常见变式有“给出查询过程判断查询类型”“分析缓存命中/未命中的访问路径”。复习时应结合 TCP/IP 体系结构，画 DNS 查询流程图，并掌握缓存与 TTL 机制。

**题目 6.3-1（文件传输协议 FTP）**

**答案**：FTP 通过两条 TCP 连接工作：控制连接（端口 21）用于传输命令与应答，数据连接（主动模式端口 20，被动模式为协商出的随机端口）用于传输文件内容。服务器端主进程在 21 端口监听客户端连接，每接受一个连接就创建一个从属进程；从属进程负责该客户的具体 FTP 会话，包括解析命令、建立数据连接、执行文件上传/下载，并在数据传送完毕后关闭数据连接。

**解题切入点**：拿到题目先问三个问题：“谁在监听？”（主进程）、“谁在干活？”（从属进程）、“几条连接分别干什么？”（控制+数据）。算法竞赛中写多线程服务器时，主线程负责 `accept`，工作线程处理请求，这里的主进程和从属进程正是这种 master-worker 模型；命令与数据分离也类似将“控制信号”与“数据流”分开传递，避免相互阻塞。

**推演**：

1. FTP 采用客户/服务器模式，基于 TCP 提供可靠传输。

2. 主要工作过程：
   - 服务器主进程启动时在 21 端口被动打开，等待客户端连接。
   - 客户端主动连接服务器 21 端口，建立控制连接。
   - 主进程接受连接后，创建从属进程专门处理该客户端；主进程继续回到监听状态，等待其他客户端。
   - 从属进程通过控制连接接收命令（如 `USER`、`PASS`、`RETR`、`STOR`）并发送应答。
   - 需要传输文件时，从属进程按主动/被动模式建立数据连接：
     - 主动模式：服务器从 20 端口主动连接客户端的临时端口。
     - 被动模式：服务器告知客户端一个临时端口，客户端主动连接该端口。
   - 数据连接上只传输文件数据或目录列表，一次传输结束后关闭数据连接；控制连接在整个会话期间始终保留。
   - 客户端发送 `QUIT` 命令后，控制连接关闭，从属进程终止。

3. 主进程与从属进程的作用：
   - 主进程：只负责监听 21 端口、接受新连接、创建从属进程，不参与具体文件传输。
   - 从属进程：每个客户对应一个，负责该客户的完整交互，包括登录验证、命令处理、数据连接的建立与关闭、文件发送/接收，是实际执行任务的工作进程。

**易错点**：
- 端口混淆：控制连接固定为 21，主动模式数据连接为 20，被动模式数据连接为随机端口。
- 误以为 FTP 只用一条连接完成所有工作：实际是“控制连接 + 数据连接”双连接。
- 把主进程当成“服务员”，其实主进程只负责“接客”，具体服务由从属进程完成。
- 忽略数据连接在每次传输后关闭，而控制连接持久存在。
- 主动/被动模式方向记反：主动是服务器连客户端，被动是客户端连服务器。

**命题规律**：考点聚焦 FTP 的端口号、双连接模型、主动/被动模式以及主从进程职责；常见变式包括给传输场景判断端口或模式，或与 HTTP 的文件传输方式对比。复习时应记住 FTP 的“一控一数”模型，并动手画出主动、被动模式下的连接建立时序图，以应对选择题和简答题。
