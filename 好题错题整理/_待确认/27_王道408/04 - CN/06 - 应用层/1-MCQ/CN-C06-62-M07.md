# 选择题 第 7 题

![[_Attachments/题目识别/27_王道408-题目/CN-C06-62-M07_题目.png|题目]]

7.当本地域名服务器向根域名服务器查询一个域名时,根域名服务器返回一个负责该域名的顶级域名服务器的 IP 地址,让本地域名服务器再向该域名服务器查询,这种查询方式称为( )

(A) 递归查询  
(B) 迭代查询  
(C) 重定向查询  
(D) 广播查询

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C06-62-M07_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：B。  
根域名服务器没有继续替本地域名服务器递归地查下去，而是返回下一级（顶级域名）服务器 IP，由本地域名服务器继续查询，因此是迭代查询。

**解题切入点**：先抓住“返回的是什么”和“谁继续查”。  
如果被查询服务器返回的是“最终结果”，则是递归查询；如果返回的是“下一个该去问谁的地址”，让查询方自己继续查，则是迭代查询。  
这类似算法里的“递归”与“迭代”：递归是函数调用栈帮你完成后续步骤后把结果返回；迭代是你自己维护一个“当前节点/当前服务器”指针，在循环里不断向后跳转。

**推演**：

以解析某个域名为例：

1. 主机向本地域名服务器发出查询请求，通常本地域名服务器负责给出最终结果。
2. 本地域名服务器向根域名服务器查询该域名。
3. 根域名服务器不知道被查询域名的最终 IP，但它知道负责该域名的顶级域名服务器的 IP。
4. 因此根域名服务器返回的不是最终解析结果，而是“顶级域名服务器的 IP 地址”。
5. 本地域名服务器收到这个 IP 后，再主动向该顶级域名服务器继续查询。

在这个过程中，查询方始终是本地域名服务器，而被查询的根域名服务器并没有代替本地域名服务器继续向其他服务器查询，也没有把最终结果回传，它只是告诉本地域名服务器“下一步该找谁”。

因此，这种查询方式称为迭代查询。

若采用递归查询，则根域名服务器收到查询后，会代替本地域名服务器继续向顶级域名服务器、权威域名服务器逐级查询，最后把最终解析结果返回给本地域名服务器。

**易错点**：

- 容易把“本地域名服务器向根域名服务器查询”一律误判为递归查询。  
  判断依据不是“谁发给谁”，而是“被查询服务器返回的是最终答案，还是下一级服务器的地址”。
- 容易误选“重定向查询”。  
  重定向多出现在 HTTP 等场景，DNS 标准查询方式中没有以“重定向查询”为名的基本查询类型。
- 容易误选“广播查询”。  
  DNS 通常使用单播 UDP 查询，不是广播查询；广播查询也不符合题目描述的“返回一个 IP 让本地服务器再查”的过程。
- 注意“主机到本地域名服务器”和“本地域名服务器到其他域名服务器”的查询方式可能不同：前者常是递归查询，后者常是迭代查询。题目描述的是后者。

**命题规律**：  
本考点属于 DNS 域名解析过程，常以选择题形式考查递归查询与迭代查询的区别。常见变式包括：给出某次查询过程的描述，判断是递归还是迭代；或问“主机向本地域名服务器查询”通常使用哪种方式。  
复习时建议对比记忆：  
- 递归查询：被查询者替查询者继续查，最终只返回最终结果；  
- 迭代查询：被查询者返回下一级服务器地址，查询者自己继续查。  
同时掌握 DNS 层次结构：根域名服务器、顶级域名服务器、权限域名服务器、本地域名服务器，以及它们之间的协作关系。
