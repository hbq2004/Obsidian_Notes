# 选择题 第 7 题

![[_Attachments/题目识别/27_王道408-题目/CN-C06-65-M07_题目.png|题目]]

7.仅需Web服务器对HTTP报文进行响应,但不需要返回请求对象时,HTTP请求报文应该使用的方法是（ ）

(A) GET
(B) PUT
(C) POST
(D) HEAD

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C06-65-M07_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：D（HEAD）。理由：HEAD 方法与 GET 类似，但服务器在响应中只返回状态行和首部字段，不返回请求对象的实体主体，因此满足“不需要返回请求对象”的响应需求。

**解题切入点**：拿到题目先抓“不需要返回请求对象”这个关键词，定位到 HTTP 请求方法中“只获取元信息、不获取实体”的方法。类似在算法竞赛中，有时需要只查询数据结构的大小/哈希值而不导出全部元素，就构造一个返回摘要的接口，而不是返回完整数据。这里 HEAD 就是 HTTP 的“摘要查询”接口。

**推演**：HTTP/1.1 定义了几种常用请求方法：

- GET：请求指定的资源，服务器返回响应报文，其主体包含所请求对象的实体内容。
- HEAD：与 GET 类似，但服务器在响应时只返回响应首部（状态行和首部字段），不返回实体主体。因此 HEAD 可用于在下载前获取资源元信息（如 Content-Length、Content-Type、Last-Modified 等），节省带宽。
- POST：向指定资源提交数据，由服务器处理，一般用于表单提交或上传数据；服务器响应可以包含处理结果，但不是“返回请求对象”。
- PUT：将请求体中的数据上传到指定 URI，用于更新或创建资源；服务器通常返回状态码，不返回该对象本身。

题干强调“仅需 Web 服务器对 HTTP 报文进行响应，但不需要返回请求对象”。若使用 GET，则响应报文中会携带请求对象的实体，浪费带宽且不符合“不需要”的要求；使用 POST 或 PUT 则语义不对，它们主要用于提交/上传数据。只有 HEAD 方法恰好满足“响应报文只含首部，不含实体主体”的条件，因此选 D。

**易错点**：

1. 混淆 GET 与 HEAD：GET 会返回完整资源，HEAD 不返回实体主体；HEAD 常用于测试链接有效性、获取资源大小等。
2. 误选 POST：POST 虽也可有响应，但它的主要语义是提交数据，且响应体通常不是“请求对象”本身；题目中“不需要返回请求对象”是 HEAD 的关键特征。
3. 忽略“报文”与“实体”的区别：HTTP 响应报文由状态行 + 首部 + 空行 + 实体主体构成，HEAD 响应中实体主体为空，但仍含状态行和首部字段。

**命题规律**：HTTP 请求方法是计算机网络应用层的常考基础点，通常以选择题形式出现，考查各方法的语义区别。常见变式包括：

- 给出某个应用场景（如“只检查资源是否存在”“只获取文件修改时间”）选择合适方法。
- 结合状态码（如 200 OK、404 Not Found）问 HEAD 响应是否包含实体主体。
- 与 HTTPS、HTTP/2 方法安全性和幂等性结合考查（如 GET/HEAD 是安全方法，GET/HEAD/PUT/DELETE 等幂等性）。

复习建议：熟记 HTTP/1.1 常用方法（GET、HEAD、POST、PUT、DELETE、OPTIONS、TRACE、CONNECT）的语义、是否安全、是否幂等，并能在具体场景中快速匹配。尤其在“返回资源”和“只返回元信息”之间要能立刻联想到 HEAD。
