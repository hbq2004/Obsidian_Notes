# 选择题 第 3 题

![[_Attachments/题目识别/27_王道408-题目/CN-C06-63-M03_题目.png|题目]]

3.控制信息是带外传送的协议是(  ).

(A) HTTP  
(B) SMTP  
(C) FTP  
(D) POP

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C06-63-M03_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：C（FTP）。理由：FTP 使用独立的控制连接（端口 21）传送命令和响应，与传送文件数据的数据连接（端口 20 或动态端口）分离，属于“带外传送”；HTTP、SMTP、POP 的控制信息与数据都在同一条连接中传送，属于“带内传送”。

**解题切入点**：先抓住题干关键词“控制信息”和“带外传送”。这相当于判断：协议的控制指令是不是和数据内容在同一条传输通道中传送。算法竞赛中也可以类比：如果我们需要单独维护一个“操作序列”或“元数据数组”，而不是把指令混在业务数据里同步处理，就类似“带外”；如果把指令直接写在数据流头部或和数据一起处理，就是“带内”。FTP 的做法是“另开一条专门传指令的通道”，数据通道只传文件内容，这就是典型的带外控制。

**推演**：

逐项分析各协议的控制信息所在位置：

| 协议 | 控制信息的传送方式 | 是否与数据同连接 |
|---|---|---|
| HTTP | 请求行、状态行、头部字段与请求/响应体在同一条 TCP 连接上传送 | 是，带内 |
| SMTP | HELO、MAIL FROM、RCPT TO、DATA 等命令与邮件内容在同一条 TCP 连接上传送 | 是，带内 |
| FTP | USER、PASS、LIST、RETR、STOR 等命令在控制连接上传送，文件数据在另一条数据连接上传送 | 否，带外 |
| POP | USER、PASS、RETR、DELE 等命令与邮件内容在同一条 TCP 连接上传送 | 是，带内 |

FTP 使用两条 TCP 连接：

$$
\text{控制连接：端口 }21，\text{传送命令和响应}
$$

$$
\text{数据连接：端口 }20\text{（或动态端口），传送文件数据}
$$

控制连接在整个会话期间保持，数据连接在每次传输数据时建立，传输结束后可关闭。因此 FTP 的控制信息相对于数据信息是“带外”的。

而 HTTP 虽然把控制信息放在头部，但它和正文共用同一个 TCP 字节流；SMTP 虽然先用命令“协商”邮件，但命令和邮件正文也在同一条连接中；POP 同理。所以它们都是“带内传送”。

**易错点**：

1. **误以为“头部在数据之前”就是带外**  
   HTTP 的请求头、状态行虽然可以看作控制信息，但它们和 body 都在同一个 TCP 连接中传送，属于带内，不是带外。

2. **误以为 SMTP 有命令就算带外**  
   SMTP 的 HELP、MAIL、RCPT、DATA 等命令和邮件正文确实分阶段，但仍在同一条 TCP 连接内，不能叫带外。

3. **混淆 TCP 紧急数据和协议层带外控制**  
   TCP 有“紧急数据/带外数据”的概念，但本题问的是应用层协议中控制信息的传送方式，不应把两者混为一谈。

4. **记错 FTP 端口**  
   控制连接固定使用端口 21，数据连接常见为端口 20，不要与 HTTP（80）、SMTP（25）、POP（110）混淆。

**命题规律**：这是 408 计算机网络中应用层协议的常考点，重点考查各类协议使用的传输层端口、连接数量以及“控制信息”与“数据信息”的传送方式。常见变式有：“FTP 使用几条 TCP 连接”、“控制信息带外传送的是哪个协议”、“下列哪个协议使用 20/21 端口”、“SMTP 是否使用持久连接”等。复习时应把常见应用层协议整理成表，对比 HTTP、SMTP、FTP、POP、IMAP、DNS 等协议的传输层协议、默认端口、控制/数据通道、连接方式，并理解“带内/带外”的本质差异。
