# 选择题 第 1 题

![[_Attachments/题目识别/27_王道408-题目/CN-C06-63-M01_题目.png|题目]]

1. 文件传输协议(FTP)的一个主要特征是（  ）
(A) 允许客户指明文件的类型但不允许指明文件的格式
(B) 不允许客户指明文件的类型但允许指明文件的格式
(C) 允许客户指明文件的类型与格式
(D) 不允许客户指明文件的类型与格式

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C06-63-M01_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：C。FTP 允许客户在建立数据连接时指明传输文件的类型（如 ASCII、二进制）与格式（如文件结构、传输方式等），因此选 C。

**解题切入点**：本题直接考查 FTP 协议的基本功能，属于应用层协议细节题。可以类比为“使用一个文件传输 API 时，调用者能否自定义请求参数”：类型≈数据编码方式（文本/二进制），格式≈传输结构（流/记录/页）。拿到这类题，先圈定协议名（FTP），回忆其控制连接与数据连接中可协商的参数即可，不需深究实现。

**推演**：
FTP（File Transfer Protocol）使用客户/服务器模式，建立双重连接：控制连接（端口 21）与数据连接（端口 20）。在控制连接上，客户端通过 FTP 命令与服务器协商传输参数，其中主要包括：

- **文件类型（Type）**：  
  - ASCII（默认）：用于文本文件，传输时进行换行符转换；  
  - EBCDIC：用于 IBM 大型机文本；  
  - Image（二进制）：用于非文本文件，按原始字节流传输。  
  客户端可用 `TYPE A`、`TYPE I` 等命令指明。

- **文件格式（Format）**：主要指文件结构（Structure）与传输方式（Transmission Mode）。  
  - 文件结构：File（无结构）、Record（记录结构）、Page（页结构）；  
  - 传输方式：Stream（流方式）、Block（块方式）、Compressed（压缩方式）。  
  客户端可用 `STRU`、`MODE` 等命令指明。

因此，FTP 不仅允许客户指明“文件的类型”，还允许指明“文件的格式”。选项 A、B、D 均与协议设计不符。正确选项为 C。

**易错点**：
1. **混淆“文件类型”与“文件格式”**：部分考生误认为 FTP 只区分 ASCII 和二进制，不能指定更细的格式，从而误选 A 或 B。实际上 FTP 标准（RFC 959）同时定义了 Type、Structure、Mode 等可协商参数。
2. **与 HTTP 的 Content-Type 混淆**：HTTP 通过 MIME 类型描述资源类型，而 FTP 是独立的文件传输协议，其协商参数更接近底层传输控制。
3. **忽略控制连接的作用**：FTP 的参数协商发生在控制连接上，数据连接只负责传输数据。若只记住“FTP 传文件”，容易遗漏其可协商特性。

**命题规律**：  
- 该考点属于“应用层协议”基础内容，通常在选择题中直接考查协议特征的记忆，难度较低。  
- 常见变式：给出 FTP 的某条命令（如 `TYPE I`）问其含义；或将 FTP 与 TFTP 对比，考查“FTP 有控制连接、TFTP 基于 UDP”等区别。  
- 复习建议：将常用应用层协议（HTTP、FTP、SMTP、POP3、DNS、DHCP）的端口、连接方式、传输层协议、主要功能列表对比记忆，特别注意 FTP 的双连接和参数协商机制。
