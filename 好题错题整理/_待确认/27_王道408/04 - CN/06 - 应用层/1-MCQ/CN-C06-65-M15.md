# 选择题 第 15 题

![[_Attachments/题目识别/27_王道408-题目/CN-C06-65-M15_题目.png|题目]]

15. 假定一个 NAT 路由器的公网地址为 205.56.79.35,并且有如下表项:

| 转换端口 | 源 IP 地址 | 源端口 |
| :--- | :--- | :--- |
| 2056 | 192.168.32.56 | 21 |
| 2057 | 192.168.32.56 | 20 |
| 1892 | 192.168.48.26 | 80 |
| 2256 | 192.168.55.106 | 80 |

它收到一个源 IP 地址为 192.168.32.56、源端口为 80 的分组,其动作是 ( ).

(A) 转换地址,将源 IP 变为 205.56.79.35,端口变为 2056,然后发送到公网

(B) 添加一个新的条目,转换 IP 地址及端口然后发送到公网

(C) 不转发,丢弃该分组

(D) 直接将分组转发到公网

## DeepSeek V4 Flash Max 解析

**答案**：B。该分组的“内网标识”$(192.168.32.56,80)$ 在 NAT/NAPT 表中未命中，因此 NAT 应新建映射，将源 IP 改为公网 IP、源端口改为新分配的公网端口后再转发。

**解题切入点**：拿到题先看表头：表项是“转换端口 + 源 IP + 源端口”，说明这是 NAPT，不是简单的一个公网 IP 对应一个内网 IP。对出站分组，要用 $(内网IP, 内网端口)$ 作为键查表。这类似算法竞赛里的哈希表：$key=(ip,port)$，$value=公网端口$；查不到就分配新 value 插入，而不是因为 key 的前半部分相同就复用另一个 key 的旧 value。

**推演**：NAT 表中已有映射为：

$$
(192.168.32.56,21)\to2056,\quad
(192.168.32.56,20)\to2057
$$

$$
(192.168.48.26,80)\to1892,\quad
(192.168.55.106,80)\to2256
$$

收到的出站分组键是：

$$
(192.168.32.56,80)
$$

它不等于表中任何已有键：

- 同一 IP $192.168.32.56$ 对应的源端口是 $21$ 和 $20$，不是 $80$；
- 同一源端口 $80$ 对应的源 IP 是 $192.168.48.26$ 和 $192.168.55.106$，不是 $192.168.32.56$。

所以不能使用已有表项。若把该分组错误地转换成公网端口 $2056$，则回程分组会被 NAT 映射回 $(192.168.32.56,21)$，而不是 $(192.168.32.56,80)$，连接无法建立。

因此 NAT 应选择一个空闲公网端口 $p^*$，新建表项：

$$
(192.168.32.56,80)\to p^*
$$

并把分组改写为：

$$
(192.168.32.56,80)\rightarrow(205.56.79.35,p^*)
$$

然后发送到公网。对应选项 B。

**易错点**：

- 容易误选 A：认为同一个内网 IP 的流量都使用同一个转换端口；实际上 NAPT 的键是“内网 IP + 内网端口”，不能只看 IP。
- 容易因源端口是 $80$，就对应表中已有的两个端口 $80$ 表项；但源 IP 也必须匹配。
- 容易误选 C：未命中表项不等于丢弃，NAT 可以新建表项；只有端口耗尽或策略禁止时才丢弃。
- 容易误选 D：私有地址不能直接出现在公网分组中，NAT 必须改写源地址。

**命题规律**：考点是 NAT/NAPT 的表项匹配与地址端口转换，常结合私有 IP、TCP/UDP 端口、网络层与传输层协作考查。常见变式包括：给出公网收到的分组，反向查 NAT 表确定内网主机；多个内网主机使用相同源端口时如何分配不同公网端口；静态 NAT 与 NAPT 的区别；NAT 端口耗尽时的处理。复习时应把 NAT 表看成“会话状态表”，明确“出站查源，入站查目的”，拿到题目先在表中精确匹配完整键，再判断是复用、新增还是丢弃。
