# 选择题 第 9 题

![[_Attachments/题目识别/27_王道408-题目/CN-C06-65-M09_题目.png|题目]]

9. 下列关于 $Cookie$ 的说法中,错误的是( )

(A) $Cookie$ 仅存储在服务器端  
(B) $Cookie$ 是服务器产生的  
(C) $Cookie$ 会威胁客户的隐私  
(D) $Cookie$ 的作用是跟踪用户的访问和状态

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C06-65-M09_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：A。Cookie 由服务器产生后发送并存储在**客户端浏览器**中，而不是仅存储在服务器端；因此“仅存储在服务器端”说法错误。

**解题切入点**：拿到题目先锁定两个关键点：Cookie 的**产生方**和**存储位置**。这类似算法竞赛中遇到“状态存哪里”的问题：服务器是无状态的“纯函数”，每次请求都是一次独立调用，它需要把“记忆”交给客户端保管，就像在分布式计算中把快照保存在节点本地，而不是集中式服务器上。抓住“谁生成、谁保存”即可定位考点——HTTP 中的 Cookie 机制。

**推演**：  
HTTP 是无状态协议，即服务器不自动保存每个请求的上下文。设第 $t$ 次请求为 $R_t$，服务器状态为 $S_t$，若无 Cookie，则服务器处理结果仅由当前请求决定：$S_t = f(R_t)$，不依赖 $S_{t-1}$。为维持会话，服务器产生一个标识符 $C$，通过响应头 `Set-Cookie` 发送给客户端；浏览器保存该 Cookie，并在后续请求的请求头 `Cookie` 中携带。于是服务器可恢复会话状态：$S_t = g(C, R_t)$。  
具体过程：

1. 浏览器首次请求服务器；
2. 服务器生成 Cookie，并在响应头 `Set-Cookie` 中返回；
3. 浏览器收到后，将 Cookie 存储在客户端本地；
4. 以后每次请求，浏览器自动携带该 Cookie；
5. 服务器根据 Cookie 识别用户并维护状态。

因此：
- A 错误：Cookie 存储在客户端，不是“仅存储在服务器端”；
- B 正确：Cookie 由服务器产生；
- C 正确：Cookie 可能被第三方追踪，用于分析用户行为，确实会威胁隐私；
- D 正确：Cookie 的核心作用就是跟踪用户访问行为和维持会话状态。

**易错点**：  
常见错误一是混淆 Cookie 与 Session，误以为 Cookie 存储在服务器端，实际上 Session 数据通常在服务器端，Cookie 只是客户端保存的“票据”；二是误认为 Cookie 由客户端生成，实际产生方是服务器；三是忽略 Cookie 的隐私风险，认为 Cookie 只是无害标识符。规避方法：记住“服务器产生 → 客户端保存 → 下次请求自动携带”的三角关系，并把 Cookie 类比为商家发给顾客的“会员卡”：卡由商家制作（服务器产生），但由顾客携带（客户端存储），商家凭卡识别顾客并记录消费（跟踪状态），但卡本身可能泄露顾客隐私。

**命题规律**：本题属于“应用层 HTTP 协议”中的高频考点，常与 Session、Token 进行比较。常见变式有：判断 Session 与 Cookie 的区别、给出报文片段要求识别 `Set-Cookie` 或 `Cookie` 首部、讨论 Cookie 的 `HttpOnly` 或 `Secure` 属性对安全性的影响。复习时应掌握 Cookie 的工作过程、属性字段（如 Domain、Path、Expires、HttpOnly、Secure），以及 Cookie 与 Session 在存储位置、安全性、生命周期上的差异。408 真题常以“下列说法错误的是”形式考查概念识记，熟练记住机制即可快速得分。
