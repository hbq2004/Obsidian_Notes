# 选择题 第 12 题

![[_Attachments/题目识别/27_王道408-题目/CN-C06-65-M12_题目.png|题目]]

12. 假设主机通过 $HTTP/1.1$(流水线方式)请求浏览某个 $Web$ 服务器 $S$ 上的 $Web$ 页 $rfc.html$,$rfc.html$ 引用了同目录下的 3 个 $JPEG$ 小图像(假设只有在收到 $rfc.html$ 后才能发送对其引用图像的请求),一次请求响应的时间为 $RTT$,忽略其他各种时延,不考虑拥塞控制和流量控制,则从发出 $HTTP$ 请求报文开始到收到全部内容为止,所耗费的时间是（ ）

(A) $2RTT$

(B) $2.5RTT$

(C) $4RTT$

(D) $4.5RTT$

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C06-65-M12_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：A（$2RTT$）。理由：HTTP/1.1 流水线在一条持久连接上成批发出后续 3 个图像请求，只有先获取 $rfc.html$ 是必须等待的前置阶段，所以总时间为 $1RTT+1RTT=2RTT$。

**解题切入点**：先抓题眼“HTTP/1.1 流水线”和“只有在收到 $rfc.html$ 后才能发送图像请求”。这相当于算法竞赛里的依赖关系：$rfc.html$ 是前置任务，必须先完成；3 个 JPEG 是互不依赖的独立任务，应“并发/批量”处理，而不是串行逐个等待。计算总时间应找关键路径，而不是把所有对象的时间简单相加。

**推演**：设每个 HTTP 请求-响应过程耗时 $RTT$，题目从发出 HTTP 请求报文开始计时，因此 TCP 连接建立时间不计入。

阶段一：获取 $rfc.html$  
- 发送 `GET rfc.html`，收到响应，耗时 $1RTT$。  
- 此时才能解析出 3 个 JPEG 的 URL，所以这一步不能被流水线跳过。

阶段二：获取 3 个 JPEG 图像  
- HTTP/1.1 流水线方式下，客户端保持同一 TCP 连接，连续发送 3 个图像请求，不必等第 1 个图像响应后再发第 2 个。  
- 题设说明忽略其他时延，且不考虑拥塞控制和流量控制，因此这 3 个请求和对应响应可以重叠完成，第二阶段仍只需 $1RTT$。

总时间：
$$
T=1RTT+1RTT=2RTT
$$

所以选 **A**。若改为 HTTP/1.1 非流水线持久连接，则会得到 $4RTT$，即选项 C；但本题明确是流水线方式。

**易错点**：

- 误选 C：把 3 个图像请求看作必须串行等待响应，得到 $1RTT+3RTT=4RTT$。这是“非流水线”持久连接的时间，不是本题的 HTTP/1.1 流水线。
- 误以为 4 个对象全部一开始就并发：忽略“只有在收到 $rfc.html$ 后才能发送图像请求”的依赖关系，会错误地少算一个 RTT。
- 重复计算 TCP 连接建立：题目从“发出 HTTP 请求报文”开始，不计 TCP 三次握手；若从建立 TCP 连接开始算，则应额外加 $1RTT$。
- 担心 3 个响应不能在一个 RTT 内传完：题设已说明忽略其他时延，且不考虑拥塞控制和流量控制，所以可按理想流水线模型计算。

**命题规律**：考点是 HTTP/1.1 持久连接与流水线机制下的 RTT 计算。常见变式有：改为 HTTP/1.1 非流水线、改为需要先建立 TCP 连接、改为 HTTP/1.0 非持久连接等。复习时应画时间轴，区分“建立连接、发送请求、收到响应、解析引用”各阶段，并重点判断多个对象之间是串行还是可流水线重叠。
