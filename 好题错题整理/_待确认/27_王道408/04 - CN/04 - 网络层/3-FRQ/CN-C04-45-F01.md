# 综合题 第 1 题

![[_Attachments/题目识别/27_王道408-题目/CN-C04-45-F01_题目.png|题目]]

1.互联网的多播是怎样实现的?为什么因特网上的多播比以太网上的多播复杂得多?

4.7 网络层设备
1.某个单位的网点由4个子网组成,结构如下图所示,其中主机 $H1$、$H2$、$H3$ 和 $H4$ 的 IP 地址和子网掩码见下表.

| 主机 | IP 地址 | 子网掩码 |
| --- | --- | --- |
| $H1$ | 202.99.98.18 | 255.255.255.240 |
| $H2$ | 202.99.98.35 | 255.255.255.240 |
| $H3$ | 202.99.98.51 | 255.255.255.240 |
| $H4$ | 202.99.98.66 | 255.255.255.240 |

【图：网络拓扑。四个子网 Net1、Net2、Net3、Net4，路由器 R1、R2、R3，主机 H1、H2、H3、H4。连接关系为：R1 连接 Net1、Net2、Net4；R2 连接 Net2、Net3；R3 连接 Net3、Net4；H1 连接 Net1；H2 连接 Net2；H3 连接 Net3；H4 连接 Net4。各子网标签分别为 202.99.98.17、202.99.98.33、202.99.98.49、202.99.98.65。】

(1) 请写出路由器 $R1$ 到 4 个子网的路由表.
(2) 试描述主机 $H1$ 发送一个 IP 数据报到主机 $H2$ 的过程(包括物理地址解析过程)

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C04-45-F01_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：  
（第一问）互联网多播的实现主要依靠 IGMP 进行组成员管理，以及多播路由协议（如 PIM）构建多播分发树进行跨网络转发。因特网多播需要路由器处理组成员动态变化、跨网络路由、避免环路等问题，而以太网多播只需在同一个广播域内通过 MAC 地址映射即可，因此因特网多播复杂得多。  

（第二问）  
(1) 路由器 R1 的路由表（假设 R1 接口 IP 分别为 $202.99.98.17$（Net1）、$202.99.98.33$（Net2）、$202.99.98.65$（Net4），R2 在 Net2 接口为 $202.99.98.34$，R2 在 Net3 接口为 $202.99.98.49$，R3 在 Net3 接口为 $202.99.98.50$，R3 在 Net4 接口为 $202.99.98.67$，且 R1 选择通过 R2 到达 Net3）  

| 目的网络 | 子网掩码 | 下一跳 | 接口 |
|---------|---------|-------|------|
| $202.99.98.16/28$ | $255.255.255.240$ | 直接 | 接口1（Net1） |
| $202.99.98.32/28$ | $255.255.255.240$ | 直接 | 接口2（Net2） |
| $202.99.98.64/28$ | $255.255.255.240$ | 直接 | 接口3（Net4） |
| $202.99.98.48/28$ | $255.255.255.240$ | $202.99.98.34$ | 接口2（Net2） |

（注：实际下一跳可根据具体情况选择，本表假设通过 R2 转发。）  

(2) $H1$ 发送 IP 数据报到 $H2$ 的过程：  
- $H1$ 检测到目的 IP $202.99.98.35$ 与自己不在同一子网（子网掩码 $255.255.255.240$），故将数据报发送给默认网关 $202.99.98.17$（即 R1 的 Net1 接口）。  
- $H1$ 通过 ARP 广播获取网关的 MAC 地址，然后封装成帧（源 MAC：$H1$ MAC，目的 MAC：R1 的 Net1 接口 MAC，源 IP：$202.99.98.18$，目的 IP：$202.99.98.35$）发送到 Net1。  
- R1 收到帧后，解封，查询路由表，发现目的网络 $202.99.98.32/28$ 直接连接在 Net2 接口，故从 Net2 接口转发。  
- R1 通过 ARP 广播获取 $H2$ 的 MAC 地址，然后封装成帧（源 MAC：R1 的 Net2 接口 MAC，目的 MAC：$H2$ MAC，源 IP：$202.99.98.18$，目的 IP：$202.99.98.35$）发送到 Net2。  
- $H2$ 收到帧后，解封，得到 IP 数据报，交付给上层协议。  

**解题切入点**：  
- 多播问题：抓住“跨网络”与“单网络”的本质区别，类比算法竞赛中“单机数据处理”与“分布式系统协作”的复杂度差异。  
- 子网路由问题：先从 IP 和子网掩码计算出各子网网络地址，再根据拓扑结构确定路由器接口和邻居关系，最后模拟数据包转发过程，注意 ARP 只在本链路层网络进行。  

**推演**：  
- 第一问详细展开：互联网多播的实现包括 IGMP（组成员管理）和多播路由协议（如 PIM-SM/DM、DVMRP）。多播路由器通过 IGMP 了解直连网络是否有组成员，并利用多播路由协议建立分发树，数据沿着树转发，通过 RPF 检查防止环路。因特网多播需要处理不同自治域、动态组成员、路由协议交互等，而以太网多播只需在同一个广播域内通过 IP 多播地址到 MAC 多播地址的映射，交换机即可转发，无需路由，因此相对简单。  
- 第二问详细推导：  
  1. 计算各主机所在子网网络地址：  
     - $H1$: $202.99.98.18 \ \&\ 255.255.255.240 = 202.99.98.16/28$  
     - $H2$: $202.99.98.35 \ \&\ 255.255.255.240 = 202.99.98.32/28$  
     - $H3$: $202.99.98.51 \ \&\ 255.255.255.240 = 202.99.98.48/28$  
     - $H4$: $202.99.98.66 \ \&\ 255.255.255.240 = 202.99.98.64/28$  
  2. 根据拓扑，R1 直接连接 Net1 ($202.99.98.16/28$)、Net2 ($202.99.98.32/28$)、Net4 ($202.99.98.64/28$)，因此有直接路由。  
  3. 对于 Net3 ($202.99.98.48/28$)，R1 需要通过其他路由器。由于 R1 同时连接 Net2 和 Net4，而 R2 连接 Net2 和 Net3，R3 连接 Net3 和 Net4，因此 R1 可经 R2 或 R3 到达 Net3。假设 R1 选择经 R2，则下一跳应为 R2 在 Net2 的接口 IP。为具体化，假设各路由器接口 IP 分配如下（子网内第一个可用 IP 优先分配给 R1）：  
     - R1 在 Net1: $202.99.98.17$  
     - R1 在 Net2: $202.99.98.33$  
     - R1 在 Net4: $202.99.98.65$  
     - R2 在 Net2: $202.99.98.34$  
     - R2 在 Net3: $202.99.98.49$  
     - R3 在 Net3: $202.99.98.50$  
     - R3 在 Net4: $202.99.98.67$  
     （注：实际分配可能不同，但任意合理分配均可，只要符合子网范围。）  
  4. 由此得到 R1 路由表如上。  
  5. 数据包转发过程：H1 判断不在同一子网，查默认网关（R1 的 Net1 接口），通过 ARP 获取 MAC，发送帧；R1 解包后查路由表，发现目的网络直连，从 Net2 接口转发，需通过 ARP 获取 H2 的 MAC，然后发送帧；H2 接收。  

**易错点**：  
1. 子网地址计算错误：容易将主机 IP 与子网掩码进行与运算时出错，注意二进制位。  
2. 路由表下一跳混淆：对于间接路由，下一跳必须是相邻路由器在本子网的接口 IP，不能写成其他子网的 IP。  
3. ARP 解析范围：ARP 只在同一广播域（子网）内有效，跨子网时必须通过路由器，不能直接获取目的主机的 MAC。  
4. 多播实现中，忽略 IGMP 和组播路由协议的区别，或误认为多播与广播相同。  

**命题规律**：  
- 多播考点：常考查 IGMP 的作用、组播路由协议（如 PIM）的基本原理、与单播路由的区别、以太网多播的地址映射。  
- 子网路由考点：通常结合 IP 地址计算、子网划分、路由表编写、ARP 协议、数据包转发过程，是必考综合题。变式包括：给定拓扑和 IP 要求写路由表、描述数据包传输过程、分析广播域与冲突域等。复习时应熟练掌握子网掩码计算、路由表传递，以及 ARP 与 IP 转发的配合。
