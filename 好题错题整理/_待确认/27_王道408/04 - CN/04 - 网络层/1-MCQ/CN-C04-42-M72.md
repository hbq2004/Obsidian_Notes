# 选择题 第 72 题

![[_Attachments/题目识别/27_王道408-题目/CN-C04-42-M72_题目.png|题目]]

72.【2025年统考真题】一台新接入网络的主机H通过DHCP服务器动态请求IP地址过程中,与DHCP服务器交换DHCP报文过程如下图所示。封装DHCPREQUEST报文的IP数据报的目的IP地址和源IP地址分别是( ).

【图：主机H与DHCP服务器（192.168.5.1）的交互过程。服务器向主机H发送DHCPOFFER报文，报文内容包含yiaddr:192.168.5.9；主机H向服务器发送DHCPREQUEST报文，报文内容包含yiaddr:192.168.5.9。时间自上而下。】

(A) 192.168.5.1、0.0.0.0
(B) 192.168.5.1、192.168.5.9
(C) 255.255.255.255、0.0.0.0
(D) 255.255.255.255、192.168.5.9

## DeepSeek V4 Flash Max 解析

**答案**：C。在 DHCP 请求（REQUEST）阶段，主机尚未获得 IP 地址，因此源 IP 地址只能使用 $0.0.0.0$，且需以广播方式通知所有 DHCP 服务器，故目的 IP 地址为 $255.255.255.255$。

**解题切入点**：抓住 DHCP 工作流程中客户端的 IP 配置状态。新接入主机在未完成地址分配时，其 IP 地址为 $0.0.0.0$，且无法进行单播通信，只能使用广播（$255.255.255.255$）发送报文。这类似于算法竞赛中构建辅助数据结构时，需要先明确基本变量（如初始状态为 0）后再进行操作。

**推演**：DHCP 协议中，客户端在 SELECTING 状态发送 DHCPREQUEST 以接受某个 DHCPOFFER 中的 IP 地址。此时客户端尚未配置 IP，因此其 IP 数据报的源 IP 地址只能是 $0.0.0.0$。目的 IP 地址通常为 $255.255.255.255$（广播），原因有二：一是客户端无法确定 DHCP 服务器的具体位置（尽管可能从 OFFER 中得知服务器 IP，但为通知所有服务器并避免冲突，广播是标准做法）；二是客户端尚未拥有 IP，无法进行单播。题目图中，服务器（$192.168.5.1$）已向主机 H 发送了包含 yiaddr=$192.168.5.9$ 的 DHCPOFFER，主机 H 随后发送 DHCPREQUEST 请求该地址，但此时主机 H 的 IP 仍是 $0.0.0.0$，因此源 IP 为 $0.0.0.0$，目的 IP 为 $255.255.255.255$。选项分析：
- A：目的 IP $192.168.5.1$ 错误，主机无法单播；
- B：源 IP $192.168.5.9$ 错误，主机尚未分配该 IP；
- D：源 IP $192.168.5.9$ 错误。
故 C 正确。

**易错点**：
1. 误认为 DHCPREQUEST 可以单播，从而选择目的 IP 为服务器地址（如 $192.168.5.1$）。实际上，客户端在完成配置前只能使用广播，且广播是标准行为。
2. 混淆 DHCPOFFER 与 DHCPREQUEST 的源 IP：OFFER 由服务器发往客户端，目的 IP 可为 $255.255.255.255$ 或客户端 MAC 对应的单播，但此时客户端 IP 仍为 $0.0.0.0$；而 REQUEST 的源 IP 一定是 $0.0.0.0$。
3. 认为客户端在收到 OFFER 后已经获得 IP 地址，从而误将源 IP 设为 $192.168.5.9$。实际上，IP 地址只有在收到 DHCPACK 后才正式生效，REQUEST 阶段仍为 $0.0.0.0$。

**命题规律**：DHCP 协议是网络层动态地址分配的常考知识点，重点考查客户端在 DISCOVER、REQUEST 阶段的 IP 地址封装（源 IP 为 $0.0.0.0$，目的 IP 为 $255.255.255.255$）以及服务器在 OFFER、ACK 阶段的地址封装。常见变式包括：判断 DHCPOFFER 的目的 IP（可能为广播或单播）、DHCP 中继代理下的 IP 封装、以及 DHCP 冲突检测（ARP 探测）的源 IP 设置。复习时需牢记 DHCP 四个阶段的交互细节，尤其注意客户端在未获得 IP 前只能使用 $0.0.0.0$ 和广播地址。
