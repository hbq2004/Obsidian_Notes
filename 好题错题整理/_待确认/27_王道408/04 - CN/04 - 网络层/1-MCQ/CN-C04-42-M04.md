# 选择题 第 4 题

![[_Attachments/题目识别/27_王道408-题目/CN-C04-42-M04_题目.png|题目]]

4. 下列关于 IP 分组的首部检验和字段的说法中,正确的是( ).
(A) 检验和字段检查的范围是整个 IP 分组
(B) 计算检验和的方法是对首部的每个 16 比特按反码运算求和再取反码
(C) 若网络层发现检验和错误,则丢弃该 IP 分组并发送 ICMP 差错报文
(D) IP 分组的检验和的计算需要加入一个伪首部

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C04-42-M04_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：B。IP 首部检验和只覆盖 IP 首部，不覆盖数据部分；计算时把首部按 16 bit 分组，用反码算术求和后再取反码。检验和出错时通常静默丢弃，不发送 ICMP 差错报文；伪首部是 TCP/UDP 校验和使用的，与 IP 首部检验和无关。

**解题切入点**：看到“首部检验和”先定位到 IPv4 数据报格式。题目四个选项分别考“校验范围”“计算方法”“出错处理”“伪首部”，可以类比算法竞赛里“哈希/校验到底覆盖哪些字段”：  
- 先确定范围，不要盲目把整个结构体都丢进哈希；  
- 看到“伪首部”要立刻想到 TCP/UDP，而不是 IP；  
- 看到“检验和错误 + ICMP”要想到：不是所有丢弃都会发 ICMP。

**推演**：

- **A 错**。IP 分组 = IP 首部 + 数据部分。IPv4 的检验和字段是“首部检验和”，只对 IP 首部做校验，不检查整个 IP 分组。数据部分由上层协议如 TCP/UDP 负责校验。

- **B 对**。IPv4 首部检验和的计算方法为：  
  1. 计算前把检验和字段置为 0；  
  2. 把 IP 首部划分为若干个 16 bit 字；  
  3. 对这些 16 bit 字按反码算术运算求和，即有进位时把最高位的进位回卷加到最低位；  
  4. 将所得和按位取反，写入检验和字段。  

  设反码和为 $S$，则写入的检验和为：
  $$C=\overline{S}=(2^{16}-1)-S.$$

  接收端把整个首部（包括收到的检验和字段）一起按反码算术求和，若结果应为：
  $$S+C=0xFFFF,$$
  则表示首部没有检测出错误。这正对应选项 B 的“按反码运算求和再取反码”。

- **C 错**。若 IP 首部检验和错误，路由器或目的主机应丢弃该 IP 分组，但不发送 ICMP 差错报文。因为首部本身可能已经不可靠，源 IP 地址等信息可能无效；发送 ICMP 还可能引发差错报文风暴。

- **D 错**。伪首部是 TCP/UDP 计算校验和时临时加上的一个虚拟首部，包含源 IP 地址、目的 IP 地址、协议号、TCP/UDP 长度等字段，用于让传输层校验和也能覆盖 IP 地址信息。IP 首部检验和直接对 IP 首部本身计算，不需要伪首部。

因此正确选项是 B。

**易错点**：

- **误以为 IP 检验和覆盖整个 IP 分组**：IP 层是尽力而为的，数据部分出错由上层协议发现；IP 只保护首部，因为首部中的地址、长度、协议等字段用于转发，一旦出错无法正确处理。
- **误以为检验和错误会发送 ICMP 差错报文**：ICMP 差错报文只在 TTL 超时、目的不可达、参数错误等情况下发送；首部检验和错误通常直接丢弃。
- **把“伪首部”安到 IP 头上**：伪首部是传输层 TCP/UDP 校验和用来“借用”IP 地址信息的，不是网络层 IP 首部检验和的一部分。
- **混淆反码与补码**：IP 首部检验和使用的是反码算术，最高位进位要回卷；如果按普通补码加法直接丢弃进位，计算结果会错。

**命题规律**：考点集中在 IPv4 首部格式、首部检验和算法、ICMP 差错处理，以及 TCP/UDP 校验和与 IP 首部检验和的区别。常见变式包括：给出 IPv4 首部的十六进制序列要求判断或计算检验和；问路由器转发时为什么每跳都要重算首部检验和（因为 TTL 改变）；问 TCP/UDP 为什么需要伪首部；比较 IPv4 与 IPv6 的差错检测设计。复习时建议把链路层差错检测、IPv4 首部检验和、TCP/UDP 校验和放在一起对比记忆，重点记住：IP 只校验首部，传输层做端到端校验。
