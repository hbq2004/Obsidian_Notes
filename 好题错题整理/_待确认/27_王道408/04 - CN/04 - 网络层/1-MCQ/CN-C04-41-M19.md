# 选择题 第 19 题

![[_Attachments/题目识别/27_王道408-题目/CN-C04-41-M19_题目.png|题目]]

19.【2011统考真题】TCP/IP模型的网络层提供的是（  ）
(A) 无连接不可靠的数据报服务
(B) 无连接可靠的数据报服务
(C) 有连接不可靠的虚电路服务
(D) 有连接可靠的虚电路服务

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C04-41-M19_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：A。TCP/IP 模型的网络层（IP 层）提供无连接、不可靠的数据报服务，可靠性由上层传输层（TCP）负责。

**解题切入点**：拿到题目先定位“网络层提供服务类型”这一考点，核心是区分“无连接/有连接”和“可靠/不可靠”两个维度。这就像算法竞赛中设计一个“消息传递系统”：如果每个数据包都自带完整目标地址、独立路由（类似无状态哈希分发），就是“无连接数据报”；如果每条连接先建立会话、维护状态、保证顺序与不丢失（类似有状态双端队列+确认机制），就是“有连接虚电路”。TCP/IP 的 IP 层选择的是前者，把可靠性留给上层 TCP 去“特判重试”。

**推演**：

1. 网络层可提供的服务主要有两大类：

   - 数据报服务：无连接。每个分组（数据报）独立选择路径，路由器不提前建立“会话”。因此分组可能乱序、重复、丢失。
   - 虚电路服务：有连接。通信前先建立虚电路，所有分组沿着同一路径按序传输，网络负责顺序、差错控制等。

2. 可靠性与连接方式不是必然绑定：

   - 无连接数据报服务通常不可靠（如 IP）。
   - 有连接虚电路服务通常可靠（如 X.25，但 ATM 可做到有连接且可带不同服务质量）。
   - 也可以有无连接但可靠的服务（如某些可靠 UDP 协议在上层实现），以及有连接但不可靠的服务（如部分实时传输），但本题考察“TCP/IP 模型网络层”的标准实现。

3. TCP/IP 模型的网络层核心协议是 IP（Internet Protocol），其设计目标是最简单的“尽力而为”（best-effort）交付：

   - IP 数据报独立发送，每个路由器只根据目的地址查表转发，不维护连接状态。
   - 数据报可能丢失（路由器拥塞丢包）、可能乱序（不同路径延迟不同）、可能重复（重传导致）。
   - IP 只提供首部校验和（仅校验首部，不校验数据），不负责端到端可靠传输。

   因此，网络层是：
   $$
   \text{无连接} + \text{不可靠} = \text{数据报服务}
   $$

4. 可靠性由谁保证？在 TCP/IP 模型中，由传输层 TCP 提供可靠传输：确认、重传、排序、流量控制、拥塞控制。这体现了“端到端原则”：网络层保持简单，复杂可靠性放在端系统完成。

5. 对照选项：

   - (A) 无连接不可靠的数据报服务：符合 IP。
   - (B) 无连接可靠的数据报服务：与 IP 的“尽力而为”矛盾。
   - (C) 有连接不可靠的虚电路服务：TCP/IP 网络层没有虚电路。
   - (D) 有连接可靠的虚电路服务：这是面向连接网络（如 X.25/帧中继/ATM 的某些模式）的特点，不是 TCP/IP。

   所以选 (A)。

**易错点**：

- 误选 (B)：以为 TCP/IP 可靠，就把可靠性当成网络层的属性。实际上 TCP 是传输层，IP 网络层不提供可靠交付。
- 误选 (D)：把“TCP 面向连接”的错误印象迁移到网络层，混淆了传输层的 TCP 与网络层的 IP。
- 概念混淆：认为“有连接=可靠”“无连接=不可靠”。虽然常见组合如此，但两者不是严格等价关系，解题时应分别判断“连接方式”和“可靠性”两个维度。
- 规避方法：记口诀“IP 尽力而为，TCP 可靠负责”。题目问 TCP/IP 模型网络层，先锁定 IP 的特性，再对照选项。

**命题规律**：

- 这是 408 高频基础题，常考“网络层服务的两种类型”和“TCP/IP 与 OSI 在服务理念上的区别”。
- 常见变式：
   1. 问“OSI 参考模型网络层默认提供什么样的服务？”通常教材以虚电路/数据报均可描述，但 TCP/IP 明确为数据报。
   2. 问“IPv4 分组在网络中可能出现的现象”，考查乱序、丢失、重复等。
   3. 问“可靠性由哪一层保证”，答案常为传输层 TCP。
   4. 与“路由器工作在哪一层”“分组交换 vs 报文交换”结合考查。
- 复习建议：把网络层服务与传输层服务对照整理成表格：连接方式、可靠性、典型协议、实现位置。重点理解“端到端原则”和“尽力而为”的设计思想，这既是考点，也是理解 TCP/IP 体系结构的关键。
