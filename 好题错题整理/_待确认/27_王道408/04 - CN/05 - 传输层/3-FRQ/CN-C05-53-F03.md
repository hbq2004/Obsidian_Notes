# 综合题 第 3 题

![[_Attachments/题目识别/27_王道408-题目/CN-C05-53-F03_题目.png|题目]]

3.一个 TCP 连接要发送 3200B 的数据。第一个字节的编号为 10010。若前两个报文段各携带 1000B 的数据,最后一个报文段携带剩下的数据,请写出每个报文段的序号。

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C05-53-F03_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：三个报文段的序号依次为 $10010$、$11010$、$12010$。理由：TCP 报文段的序号字段表示本报文段携带数据的第一个字节的编号；后一段的序号等于前一段的序号加上前一段携带的数据字节数。

**解题切入点**：拿到题目先抓“TCP 序号”的语义，题干只给了首字节编号和各段数据长度，说明考点就是“序号是字节流的偏移量，而不是报文段编号”。可以类比算法竞赛中维护一个数组：把要发送的 3200B 看成一段连续区间，每一个 TCP 报文段相当于一个区间切片，序号就是该切片在整体字节流中的起始下标；下一个切片起点 = 当前起点 + 当前切片长度。分层协议把大任务按块切分，正像分治中计算区间端点一样。

**推演**：

TCP 中，序号是“字节流编号”。设第 $i$ 个报文段的序号为 $S_i$，携带数据长度为 $L_i$。

题中第一个字节编号为 $10010$，所以第一个报文段：

$$S_1 = 10010$$

前两个报文段各携带 $1000$ B，所以：

$$L_1 = L_2 = 1000$$

总数据量为 $3200$ B，因此最后一个报文段携带：

$$
L_3 = 3200 - 1000 - 1000 = 1200
$$

第二个报文段的序号等于第一个报文段序号加上第一个报文段携带的数据长度：

$$
S_2 = S_1 + L_1 = 10010 + 1000 = 11010
$$

第三个报文段的序号等于第二个报文段序号加上第二个报文段携带的数据长度：

$$
S_3 = S_2 + L_2 = 11010 + 1000 = 12010
$$

对应各个报文段携带的字节区间为：

- 第一个报文段：序号 $10010$，携带字节 $10010 \sim 11009$；
- 第二个报文段：序号 $11010$，携带字节 $11010 \sim 12009$；
- 第三个报文段：序号 $12010$，携带字节 $12010 \sim 13209$。

因此三个报文段的序号依次为：

$$
10010,\quad 11010,\quad 12010
$$

最后一个报文段发送完后，下一个待发送数据的字节编号为：

$$
12010 + 1200 = 13210
$$

**易错点**：

1. 把“序号”当作“报文段编号”，误以为依次是 $1,2,3$。  
   规避：TCP 序号表示的是字节流中的位置，不是报文段个数。

2. 计算第二段序号时误加 $1$，写成 $10010 + 1000 + 1 = 11011$。  
   规避：第一段最后一个字节是 $10010+1000-1=11009$，下一段第一字节就是 $11010$，所以直接加数据长度，不加 $1$。

3. 剩余数据长度算错，把第三段长度误算成 $200$ 或 $2200$。  
   规避：总长度 $3200$ 减去前两段共 $2000$，剩 $1200$。

4. 混淆“字节区间”和“下一个序号”。  
   规避：最后一个字节编号是“序号 + 数据长度 $-1$”，而下一个待发序号是“序号 + 数据长度”。

**命题规律**：这是 408 中 TCP 协议常考的“序号计算”基础题。考点非常集中：TCP 序号字段的含义、字节流编号方式、多报文段连续发送时的序号推进。常见变式包括：建立连接后第一个数据字节序号是 `ISN+1`；给出 MSS 和各段长度，求第三段序号；结合 ACK 号，问接收方期望收到的下一字节序号；或把序号计算与拥塞控制、超时重传结合。复习建议：把 TCP 序号理解成字节流下标，明确 `SYN` 和 `FIN` 各占一个序号；做题时列出“起始序号 + 数据长度 + 下一序号”的关系，可避免几乎所有此类错误。
