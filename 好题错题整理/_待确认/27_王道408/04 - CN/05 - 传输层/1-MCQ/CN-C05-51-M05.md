# 选择题 第 5 题

![[_Attachments/题目识别/27_王道408-题目/CN-C05-51-M05_题目.png|题目]]

5. 可靠传输协议中的“可靠”指的是 ( )
(A) 使用面向连接的会话
(B) 使用尽力而为的传输
(C) 使用滑动窗口来维持可靠性
(D) 使用确认机制来确保传输的数据不丢失

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C05-51-M05_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：D。可靠传输中的“可靠”是指通过确认（ACK）与超时重传等机制，确保发送的数据不丢失；在四个选项中，D 最准确地描述了可靠性的核心保障。

**解题切入点**：拿到题目先定位考点：这是计算机网络中“可靠传输”的基本概念题，问的是“可靠”的定义，而不是问“哪种协议可靠”或“可靠传输有哪些机制”。不要把“实现手段”和“本质目标”混淆。  
打个算法竞赛的比方：一道题目要被评判为 AC，本质是“输出结果正确”，而不是“代码用了高级数据结构”或“运行时间看起来很优”。同样，可靠传输的本质是“数据最终完整、正确地到达接收方”，确认机制就像在线评测的反馈信号：只有收到 ACK 才表示“这次提交成功”；一直没反馈，就需要超时重试。

**推演**：

1. 可靠传输服务的目标是：发送方发送的数据，接收方最终能正确、不丢失、不重复、不乱序地交付给上层。  
   用逻辑关系表示为：
   $$
   \text{发送方发送 } m_i \Rightarrow \text{接收方最终正确收到一次 } m_i
   $$
   这里的“可靠”是对这一结果的保证，而不是对“是否建立连接”等形式的描述。

2. 不可靠信道（如 IP 层的“尽力而为”）可能出现三种典型问题：
   - 比特差错：数据在传输中被破坏；
   - 分组丢失：数据没有到达接收方；
   - 分组乱序或重复：数据到达顺序错乱或出现重复副本。

   因此，可靠传输必须针对这些问题提供机制。

3. 在可靠传输协议中，最标志性的机制是“确认 + 超时重传”：
   - 接收方收到一个正确的分组后，返回确认 ACK；
   - 发送方收到 ACK，就说明该分组已成功到达；
   - 如果发送方在超时时间内没有收到 ACK，就重新发送该分组；
   - 配合序号和检验和，还能进一步处理重复、乱序和比特差错。

   因此，“确认机制”直接服务于“确保数据不丢失”这一目标。

4. 逐项排除：
   - A 错误：“面向连接的会话”只说明双方建立了逻辑上的连接状态，不等于一定可靠；连接也可能只负责管理状态，而不保证数据不丢失。
   - B 错误：“尽力而为”恰恰是网络层不可靠服务的典型描述，和“可靠”相反。
   - C 错误：“滑动窗口”主要用于流量控制、连续发送和提高链路利用率，它不是“可靠”的定义；滑动窗口必须配合确认、重传等机制才能保证可靠。
   - D 正确：“确认机制”是可靠传输的核心保障手段，能确保数据不丢失。

所以选 D。

**易错点**：

- 易错选 A：把“面向连接”等同于“可靠”。面向连接是 TCP 的特点之一，但可靠是一种服务保证；面向连接不等于一定可靠。
- 易错选 C：把“滑动窗口”当作可靠性的本质。滑动窗口本身是传输策略，不能单独保证可靠；真正起作用的是窗口机制中的 ACK 与超时重传。
- 忽略“确认机制”必须配合“超时重传”。仅靠 ACK 不能处理 ACK 丢失或数据丢失，必须有定时器触发重传。
- 混淆“可靠”与“尽力而为”：IP 层是尽力而为的不可靠服务，而 TCP 等可靠传输协议是在不可靠信道上通过确认/重传实现可靠。

**命题规律**：

- 考点定位：传输层“可靠数据传输”（rdt）的基本概念，常以选择题形式出现，也可能结合“停止等待协议”“回退 N 帧 GBN”“选择重传 SR”“TCP 可靠传输”一起考查。
- 常见变式：
  - 问“可靠传输需要哪些机制”：检验和、确认、序号、超时重传；
  - 问“滑动窗口的作用”：流量控制、连续传输、配合确认实现可靠；
  - 问“TCP 如何保证可靠”：校验、序号、确认、重传、乱序重组等。
- 复习建议：从 rdt1.0 到 rdt3.0 理解可靠传输的演进：底层信道从可靠到有比特差错、再到有分组丢失，逐步加入差错检测、ACK/NAK、超时重传和序号。再对比 GBN 与 SR 的窗口机制，就能把“可靠”的相关题目一网打尽。
