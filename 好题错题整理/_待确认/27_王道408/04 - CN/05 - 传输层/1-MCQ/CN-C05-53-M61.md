# 选择题 第 61 题

![[_Attachments/题目识别/27_王道408-题目/CN-C05-53-M61_题目.png|题目]]

61.【2025统考真题】Time 是一个提供时间查询服务的 C/S 架构网络应用,支持客户通过 UDP 或 TCP 向 Time 服务器请求时间服务.若某客户与某 Time 服务器通信的往返时间 $RTT=8\text{ms}$，则该客户分别通过 UDP 和 TCP 向该服务器请求服务,所需的最少时间分别是(  )

A. $8\text{ms}$、 $8\text{ms}$
B. $8\text{ms}$、 $16\text{ms}$
C. $16\text{ms}$、 $16\text{ms}$
D. $16\text{ms}$、 $16\text{ms}$

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C05-53-M61_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：B（$8\text{ms}$、$16\text{ms}$）。理由：UDP 无连接，一次请求‑响应只需 $1$ 个 RTT（$8\text{ms}$）；TCP 需三次握手，若第三次握手携带请求，则最少需 $2$ 个 RTT（$16\text{ms}$）。

**解题切入点**：首先识别考点：UDP 与 TCP 的传输时延比较。注意题目强调“最少时间”，要考虑协议的最小开销。UDP 是无连接协议，直接发送数据，时间只需一个 RTT；TCP 是面向连接的，需要建立连接，最小时间包括连接建立和数据传输。可以类比算法竞赛中的“构造辅助函数”：UDP 像直接调用函数，TCP 像先建立连接（如初始化）再调用，并且可以在建立连接的最后一步携带数据，以节省时间。

**推演**：设往返时间 $RTT=8\text{ms}$，单程时延 $\frac{RTT}{2}=4\text{ms}$。客户与服务器通信，忽略处理时延。

- **UDP**：客户直接发送请求（$4\text{ms}$ 到达服务器），服务器立即回复响应（$4\text{ms}$ 到达客户）。总时间 $4+4=8\text{ms}$，即 $1$ 个 $RTT$。

- **TCP**：采用三次握手建立连接，且可在第三次握手时携带请求数据（即 ACK+请求）。
  - 时刻 $0$：客户发送 SYN。
  - 时刻 $4\text{ms}$：服务器收到 SYN，回复 SYN-ACK。
  - 时刻 $8\text{ms}$：客户收到 SYN-ACK，此时连接建立（客户视角），立即发送 ACK+请求。
  - 时刻 $12\text{ms}$：服务器收到 ACK+请求，处理并回复响应。
  - 时刻 $16\text{ms}$：客户收到响应。
  总时间 $16\text{ms}$，即 $2$ 个 $RTT$。

若第三次握手不携带数据，则需额外 $1$ 个 $RTT$ 传输请求与响应，总时间 $3$ 个 $RTT$（$24\text{ms}$），但题目要求“最少时间”，故取 $2$ 个 $RTT$。

因此，UDP 最少时间 $8\text{ms}$，TCP 最少时间 $16\text{ms}$。

**易错点**：
1. 误认为 TCP 三次握手需 $1.5$ 个 RTT 即可完成数据传输（如认为第三次握手是单独的数据传输）。实际上，从客户发起 SYN 到收到响应，至少需要 $2$ 个 RTT。
2. 忽略第三次握手可携带数据，误以为 TCP 需额外 RTT 传输请求，得出 $3$ 个 RTT。
3. 混淆 RTT 与单程时间，计算时需注意 RTT 是往返时间，单程为 $\frac{RTT}{2}$。

**命题规律**：本题属于网络应用层与传输层结合的时延计算题，常考 TCP 与 UDP 在传输时间上的差异。变式可能考虑 HTTP 请求、DNS 查询等类似场景。复习时应重点理解 TCP 三次握手过程及数据携带时机，以及 UDP 的无连接特性。建议结合 TCP 状态转移图，掌握最小时间计算。
