# 选择题 第 1 题

![[_Attachments/题目识别/27_王道408-题目/CN-C05-52-M01_题目.png|题目]]

1. 使用 $UDP$ 的网络应用,其数据传输的可靠性由( )负责.

A. 传输层  
B. 应用层  
C. 数据链路层  
D. 网络层

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C05-52-M01_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：B。UDP 只提供无连接、不可靠的数据报服务，可靠性必须由调用 UDP 的应用层自行保证。

**解题切入点**：看到“UDP”和“可靠性”两个关键词，立刻定位到传输层的两个协议对比：TCP 可靠、UDP 不可靠。题目问“由谁负责”，就是在问“谁来补齐 UDP 缺失的可靠性”。这类似于算法竞赛中：如果系统库提供的排序不稳定，你需要自己写一个稳定的排序函数来保证结果——UDP 相当于“不保证有序不保证到达”的裸通道，应用层就是那个自己实现排序/重传/确认的“补救层”。

**推演**：

1. UDP 是传输层协议，其头部只有源端口、目的端口、长度、校验和，没有序号、确认号、窗口等机制，因此不提供确认、重传、排序、流量控制和拥塞控制。  
2. 因此，UDP 本身不能保证数据一定到达、不重复、不乱序，即“不可靠”。  
3. 网络层（IP）也只提供“尽力而为”的交付，同样不保证可靠性。数据链路层只负责相邻节点之间的帧传输，也不对端到端可靠性负责。  
4. 当应用选择 UDP 时，若业务需要可靠传输，就必须由应用进程自己设计机制来保证，例如：  
   - 发送方维护超时重传；  
   - 接收方发送确认（ACK）；  
   - 应用层加入序号以处理乱序和重复；  
   - 应用层自己做流量控制等。  
   这些机制都位于传输层之上的应用层。  
5. 用分层模型看：
   $$UDP \text{ 不可靠} + \text{应用层可靠性机制} = \text{端到端可靠}$$
   所以负责方是应用层。

**易错点**：

- 误选 A（传输层）：TCP 的可靠性才由传输层负责，UDP 不是。题目明确说“使用 UDP”，不能把 TCP 的功能套在 UDP 上。  
- 误选 D（网络层）：网络层 IP 也是不可靠的，它只做尽力交付，不会因为上层是 UDP 就额外提供可靠服务。  
- 误选 C（数据链路层）：数据链路层只负责相邻节点间帧的传输，且有差错校验，但并非端到端的可靠性保证；即便有重传，也只覆盖单条链路。  
- 关键区分：UDP 的校验和能检错但不能纠错，发现错误后直接丢弃，不通知发送方重传，因此不能认为 UDP 提供了可靠性。

**命题规律**：

- 考点定位：传输层 UDP 的特点，以及各层职责的划分。  
- 常见变式：
  1. “TCP 的可靠性由谁负责？” → 传输层。  
  2. “IP 协议提供什么服务？” → 无连接、不可靠、尽力而为。  
  3. “哪些应用适合 UDP？为什么？” → 实时音视频、DNS、DHCP 等，因为容忍少量丢失但要求低延迟，可靠性由应用层自己处理。  
  4. “UDP 校验和的作用范围” → 伪首部 + UDP 首部 + 数据，用于检错但不负责重传。  
- 复习建议：把 TCP 和 UDP 的头部字段、连接管理、可靠性机制对比记忆；同时厘清“可靠传输”在不同层次的含义——链路层可靠 ≠ 端到端可靠，网络层尽力而为 ≠ 应用层可靠。做题时先判断协议在哪一层，再判断该层是否提供可靠性，最后确定缺失部分由谁补。
