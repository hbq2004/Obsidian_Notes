# 选择题 第 57 题

![[_Attachments/题目识别/27_王道408-题目/CN-C05-53-M57_题目.png|题目]]

57.【2022统考真题】假设主机甲和主机乙已建立一个TCP连接，最大段长 $MSS=1\text{KB}$，甲一直向乙发送数据，当甲的拥塞窗口为 $16\text{KB}$ 时，计时器发生了超时，则甲的拥塞窗口再次增长到 $16\text{KB}$ 所需要的时间至少是（ ）

(A) $4RTT$

(B) $5RTT$

(C) $11RTT$

(D) $16RTT$

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C05-53-M57_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：C，因为超时后拥塞窗口降为 $1\ \text{MSS}$，慢启动门限设为 $8\ \text{MSS}$，经过 $3\ \text{RTT}$ 慢启动到 $8\ \text{MSS}$，再经过 $8\ \text{RTT}$ 拥塞避免到 $16\ \text{MSS}$，共需 $11\ \text{RTT}$。

**解题切入点**：本题考察 TCP 拥塞控制中超时事件后的窗口调整机制。核心是抓住超时后立即进入慢启动，设置慢启动门限 $\text{ssthresh} = \text{cwnd}/2$，$\text{cwnd}=1\ \text{MSS}$，然后慢启动直到 $\text{ssthresh}$ 再转入拥塞避免。类似于算法竞赛中模拟一个过程，这里只需按规则逐步计算窗口增长到目标值所需的 RTT 数。

**推演**：  
已知 $\text{MSS}=1\ \text{KB}$，超时发生前 $\text{cwnd}=16\ \text{KB}=16\ \text{MSS}$。  
TCP 超时后：  
- 设置慢启动门限 $\text{ssthresh} = \frac{\text{cwnd}}{2} = 8\ \text{KB} = 8\ \text{MSS}$。  
- 设置拥塞窗口 $\text{cwnd} = 1\ \text{MSS}$。  

慢启动阶段（每 RTT，$\text{cwnd}$ 翻倍）：  
- 初始 $\text{cwnd}=1$。  
- 第 $1$ 个 RTT 结束，$\text{cwnd}=2$。  
- 第 $2$ 个 RTT 结束，$\text{cwnd}=4$。  
- 第 $3$ 个 RTT 结束，$\text{cwnd}=8$，达到 $\text{ssthresh}$，进入拥塞避免。  

拥塞避免阶段（每 RTT，$\text{cwnd}$ 增加 $1\ \text{MSS}$）：  
- 第 $4$ 个 RTT 结束，$\text{cwnd}=9$。  
- 第 $5$ 个 RTT 结束，$\text{cwnd}=10$。  
- 第 $6$ 个 RTT 结束，$\text{cwnd}=11$。  
- 第 $7$ 个 RTT 结束，$\text{cwnd}=12$。  
- 第 $8$ 个 RTT 结束，$\text{cwnd}=13$。  
- 第 $9$ 个 RTT 结束，$\text{cwnd}=14$。  
- 第 $10$ 个 RTT 结束，$\text{cwnd}=15$。  
- 第 $11$ 个 RTT 结束，$\text{cwnd}=16$。  

因此，从超时到 $\text{cwnd}$ 再次增长到 $16\ \text{KB}$ 至少需要 $11$ 个 RTT。

**易错点**：  
1. 混淆超时与快速重传：超时后进入慢启动（$\text{cwnd}=1$），而快速重传后进入快速恢复（$\text{cwnd}$ 减半并线性增长）。  
2. 忽略 $\text{ssthresh}$ 限制：误以为一直慢启动到 $16\ \text{MSS}$，需 $4\ \text{RTT}$（$1\to2\to4\to8\to16$），但实际超过 $\text{ssthresh}$ 后必须转入拥塞避免。  
3. 单位换算错误：MSS 与 KB 直接对应，无需额外换算。  
4. 计数 RTT 时易漏算或重复：建议画时间轴逐步模拟。

**命题规律**：TCP 拥塞控制是 408 高频考点，常以超时或快速重传为背景，计算窗口增长到特定值所需的 RTT 数。变式包括：比较 Tahoe 与 Reno 的差异、给定初始窗口和 MSS 求最终窗口、结合慢启动和拥塞避免的公式推导。复习时需熟练掌握状态转换图，明确各阶段窗口调整规则，并勤于画图模拟。
