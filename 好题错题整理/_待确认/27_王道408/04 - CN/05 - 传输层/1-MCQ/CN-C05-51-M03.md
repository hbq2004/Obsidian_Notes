# 选择题 第 3 题

![[_Attachments/题目识别/27_王道408-题目/CN-C05-51-M03_题目.png|题目]]

3. 下列关于传输层的面向连接服务特性的说法中，正确的是（  ）
(A) 不保证可靠和顺序交付
(B) 不保证可靠但保证顺序交付
(C) 保证可靠但不保证顺序交付
(D) 保证可靠和顺序交付

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C05-51-M03_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：D。传输层的面向连接服务（典型如 TCP）通过确认、重传、序号等机制同时保证可靠交付和顺序交付。

**解题切入点**：先抓住题干关键词“传输层”“面向连接服务”，马上定位到 TCP 的核心特性。可以把“面向连接”比作建立一条专用的“逻辑管道”，管道两端维护状态（如序号、确认号）。要判断“可靠”和“顺序”是否都被保证，相当于判断该管道是否同时具备“不丢包”和“不乱序”两个性质。在算法竞赛中，这类似判断一个数据结构是否同时支持“去重”和“有序输出”——TCP 用序号和滑动窗口同时解决了这两个问题。

**推演**：

- 传输层的两种服务：面向连接服务（如 TCP）和无连接服务（如 UDP）。
- 面向连接服务在通信前需要经过“三次握手”建立连接，通信结束后“四次挥手”释放连接。
- TCP 提供的主要保证：
  1. **可靠交付**：通过序号、确认（ACK）、超时重传、校验和等机制，确保数据无差错、不丢失、不重复地到达目的端。
  2. **顺序交付**：发送端给每个字节一个序号，接收端按序号排序后再交给应用层，因此即使 IP 层乱序到达，TCP 仍能恢复正确的顺序。
- 因此，面向连接服务同时满足“可靠”和“顺序”两个条件。

对应选项：
- (A) “不保证可靠和顺序交付”描述的是无连接服务 UDP 的某些特点，错误。
- (B) “不保证可靠但保证顺序交付”不合理，可靠性与顺序性在 TCP 中同时得到保证，错误。
- (C) “保证可靠但不保证顺序交付”忽略了 TCP 的序号排序机制，错误。
- (D) “保证可靠和顺序交付”正确，故选 D。

**易错点**：

- 混淆 TCP 与 UDP：UDP 只提供“尽力而为”的服务，不保证可靠，也不保证顺序，因此不要将 UDP 的特性套在“面向连接”上。
- 误以为“面向连接”只是建立连接，不代表可靠传输。但考研中“传输层的面向连接服务”通常具体指 TCP，默认包含可靠与顺序保证。
- 忽略“顺序交付”的含义：顺序交付不是指网络层按序到达，而是指接收端通过序号重组后按序提交给应用层。即便底层乱序，TCP 也能保证应用层看到的顺序正确。

**命题规律**：

- 考点定位：传输层服务特性，尤其是 TCP 与 UDP 的对比。
- 常见变式：  
  1. 直接问“UDP 的特点是？”——选“无连接、不可靠、不保证顺序”。  
  2. 给出一系列说法判断正误，如“TCP 保证可靠但不保证顺序”。  
  3. 结合“三次握手”“滑动窗口”考查可靠与顺序实现机制。
- 复习建议：牢记“面向连接 + TCP = 可靠 + 顺序”，“无连接 + UDP = 不可靠 + 不保证顺序”。同时理解 TCP 通过序号、确认、重传、滑动窗口保证可靠，通过序号排序保证顺序，这样即使变式也能稳拿分。
