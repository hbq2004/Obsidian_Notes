# 选择题 第 15 题

![[_Attachments/题目识别/27_王道408-题目/CN-C05-52-M15_题目.png|题目]]

15.【2018统考真题】UDP 实现分用时所依据的头部字段是（  ）

(A) 源端口号
(B) 目的端口号
(C) 长度
(D) 检验和

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C05-52-M15_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：B（目的端口号）。UDP 接收端根据首部中的目的端口号，将数据报交付给本机对应端口上的应用进程。

**解题切入点**：本题考点是传输层的“多路分用”（demultiplexing）。拿到题先抓两个词：“UDP”和“分用”。分用是接收方的动作，本质是“本机收到数据报后，应该交给哪个应用进程”。这就像在算法竞赛中，IP 层已经把数据“路由”到了当前节点，而 UDP 层需要在节点内部做一次“哈希查找”：

- 目的端口号 = 查找的 key / 数据结构下标；
- 源端口号 = 回信地址，不是本地索引；
- 长度 = 数据块大小；
- 检验和 = 完整性校验值，不参与索引。

分层协议类似“分治”：IP 解决“主机到主机”，UDP 解决“主机内进程到进程”。分治时每层只关心自己该用的 key，UDP 这层负责分用的 key 就是目的端口号。

**推演**：

UDP 首部共有 4 个字段：

$$
\text{UDP 首部} = \text{源端口号}(16\text{ bit}) + \text{目的端口号}(16\text{ bit}) + \text{长度}(16\text{ bit}) + \text{检验和}(16\text{ bit})
$$

接收端收到 UDP 数据报后，IP 层已经根据目的 IP 地址把数据报送到本机，接下来 UDP 层要完成主机内部分发。UDP 实现分用时可看作一张映射表：

$$
\text{目的端口号} \rightarrow \text{应用进程}
$$

因此 UDP 提取出首部中的目的端口号，用它查找本机端口表：

- 若找到对应端口，则把数据报交给该端口绑定的应用进程；
- 若找不到，则丢弃该数据报，并可能向源端发送“端口不可达”ICMP 报文。

其他字段的作用不是为了分用：

- 源端口号：主要用于对端回复报文时作为目的端口，不属于本端分用依据；
- 长度：只表示 UDP 数据报总长度，不参与进程匹配；
- 检验和：用于差错检测，检测失败时直接丢弃，也不用于分用。

因此 UDP 分用所依据的头部字段是目的端口号，选 B。

**易错点**：

- 易错选 A（源端口号）：源端口是“对方回复时用的地址”，不是本机分用时的查找 key。
- 易错选 C（长度）：长度只是报文大小，类似数组长度，不能作为进程索引。
- 易错选 D（检验和）：检验和用来保证数据完整性，出错时丢包，不能决定数据交给谁。
- 容易与 TCP 分用混淆：TCP 是面向连接的，分用通常需要匹配四元组（源 IP、源端口、目的 IP、目的端口）；UDP 无连接，分用时主要看目的端口号。

**命题规律**：本题属于传输层“端口号与复用/分用”的经典考点。2018 年统考直接考查了 UDP 分用字段，命题人喜欢把 UDP 与 TCP 对比出题，例如：

- UDP 分用依据是什么？
- TCP 分用需要哪些字段？
- 端口号范围是多少？
- 端口不可达由什么协议报告？

复习时要抓住本质：网络层按 IP 找主机，传输层按端口找进程。可以把传输层分用理解成“按 key 查表”，目的端口号就是 UDP 分用的唯一 key。理解了这一点，这类题无论怎么变都能快速定位。
