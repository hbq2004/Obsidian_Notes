# MCQ 第 28 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C01-S03-Q028_题目.png|题目]]

下列指令中,只能在内核态执行的是( ).
(A) $trap$ 指令
(B) $I/O$ 指令
(C) 数据传送指令
(D) 设置断点指令

## DeepSeek V4 Flash Max 解析
**答案**：  
$ \boxed{\text{B}} $

**解题切入点**：  
从特权指令与非特权指令的概念出发，区分内核态和用户态的执行边界。可将操作系统类比为算法竞赛平台——内核态是管理员后台，用户态是参赛者的提交环境。特权指令（如直接控制硬件）只有管理员才能执行，相当于只有 root 权限才能修改系统配置；而 $ \text{trap} $ 指令是用户程序主动请求系统服务的“软中断”，类似于提交一个 API 调用，用户在用户态即可执行；$ \text{I/O} $ 指令则直接操作外设，必须由操作系统统一管理，如同直接访问底层硬件资源只能由管理员控制。

**推演**：  
- $ \text{trap} $ 指令：用于系统调用，用户态程序通过执行 $ \text{trap} $ 陷入内核，因此用户态可执行，非特权。  
- $ \text{I/O} $ 指令：直接控制外设，若允许用户态执行会破坏系统安全与资源隔离，只能在内核态执行，属于特权指令。  
- 数据传送指令（如 $ \text{mov} $）：CPU 基本操作，用户态可执行，非特权。  
- 设置断点指令（如 $ \text{int3} $）：通常用于调试，用户态程序也可使用，不属于特权指令。  
综上，只有 $ \text{I/O} $ 指令满足“只能在内核态执行”的条件。

**易错点**：  
- 误认为 $ \text{trap} $ 指令是特权指令，因为它会触发模式切换，但其本身是用户态可执行的“陷入”指令，常用于系统调用。  
- 部分考生可能将设置断点指令视为特权指令，但在常见体系结构（如 x86）中，$ \text{int3} $ 是用户态可用的软中断，不属于特权指令。需结合教材典型定义区分。

**命题规律**：  
本题是考研操作系统基础题，考查特权指令的识别。常以选择题形式出现，要求考生熟记常见特权指令（如 $ \text{I/O} $ 指令、时钟指令、中断指令、内存管理指令等）与非特权指令（如算术运算、数据传送、$ \text{trap} $ 等）。备考时需结合具体 CPU 架构（如 x86）巩固记忆，并注意区分“用户态执行后会导致切换”的指令与“只能在内核态执行”的指令。
