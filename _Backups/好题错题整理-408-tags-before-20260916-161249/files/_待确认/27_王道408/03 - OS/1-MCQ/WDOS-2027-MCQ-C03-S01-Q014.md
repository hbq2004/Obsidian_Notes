# MCQ 第 14 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C03-S01-Q014_题目.png|题目]]

对重定位存储管理方式,应（ ）.
(A) 在整个系统中设置一个重定位寄存器
(B) 为每道程序设置一个重定位寄存器
(C) 为每道程序设置两个重定位寄存器
(D) 为每道程序和数据都设置一个重定位寄存器

## DeepSeek V4 Flash Max 解析
**答案**：
选 A。准确含义是：每个 CPU 只需要一个重定位寄存器，存放当前运行进程在内存中的起始地址（基址）。题目按经典单处理机系统命题，因此可表述为“整个系统设置一个重定位寄存器”。

**解题切入点**：
题目问的是“重定位方式需要几个寄存器”，本质是问地址变换发生在什么时刻、由谁完成、和当前进程如何对应。动态重定位的核心是
$$ PA = LA + \text{reloc} $$
其中 $\text{reloc}$ 是重定位寄存器中的基址。一个 CPU 同一时刻只执行一个进程，所以“当前进程”只有一个；重定位寄存器只需要保存“当前进程”的基址。这就像 DFS 中当前路径用一份全局 `cur` 记录，递归到每个状态时把 `cur` 保存在栈帧里，而不是给每个状态都复制一份 `cur`。

**推演**：
1. 设进程 $P$ 被装入物理地址 $base$。动态重定位时，硬件把逻辑地址 $LA$ 与重定位寄存器中的 $base$ 相加：
   $$ PA = LA + base $$
2. 当进程切换时，旧进程的重定位寄存器值先保存到它的 PCB 中；再从新进程的 PCB 中读出它的 base 装入重定位寄存器：
   $$ \text{reloc} \leftarrow \text{PCB}_{\text{new}}.\text{base} $$
   因此，寄存器数量不需要随程序道数增加，切换时“换值”即可。
3. 选项 B 错在把重定位寄存器当作每道程序的私有硬件；程序私有的只是 PCB 中的基址字段。选项 C 的两个寄存器没有依据；选项 D 把程序和数据分开重定位也无必要，同一个进程的代码和数据在连续分配方式下共用同一个基址映射。

**易错点**：
- 易错选 B：以为“每道程序地址不同，就要有各自的重定位寄存器”。实际上，寄存器是 CPU 执行现场的一部分，同一时刻只有当前进程在用；其他进程的基址保存在 PCB 中。这与“每个状态都复制一份数组”相比，“全局数组 + 回溯/恢复现场”才是更省的做法。
- 不要把“重定位寄存器”和“界限寄存器”混淆。若考虑越界保护，通常还要配一个界限寄存器判断 $LA < \text{limit}$，但这是另一个寄存器，不是两个重定位寄存器。
- 不要忘了动态重定位的地址加法由硬件完成；OS 只在进程切换或程序移动后修改寄存器/PCB 中的基址。静态重定位则不需要这个寄存器，但程序装入后不能移动。

**命题规律**：
408 和经典 OS 选择题常把“动态重定位”设为一个概念题，考点集中在：
- 地址映射公式 $PA = LA + \text{reloc}$；
- 重定位寄存器是“每 CPU 一个”，不是“每进程一个”；
- 进程切换时要保存/恢复重定位寄存器；
- 与“紧凑”“可重定位分区分配”结合，说明程序在内存中移动后只需修改基址，不必改程序内部地址。

这类题本质上考“寄存器是 CPU 共享的当前状态，不是进程的持久化存储”。可以类比图论匹配中的全局匹配集：匹配边不是每个点一条私有边，而是整个算法维护一份全局匹配，增广/修改时只更新全局状态，必要时把旧状态记录在路径上用于回溯。
