# MCQ 第 29 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S02-Q029_题目.png|题目]]

假设系统采用多级反馈队列调度算法，系统中设置了三个不同优先级的队列 $A、$B 和 $C，优先级 $A>B>C，$A 的时间片为 $10ms，$B 的时间片为 $20ms，$C 的时间片为 $30ms。当 $t=0 时，进程 $P\_1 到达，$P_1 所需的运行时间为 $90ms；当 $t=30ms 时，进程 $P\_2 到达，$P_2 所需的运行时间为 $30ms，不考虑任何其他系统开销，进程 $P_1 的周转时间为（  ）
(A) $90ms$
(B) $100ms$
(C) $110ms$
(D) $120ms$

## DeepSeek V4 Flash Max 解析
**答案**：

选 **D**。$P_1$ 最终完成时刻为 $t=120\ \mathrm{ms}$，到达时刻为 $t=0$，所以：

$$
T_{P_1}=t_{\text{完成}}-t_{\text{到达}}=120-0=120\ \mathrm{ms}
$$

---

**解题切入点**：

多级反馈队列调度本质上是一个“抢占式状态机模拟题”。

可以这样理解：每个进程的状态是“当前所在队列 + 当前时间片内已运行时间 + 剩余运行时间”。事件只有两类：

1. 新进程到达；
2. 当前时间片用完。

算法竞赛视角：这就像在时间轴上做事件驱动模拟，维护多个队列；高优先级队列非空时，低优先级队列不能运行。不要试图直接拿总运行时间去算完成时刻，而要像“按时间片逐段推进”的状态搜索。

---

**推演**：

| 时间 | 调度事件 | 运行结果 |
|---|---|---|
| $t=0$ | $P_1$ 进入 A 队，运行 $0\sim10\ \mathrm{ms}$ | $P_1$ 剩余 $80\ \mathrm{ms}$，降入 B 队 |
| $t=10$ | $P_1$ 在 B 队运行 $10\sim30\ \mathrm{ms}$ | $P_1$ 剩余 $60\ \mathrm{ms}$，降入 C 队 |
| $t=30$ | $P_2$ 到达进入 A 队，抢占 CPU；$P_2$ 运行 $30\sim40\ \mathrm{ms}$ | $P_2$ 剩余 $20\ \mathrm{ms}$，降入 B 队 |
| $t=40$ | B 队有 $P_2$，C 队有 $P_1$；$P_2$ 运行 $40\sim60\ \mathrm{ms}$ | $P_2$ 正好完成 |
| $t=60$ | 只剩 $P_1$ 在 C 队，运行 $60\sim90\ \mathrm{ms}$ | $P_1$ 剩余 $30\ \mathrm{ms}$ |
| $t=90$ | $P_1$ 继续在 C 队运行 $90\sim120\ \mathrm{ms}$ | $P_1$ 完成 |

所以：

$$
P_1 \text{ 的周转时间}=120-0=120\ \mathrm{ms}
$$

选 **D**。

---

**易错点**：

1. 把周转时间直接算成 $P_1$ 的运行时间 $90\ \mathrm{ms}$，忽略了 $P_2$ 在 $t=30$ 到达后会抢占 CPU。
2. 把新到达的 $P_2$ 放错队列。多级反馈队列中，新进程总是进入最高优先级 A 队，而不是按进程长度预先放入 B 或 C。
3. 忽略 $t=30$ 时 $P_1$ 的 B 队时间片也恰好用完，因此 $P_1$ 应降入 C 队。
4. 忘记最低优先级队列 C 也有时间片限制。本题中 C 队只有 $P_1$，所以 $60\sim90\ \mathrm{ms}$ 后还需要再运行 $90\sim120\ \mathrm{ms}$。
5. 混淆“运行时间”和“周转时间”。周转时间 = 完成时刻 $-$ 到达时刻，不是累计 CPU 运行时间。

---

**命题规律**：

408 操作系统喜欢用“多级反馈队列 + 抢占 + 多时间片”出小型计算题，核心考察对调度过程的精确跟踪。

这类题的通用解法就是“画时间轴 + 维护各队列状态”。就像算法竞赛中的模拟题，状态转移不复杂，但必须按时间顺序逐步推演。

后续变式可能包括：多个进程同时在队列中轮转、增加 I/O 等待时间、或者询问平均周转时间。只要抓住“当前队列、时间片余量、剩余运行时间”这三个核心量，就不会出错。
