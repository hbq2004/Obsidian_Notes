16. 以下排序算法中,稳定的是 ( ).

## DeepSeek V4 Flash Max 解析

**答案**：稳定排序算法为 **C. 直接插入排序**。

**解题切入点**：本题直接考查排序算法的稳定性，属于概念记忆型题目。拿到题先回忆“稳定性”的定义：若排序前后相等元素的相对次序不变，则称该排序算法是稳定的。务必把常见排序算法的稳定性结论记牢，尤其是快速排序、堆排序和简单选择排序均为不稳定，直接插入排序为稳定。

**推演**：

1. **稳定性定义**  
   设待排序序列中有两个相等元素 $a_i$ 与 $a_j$（$i<j$），若排序后 $a_i$ 仍位于 $a_j$ 之前，则算法是稳定的；否则不稳定。

2. **逐项分析**  
   - **A. 快速排序**  
     快速排序的分区操作会跨越式地交换元素。例如，以基准元素进行划分时，可能与距离较远的元素交换，导致相等元素的相对位置发生改变。  
     最典型例子：序列 $\{3, 3', 1\}$，以第一个 $3$ 为基准，一趟划分后可能得到 $\{1, 3', 3\}$，两个相等的 $3$ 相对次序改变，故快速排序不稳定。
   
   - **B. 堆排序**  
     堆排序在筛选（调整堆）过程中，父子结点之间进行交换，这种交换可能跨越多个位置，且无法保证相等元素的相对次序。例如，序列 $\{5, 5', 3\}$ 建堆或调整时，可能使 $5$ 与 $5'$ 互换位置，故堆排序不稳定。
   
   - **C. 直接插入排序**  
     算法思想：将待排序元素依次插入到前面已有序的序列中。插入时，从后向前比较，若遇到相等元素，则将新元素插入到该相等元素之后，而不是之前，因此相等元素的相对次序保持不变。  
     伪代码核心：
     ```
     for i = 2 to n:
         temp = A[i]
         j = i - 1
         while j >= 1 and A[j] > temp:   // 注意是严格大于，相等时不移动
             A[j+1] = A[j]
             j--
         A[j+1] = temp
     ```
     由于 `A[j] > temp` 采用严格大于，相等元素不会被交换，所以直接插入排序是稳定的。
   
   - **D. 简单选择排序**  
     每趟选择最小（或最大）元素与当前位置元素交换，若最小元素与某个相等元素交换，可能破坏相对次序。  
     例：序列 $\{2, 2', 1\}$，第一趟选出最小元素 $1$ 与第一个 $2$ 交换，得 $\{1, 2', 2\}$，两个相等的 $2$ 次序变为 $2'$ 在前，故不稳定。

3. **结论**：四个选项中，只有直接插入排序是稳定的，故选 **C**。

**易错点**：
- **混淆“选择排序”与“插入排序”**：简单选择排序不稳定，直接插入排序稳定，二者名称相似但稳定性不同。
- **对“稳定”理解偏差**：稳定不是指排序结果唯一，而是相等元素的相对次序不变。部分考生误以为“时间复杂度低”或“基于比较”就稳定，均不对。
- **记忆口诀错误**：常见口诀“快选堆希不稳定”（快速、选择、堆、希尔不稳定），背诵时注意“选择”指简单选择排序，不要漏掉或错记。
- **忽略实现细节**：直接插入排序若实现为 `while j >= 1 and A[j] >= temp`，则相等元素会移动，导致不稳定。408 教材默认采用严格大于的判断，需注意标准写法。

**命题规律**：
- 本题是选择题中的基础送分题，通常出现在“排序”章节的概念题中，难度较低。
- 常考变式：给出多个排序算法判断稳定性；或结合具体序列（如 $\{2,2',1\}$）要求选出不稳定算法的一趟排序结果；也可能与快速排序、堆排序的“不稳定性”证明结合出题。
- 复习建议：将常见排序算法的稳定性、时间复杂度、空间复杂度、是否基于比较等性质整理成表格，反复记忆。同时理解不稳定算法为何不稳定（如交换跨越式进行），能够举出反例，这样即使题目改变形式也能应对。
