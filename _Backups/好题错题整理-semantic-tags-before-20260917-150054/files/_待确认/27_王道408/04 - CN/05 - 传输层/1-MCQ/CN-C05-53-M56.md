# 选择题 第 56 题

![[_Attachments/题目识别/27_王道408-题目/CN-C05-53-M56_题目.png|题目]]

56.【2021统考真题】设主机甲通过 TCP 向主机乙发送数据，部分过程如下图所示。甲在 $t_0$ 时刻发送一个序号 $seq = 501$、封装 $200B$ 数据的段，在 $t_1$ 时刻收到乙发送的序号 $seq = 601$、确认序号 $ack\_seq = 501$、接收窗口 $rcvwnd = 500B$ 的段，则甲在未收到新的确认段之前，可以继续向乙发送的数据序号范围是 ( )

【图：TCP 报文段交互时序图。左侧为甲主机，右侧为乙主机，时间轴竖直向下。在 $t_0$ 时刻甲向乙发送 $seq=501$、$200B$ 数据段；在 $t_1$ 时刻乙向甲发送 $seq=601$、$ack\_seq=501$、$rcvwnd=500B$ 段。】

(A) 501 ~ 1000  
(B) 601 ~ 1100  
(C) 701 ~ 1000  
(D) 801 ~ 1100

## DeepSeek V4 Flash Max 解析

**答案**：C。甲在 $t_0$ 已发送 $seq=501$ 开始的 200B，即字节 $501\sim700$；$t_1$ 收到 $ack\_seq=501$、$rcvwnd=500B$，说明发送窗口左边界仍为 501，右边界为 $501+500-1=1000$，所以未收到新确认前可继续发送的新数据序号为 $701\sim1000$。

**解题切入点**：把 TCP 发送窗口看成算法题里的双指针区间：左指针是累计确认号 $L=ack\_seq$，右指针是 $L+rcvwnd$，当前已发送位置是 $cur$。能“继续发送”的区间就是 $[cur,R)$。本题先由数据段长度求出 $cur=701$，再由接收窗口求出右边界 $1000$。乙发来的 $seq=601$ 是乙自己发送方向的序号，与甲发送窗口无关，是干扰信息。

**推演**：

TCP 按字节流编号，$seq=501$、封装 200B 数据，则该段覆盖序号：

$$501,502,\dots,700$$

下一个待发送字节序号为：

$$\mathrm{SND.NXT}=501+200=701$$

收到 $ack\_seq=501$ 表示乙期待的下一个字节序号仍是 501，即累计确认到 500。因此发送窗口左边界为：

$$\mathrm{SND.UNA}=501$$

接收窗口 $rcvwnd=500B$。若严格按 TCP 发送窗口公式，窗口大小为 $\min(\text{cwnd},rcvwnd)$；题目未给 $cwnd$，按 $cwnd$ 不构成瓶颈处理，则发送窗口：

$$W_s=500B$$

窗口右边界：

$$\text{右边界}=501+500-1=1000$$

所以窗口内允许的字节序号是 $501\sim1000$。但其中 $501\sim700$ 在 $t_0$ 已发送，占用了 200B 的窗口；还能继续发送的数据量是：

$$500-200=300B$$

从当前待发序号 701 开始，可发送：

$$701\sim701+300-1=701\sim1000$$

若用左闭右开区间表示，则可继续发送区间是 $[701,1001)$，对应离散序号 $701\sim1000$。

**易错点**：

1. 误以为 $ack\_seq=501$ 表示“确认了序号 501 的段”。TCP 确认号是累计确认，$ack\_seq=501$ 表示乙期望收到的下一字节是 501，并不确认 501$\sim$700 这段数据；若确认了该段，$ack\_seq$ 应为 701。  
2. 把乙发来的 $seq=601$ 当成甲的发送窗口左边界，导致误选 B。TCP 是全双工的，两个方向的序号空间相互独立。  
3. 算出窗口范围 $501\sim1000$ 后直接选 A，忘记题目问的是“继续发送”，要扣除已经发送的 200B 数据。  
4. 序号个数算错：$501\sim700$ 共 $700-501+1=200$ 个字节，不能按“末序号减首序号”得到 199。

**命题规律**：考点是 TCP 可靠传输中的序号、确认号与滑动窗口。常见变式包括：给定 $ack\_seq$、$rcvwnd$ 和已经发送的数据量，求还能发送多少字节、下一个待发序号、窗口右边界；有时还结合拥塞窗口，要求计算 $\min(cwnd,rwnd)$。复习时应把 TCP 发送窗口看成“左端由累计 ACK 决定，右端由接收窗口/拥塞窗口决定”的滑动区间，并注意区分发送方的 $seq$ 与 ACK 中的 $ack\_seq$。
