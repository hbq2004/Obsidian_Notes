# 选择题 第 15 题

![[_Attachments/题目识别/27_王道408-题目/DS-C06-62-M15_题目.png|题目]]

15. 设$n$个顶点、e条边的有向图用邻接表表示，则求某顶点$v$的入度的时间复杂度为 (  ).
A. $O(n)$
B. $O(\mathrm{e})$
C. $O(n+\mathrm{e})$
D. $O(n\mathrm{e})$

## 答案

![[_Attachments/题目识别/27_王道408-答案/DS-C06-62-M15_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：选 C，$O(n+\mathrm{e})$。求某顶点 $v$ 的入度需遍历邻接表中全部 $n$ 个头结点和 $e$ 个边结点。

**解题切入点**：先抓住“存储结构 + 所求操作”的对应关系。有向图普通邻接表存的是“从某个顶点出发的边”，而入度是“指向 $v$ 的边”，属于反向信息。可以这样理解：手里只有“我关注了谁”的名单，要查“谁关注了我”，只能翻遍所有人的关注名单。

**推演**：

设该有向图为 $G=(V,E)$，其中 $|V|=n$，$|E|=\mathrm{e}$。邻接表为每个顶点 $u$ 建立一条链表，链表中的每个结点对应一条从 $u$ 出发的有向边 $(u,w)$。

顶点 $v$ 的入度定义为：

$$
\mathrm{indeg}(v)=|\{(u,v)\in E\}|
$$

因为 $v$ 可能是任意顶点 $u$ 的出边终点，所以不能只查 $v$ 自己的邻接链表。必须扫描所有顶点的邻接链表，统计“终点为 $v$”的边结点个数。

算法核心过程如下：

```c
int Indegree(Graph G, int v) {
    int cnt = 0;
    for (int i = 0; i < G.vexnum; ++i) {       // 遍历 n 个头结点
        ArcNode *p = G.vertices[i].first;
        while (p != NULL) {                    // 遍历该顶点的出边链表
            if (p->adjvex == v)
                ++cnt;
            p = p->next;
        }
    }
    return cnt;
}
```

该过程需要访问 $n$ 个头结点，并遍历所有边结点；所有邻接链表中的边结点总数恰好为 $e$。因此总时间复杂度为：

$$
O(n+\mathrm{e})
$$

严格地说，在标准邻接表实现下，求单个顶点的入度需要检查所有 $n$ 个头结点和所有 $e$ 个边结点，所以量级为 $\Theta(n+\mathrm{e})$。

**易错点**：

- 误选 B：$O(\mathrm{e})$。只想到要遍历所有边，却忽略了邻接表还需要通过 $n$ 个头结点才能访问这些边，空链表也要判断。
- 误选 A：$O(n)$。把入度和出度搞混了。邻接表中求 $v$ 的出度可以只遍历 $v$ 的链表，但求入度不能只查 $v$ 的链表。
- 误选 D：$O(n\mathrm{e})$。没有理解所有邻接链表中的边结点总数是 $e$，而不是每个顶点的链表都有 $e$ 个结点。
- 若题目改为“逆邻接表”求 $v$ 的入度，则只需查 $v$ 的逆邻接链表，复杂度约为 $O(1+\mathrm{indeg}(v))$，不能与本题混淆。

**命题规律**：本题是“图的存储结构 + 基本操作复杂度”的经典考点。408 中常与邻接矩阵、邻接表、逆邻接表、十字链表对比考查。常见变式有：

1. 邻接矩阵求有向图某顶点入度/出度：$O(n)$。
2. 邻接表求某顶点出度：只遍历该顶点链表，$O(1+\mathrm{outdeg}(v))$。
3. 邻接表求所有顶点的入度：初始化入度数组后扫描全部边结点，$O(n+\mathrm{e})$。
4. 逆邻接表求入度、十字链表同时求入度和出度等。

复习时建议把各存储结构下“求入度、求出度、判断边是否存在、找邻接点”的复杂度整理成表，并注意 $n$ 与 $\mathrm{e}$ 不能相互省略。
