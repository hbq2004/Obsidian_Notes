# MCQ 第 26 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S03-Q026_题目.png|题目]]

一个进程因在互斥信号量 $mutex$ 上执行 $V(mutex)$ 操作而导致唤醒另一个进程时，执行 $V$ 操作后 $mutex$ 的值为 ( )
(A) 大于 $0$
(B) 小于 $0$
(C) 大于等于 $0$
(D) 小于等于 $0$

## DeepSeek V4 Flash Max 解析
**答案**：D. 小于等于 $0$（即 $mutex \le 0$）

**解题切入点**：  
从信号量 $V$ 操作的定义入手：$V(mutex)$ 使 $mutex$ 加 $1$，若加 $1$ 后 $mutex \le 0$，则唤醒一个等待进程。题目中 $V$ 操作导致了唤醒，故加 $1$ 后必然满足 $mutex \le 0$，因此 $V$ 操作后 $mutex$ 的值一定小于等于 $0$。这类似于算法竞赛中的“状态机”设计——触发条件（唤醒）对应状态转移的约束，必须满足特定条件才能进入下一状态。

**推演**：  
设互斥信号量 $mutex$ 初值为 $1$（表示资源可用）。  
- 进程 A 执行 $P(mutex)$：$mutex = 0$，A 进入临界区。  
- 进程 B 执行 $P(mutex)$：$mutex = -1$，B 阻塞（等待队列非空）。  
- 进程 A 执行 $V(mutex)$：$mutex = -1 + 1 = 0$，此时 $mutex \le 0$，故唤醒 B。$V$ 操作后 $mutex = 0$。  
若多个进程等待（如 $mutex = -2$），则 $V$ 操作后 $mutex = -1$，仍 $\le 0$。  
因此，只要 $V$ 操作唤醒了一个进程，$V$ 操作后的 $mutex$ 必满足 $\le 0$。这类似于图论中的“匹配”过程：资源分配后剩余容量非正时才需要从等待队列中调度。

**易错点**：  
- 误认为唤醒时 $mutex$ 一定为 $0$，忽略多进程等待时可能为负（如 $-1$）。  
- 混淆信号量正负含义：$V$ 操作后 $mutex$ 可能为 $0$ 或负数，但不会为正（若为正则无等待进程，不会唤醒）。  
- 将“互斥信号量”与“计数信号量”的初值混淆，但唤醒条件本质相同。

**命题规律**：  
考查信号量 $P$、$V$ 操作的核心机制，特别是 $V$ 操作唤醒条件的判断。常结合多进程并发场景，要求分析 $V$ 操作前后信号量的取值范围，或与 $P$ 操作对比。理解负值代表等待进程数是关键，类似算法竞赛中“构造题”需严格按定义推导，不可凭直觉。
