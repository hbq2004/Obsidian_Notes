# 综合题 第 4 题

![[_Attachments/题目识别/27_王道408-题目/CO-C03-35-F04_题目.png|题目]]

4.【2011统考真题】某计算机的主存地址空间大小为256MB，按字节编址. 指令Cache和数据Cache分离，均有8个Cache行，每个Cache行大小为64B，数据Cache采用直接映射方式. 现有两个功能相同的程序A和B，其伪代码如下所示：

程序 A:
```c
int a[256][256];
...
int sum_array1() {
    int i, j, sum=0;
    for(i=0; i<256; i++)
        for(j=0; j<256; j++)
            sum+=a[i][j];
    return sum;
}
```
程序 B:
```c
int a[256][256];
...
int sum_array2() {
    int i, j, sum=0;
    for(j=0; j<256; j++)
        for(i=0; i<256; i++)
            sum+=a[i][j];
    return sum;
}
```
假定int型数据用32位补码表示，程序编译时，$i$、$j$和$sum$均分配在寄存器中，数组$a$按行优先方式存放，其首地址为320（十进制数）. 回答下列问题，要求说明理由或给出计算过程.
(1) 不考虑用于Cache一致性维护和替换算法的控制位，数据Cache的总容量为多少？
(2) 数组元素$a[0][31]$和$a[1][1]$各自所在的主存块对应的Cache行号是多少（Cache行号从0开始）？
(3) 程序A和B的数据访问命中率各是多少？哪个程序的执行时间更短？

## 答案

![[_Attachments/题目识别/27_王道408-答案/CO-C03-35-F04_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：  
(1) 数据Cache的总容量为532 B（或4256 bit）。  
(2) 数组元素 $a[0][31]$ 所在主存块对应的Cache行号为6，$a[1][1]$ 对应的Cache行号为5。  
(3) 程序A的数据访问命中率为93.75%，程序B的命中率为0，程序A的执行时间更短。

**解题切入点**：  
首先明确直接映射Cache的地址划分（标记、行索引、块内偏移），根据主存空间大小、Cache行数和块大小计算出各字段位数，进而得到Cache总容量。对于数组元素的Cache行号，先计算元素的主存地址，再除以块大小得到块号，块号对Cache行数取模即得行号。命中率分析需结合数组的存储顺序（行优先）和访问模式（行优先/列优先），考虑每个主存块内元素是否连续访问以及Cache冲突情况。程序A按行访问，每个块内16个元素连续访问，故除第一次缺失外其余15次均命中；程序B按列访问，同一列的所有元素映射到同一Cache行且每次访问不同块，产生大量冲突，导致全部缺失。

**推演**：  

1. **数据Cache总容量**  
   - 主存地址空间 $256\text{MB} = 2^{28}\text{B}$，地址位数 $28$。  
   - 每个Cache行大小 $64\text{B}=2^6\text{B}$，故块内偏移位数 $b=6$。  
   - Cache行数 $8=2^3$，故行索引位数 $r=3$。  
   - 标记位数 $t = 28 - b - r = 28-6-3=19$。  
   - 每个Cache行包括：数据 $64\text{B}=512\text{bit}$，标记 $19\text{bit}$，有效位 $1\text{bit}$（不考虑其他控制位）。  
   - 总容量 $= 8 \times (512+19+1) = 8 \times 532 = 4256\text{bit} = 532\text{B}$。  

2. **数组元素的Cache行号**  
   - 数组首地址 $320$，int 占 $4\text{B}$，按行优先存储。  
   - $a[0][31]$ 地址：$320 + 31 \times 4 = 320 + 124 = 444$。  
     块号 $= \lfloor 444/64 \rfloor = 6$（$6\times 64=384$，$7\times 64=448$），行号 $= 6 \bmod 8 = 6$。  
   - $a[1][1]$ 地址：$320 + 1 \times 256 \times 4 + 1 \times 4 = 320 + 1024 + 4 = 1348$。  
     块号 $= \lfloor 1348/64 \rfloor = 21$（$21\times 64=1344$），行号 $= 21 \bmod 8 = 5$。  

3. **命中率分析**  
   - 数组总大小 $256 \times 256 \times 4\text{B} = 256\text{KB}$，总块数 $= \frac{256\text{KB}}{64\text{B}} = 4096$，每块含 $16$ 个int。  
   - **程序A**（按行访问）：  
     每一行内，访问顺序为连续地址。对于每个块，$16$ 个元素连续访问，第一次访问缺失并调入，后续 $15$ 次命中。行内无其他块干扰，故每块 $1$ 次缺失、$15$ 次命中。  
     总访问次数 $= 256 \times 256 = 65536$，总缺失次数 $= 4096$，命中次数 $= 65536-4096=61440$，命中率 $= \frac{61440}{65536}=93.75\%$。  
   - **程序B**（按列访问）：  
     固定列 $j$，所有 $i$ 的元素地址为 $320 + i \cdot 1024 + j \cdot 4$，块号 $= 5 + i \cdot 16 + \lfloor j/16 \rfloor$。由于 $i\cdot 16$ 是 $8$ 的倍数，故所有 $i$ 的块号模 $8$ 相同，即同一列的所有元素映射到同一Cache行。  
     对于一列，$i$ 从 $0$ 到 $255$，依次访问 $256$ 个不同块，每个块第一次访问时缺失，且立即被下一块替换。后续列中，同一块再次出现时，因已被替换仍缺失。故每一列 $256$ 次访问全部缺失，总缺失 $256 \times 256 = 65536$，命中率 $0$。  
   - 因此程序A的执行时间更短。

**易错点**：  
- 计算Cache行号时，误将元素地址直接对8取模而忽略块内偏移，正确做法是先求块号再取模。  
- 计算Cache总容量时，遗漏标记位或有效位，或错误认为只算数据部分。注意题目明确“不考虑一致性维护和替换算法控制位”，但有效位和标记位必须计入。  
- 分析命中率时，忽略程序B中同一列内元素映射到同一Cache行导致的冲突，误以为每个块能连续访问而得到非零命中率。  
- 混淆行优先与列优先对Cache行为的影响，需结合地址计算及直接映射的冲突特性。

**命题规律**：  
本题是直接映射Cache的典型考题，重点考查地址划分、容量计算、数组访问命中率分析。常见变式包括：改变映射方式（全相联、组相联）、改变数组大小或块大小、加入循环多次访问等。复习时应熟练掌握地址结构、标记/有效位计算，并能根据访问模式分析冲突情况。对于数组类问题，务必明确存储方式（行优先/列优先）和访问顺序，通过绘制地址映射关系或模拟少量元素来理解规律。
