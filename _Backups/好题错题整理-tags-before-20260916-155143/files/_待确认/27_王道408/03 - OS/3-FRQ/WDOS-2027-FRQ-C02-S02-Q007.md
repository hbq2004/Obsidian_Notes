# FRQ 第 7 题

![[_Attachments/题目识别/WDOS-2027-FRQ/WDOS-2027-FRQ-C02-S02-Q007_题目.png|题目]]

7. 假设一个计算机系统具有如下性能特征：处理一次中断平均需要花费 $500\mu s$，一次进程调度平均需要花费 $1ms$，进程的切换平均需要花费 $2ms$。若该计算机系统定时器每秒发出 120 次时钟中断，忽略其他 $I/O$ 中断的影响，请问：
(I) 操作系统将百分之几的 $CPU$ 时间分配给时钟中断处理程序？
(II) 若系统采用时间片轮转调度算法，24 个时钟中断为一个时间片，操作系统每进行一次进程的切换，需要花费百分之几的 $CPU$ 时间？
(III) 根据上述结果，说明为了提高 $CPU$ 的使用效率，可以采用什么对策.

## DeepSeek V4 Flash Max 解析
**答案**：
(I) $6\%$； (II) $1.5\%$； (III) 适当降低时钟中断频率（如减少每秒定时器中断次数）或增大时间片长度（即增加每个时间片包含的时钟中断数），从而减少进程调度和切换的次数；同时优化中断处理、调度和切换过程（如使用硬件支持，缩短每次开销），以提高 $CPU$ 利用率。

**解题切入点**：
计算系统开销的 $CPU$ 占比，关键是确定各事件每秒发生的次数和每次花费的时间。 （I）时钟中断处理：每秒 $120$ 次中断，每次 $500\mu s$，直接相乘即得总时间，再除以 $1s$ 得百分比。 （II）时间片轮转调度：$24$ 个时钟中断为一个时间片，所以时间片长度 $= 24 \times (1/120)s = 0.2s$，每秒有 $5$ 个时间片，即每秒进行 $5$ 次进程切换（包括调度和上下文切换）。每次切换开销为 $1ms$（调度）$+2ms$（切换）$=3ms$，从而计算总时间占比。 （III）根据结果，系统开销主要来自时钟中断和进程切换，要提高效率需减少这些开销的频率或单次耗时。 可将此问题类比为算法竞赛中的“时间复杂度分析”：总时间开销 $= 次数 \times 单次开销$，优化方向就是降低次数或单次代价。

**推演**：
(I) 每秒 $120$ 次时钟中断，每次中断处理需 $500\mu s = 500 \times 10^{-6} s = 0.0005s$。  
每秒用于中断处理的总时间 $T_{int} = 120 \times 0.0005s = 0.06s$。  
故 $CPU$ 占比 $= \dfrac{0.06}{1} \times 100\% = 6\%$。

(II) 时钟中断间隔 $= \dfrac{1}{120}s$。  
时间片 $= 24 \times \dfrac{1}{120}s = \dfrac{24}{120}s = 0.2s$。  
每秒时间片个数 $= \dfrac{1}{0.2} = 5$，即每秒进行 $5$ 次进程调度和切换。  
每次进程调度耗时 $1ms = 0.001s$，每次进程切换耗时 $2ms = 0.002s$，  
故每秒用于调度和切换的总时间 $T_{sched} = 5 \times (0.001+0.002)s = 5 \times 0.003s = 0.015s$。  
$CPU$ 占比 $= \dfrac{0.015}{1} \times 100\% = 1.5\%$。

(III) 由 (I)(II) 知，时钟中断处理占 $6\%$，进程调度和切换占 $1.5\%$，合计 $7.5\%$ 的 $CPU$ 时间花费在系统开销上。为提高 $CPU$ 利用率，可采取以下对策：  
- 减少时钟中断频率（例如降低定时器节拍率），从而减少中断处理时间以及调度切换的发生次数；  
- 增大时间片（即增加每个时间片包含的时钟中断数），使得单位时间内调度切换次数减少，但时间片过大可能影响交互性；  
- 优化中断处理程序、调度算法和上下文切换机制（如使用硬件加速、快速上下文切换技术），降低每次开销。

**易错点**：
1. 单位换算错误：$500\mu s$ 误为 $0.5ms$ 或 $0.0005s$，但计算时需统一单位（如秒）。  
2. 混淆“进程调度”和“进程切换”：前者是选择下一个进程，后者是保存/恢复上下文，二者在时间片轮转中都会发生，需相加。  
3. 错误计算时间片长度：$24$ 个时钟中断的时间片应为 $24 \times (1/120)s = 0.2s$，而非 $24/120s$ 以外的错误值。  
4. 误认为每个时钟中断都触发调度和切换，实际只有时间片耗尽（即第 $24$ 个中断）时才进行。  
5. 在计算 $(II)$ 时遗漏调度时间或只考虑切换时间，导致结果错误。  
6. 对策部分可能忽略“增大时间片”或“减少中断频率”带来的副作用（如响应变慢），但题目只要求说明提高效率的对策，指出方向即可。

**命题规律**：
此类题目是操作系统“时间开销分析”的典型考法，常结合中断处理、进程调度、上下文切换等概念，考察学生对系统事件频率和开销的理解。命题方式通常给出各操作的时间开销，然后设定某种调度策略（如时间片轮转），计算 $CPU$ 时间分配比例，并据此提出优化建议。难度中等，关键在于正确识别各事件的发生次数。与算法竞赛中的“复杂度分析”类似，需将“总时间 = 次数 × 单次时间”的思想迁移到系统开销计算中。未来考题可能变化：调整中断频率、时间片大小、引入设备中断，或换用多级队列调度等，但分析思路一致。
