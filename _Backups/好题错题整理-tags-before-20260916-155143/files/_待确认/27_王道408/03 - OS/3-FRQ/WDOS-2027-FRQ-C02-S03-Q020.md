# FRQ 第 20 题

![[_Attachments/题目识别/WDOS-2027-FRQ/WDOS-2027-FRQ-C02-S03-Q020_题目.png|题目]]

系统中有多个生产者进程和多个消费者进程,共享一个能存放 1000 件产品的环形缓冲区 (初始为空). 缓冲区未满时,生产者进程可以放入其生产的一件产品,否则等待;缓冲区未空时,消费者进程可从缓冲区取走一件产品,否则等待. 要求一个消费者进程从缓冲区连续取出 10 件产品后,其他消费者进程才可以取产品. 请使用信号 $P,V$ [或 $wait(),signal()$] 操作实现进程间的互斥与同步,要求写出完整的过程,并说明所用信号量的含义和初值.

## DeepSeek V4 Flash Max 解析
**答案**：

用 $P$ 表示 $\mathrm{wait}$，$V$ 表示 $\mathrm{signal}$。定义信号量：

- $\text{mutex}=1$：保护环形缓冲区以及 $\mathit{in},\mathit{out}$ 指针的互斥信号量；
- $\text{empty}=1000$：缓冲区空位数，初值为缓冲区容量；
- $\text{full}=0$：缓冲区产品数，初值为 $0$；
- $\text{consumer\_mutex}=1$：消费者“批次”互斥信号量，保证一个消费者连续取 $10$ 件产品期间，其他消费者不能取产品。

设环形缓冲区为 `buffer[1000]`，$ \mathit{in}=0,\ \mathit{out}=0 $。完整过程如下：

```c
semaphore mutex = 1;
semaphore empty = 1000;
semaphore full = 0;
semaphore consumer_mutex = 1;

item buffer[1000];
int in = 0, out = 0;

void producer() {
    while (true) {
        item p = produce();

        P(empty);        // 申请一个空位
        P(mutex);        // 进入缓冲区临界区
        buffer[in] = p;
        in = (in + 1) % 1000;
        V(mutex);        // 离开缓冲区临界区
        V(full);         // 增加一件产品
    }
}

void consumer() {
    while (true) {
        item batch[10];

        P(consumer_mutex);          // 一个消费者进入“连续取 10 件”批次
        for (int i = 0; i < 10; ++i) {
            P(full);                // 申请一件产品
            P(mutex);               // 进入缓冲区临界区
            batch[i] = buffer[out];
            out = (out + 1) % 1000;
            V(mutex);               // 离开缓冲区临界区
            V(empty);               // 增加一个空位
        }
        V(consumer_mutex);          // 取完 10 件，允许其他消费者取

        for (int i = 0; i < 10; ++i) {
            consume(batch[i]);
        }
    }
}
```

**解题切入点**：

这道题本质上是“生产者—消费者模型”加上一个“消费者批次限制”。

先识别资源：

- 缓冲区空位是生产者需要的资源，用 $\text{empty}$ 计数；
- 缓冲区产品是消费者需要的资源，用 $\text{full}$ 计数；
- 环形缓冲区本身是共享数据结构，用 $\text{mutex}$ 保护。

额外限制“一个消费者连续取 $10$ 件后，其他消费者才能取”等价于：消费者的 $10$ 次取操作必须作为一个整体临界区。因此再加一个互斥信号量 $\text{consumer\_mutex}$，包住消费者的整个 $10$ 次循环。

这很像算法竞赛中的“构造题”：不要在基础模型上乱加复杂逻辑，而是先写出标准生产者—消费者模板，再把额外限制抽象成一把“批次锁”。

**推演**：

- 缓冲区容量约束：

初始时 $\text{full}=0$，$\text{empty}=1000$，满足：

$$
\text{full}+\text{empty}=1000
$$

生产者每次先 $P(\text{empty})$，再放产品，最后 $V(\text{full})$；消费者每次先 $P(\text{full})$，再取产品，最后 $V(\text{empty})$。因此不会出现“缓冲区满还放”或“缓冲区空还取”的情况。

- 缓冲区互斥：

所有对 `buffer[in]`、`buffer[out]` 以及指针 $\mathit{in},\mathit{out}$ 的修改都在：

$$
P(\text{mutex}) \sim V(\text{mutex})
$$

之间完成，所以多个生产者和消费者不会同时读写同一个环形缓冲区单元。

- 消费者“连续取 $10$ 件”约束：

消费者必须先执行：

$$
P(\text{consumer\_mutex})
$$

然后进入 $10$ 次取产品循环，直到 $10$ 次全部取完才执行：

$$
V(\text{consumer\_mutex})
$$

因此任意时刻最多只有一个消费者处于“连续取 $10$ 件”的批次中，其他消费者不能插入取产品操作。

- 不死锁：

所有进程都是先申请资源信号量 $\text{empty}$ 或 $\text{full}$，再申请互斥信号量 $\text{mutex}$，不会出现“拿着 $\text{mutex}$ 等资源”的情况。消费者等待产品时虽然持有 $\text{consumer\_mutex}$，但生产者不需要 $\text{consumer\_mutex}$，仍可以继续生产并 $V(\text{full})$，所以不会形成循环等待。

**易错点**：

- 不要把 $P(\text{mutex})$ 放在 $P(\text{empty})$ 或 $P(\text{full})$ 之前。否则生产者可能拿着 $\text{mutex}$ 等空位，消费者却无法取产品释放空位；消费者也可能拿着 $\text{mutex}$ 等产品，生产者却无法放产品，导致死锁。

- 不能只靠 $\text{mutex}$ 实现消费者互斥。$\text{mutex}$ 只能保证“一次取产品操作”的原子性，不能保证一个消费者连续取 $10$ 件。必须额外使用 $\text{consumer\_mutex}$。

- $\text{consumer\_mutex}$ 不能放在 for 循环内部。如果每取一件就释放，其他消费者会在中间插入，违反“连续取 $10$ 件”的要求。它应该包住整个 $10$ 次取产品循环。

- 初值不能写错：$\text{empty}=1000$，$\text{full}=0$，$\text{consumer\_mutex}=1$。如果把 $\text{consumer\_mutex}$ 初值写成 $0$，所有消费者都无法进入。

**命题规律**：

这是典型的“经典生产者—消费者模型 + 附加限制”题型。408 操作系统喜欢在基础同步模型上增加一个额外条件，考察学生能否把额外条件转换成信号量。

做题顺序永远是：

1. 找到资源和计数器；
2. 找到共享缓冲区；
3. 找到附加限制对应的临界区；
4. 增加一个互斥信号量包住这个临界区。

这就像算法竞赛中先写对暴力模板，再加优化状态；基础模型不能错，附加限制要抽象成“锁”或“状态”。本题中，“连续取 $10$ 件”就是把消费者的 $10$ 次取产品操作看成一个不可被其他消费者插入的状态段，用一把互斥锁包住即可。
