# FRQ 第 3 题

![[_Attachments/题目识别/WDOS-2027-FRQ/WDOS-2027-FRQ-C05-S02-Q003_题目.png|题目]]

3. 【2023 统考真题】 进程 P 通过执行系统调用从键盘接收一个字符的输入，已知此过程中与进程 P 相关的操作包括：①将进程 P 插入就绪队列；②将进程 P 插入阻塞队列；③将字符从键盘控制器读入系统缓冲区；④启动键盘中断处理程序；⑤进程 P 从系统调用返回；⑥用户在键盘上输入字符。以上编号①～⑥仅用于标记操作，与操作的先后顺序无关。请回答下列问题。

(1) 按照正确的操作顺序，操作①的前一个和后一个操作分别是上述操作中的哪一个？操作⑥的后一个操作是上述操作中的哪一个？

(2) 在上述哪个操作之后 CPU 一定从进程 P 切换到其他进程？在上述哪个操作之后 CPU 调度程序才能选中进程 P 执行？

(3) 完成上述哪个操作的代码属于键盘驱动程序？

(4) 键盘中断处理程序执行时，进程 P 处于什么状态？CPU 是处于内核态还是处于用户态？

## DeepSeek V4 Flash Max 解析
**答案**：
(1) 操作①的前一个操作是③，后一个操作是⑤；操作⑥的后一个操作是④。  
(2) 操作②之后 CPU 一定从进程 P 切换到其他进程；操作①之后 CPU 调度程序才能选中进程 P 执行。  
(3) 完成操作③和操作④的代码属于键盘驱动程序。  
(4) 键盘中断处理程序执行时，进程 P 处于阻塞状态；CPU 处于内核态。

**解题切入点**：
将系统调用视为算法竞赛中的“构造题”——调用一个自定义函数，当数据未就绪时，当前进程“阻塞”相当于在递归或 BFS 中把当前节点放入等待队列；中断处理类似于“异步事件回调”，当外部输入发生时触发一个处理函数，该函数负责从硬件读取数据并唤醒等待的进程；进程调度类似于“多任务状态机”，通过就绪队列和阻塞队列管理任务切换。整道题本质是梳理 I/O 完成的全过程，关键在于理解“阻塞→等待事件→中断唤醒→就绪→调度”的顺序和状态转换。

**推演**：
进程 P 执行系统调用（如 read）时，由于键盘缓冲区为空，内核将 P 插入阻塞队列（操作②），此时 P 进入阻塞态，CPU 必须立即切换运行其他进程（操作②后一定切换）。随后用户在键盘上输入字符（操作⑥），键盘控制器产生中断，硬件自动启动键盘中断处理程序（操作④）。中断处理程序首先将字符从键盘控制器读入系统缓冲区（操作③），然后唤醒等待该输入的进程 P，即将其从阻塞队列移入就绪队列（操作①）。此后，当调度程序选中 P 时，P 从系统调用返回（操作⑤），获得输入的字符。因此正确的操作顺序为：② → ⑥ → ④ → ③ → ① → ⑤。  
由此得出：操作①的前一个操作是③，后一个操作是⑤；操作⑥的后一个操作是④。  
操作②后 P 阻塞，CPU 必须切换进程，所以 CPU 一定从 P 切换；操作①后 P 变为就绪，调度程序才能选中它。  
操作③（读字符）和操作④（中断处理程序）的代码直接与硬件交互并处理中断，属于键盘驱动程序。  
中断处理程序执行时，P 尚未被唤醒（仍处于阻塞态），且 CPU 运行内核代码，故处于内核态。

**易错点**：
- 误以为操作①在操作③之前，即先唤醒再读数据，但实际上必须先将数据读入缓冲区才能唤醒进程，顺序是③→①。  
- 忽略操作②后 CPU 必须立即切换进程，以为切换可能延迟，但阻塞态一定会导致进程被换出。  
- 认为中断处理程序执行时进程 P 已处于就绪态，实际上唤醒操作（①）是在中断处理程序内完成的，所以在中断处理程序刚开始执行时 P 仍为阻塞态。  
- 误以为只有操作③属于键盘驱动程序，而操作④是硬件启动，实际上中断处理程序的代码本身是驱动程序的核心部分，两者均属于驱动程序。

**命题规律**：
本题是操作系统 I/O 子系统与进程管理结合的典型题，常以“系统调用 + 中断处理”为背景，考查 I/O 操作的全流程、进程状态转换、CPU 模式切换以及设备驱动的基本概念。解题关键在于准确记忆“进程阻塞→外部事件→中断处理→唤醒→调度”的时序，并分清各操作所处的阶段（用户态、内核态、中断上下文）。此类题目容易在操作顺序、状态判断和驱动归属上设置陷阱，需要结合操作系统的分层模型和中断处理机制深入理解。
