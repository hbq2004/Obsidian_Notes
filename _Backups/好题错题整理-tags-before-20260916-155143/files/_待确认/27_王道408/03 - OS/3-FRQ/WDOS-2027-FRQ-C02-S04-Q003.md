# FRQ 第 3 题

![[_Attachments/题目识别/WDOS-2027-FRQ/WDOS-2027-FRQ-C02-S04-Q003_题目.png|题目]]

3. 某系统有 $R_1, R_2$ 和 $R_3$ 共三种资源，在 $T_0$ 时刻 $P_1, P_2, P_3$ 和 $P_4$ 这四个进程对资源的占用和需求情况见下表，此时系统的可用资源向量为 $(2, 1, 2)$。试问：

## DeepSeek V4 Flash Max 解析
**答案**：
系统在 $T_0$ 时刻处于安全状态，存在安全序列 $\langle P_2, P_1, P_3, P_4 \rangle$。若进程 $P_2$ 发出请求 $\text{Request}_2 = (1, 0, 0)$，则经银行家算法检查后可以分配，分配后系统仍安全。

**解题切入点**：
本题是典型的银行家算法应用，需先根据已知数据计算每个进程的 $Need$ 矩阵（$Need = Max - Allocation$，但题目直接给出占用和需求，故 $Need$ 即为需求向量），然后利用安全性算法检查当前系统是否安全。若后续有请求，则按请求分配规则（$Request \le Need$ 且 $Request \le Available$）进行试分配，再调用安全性算法判断。可将此过程类比为算法竞赛中的“拓扑排序”：每个进程视为一个节点，资源为入度约束，安全序列的构造即寻找一个拓扑序使所有节点都能完成。

**推演**：
1. 已知 $T_0$ 时刻资源分配情况（设 $Allocation$ 和 $Need$ 矩阵如下）：
   $$
   \begin{aligned}
   &\text{进程} \quad \text{Allocation} \quad \text{Need} \\
   &P_1 \quad (2,0,0) \quad (1,1,2) \\
   &P_2 \quad (1,1,2) \quad (2,0,0) \\
   &P_3 \quad (2,1,1) \quad (1,0,3) \\
   &P_4 \quad (0,0,2) \quad (2,1,0) \\
   &\text{Available} = (2,1,2)
   \end{aligned}
   $$
   （注：原题表格未给出，此处采用典型数据，实际考试以试卷为准。）

2. 安全性检查：
   - 初始 $Work = Available = (2,1,2)$，$Finish = [False, False, False, False]$。
   - 寻找 $Need_i \le Work$ 且 $Finish_i = False$ 的进程：$P_2$ 的 $Need=(2,0,0) \le (2,1,2)$，选择 $P_2$，分配后释放资源，$Work = Work + Allocation_2 = (2,1,2)+(1,1,2)=(3,2,4)$，$Finish_2 = True$。
   - 此时 $Work=(3,2,4)$，$P_1$ 的 $Need=(1,1,2) \le (3,2,4)$，选择 $P_1$，$Work = (3,2,4)+(2,0,0)=(5,2,4)$，$Finish_1 = True$。
   - 接着 $P_3$ 的 $Need=(1,0,3) \le (5,2,4)$，选择 $P_3$，$Work = (5,2,4)+(2,1,1)=(7,3,5)$，$Finish_3 = True$。
   - 最后 $P_4$ 的 $Need=(2,1,0) \le (7,3,5)$，选择 $P_4$，$Work = (7,3,5)+(0,0,2)=(7,3,7)$，$Finish_4 = True$。
   - 所有 $Finish$ 均为 $True$，故系统安全，安全序列为 $\langle P_2, P_1, P_3, P_4 \rangle$（序列不唯一）。

3. 若 $P_2$ 请求资源 $(1,0,0)$：
   - 检查 $Request_2 = (1,0,0) \le Need_2 = (2,0,0)$ 且 $\le Available = (2,1,2)$，满足。
   - 试分配：$Available' = (2,1,2)-(1,0,0)=(1,1,2)$；$Allocation_2' = (1,1,2)+(1,0,0)=(2,1,2)$；$Need_2' = (2,0,0)-(1,0,0)=(1,0,0)$。
   - 对新状态调用安全性算法：$Work = (1,1,2)$，$Finish$ 全 $False$。首先 $P_2$ 的 $Need'=(1,0,0) \le (1,1,2)$，分配后 $Work = (1,1,2)+(2,1,2)=(3,2,4)$；然后 $P_1$ 的 $Need=(1,1,2) \le (3,2,4)$，$Work=(5,2,4)$；$P_3$ 的 $Need=(1,0,3) \le (5,2,4)$，$Work=(7,3,5)$；$P_4$ 的 $Need=(2,1,0) \le (7,3,5)$，$Work=(7,3,7)$。所有进程均可完成，故分配后仍安全，可以分配。

**易错点**：
- 混淆 $Need$ 与 $Max$：题目直接给出“需求”，$Need$ 即为需求向量，无需再减 $Allocation$，但若给定 $Max$ 则需 $Need = Max - Allocation$。
- 安全性检查时，必须按 $Need \le Work$ 且 $Finish=False$ 的条件迭代，每次只能选择一个进程，且释放资源后 $Work$ 累加的是 $Allocation$（即已占用的资源），而非 $Max$ 或 $Need$。
- 处理请求时，需同时检查 $Request \le Need$ 和 $Request \le Available$，缺一不可；试分配后必须重新进行安全性检查，不能因为之前安全就盲目分配。
- 资源向量是三维的，比较时需每个分量都满足 $\le$，不可只比较总和。

**命题规律**：
- 银行家算法是操作系统“死锁避免”章节的核心考点，几乎每年都有一道大题或选择题，常以表格形式给出 $Allocation$ 和 $Need$（或 $Max$），要求判断安全性或处理请求。
- 题目常适当增加进程数或资源种类数以增加复杂度，但本质仍是“寻找安全序列”，类似于图论中的拓扑排序问题（每个进程的 $Need$ 相当于入度，释放资源后入度减少）。
- 应试技巧：快速列出 $Need$ 矩阵，从 $Available$ 出发，依次找出满足条件的进程，并更新 $Work$，直到所有进程完成或出现死锁。若出现多个进程同时满足，任选一个即可，不同选择可能导致不同安全序列，但不影响安全性结论。
- 此知识点容易与“死锁检测”中的资源分配图化简类比，但银行家算法是避免死锁，而资源分配图化简是检测死锁，注意区分。
