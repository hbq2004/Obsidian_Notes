# FRQ 第 19 题

![[_Attachments/题目识别/WDOS-2027-FRQ/WDOS-2027-FRQ-C02-S03-Q019_题目.png|题目]]

某博物馆最多可容纳 500 人同时参观,有一个出入口,该出入口一次仅允许一人通过。参观者的活动描述如下:
coBegin
    参观者进程 i:
    {
        ...
        进门;
        ...
        参观;
        ...
        出门;
        ...
    }
coEnd
请添加必要的信号量和 $P, V$[或 $wait()$、 $signal()$] 操作,以实现上述过程中的互斥与同步。要求写出完整的过程,说明信号量的含义并赋初值.

## DeepSeek V4 Flash Max 解析
**答案**：

定义信号量：
- $\text{empty}$：计数信号量，初值 $500$，表示博物馆剩余可容纳人数（空位数）。
- $\text{door}$：互斥信号量，初值 $1$，表示出入口同一时刻只允许一人通过。

```c
semaphore empty = 500;
semaphore door = 1;

coBegin
visitor_i() {
    wait(empty);       // P(empty)：申请一个空位，无空位则阻塞
    wait(door);        // P(door)：占用出入口
    进门;
    signal(door);      // V(door)：释放出入口

    // 参观
    ...

    wait(door);        // P(door)：占用出入口
    出门;
    signal(door);      // V(door)：释放出入口
    signal(empty);     // V(empty)：释放一个空位
}
coEnd
```

其中 `wait()` 即 `P()`，`signal()` 即 `V()`。

**解题切入点**：

本题本质是“容量限制 + 互斥访问”。容量限制用计数信号量：把 $\text{empty}$ 看成 $500$ 个“入场令牌”，进门消耗一个令牌，出门归还一个令牌；出入口用互斥信号量：$\text{door}$ 初值为 $1$，相当于一把锁。不要额外再设人数计数器，信号量本身已经在计数。

和算法竞赛类比，`wait(empty)` 是“先检查资源/状态是否可行”，`wait(door)` 是“再拿锁进入临界区”。整个系统可以看成状态机：状态由 $(\text{empty}, \text{door})$ 刻画，P/V 操作就是状态转移时的合法性判断。

**推演**：

1. $\text{empty}$ 初值 $500$。`wait(empty)` 使空位数减 $1$，若为 $0$ 则阻塞在馆外；`signal(empty)` 在有人真正离开后使空位数加 $1$，唤醒等待者。这保证了馆内人数不超过 $500$。
2. $\text{door}$ 初值 $1$。进门和出门都经过同一个出入口，因此两类动作都必须在 `wait(door)` 与 `signal(door)` 之间进行，保证“一次仅一人通过”。
3. `wait(empty)` 必须放在 `wait(door)` 之前。如果反过来，当博物馆满员时，一个参观者先拿到了门却申请不到空位，会占着门等待；而馆内的人要出门又需要门，导致无法释放空位，形成死锁。
4. `signal(empty)` 必须放在 `出门` 之后。如果在出门前就释放空位，那个人还在馆内，另一个参观者又进入，会突破 $500$ 人上限。

**易错点**：

- 把 `wait(door)` 和 `wait(empty)` 顺序写反：满员时会发生循环等待死锁。
- 忘记在出门后 `signal(empty)`：名额泄漏，之后参观者可能全部被阻塞。
- 提前 `signal(empty)`，例如放在 `出门` 之前：会导致同一时刻馆内人数可能超过 $500$。
- 用 `door` 把整个“参观”过程也锁住：出入口被一个人长期占用，其他参观者无法进出；临界区只应包含“进门”或“出门”这个瞬时动作。
- 只对进门加锁、不对出门加锁：不能保证出入口一次一人通过。

**命题规律**：

408 中这类“补 P/V 操作”的大题，通常给一个并发活动模板，要求识别两类信号量：容量/资源相关用计数信号量，共享设备/临界区用互斥信号量。满分的关键是写对信号量初值、P/V 的位置和顺序。

本题的“先申请容量、再拿门锁；出门后先放门锁、再释放容量”是一个可迁移的套路，类似于算法竞赛中“先检查状态合法性，再进入状态；离开时释放资源”的状态转移写法。掌握后可迁移到停车场、过桥、生产者消费者等同类场景。
