# FRQ 第 5 题

![[_Attachments/题目识别/WDOS-2027-FRQ/WDOS-2027-FRQ-C03-S02-Q005_题目.png|题目]]

一个页式虚拟存储系统,其并发进程数固定为 $4$ 个。最近测试了它的 $CPU$ 利用率和用于页面交换的磁盘的利用率,得到的结果就是下列 $3$ 组数据中的一组。针对每组数据,说明系统发生了什么事情。增加并发进程数能提升 $CPU$ 的利用率吗? 页式虚拟存储系统有用吗?
(1) $CPU$ 利用率为 $13\%$; 磁盘利用率为 $97\%$.
(2) $CPU$ 利用率为 $87\%$; 磁盘利用率为 $3\%$.
(3) $CPU$ 利用率为 $13\%$; 磁盘利用率为 $3\%$.

## DeepSeek V4 Flash Max 解析
**答案**：

| 组 | 系统发生了什么 | 增加并发进程数能否提升 CPU 利用率 | 页式虚拟存储系统有用吗 |
|---|---|---|---|
| (1) $13\% / 97\%$ | 系统发生**抖动**（thrashing）。4 个进程的工作集总和超过物理内存，进程频繁缺页，CPU 大部分时间在等待调页。 | **不能**，反而会使可用物理页更少，缺页更严重，CPU 利用率进一步下降。 | 当前配置下**没有正面作用**，甚至有害；应减少并发进程数或增加物理内存。 |
| (2) $87\% / 3\%$ | 系统运行**正常**。缺页很少，CPU 利用率高，调页磁盘基本空闲，说明当前工作集能装入内存。 | 可以**小幅尝试**增加；若内存仍有富余，可能提高 CPU 利用率，但要防止新增进程后引发抖动。 | **有用**，按需调页以很小的开销支持大地址空间和较高多道程序度。 |
| (3) $13\% / 3\%$ | 系统处于**双低**状态：CPU 不忙，分页磁盘也不忙。说明不是内存/分页瓶颈，更可能是 4 个进程大多阻塞在普通 I/O 上，就绪进程太少。 | **通常能提升**。增加可运行的并发进程，可减少“所有进程同时阻塞”造成的 CPU 空闲。 | 当前没有体现作用，瓶颈不在虚拟存储；虚拟存储本身仍是可用的。 |

总体结论：页式虚拟存储系统不是绝对“有用”或“没用”，它取决于工作集 $W(n)=\sum_{i=1}^n WS_i$ 是否超过物理内存 $M$。若 $W(n)\le M$，则有用；若 $W(n)>M$，则进入抖动，调页开销会吞掉全部收益。

---

**解题切入点**：  
这可以看成一道“根据性能计数器反推瓶颈”的题。CPU 利用率和调页磁盘利用率构成两个关键观测值：

- CPU 高、调页盘低：说明缺页少，系统在正常计算；
- CPU 低、调页盘高：说明 CPU 在等页面 I/O，典型抖动；
- CPU 低、调页盘低：说明没有足够就绪进程，进程可能在等普通 I/O。

用算法竞赛的视角看，这就是“不是无脑优化 CPU，而要先找瓶颈”。调页磁盘高相当于程序大量时间花在内存换页而不是计算上；增加并发进程数相当于在已经内存超卖的机器上多开线程，只会让 cache 和物理页被反复驱逐，吞吐量不升反降。

---

**推演**：  
把每个进程看作一个状态机：运行、就绪、阻塞。  
CPU 利用率高，说明经常有进程处于运行态；调页磁盘利用率高，说明大量进程阻塞在“等待调页”上。

设物理内存为 $M$ ，第 $i$ 个进程的工作集为 $WS_i$。若：

$$
W(n)=\sum_{i=1}^n WS_i \le M
$$

则缺页率低，CPU 可以正常工作。  
若：

$$
W(n)=\sum_{i=1}^n WS_i > M
$$

则页面刚换入又被换出，系统反复调页，进程无法真正推进。

组 (1) 正是后者：$U_{\mathrm{CPU}}$ 只有 $13\%$ ，$U_{\mathrm{disk}}$ 高达 $97\%$ ，说明 CPU 大部分时间空闲，而磁盘几乎一直在换页。此时增加并发进程数相当于继续让 $n$ 变大，$W(n)$ 进一步增大，缺页率只会更高。

组 (2) 是正常情况：$U_{\mathrm{CPU}}=87\%$ ，$U_{\mathrm{disk}}=3\%$ ，说明页面命中率很高，虚拟存储以很小的代价换来了高 CPU 利用率。

组 (3) 则类似“任务数量不足”：若每个进程阻塞概率为 $q$ ，则 CPU 空闲概率近似为：

$$
U_{\mathrm{idle}} \approx \prod_{i=1}^n q_i
$$

当 $n=4$ 且所有进程都经常阻塞时，CPU 就会很低；同时调页盘也低，说明阻塞原因不是缺页。增加 $n$ 可以降低“所有进程同时阻塞”的概率，从而提升 CPU 利用率。

---

**易错点**：  
1. 看到 CPU 低就认为应该增加进程数，这是错的。必须先看调页磁盘是否高；若磁盘高，则是抖动，增加进程只会更糟。  
2. 把调页磁盘利用率高当成系统在“正常工作”。调页磁盘高是开销高，不是收益高。  
3. 把组 (3) 误判为抖动。抖动必须伴随调页磁盘高；双低说明内存没有压力，而是就绪进程不足或进程阻塞在普通 I/O。  
4. 认为“增加并发进程数一定能提高 CPU 利用率”。实际对应一个先升后骤降的曲线：内存有冗余时上升，工作集超限后进入抖动并骤降。  
5. 混淆“页式虚拟存储是否有用”和“当前配置是否有效”。抖动时配置失效，不能因此说虚拟存储本身永远无用。

---

**命题规律**：  
408 常给 CPU 利用率和磁盘利用率，让考生判断系统是否发生抖动，并分析多道程序度与 CPU 利用率的关系。核心考点是：

- 工作集与驻留集；
- 多道程序度过高会导致抖动；
- 调页磁盘利用率高是缺页频繁的直接信号。

答题模板是：先根据两个利用率判断瓶颈，再说明增加并发进程数会改善、不变还是恶化。若调页盘高，则不能增加；若二者都低，则通常可以增加。这类题还喜欢考查“虚拟存储的代价”：按需调页有用，但必须让工作集与物理内存匹配，否则会从“缓存”变成“抖动”。
