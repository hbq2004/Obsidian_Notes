# FRQ 第 13 题

![[_Attachments/题目识别/WDOS-2027-FRQ/WDOS-2027-FRQ-C02-S03-Q013_题目.png|题目]]

13.设公共汽车上驾驶员和售票员的活动分别如下图所示。驾驶员的活动:启动车辆、正常行车、到站停车；售票员的活动:关车门、售票、开车门。在汽车不断地到站、停车、行驶的过程中，这两个活动有什么同步关系？用信号量和 $P,V$ 操作实现它们的同步.

## DeepSeek V4 Flash Max 解析
**答案**：
同步关系有两条跨进程的前置依赖：
1. 售票员的“关车门”必须发生在驾驶员的“启动车辆”之前；
2. 驾驶员的“到站停车”必须发生在售票员的“开车门”之前；
3. “售票”与“正常行车”之间没有直接同步约束，可并发执行。

设置两个二元信号量：
$$
S_1 = 0,\quad S_2 = 0
$$
其中 $S_1$ 表示“车门已关好”的事件，$S_2$ 表示“车已停稳”的事件。

```c
semaphore S1 = 0;  // 车门已关好
semaphore S2 = 0;  // 车已停稳

cobegin
process 驾驶员() {
    while (true) {
        P(S1);          // 等待售票员关好车门
        启动车辆;
        正常行车;
        到站停车;
        V(S2);          // 通知售票员可以开车门
    }
}

process 售票员() {
    while (true) {
        关车门;
        V(S1);          // 通知驾驶员可以启动
        售票;           // 与正常行车并发
        P(S2);          // 等待驾驶员到站停车
        开车门;
    }
}
coend
```

**解题切入点**：
这道题不是互斥问题，而是同步/事件顺序问题。可以把两个活动看成两个并发循环状态机，关键是不允许出现“门没关就启动”和“车没停稳就开门”这两个非法状态。算法竞赛里做 BFS 状态搜索时，只有前置条件满足才转移；这里 $P$ 就是“等待前置条件”，$V$ 就是“发布前置条件”。因此先找跨进程的先后依赖边，再为每条边配一个初值为 0 的信号量即可。

**推演**：
初始时 $S_1 = S_2 = 0$，驾驶员先执行 $P(S_1)$ 被阻塞，保证不会提前启动。售票员关门后执行 $V(S_1)$，相当于发出“车门已关”事件；若驾驶员已等在 $P(S_1)$ 上则被唤醒，若还没执行 $P(S_1)$，则 $S_1$ 成为 1，等驾驶员执行时立即通过。之后驾驶员启动、行驶、到站停车，执行 $V(S_2)$ 发出“车已停稳”事件。售票员卖完票后执行 $P(S_2)$：若车未停稳则阻塞；若已经停稳则通过，然后开车门。随后进入下一轮，两个进程回到 $P(S_1)$ 和“关车门”。每轮每个信号量恰好被 $V$ 一次、$P$ 一次，所以事件不会被错误地累计到下一轮。

**易错点**：
- $S_1,S_2$ 初值必须为 0。若 $S_1=1$，第一次驾驶员可能没等关门就启动；若 $S_2=1$，售票员可能在车未停稳时开门。
- $V$ 必须放在前置动作之后，$P$ 必须放在后续动作之前。例如“关车门”后马上 $V(S_1)$，“到站停车”后马上 $V(S_2)$，不能写反。
- 不要把“售票”放到 $P(S_2)$ 之后，否则售票会被迫等到车停稳才开始，失去与行车并发的语义；也不要给“售票”额外加锁，这里没有共享资源竞争。
- 要注意循环结构，公共汽车是不断到站、停车、行驶的，进程不能只执行一轮。

**命题规律**：
这是 408“进程同步”中典型的“事件同步”题，和生产者-消费者、读者-写者并列。命题人给出两个动作序列，让考生找同步点并用 $P,V$ 实现。答题模板是：找动作之间的“先发生/后才能”偏序关系 $\to$ 为每条跨进程约束设一个初值 0 的信号量 $\to$ 前操作后 $V$，后操作前 $P$ $\to$ 检查初始状态与循环。本质上就是在并发动作的依赖图上加“事件边”，像做拓扑排序一样，先把依赖图画清楚，代码自然就写出来了。
