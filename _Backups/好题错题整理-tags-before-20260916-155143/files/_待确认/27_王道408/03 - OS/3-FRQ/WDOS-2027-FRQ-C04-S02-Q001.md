# FRQ 第 1 题

![[_Attachments/题目识别/WDOS-2027-FRQ/WDOS-2027-FRQ-C04-S02-Q001_题目.png|题目]]

1. 简述文件的外存分配中，连续分配、链接分配和索引分配各自的主要优缺点.

## DeepSeek V4 Flash Max 解析
**答案**：
连续分配：优点——顺序访问性能优异（ $O(1)$ 偏移计算），直接访问高效；缺点——需预知文件大小，产生外部碎片，扩展困难（类似数组的静态分配）。
链接分配：优点——无外部碎片，文件可动态增长（类似链表动态节点）；缺点——仅支持顺序访问，随机访问需 $O(n)$ 指针遍历，指针占用空间，且单点故障易导致数据丢失。
索引分配：优点——支持直接访问（ $O(1)$ 索引表查询），无外部碎片，扩展方便（类似多级页表或哈希索引）；缺点——索引块额外开销，小文件时索引块利用率低，小文件访问需两次 I/O（索引块+数据块）。

**解题切入点**：
从数据结构视角切入，将三种分配方式类比为算法竞赛中常用的数据存储结构：连续分配 $\approx$ 数组（静态、连续、随机访问快但扩容难）；链接分配 $\approx$ 链表（动态、离散、插入删除快但随机访问慢）；索引分配 $\approx$ 哈希表或 B+ 树（通过索引层实现平衡，但需额外空间）。理解这些本质有助于快速记忆优缺点，并能在实际文件系统设计（如 ext2 使用混合索引）中灵活应用。

**推演**：
首先，连续分配将文件数据块连续存放，如同在栈上分配一个大数组。其优点在于顺序读取时磁盘寻道时间最短（连续块在相邻磁道），且随机访问可通过首地址+偏移量直接计算，复杂度 $O(1)$ 。缺点在于文件创建时必须指定大小（类似数组长度固定），若实际大小超出则需移动整个文件（类似 vector 扩容时的拷贝开销），且经过多次增删后磁盘空间碎片化，类似内存碎片问题。
其次，链接分配采用链表结构，每个数据块包含指向下一块的指针。优点在于文件可以动态追加，无需预知大小，且磁盘空间利用率高（无外部碎片）。但缺点明显：随机访问必须沿链表遍历（ $O(n)$ I/O 操作），顺序访问虽可达但指针跳转会引入额外寻道；此外，指针占用存储空间（每个块损失 4~8 字节），且若某个指针损坏，后续数据全部丢失（类似链表断链）。
最后，索引分配为每个文件建立索引块（表），其中存放所有数据块指针。优点支持直接访问（通过索引表 $O(1)$ 定位），且文件易扩展（只需在索引表末尾添加新指针），同时无外部碎片。缺点在于索引块本身占用空间，对于小文件（如仅 1~2 块），索引块的开销相对过大（类似 B+ 树节点利用率低）；访问小文件时需先读索引块再读数据块（两次 I/O），而大文件需多级索引（如 Unix 混合索引），增加复杂度。

**易错点**：
1. 混淆链接分配与索引分配：链接分配是“隐式”指针（块内携带），索引分配是“显式”索引表（集中管理）。2. 忽略连续分配的直接访问能力：连续分配通过偏移计算直接访问，并非只能顺序访问。3. 误认为索引分配无任何缺点：索引块额外开销及小文件效率问题常被忽略。4. 易将文件分配方式与内存管理中的分页/分段混淆，注意外存分配关注的是磁盘块的组织方式。

**命题规律**：
408 真题常以简答题或选择题考查三种分配方式的对比，也可能结合具体文件系统（如 FAT 基于链接分配，NTFS 基于索引分配）分析性能。命题角度包括：给出场景选择合适分配方式，或计算不同分配方式下的访问时间（需考虑磁盘 I/O 次数）。此外，混合索引（如 Unix 直接/间接索引）是索引分配的重要扩展，可能作为设计题出现。掌握每种分配的本质（数据结构）和磁盘 I/O 特性，即可从容应对。
