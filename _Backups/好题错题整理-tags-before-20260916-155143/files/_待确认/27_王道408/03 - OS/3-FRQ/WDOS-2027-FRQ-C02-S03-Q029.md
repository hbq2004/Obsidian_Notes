# FRQ 第 29 题

![[_Attachments/题目识别/WDOS-2027-FRQ/WDOS-2027-FRQ-C02-S03-Q029_题目.png|题目]]

29. 【2025统考真题】甲、乙、丙三人一起植树,甲负责挖树坑,乙负责将树苗放入树坑并填土,丙负责为新种的树苗浇水。植树的步骤依次为:挖树坑、放树苗、填土和浇水。现有铁锹和水桶各 1 个,铁锹用于挖树坑和填土,水桶用于浇水。当树坑的数量小于 3 时,甲才可以挖树坑。假设初始时树坑的数量为 0,铁锹和水桶均可用。请定义尽可能少的信号量,用 $wait()、$signal() 操作描述植树过程中三人之间的同步或互斥关系,并说明所用信号量的作用及其初值.

## DeepSeek V4 Flash Max 解析
**答案**：  
定义信号量：  
- $empty$：表示空闲坑位（即还能挖的树坑数量），初值为 $3$。  
- $full$：表示已挖好待填土的树坑数量，初值为 $0$。  
- $water$：表示已填好土待浇水的树苗数量，初值为 $0$。  
- $shovel$：用于铁锹的互斥，初值为 $1$。  

三人进程的 $wait()$、$signal()$ 操作描述如下：  
- 甲（挖坑）：循环执行 $wait(empty)$ 申请坑位，$wait(shovel)$ 获取铁锹，挖树坑，$signal(shovel)$ 释放铁锹，$signal(full)$ 通知乙有坑。  
- 乙（放树苗、填土）：循环执行 $wait(full)$ 等待有坑，放树苗（无需铁锹），$wait(shovel)$ 获取铁锹，填土，$signal(shovel)$ 释放铁锹，$signal(empty)$ 释放坑位，$signal(water)$ 通知丙浇水。  
- 丙（浇水）：循环执行 $wait(water)$ 等待已填土的树，浇水（用水桶），完成。  

注意，乙在放树苗时不需要铁锹，先放树苗再申请铁锹填土，可以提高并发性。  

**解题切入点**：  
本题是经典的多线程同步问题，涉及多个生产者和消费者以及互斥资源。可以将植树过程抽象为一条流水线：甲是“已挖坑”的生产者，乙是“已挖坑”的消费者兼“已填土”的生产者，丙是“已填土”的消费者。每个阶段都需要同步，铁锹是互斥资源。类比算法竞赛中的构造题，需要设计合适的信号量（状态机）来协调三个进程的执行顺序，避免死锁。资源分配类似图论匹配，每个信号量代表一种资源，$wait$ 等于获取资源，$signal$ 等于释放资源。通过三个计数信号量分别控制每个阶段的“产品”数量，一个互斥信号量保护铁锹的使用。  

**推演**：  
首先，树坑数量不能超过3，所以设置 $empty$ 初值3，甲每次挖坑前 $wait(empty)$，乙填土后 $signal(empty)$，保证树坑数量不超过3。甲挖坑后通知乙，所以 $full$ 初值0，甲 $signal(full)$，乙 $wait(full)$。乙填土后通知丙，所以 $water$ 初值0，乙 $signal(water)$，丙 $wait(water)$。铁锹是互斥资源，所以 $shovel$ 初值1，甲和乙在需要铁锹时 $wait(shovel)$，使用后 $signal(shovel)$。乙在放树苗时不需要铁锹，所以先放树苗再申请铁锹填土，这样放树苗与甲挖坑可以并发，提高效率。整个流程无死锁，因为每个进程都是先申请同步信号量（$empty$ 或 $full$）再申请互斥信号量 $shovel$，资源释放顺序对称，不会形成循环等待。  

**易错点**：  
1. 容易忘记设置 $empty$ 信号量，导致树坑数量可能超过3，违反条件。  
2. 容易忽略铁锹的互斥，导致甲和乙同时使用铁锹，造成错误。  
3. 乙在填土后必须同时 $signal(empty)$ 和 $signal(water)$，不能遗漏，否则会导致甲或丙无法继续。  
4. 注意 $wait$、$signal$ 操作的顺序，避免死锁。例如，乙若先 $wait(shovel)$ 再 $wait(full)$，而甲先 $wait(empty)$ 再 $wait(shovel)$，则可能发生死锁（甲占 $empty$ 等 $shovel$，乙占 $shovel$ 等 $full$）。所以必须按相同顺序申请资源，即先同步信号量再互斥信号量。  
5. 水桶只有一个但只被丙使用，所以不需要为水桶设置信号量，不要多定义。  

**命题规律**：  
408 操作系统真题中，同步问题是常考题型，通常涉及多个进程的同步与互斥，要求设置信号量描述。解题关键是识别资源（如铁锹、水桶）和同步关系（如生产-消费链），将问题抽象为“生产者-消费者”模型，然后确定信号量数量和初值，并写出规范的 $wait$、$signal$ 操作。本题结合了计数信号量和互斥信号量，要求考生分析清楚每一步的依赖关系，并注意避免死锁。未来命题可能继续考察类似的复杂同步问题（如“三人过桥”、“流水线”等），需要灵活运用信号量组合。
