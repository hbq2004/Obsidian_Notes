# MCQ 第 17 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S02-Q017_题目.png|题目]]

17.（ ）优先级是在创建进程时确定的,确定之后在整个运行期间不再改变.
(A) 先来先服务
(B) 动态
(C) 短作业
(D) 静态

## DeepSeek V4 Flash Max 解析
**答案**：
D 静态（静态优先级）。

**解题切入点**：
题干是一个判定型描述：优先级在进程创建时被确定，并且运行期间不变。这等价于说该优先级是进程的“不可变属性”。在算法竞赛中可类比为 `const int priority`：构造对象时初始化，之后只读；而动态优先级则是 `mutable` / 运行时更新。于是直接定位到概念分类：静态优先级 vs 动态优先级，而不是具体调度算法 FCFS / SJF。

**推演**：
设进程 $P_i$ 的优先级函数为 $\pi(P_i,t)$ ，其中 $t$ 为运行时刻。静态优先级满足：
$$
\pi(P_i,t)=\pi_0(P_i),\quad \forall t\in[t_{\text{create}},t_{\text{destroy}}],
$$
其中 $\pi_0(P_i)$ 是创建时确定的值。动态优先级则形如：
$$
\pi(P_i,t)=f(\text{等待时间},\text{CPU 使用历史},\dots),
$$
会随调度状态改变。

选项逐一对应：

- A 先来先服务：按到达时间 $t_{\text{arrival}}$ 排队，等价于 FIFO 队列，不是“优先级固定”的定义。
- B 动态：与题干“不再改变”直接矛盾。
- C 短作业：按估计/实际 CPU 突发长度 $t_{\text{burst}}$ 选择进程，属于按任务长度排序，不是静态优先级的分类。
- D 静态：完全匹配题干，创建时确定、运行期不再改变，故选 D。

**易错点**：
1. 误选 C：短作业优先的核心是比较 CPU 突发长度，而不是研究“优先级是否固定”。它可以在不同调度时刻重新计算或估计，不一定满足“创建后不变”。
2. 误选 A：FCFS 容易让人想到“到达顺序已经固定”，但它描述的是排队规则，不是优先级类型。
3. 混淆静态与动态：静态优先级不是“永远不变的好”，它缺乏 aging 机制，可能导致长进程饥饿；但这不影响概念判断。
4. 把“优先级”理解成“数值较大先运行”即可，但本题问的是该数值能否被修改。

**命题规律**：
408 基础概念题常以“定义复述+干扰项”方式考查调度分类。本题本质是概念辨析：静态优先级相当于编译期/创建期确定的常量，动态优先级相当于运行期可变状态。命题人喜欢把“先来先服务”“短作业”等具体算法混入选项中，考查考生是否区分“调度算法”与“优先级类型”。掌握“创建时定、运行期不改”这一特征即可秒杀。
