# MCQ 第 42 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S02-Q042_题目.png|题目]]

某系统正在执行三个进程 $P_1,P_2 和 $P\_3，各进程的计算 (CPU) 时间和 $I/O 时间比例如下表所示。为提高系统资源利用率，合理的进程优先级设置应为 ( ).

| 进程名 | 计算时间 | $I/O 时间 |
| :---: | :---: | :---: |
| $P_1 | 90% | 10% |
| $$P_2 | 50$% | 50% |
| $P_3 | 15% | 85% |

(A) $$P_1 > P_2 > P_3
(B)$ $P_3 > P_2 > P_1
(C) $$P_2 > P_1 = P_3
(D)$ $P\_1 > P\_2 = P\_3

## DeepSeek V4 Flash Max 解析
**答案**：
B：$P_3 > P_2 > P_1$。

**解题切入点**：
题目问的是“系统资源利用率”，不是“单个进程完成速度”。要让 CPU 和 I/O 设备尽量同时工作，调度顺序应使“CPU 需求大”的进程与“I/O 需求大”的进程形成互补。可以看成算法竞赛里的双机并行调度：短任务先跑到 I/O 请求点，另一台设备才会开始工作；如果长计算任务一直占 CPU，I/O 设备就空转。因此判断每个进程偏向哪类资源后，应让 I/O 型进程优先。

**推演**：
- $P_1$ 是 CPU 型：CPU 占比极高，I/O 占比低，适合在别人做 I/O 时占用 CPU。
- $P_3$ 是 I/O 型：I/O 占比极高，CPU 需求很小，适合最先获得 CPU，以便尽快发出 I/O 请求并阻塞，把 CPU 让出来。
- $P_2$ 介于两者之间，优先级居中。
- 若给 $P_3$ 最高优先级：$P_3$ 短时间用完 CPU 后进入 I/O，CPU 可以立刻转给 $P_2$ 或 $P_1$ 使用，形成“$P_3$ 做 I/O，$P_1 / P_2$ 做计算”的重叠。
- 若给 $P_1$ 最高优先级：$P_1$ 长时间占着 CPU，$P_3$ 无法及时发起 I/O，I/O 设备会长期空闲，整体资源利用率反而下降。

所以优先级应为 $P_3 > P_2 > P_1$。

**易错点**：
- 不要以为 I/O 时间长的进程“不重要”就降低优先级。I/O 型进程的高优先级是为了尽快“发起 I/O”，让 I/O 设备忙起来，不是让它多占 CPU。
- 不要只看 CPU 利用率。CPU 型进程给太高优先级，CPU 可能很忙，但 I/O 设备空闲；这就好比只把二分图的一侧顶点全部匹配，另一侧全部空闲，整体资源利用率不高。
- 不要把“计算时间比例”等同于“进程重要性”。调度关注的是 CPU 突发特征和资源互补性；短 CPU 突发 / I/O 型进程通常更适合优先调度。

**命题规律**：
- 408 喜欢用“CPU 时间 / I/O 时间比例表”来考查对 CPU 型、I/O 型进程的判断，并套用优先级设置原则。
- 核心结论：为提高系统资源利用率，I/O 型进程优先级一般应高于 CPU 型进程。
- 这类题与 SJF、多级反馈队列、交互式响应等概念可结合命题；解题时先分类，再按调度目标排序，类似先在状态空间里判断“谁先进入 CPU 能激活更多资源”，然后贪心选择。
