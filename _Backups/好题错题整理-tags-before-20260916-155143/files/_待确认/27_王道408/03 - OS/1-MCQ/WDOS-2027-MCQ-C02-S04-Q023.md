# MCQ 第 23 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S04-Q023_题目.png|题目]]

23. 下面是一个并发进程的程序代码,正确的是 ().
```
Semaphore x1=x2=y=1;
int c1=c2=0;
P1()                       P2()
{                          {
    while(1){                  while(1){
        P(x1);                     P(x2);
        if(++c1==1)P(y);           if(++c2==1)P(y);
        V(x1);                     V(x2);
        computer(A);               computer(B);
        P(x1);                     P(x2);
        if(--c1==0)V(y);           if(--c2==0)V(y);
        V(x1);                     V(x2);
    }                          }
}                          }
```
(A) 进程不会死锁,也不会“饥饿”
(B) 进程不会死锁,但是会“饥饿”
(C) 进程会死锁,但是不会“饥饿”
(D) 进程会死锁, 也会“饥饿”

## DeepSeek V4 Flash Max 解析
**答案**：
B。进程不会死锁，但是会“饥饿”。

**解题切入点**：
把信号量看成资源锁：

- $x_1$、$x_2$ 分别保护 $c_1$、$c_2$，是各自的“私有锁”；
- $y$ 才是两个进程真正互斥使用的“全局令牌”，保证 `computer(A)` 与 `computer(B)` 不能同时进入。

判断死锁等价于判断“持有并等待”的资源图是否有环；判断饥饿则要看某个进程是否可能被无限“插队”。

**推演**：
1. $c_1$ 只被 $P_1$ 修改，$c_2$ 只被 $P_2$ 修改，因此 $P_1$ 与 $P_2$ 之间不存在对 $x_1$ 或 $x_2$ 的跨进程竞争。$x_1$、$x_2$ 的作用只是让各自的计数操作原子化。

2. 对 $y$ 的竞争等价于：$P_1$ 通过 $++c_1==1$ 申请 $y$，通过 $--c_1==0$ 释放 $y$；$P_2$ 同理。所以 $y$ 是控制 $A$、$B$ 两段临界区互斥的二值信号量。

3. 不会死锁：若 $P_1$ 等待 $y$，它最多还持有 $x_1$；此时持有 $y$ 的只可能是 $P_2$，而 $P_2$ 退出临界区只需要自己的 $x_2$，不需要 $x_1$。反之，$P_2$ 等待 $y$ 时，$P_1$ 也不需要 $x_2$。因此“持有并等待”不构成循环等待，没有死锁。

4. 会饥饿：两个进程都是 `while(1)` 无限循环，信号量并不保证先来先服务或公平调度。若 $P_2$ 释放 $y$ 后又立刻进入下一轮并再次申请 $y$，而 $P_1$ 一直在等待 $y$，则 $P_1$ 可能被无限期推迟；对称地，$P_2$ 也可能被 $P_1$ 饿死。因此会饥饿。

**易错点**：
- 不要把 $x_1$、$x_2$ 当成双方都要抢的全局锁；它们各自只被本进程使用，构不成死锁环。
- 不要看到“两个进程都申请 $y$”就认为会死锁；死锁需要等待图成环，而这里最多是“拿着自己的锁等 $y$”，持 $y$ 者不会反向等对方的锁。
- 不要以为有 `V(y)` 就不会饥饿；信号量没有公平性保证，等待者可能被反复“插队”。

**命题规律**：
- 408 常把死锁与饥饿放在同题中对比：死锁看资源等待图是否有环，饥饿看调度/公平性是否可能让某进程无限等待。
- 题目中的 $c_1,c_2,x_1,x_2$ 很像读者-写者问题里的“计数器 + 计数器锁”，属于干扰和包装；核心是识别出真正的全局互斥信号量 $y$。
- 类似算法竞赛：把并发执行看成状态机搜索，“死锁”是状态图中存在无法推进的环，“饥饿”是某个状态反复不被选中；本题就是“无环，但可能被无限插队”。
