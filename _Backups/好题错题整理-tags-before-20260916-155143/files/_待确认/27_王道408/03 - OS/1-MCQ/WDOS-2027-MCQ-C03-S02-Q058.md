# MCQ 第 58 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C03-S02-Q058_题目.png|题目]]

对于采用虚拟内存管理方式的系统，下列关于进程虚拟地址空间的叙述中，错误的是（ ）
(A) 每个进程都有自己独立的虚拟地址空间
(B) C 语言中 $malloc()$ 函数返回的是虚拟地址
(C) 进程对数据段和代码段可以有不同的访问权限
(D) 虚拟地址空间的大小由内存和硬盘的大小决定

## DeepSeek V4 Flash Max 解析
**答案**：
D。

**解题切入点**：
虚拟地址空间是“逻辑地址的集合”，核心属性是隔离与按需映射。它像一个竞赛题的“逻辑下标域”：可以用 $32$ 位地址表示 $2^{32}$ 个不同位置，但每个位置是否真正占物理内存或磁盘，由操作系统在访问时按需分配。因此，决定地址空间大小的不是物理资源，而是地址位数。

**推演**：
- A 正确：每个进程有独立页表，同一虚拟页可映射到不同物理页；进程间天然隔离，类似两个题目共用同一组变量名，但运行在不同命名空间。
- B 正确：`malloc()` 在进程堆区返回一个虚拟地址；真正物理页要等首次读/写触发缺页异常才分配。这类似于“动态开点”或“懒分配”：逻辑上先占下标，实际访问时才建节点。
- C 正确：页表项中包含读、写、执行等保护位。代码段可设为只读 + 可执行，数据段可设为读写，甚至可用 `NX` 禁止栈执行；访问权限是页级/段级属性，不是整个地址空间一刀切。
- D 错误：进程虚拟地址空间大小由 CPU 地址宽度决定。例如 32 位地址宽度对应 $2^{32}=4\text{ GB}$ 虚拟地址空间；物理内存和硬盘（交换区）有多大，只影响系统能同时驻留或换出的实际页数，不影响进程能“看到”的虚拟地址范围。

故错误项为 **D**。

**易错点**：
1. 把“虚拟地址空间大小”和“虚拟存储器容量”混淆。后者常讨论物理内存 + 交换区能容纳多少页面，但进程虚拟地址范围由地址位数决定。
2. 误以为 `malloc()` 返回的是物理地址。C 程序员拿到的是虚拟地址，由 MMU 翻译；竞赛中把指针当“数组下标”理解即可，下标空间不等于物理存储。
3. 看到“虚拟内存”就联想到“内存 + 硬盘”，从而误选 D 为正确。虚拟内存可借用硬盘，但“借用多少”不等于“逻辑地址范围多大”。

**命题规律**：
408 常在虚拟内存章节考查“逻辑空间与物理资源解耦”这一核心观念。命题人把“内存和硬盘大小”混入地址空间大小的决定因素中，属于经典干扰项。以后遇到类似题，先看选项是否把“地址宽度 / 位数”换成“物理资源”，若是，则优先判错；同时要熟悉 `malloc` 返回虚拟地址、页表项权限位等基础结论。
