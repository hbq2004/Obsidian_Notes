# MCQ 第 13 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S02-Q013_题目.png|题目]]

13. 支持多道程序设计的操作系统在运行过程中，不断选择新进程运行来实现 $CPU$ 的共享，但其中（ ）不是引起操作系统选择新进程的直接原因.

(A) 运行进程的时间片用完
(B) 运行进程出错
(C) 运行进程要等待某一事件发生
(D) 有新进程被创建进入就绪态

## DeepSeek V4 Flash Max 解析
**答案**：  
D  

**解题切入点**：  
从进程调度发生的直接原因入手，区分哪些事件会导致当前进程无法继续运行从而必须重新调度（类似算法竞赛中任务被强制中断或主动放弃 CPU），哪些事件只是改变了就绪队列状态但不直接引发调度（如同在后台添加一个新任务，当前任务仍可继续执行）。

**推演**：  
- (A) 运行进程的时间片用完 → 当前进程被剥夺 CPU，属于强制中断，必须重新调度。  
- (B) 运行进程出错 → 进程终止，无法继续运行，需选择新进程。  
- (C) 运行进程要等待某一事件发生 → 进程阻塞，主动放弃 CPU，相当于任务等待 I/O 而挂起，需调度。  
- (D) 有新进程被创建进入就绪态 → 仅增加就绪队列长度，当前进程仍可正常运行，不直接导致调度（除非抢占式调度且新进程优先级更高，但这不是“直接原因”，而是调度策略的后续判断）。  

故 D 不是引起操作系统选择新进程的直接原因。

**易错点**：  
- 误认为新进程创建后一定会引起调度，实际上调度通常发生在当前进程无法继续（阻塞、终止、时间片用完）或中断发生时；新进程创建只是进入就绪态，并不强制当前进程让出 CPU。  
- 混淆“直接原因”与“可能触发调度的条件”，在抢占式调度中新进程优先级更高可能引发调度，但创建动作本身不是直接原因，而是调度器在检查优先级时做出的决策。

**命题规律**：  
- 常与进程状态转换结合，考察对调度时机的掌握（如阻塞、终止、时间片用完、中断等典型场景）。  
- 需区分“主动放弃 CPU”与“被动剥夺 CPU”，以及“就绪队列变化”与“调度触发”的关系。  
- 在 408 真题中，此类题目往往注重基本概念，理解调度发生的直接原因即可正确作答。
