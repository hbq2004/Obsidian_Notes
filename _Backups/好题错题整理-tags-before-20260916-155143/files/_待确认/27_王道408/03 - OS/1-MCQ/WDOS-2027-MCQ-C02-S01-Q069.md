# MCQ 第 69 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S01-Q069_题目.png|题目]]

下列事件或操作中，可能导致进程 $P$ 由执行态变为阻塞态的是（ ）.
I. 进程 $P$ 读文件
II. 进程 $P$ 的时间片用完
III. 进程 $P$ 申请外设
IV. 进程 $P$ 执行信号量的 wait( ) 操作
(A) 仅 I、IV
(B) 仅 II、III
(C) 仅 III、IV
(D) 仅 I、III、IV

## DeepSeek V4 Flash Max 解析
**答案**：  
D（仅 I、III、IV）

**解题切入点**：  
把进程状态转换看成一张状态机图：执行态、阻塞态、就绪态是节点，事件是转移边。从“执行态”到“阻塞态”的核心条件是：当前进程必须等待某事件或某种资源才能继续；而时间片用完只是被剥夺 CPU，进程仍然可运行，属于“执行态 $\to$ 就绪态”。  
算法竞赛里类似：一个 DFS/BFS 搜索节点因为等待数据、资源或信号而无法继续，只能挂起；时间片用完则只是把当前节点从队首放回 ready 队列，并没有失去继续运行的条件。

**推演**：  

I. 进程 $P$ 读文件：读文件是系统调用，传统 OS 中采用阻塞式 I/O，$P$ 要等待文件数据就绪并复制到用户空间，因此可能从执行态变为阻塞态。  

II. 进程 $P$ 的时间片用完：由时钟中断触发调度器剥夺 CPU，$P$ 回到就绪队列，仍然具备运行条件，状态变化是“执行态 $\to$ 就绪态”，不会变为阻塞态。  

III. 进程 $P$ 申请外设：外设是临界资源，若设备正被占用或系统暂时无法分配，$P$ 需要等待设备释放，从而进入阻塞态；若立即可用则可能不阻塞。题干问“可能导致”，因此成立。  

IV. 进程 $P$ 执行信号量的 wait( ) 操作：设信号量为 $S$ ，wait 操作等价于  
$$S \leftarrow S-1;\qquad \text{if } S<0 \text{ then block}(P).$$  
若资源不足，则 $P$ 被阻塞；若资源充足，则继续运行。因此也可能导致执行态变为阻塞态。  

所以 I、III、IV 都可能。

**易错点**：  
- 容易把时间片用完当成阻塞。时间片用完只是 CPU 被抢占，进程仍处于就绪状态，不是等待外部事件。  
- 容易把 wait( ) 一律当成阻塞。只有信号量资源不足时才会阻塞；如果资源充足，进程会继续运行并占用资源。  
- 容易把“申请外设”理解成一定成功或一定失败。外设可能立即可用，也可能需要等待，因此要抓“可能导致”这个措辞。  
- 读文件可能被误认为只消耗 CPU，不阻塞。但 408 语境下的同步读文件会使进程等待 I/O 完成；若特别说明非阻塞 I/O 或异步 I/O，则另当别论。

**命题规律**：  
这是进程状态转换的经典选择题，常把 I/O 操作、时间片、资源申请、信号量 wait/signal 混在一起考。核心是建立状态机模型：执行态到阻塞态必须等待某事件或资源；执行态到就绪态只需要被剥夺 CPU。算法竞赛里可类比为事件驱动的状态转移：不要看操作名，要看转移条件是否真实阻塞。后续还可能结合中断、系统调用、调度算法一起考，例如时间片轮转中进程在 ready 和 running 之间切换，而等待 I/O 时才会进入 blocked 队列。
