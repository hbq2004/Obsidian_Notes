# MCQ 第 52 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S01-Q052_题目.png|题目]]

52. 下列选项中，可能导致用户级线程切换的事件是（ ）
(A). 系统调用
(B). I/O 请求
(C). 异常处理
(D). 线程同步

## DeepSeek V4 Flash Max 解析
## 答案

**D. 线程同步**

（按 408 标准单选题作答。）

## 解题切入点

用户级线程的调度器在用户态，内核完全不知道用户线程的存在。切换本质上相当于用户态任务队列中的“当前任务”被换下、“下一个任务”被换上。因此，必须是由线程库中可被触发的调度点引起。

系统调用、I/O 请求、异常处理都会进入内核，它们引起的是“进程 / 内核线程”层面的状态转移；若 I/O 阻塞，则整个进程被挂起，用户态调度器根本得不到运行机会。线程同步（例如执行 $\mathrm{lock}$ 或 $\mathrm{wait}$）会调用线程库，若资源不可用，线程库可把当前线程移入等待队列并调度另一个用户线程，故可能引起用户级线程切换。

可以把用户级线程库看成一个协作式任务调度器：每个线程是一个状态，线程同步就是在状态图上做“等待 / 唤醒”的转移；而系统调用、I/O、异常相当于从当前状态直接跳去执行内核代码，不是由你的调度器选择下一个状态。

## 推演

- **A. 系统调用**：用户线程执行系统调用后进入内核态。若阻塞，整个进程被阻塞；若立即返回，仍回到原用户线程。线程库没有执行调度函数。
- **B. I/O 请求**：本质是系统调用，可能使当前进程进入等待状态。进程不在用户态运行，也就无法执行用户级线程切换。
- **C. 异常处理**：由内核处理缺页、非法指令等；处理完成后通常返回原控制流，或终止进程，不经过线程库调度。
- **D. 线程同步**：用户级线程库维护就绪队列 $\mathcal{R}$ 和等待队列 $\mathcal{W}$。当线程 $T_{\mathrm{cur}}$ 执行同步原语时若资源不可用，线程库将其移入 $\mathcal{W}$，再从 $\mathcal{R}$ 中选出 $T_{\mathrm{next}}$ 并恢复其上下文：

$$
T_{\mathrm{cur}} \xrightarrow{\text{同步阻塞}} \mathcal{W}, \qquad
T_{\mathrm{next}} \leftarrow \mathrm{pop}(\mathcal{R}), \qquad
\mathrm{switch}(T_{\mathrm{cur}}, T_{\mathrm{next}}).
$$

这类似于算法竞赛中手写协程调度器：当前协程申请一把已被占用的锁时，把它挂起，再从就绪协程队列中取下一个继续搜索；系统调用、I/O、异常则类似于整个程序被外部切走，而不是你自己的 DFS 在换状态。

## 易错点

1. 把“系统调用”当作线程切换。系统调用是用户态到内核态的控制转移，不是用户级线程调度器的切换指令。
2. 认为“I/O 请求”会让用户线程等待另一个线程。阻塞式 I/O 会阻塞整个进程，用户线程库没有运行机会；只有经用户态封装为非阻塞 / 异步 I/O 后才可能间接引起切换，但 408 默认不把此项作为答案。
3. 忽略“线程同步”不一定每次切换。若锁未被占用，同步原语直接成功，不切换。题干问“可能导致”，所以选 D。
4. 区分“用户级线程切换”和“进程 / 内核级线程切换”。前者只在用户态由线程库完成，后者才可能由系统调用、I/O、异常或时钟中断触发。

## 命题规律

该题考的是线程模型中“谁拥有调度权”。用户级线程调度权在线程库，内核级线程 / 进程调度权在操作系统内核。

可以把用户级线程切换理解成在自己的代码里维护一个就绪任务队列，等价于“状态图上的 DFS/BFS 换状态”；系统调用、异常、I/O 是进入内核的“系统级事件”，会导致进程 / 内核线程切换，而不是用户态任务队列调度。

复习时抓住：看到“线程同步 / yield / 条件变量”等用户态主动让出点，才可能是用户级线程切换；看到“系统调用 / I/O / 时钟中断 / 异常”优先考虑内核级切换。
