# MCQ 第 11 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S01-Q011_题目.png|题目]]

11. 操作系统是根据（ ）来对并发执行的进程进行控制和管理的.
(A) 进程的基本状态
(B) 进程控制块
(C) 多道程序设计
(D) 进程的优先权

## DeepSeek V4 Flash Max 解析
**答案**：

B. 进程控制块（PCB）。

操作系统对并发进程进行控制和管理时，核心依据是 **PCB**（Process Control Block）。PCB 是进程存在的唯一标志，OS 通过 PCB 感知、控制、调度每一个进程。

---

**解题切入点**：

并发进程在 CPU 上交替执行，OS 必须能随时“找到”每个进程的现场信息。这类似于算法竞赛中，DFS/BFS 搜索时每个状态都要有完整的“状态节点”，否则无法恢复现场、无法继续转移。

本题问的是“根据什么来管理进程”，而不是“进程有哪些状态”或“调度时考虑什么”。所以要找的是：**能够唯一标识并承载进程全部管理信息的数据结构**，即 PCB。

---

**推演**：

1. **PCB 是进程的“状态对象”**  
   一个进程能被管理，必须有一个结构记录它的全部上下文，例如：

   \[
   \text{PCB} = \langle pid,\ state,\ PC,\ 寄存器,\ 内存信息,\ 资源信息,\ 调度信息 \rangle
   \]

   这就像竞赛中每个节点要维护自己的 `dist`、`vis`、`pre` 等字段，没有这些字段就没法进行状态转移。

2. **OS 的所有进程管理操作都围绕 PCB 展开**  
   - 创建进程：分配 PCB 并初始化；
   - 调度进程：根据 PCB 中的状态和优先级选择；
   - 挂起/恢复：修改 PCB 中的状态字段；
   - 撤销进程：回收 PCB。

   可以类比为：在图上做算法时，每个点的信息都挂在“节点结构体”上，操作节点本质上就是操作这个结构体。

3. **选项分析**  
   - (A) 进程的基本状态：只是 PCB 中的一个字段，OS 根据 PCB 中的状态字段来感知进程处于就绪、运行还是阻塞，而不是根据抽象状态本身。  
   - (B) 进程控制块：正确，是 OS 管理进程的直接依据。  
   - (C) 多道程序设计：是并发执行的技术前提，不是管理进程的具体依据。  
   - (D) 进程的优先权：只是调度时参考的一个属性，同样记录在 PCB 中，不是全局管理依据。

因此选 B。

---

**易错点**：

- 容易误选 D：看到“控制和管理”就联想到调度，从而选了“优先权”。但优先权只是 PCB 中的一个字段，调度算法会使用它，而不是 OS 管理进程的直接依据。
- 容易误选 A：进程基本状态是进程状态机中的节点集合，但 OS 并不知道“抽象的进程状态”，它只知道 PCB 里记录的状态值。  
- 容易误选 C：多道程序设计是操作系统实现并发的基础，但它是“环境”而非“依据”。  
- 核心易混点：**PCB 是进程的唯一标志**。没有 PCB，进程就不存在；这与程序段、数据段不同。

---

**命题规律**：

408 操作系统喜欢考这种“最本质的概念”题，尤其是：

- PCB 是进程存在的唯一标志；
- 进程实体 = 程序段 + 数据段 + PCB；
- OS 的所有进程管理操作都围绕 PCB 进行。

这类题目的干扰项往往来自同一章的概念，比如进程状态、优先级、多道程序设计。复习时可以类比竞赛中的“状态搜索”：每个状态节点必须携带完整上下文，没有 PCB 就没有进程，就像没有状态数组就无法完成 DFS/BFS 转移。掌握这一点，再遇到类似题可直接定位到 PCB。
