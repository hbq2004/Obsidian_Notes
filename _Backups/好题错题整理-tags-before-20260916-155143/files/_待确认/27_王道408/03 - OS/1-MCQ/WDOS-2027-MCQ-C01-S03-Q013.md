# MCQ 第 13 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C01-S03-Q013_题目.png|题目]]

13. 下列关于库函数和系统调用的说法中,不正确的是 ( ).

(A) 库函数运行在用户态,系统调用运行在内核态.

(B) 使用库函数时开销较小,使用系统调用时开销较大.

(C) 库函数不方便被替换,系统调用通常很方便被替换.

(D) 库函数可以很方便地调试,而系统调用很麻烦.

## DeepSeek V4 Flash Max 解析
**答案**：
$\boxed{\text{C}}$ 。

**解题切入点**：
库函数是“用户态可替换的实现”，系统调用是“内核态固定接口”。在算法竞赛里，库函数相当于你本地随时能改的模板函数或 STL 实现；系统调用则相当于 OJ 内核提供的 `read`/`write` 接口，你不能替换其内部实现，只能按规则调用。抓住“可替换性说反了”，就能直接定位 C。

**推演**：
- 选项 A：库函数代码由用户态执行；系统调用经陷入指令 $\text{trap}$ 进入内核，由内核态代码完成服务。A 正确。
- 选项 B：系统调用多了一次“用户态 $\to$ 内核态 $\to$ 用户态”的状态迁移，需要保存/恢复现场，所以开销显著大于普通库函数调用：
$$\text{Cost}_{\text{系统调用}} \gg \text{Cost}_{\text{库函数调用}}$$
B 正确。
- 选项 C：可替换性说反了。库函数可以通过换链接库、改源码重新编译等方式方便替换；系统调用是操作系统对外接口，不能由用户程序方便替换。C 不正确。
- 选项 D：库函数在用户态，可用调试器设断点；系统调用执行在内核态，调试需要额外工具或内核级手段，相对麻烦。D 正确。

**易错点**：
- `printf`、`malloc` 是库函数，不是系统调用；它们内部可能封装 `write`、`brk`/`mmap` 等系统调用。
- 库函数内部触发系统调用，不代表库函数本身运行在内核态；运行层次要看“代码/服务执行的位置”。
- 不要把“可替换性”记反：用户态库函数易替换，内核系统调用接口难替换。
- 对 B 不要极端化：若库函数内部封装了系统调用，它的总开销会包含陷入开销；本题比较的是普通用户态调用与系统调用两种机制。

**命题规律**：
408 常在“用户态 vs 内核态”“接口 vs 实现”上设置反说干扰项。系统调用与库函数辨析题，重点记：状态迁移、陷入开销、可替换性、可调试性。这类题适合用排除法，先找“性质被对调”的选项；本质上和竞赛中“利用固定系统接口 vs 自己写模板”的思维一致。
