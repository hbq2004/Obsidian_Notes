# MCQ 第 20 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S04-Q020_题目.png|题目]]

某系统采用如下资源分配策略: 当一个进程提出资源请求而暂时无法满足时,若当前没有其他进程因等待资源而被阻塞,则该进程自行阻塞;若已有因等待资源而被阻塞的进程,则系统检查所有被阻塞的进程,若其中某些进程所占有的资源恰好是当前申请进程所需的,则立即剥夺这些资源并分配给申请进程。该策略可能导致 ( )

(A) 系统死锁
(B) 系统陷入死循环
(C) 进程回退
(D) 进程饥饿

## DeepSeek V4 Flash Max 解析
**答案**：
D：进程饥饿。

**解题切入点**：
- 抓住策略核心：一旦有进程因等待资源而阻塞，新请求者就可以剥夺该阻塞进程的资源。这本质上是“抢占 + 无公平保证”。
- 用图论类比：死锁是资源分配图中的有向环；该策略会在环即将形成时，从已阻塞进程处把资源抢走，相当于拆掉了环的最后一条边。因此不应先选“死锁”，而要思考公平性。
- 题目问“可能导致”，只需构造一个合法调度序列，使某个进程无限等待即可，类似构造题里找反例。

**推演**：
若发生死锁，取死锁进程集合中最后一个进入阻塞的进程 $P_k$。在 $P_k$ 提出资源请求时，集合中其他进程必然已经全部阻塞，而 $P_k$ 所需的资源一定由某个已阻塞进程持有。按题目策略，系统会立即剥夺该资源并分配给 $P_k$，所以 $P_k$ 不会阻塞，矛盾。因此该策略不会形成死锁。

但该策略不保证公平。例如进程 $P_0$ 需要同时持有 $R_1$ 与 $R_2$ 才能完成：

$$
P_0:\ \text{holds } R_1,\ \text{waits for } R_2 \;\Rightarrow\; \text{holds } R_2,\ \text{waits for } R_1
$$

每当 $P_0$ 因申请另一个资源而阻塞时，后来的进程就申请它手中已持有的资源；系统因 $P_0$ 已阻塞而将资源剥夺给后来者。反复如此，$P_0$ 始终不能同时凑齐 $R_1,R_2$，导致进程饥饿。系统整体仍有其他进程在推进，所以不是死锁，也不是死循环。

**易错点**：
- 误选 A：认为“资源不足且相互等待”就是死锁。但本题中最后一个阻塞者会被满足，循环等待无法稳定形成。
- 混淆“死锁”与“饥饿”：死锁是多个进程互相等待且都无法推进；饥饿是某个进程可能无限等待，但其他进程仍可正常推进。
- 误选 C：进程回退需要检查点、撤销或事务回滚等额外机制；单纯剥夺资源不等于让进程回退。
- 误选 B：系统死循环是系统级忙等或内核无限循环；本题中被剥夺资源的是阻塞进程，不参与调度推进，属于进程级等待问题。
- 注意“可能”二字：只要存在一种调度序列使某个进程无限等待，就可以选 D。

**命题规律**：
- 408 常把“死锁四条件”与“死锁 vs 饥饿”放在一起考；看到“抢占、剥夺”要想到：可能破坏死锁，但可能产生饥饿。
- 资源分配类题目可以先用资源分配图判环，再判断公平性；类似算法竞赛中判环与匹配调整问题。
- 典型结论：一次性申请破坏“占有并等待”，资源编号破坏“循环等待”，主动释放/剥夺破坏“不可剥夺”，但抢占不保证公平，因此常对应“饥饿”。
- 复习时注意区分：死锁、饥饿、死循环、回退是四个不同层次的问题，答题时术语要精确。
