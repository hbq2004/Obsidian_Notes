# MCQ 第 2 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C04-S02-Q002-R02_题目.png|题目]]

2. 逻辑文件系统的功能有 ( ).  
I.文件按名存取  
II.文件目录组织管理  
III.把文件名转换为文件描述符或文件句柄  
IV.存储保护  
(A) I、II 和 III  
(B) II、III 和 IV  
(C) I、II 和 IV  
(D) I、II、III 和 IV

## DeepSeek V4 Flash Max 解析
**答案**：  
（D）I、II、III、IV

**解题切入点**：  
按文件系统分层定位。逻辑文件系统是“能看到文件名、目录项、FCB/索引节点、访问权限”的层，它负责把用户给出的名字解析成系统内部对象；再往下是文件组织模块、基本文件系统和 I/O 控制。因此判断标准很直接：凡是和“名字—目录—元数据—权限/句柄”有关的，都是逻辑文件系统职责。

$$
\text{User/App} \rightarrow \text{Logical File System} \rightarrow \text{File-Organization Module} \rightarrow \text{Basic File System} \rightarrow \text{I/O Control}
$$

**推演**：  
- I：按名存取。用户只需传文件名，不需要知道磁盘物理位置；逻辑文件系统维护“文件名→文件控制块”的索引关系，相当于哈希表/Trie 的查找封装。
- II：目录组织管理。目录是文件名与 FCB 的映射集合，逻辑文件系统负责目录项的增删改查，就像维护一棵多叉搜索树/Trie。
- III：文件名→文件描述符/句柄。打开文件时，逻辑文件系统沿目录路径查找 FCB，并为该文件建立可供用户程序使用的句柄或文件描述符；本质上是“名字→对象”的映射。
- IV：存储保护。这里指文件/数据的访问保护，如权限位、ACL 等；逻辑文件系统在解析到 FCB 后执行权限校验，防止越权访问。

所以四项都是逻辑文件系统的功能。

**易错点**：  
- 不要把 III 与进程自己管理 fd 表混淆：题目说的是“把文件名转换为文件描述符/句柄”，这个转换动作在逻辑文件系统中完成；进程 fd 表的管理是后面的打开文件描述符层的继续处理。
- 不要把 IV 理解为内存保护或硬件保护。这里的存储保护是文件访问控制，依赖 FCB 中的权限字段，仍属逻辑层。
- 不要认为“按名存取”只是用户接口的口号。用户接口只是系统调用入口，真正实现按名解析的是逻辑文件系统。
- 注意与底层功能区分：盘块分配、空闲空间管理、磁盘驱动等不属于逻辑文件系统。

**命题规律**：  
408 常考“文件系统分层职责归属”，给出若干个功能，让考生判断属于哪一层。核心规律：  
1. 看到“文件名、目录、FCB、inode、句柄、权限/保护” → 逻辑文件系统。  
2. 看到“逻辑块号到物理块号、盘块分配、空闲空间管理” → 文件组织模块。  
3. 看到“通用 I/O 指令、设备驱动、中断、DMA” → 基本文件系统 / I/O 控制。  

像竞赛中“哈希表做键值映射、树上维护附加信息、访问节点前先做权限校验”一样，逻辑文件系统负责索引与校验，底层负责物理执行；做题时先判断数据流经过了哪一层，就能避开跨层干扰项。
