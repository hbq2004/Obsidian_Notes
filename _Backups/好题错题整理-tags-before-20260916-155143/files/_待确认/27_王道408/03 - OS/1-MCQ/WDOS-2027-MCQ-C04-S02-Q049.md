# MCQ 第 49 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C04-S02-Q049_题目.png|题目]]

49. 文件系统中，文件访问控制信息存储的合理位置是（ ）.
(A) 文件控制块
(B) 文件分配表
(C) 用户口令表
(D) 系统注册表

## DeepSeek V4 Flash Max 解析
**答案**：A（文件控制块）。

**解题切入点**：文件访问控制信息属于“文件自身的属性/元数据”，而不是“磁盘块分配信息”或“用户身份信息”。可以类比算法竞赛中的对象设计：FCB 就是一个文件对象的 struct，$owner$、$group$、$rwx$ 权限位、ACL 等字段自然应该放在这个 struct 中；而 FAT 只是维护块链的 `next` 数组，用户口令表只是登录认证的全局 `auth` 表，系统注册表只是全局配置。因此按信息归属划分，FCB 是最合理位置。

**推演**：

- 正选 A：FCB 中保存文件的基本信息、存取控制信息和使用信息。访问控制信息如“谁可读、谁可写、谁可执行”属于文件属性，通常存放在 FCB 中。Unix 的 inode 是 FCB 的等价实现，其中的 mode 字段记录 $r,w,x$ 权限位，ACL 也可作为扩展属性挂在 inode 上。
- 排除 B：文件分配表 FAT 只负责记录文件占用的簇与下一簇的链接关系，相当于链表中的 `next` 指针数组，不保存文件的权限/属主信息。
- 排除 C：用户口令表用于身份认证，证明“你是谁”，但不等同于“你能访问哪些文件”。认证与授权是两层逻辑，口令表没有文件粒度。
- 排除 D：系统注册表是操作系统和应用的全局配置数据库，与单个文件的访问控制信息没有直接绑定，且并非所有 OS 都有注册表。

所以，访问控制信息应存放在文件控制块中。

**易错点**：

- 容易误选 C：看到“访问控制”就联想到“口令”。但口令表只负责认证，不负责对具体文件授权。类比 OJ：账号密码表只负责登录，而“某人能否查看某题/提交某题”的权限字段应存在题目或比赛的元数据中。
- 容易混淆 FCB 与 FAT：FAT 只表示磁盘块分配链，不包含文件属性；文件名、权限、时间等都在 FCB/inode 或目录项对应结构中。
- 注意 inode 与 FCB 的关系：inode 是 FCB 的一种实现方式，做题时看到“索引结点”也应归为 FCB 同类。

**命题规律**：

- 408 常把“文件属性、盘块分配、用户管理、系统配置”放在同一题中作概念区分。遇到“文件访问控制信息”，优先锁定“FCB/inode”。 
- 可总结成一句话：文件粒度信息放 FCB/inode，块分配信息放 FAT/索引/位示图，文件名到 FCB 的映射放目录，用户身份信息放口令表。
- 这类题本质是“数据存储位置”的判断题，和算法竞赛中“状态信息放在节点里还是放在边里”的建模决策类似：权限是节点属性，不是边/路径属性。
