# MCQ 第 36 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C03-S02-Q036_题目.png|题目]]

36. 内存映射可以将一个文件映射到进程的虚拟地址空间的某个区域,实现文件磁盘地址和进程虚拟地址空间的映射关系,下列说法中正确的是 ( )
(A) 内存映射文件是将整个文件内容一次性加载到内存中的一种方式
(B) 内存映射文件只适用于读取文件,不支持对文件进行写操作
(C) 内存映射文件可以通过修改内存中的数据来实现对文件的写操作
(D) 由于进程的虚拟地址空间是独立的,内存映射文件不支持多进程映射到同一文件

## DeepSeek V4 Flash Max 解析
**答案**：
$\boxed{\text{C}}$

**解题切入点**：
内存映射文件的核心是“按需加载 + 内存视图”，不是把文件一次性读入内存。可以把文件想象成一个巨大的数组，`mmap` 只是拿到指向这个数组的指针，真正访问某个页时才触发缺页异常调入磁盘数据。算法竞赛里类似“在线查询”或“DFS 访问到某节点才展开其邻接表”，不是预处理时把所有状态都展开。

**推演**：
$$
\text{文件磁盘块} \xrightarrow{\text{缺页时调入}} \text{物理页框} \xrightarrow{\text{页表映射}} \text{进程虚拟地址}
$$

A 错：映射建立的是虚拟地址与文件磁盘地址之间的关系，访问时按需调页，不会一次性加载整个文件。

B 错：内存映射文件可以支持写操作。只要映射权限包含写权限，进程修改对应内存页后，脏页最终会被 OS 回写到文件中。

C 对：通过修改映射区域的内存数据，相当于修改文件在内存中的缓存页；OS 会在适当时候或调用 `msync` / `munmap` 时把改动写回磁盘文件。这正是内存映射文件的意义：用内存操作代替显式的 `read` / `write`。

D 错：多个进程可以映射同一个文件，这是常见的共享内存实现方式。进程虚拟地址空间独立，不代表物理页不能共享；不同虚拟地址可以映射到同一物理页框或同一文件页。

**易错点**：
1. 把“映射”误解为“一次性读入”。实际上缺页中断驱动加载，不访问的页可以一直不占物理内存。
2. 忽略写回机制：内存映射文件修改不是每次立即落盘，但“可以通过修改内存实现写操作”本身是对的。
3. 误以为虚拟地址空间独立就不能共享文件。页表负责把虚拟地址映射到物理地址，多进程完全可以通过各自页表映射到同一文件页。

**命题规律**：
408 常把内存映射文件放在“虚拟存储器”与“文件系统”的交叉点考查。重点就三个：是否按需加载、是否支持读写、多进程能否共享。用算法竞赛的视角看，这就是“把文件当作内存数组”的抽象题：`mmap` 后文件变成一块可以直接寻址的内存区域，读改写走内存路径，落盘由 OS 统一管理。
