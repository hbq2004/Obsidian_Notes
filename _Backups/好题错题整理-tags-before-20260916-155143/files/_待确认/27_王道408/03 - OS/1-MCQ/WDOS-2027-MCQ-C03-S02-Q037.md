# MCQ 第 37 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C03-S02-Q037_题目.png|题目]]

37. 在虚拟分页存储管理系统中,若进程访问的页面不在主存中,且主存中没有可用的空闲帧时,系统正确的处理顺序为( ).
(A) 决定淘汰页 → 页面调出 → 缺页中断 → 页面调入
(B) 决定淘汰页 → 页面调入 → 缺页中断 → 页面调出
(C) 缺页中断 → 决定淘汰页 → 页面调出 → 页面调入
(D) 缺页中断 → 决定淘汰页 → 页面调入 → 页面调出

## DeepSeek V4 Flash Max 解析
**答案**：
C。标准处理顺序为
$$
\text{缺页中断} \rightarrow \text{决定淘汰页} \rightarrow \text{页面调出} \rightarrow \text{页面调入}。
$$
注意：页面调出只对“脏页”（修改位为 $1$ ）是真正写回；若淘汰页修改位为 $0$ ，可直接丢弃，但它在流程中的位置不变。

**解题切入点**：
先抓住触发点：缺页中断是硬件在地址变换时发现页不在主存而触发的一次异常，而不是操作系统主动执行的一个决策。主存中无空闲帧，只是让处理流程多走了“页面置换”分支，并没有改变“缺页中断最先发生”这一顺序。可以把整个处理过程看成一个有依赖关系的事件链：
$$
\text{访存缺页} \rightarrow \text{中断处理} \rightarrow \text{找空闲帧} \rightarrow \text{有帧直接调入，无帧则置换}
$$
无空闲帧时，“选淘汰页”“调出旧页”“调入新页”之间存在明确的先后依赖关系。

**推演**：
整个流程可以拆成如下步骤：

1. 进程访问页面 $p$ ，地址变换机构发现 $p$ 不在主存，立即产生缺页中断，进入操作系统中断处理程序。
2. 检查空闲帧集合。本题明确“没有可用空闲帧”，所以不能直接调入，必须先执行页面置换算法，选出一个淘汰页 $v$ 。
3. 检查 $v$ 的修改位。若 $M(v)=1$ ，说明该页在主存期间被修改过，需要先写回外存，这就是“页面调出”；若 $M(v)=0$ ，说明外存副本仍有效，可直接丢弃。
4. 淘汰完成后腾出空闲帧，再把目标页 $p$ 从外存调入该帧，更新页表，恢复进程现场并重新执行被中断的指令。

所以流程是
$$
\text{缺页中断} \rightarrow \text{决定淘汰页} \rightarrow \text{页面调出} \rightarrow \text{页面调入}。
$$

这很像竞赛里实现 LRU Cache 的 `get` 流程：未命中时先进入 miss handler；若容量已满，先选择 victim，若 victim 有 pending write 则先写回，再读入新数据。顺序反了，就可能覆盖尚未写回的脏数据。

**易错点**：
- 不能选 A：缺页中断是事件起点，不可能在缺页中断发生之前先决定淘汰页。
- 不能选 B / D：页面调出和页面调入的顺序不能颠倒。调入必须发生在获得空闲帧之后；若先调入，帧容量不足，且可能覆盖淘汰页尚未写回的数据。
- 容易忽略修改位：不是每次淘汰都必须真正调出页面。若淘汰页是干净页，即修改位为 $0$ ，则不需要写回，直接覆盖即可。
- 不要把“缺页中断”和“缺页处理”混为一谈。缺页中断是硬件的异常触发，决定淘汰页、调出、调入都属于操作系统在中断处理中完成的后续步骤。

**命题规律**：
408 常考缺页中断处理流程与页面置换算法的配合，选项通常围绕“缺页中断、淘汰页选择、调出、调入”的相对顺序设置陷阱。这类题属于基础流程题，解法可以固定为依赖关系判断：事件最先，然后分配/腾挪帧，最后读入目标页。以后遇到类似题，直接用“先中断、再淘汰、先调出、后调入”的顺序即可快速排除错误选项。
