# MCQ 第 62 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S01-Q062_题目.png|题目]]

下列关于管道 (Pipe) 通信的叙述中,正确的是 ( ).
(A) 一个管道可实现双向数据传输
(B) 管道的容量仅受磁盘容量大小限制
(C) 进程对管道进行读操作和写操作都可能被阻塞
(D) 一个管道只能有一个读进程或一个写进程对其操作

## DeepSeek V4 Flash Max 解析
**答案**：C

**解题切入点**：
把管道看成一条有向边和一个有界缓冲区，而不是一个可以随便读写的共享文件。四个选项分别从方向、容量、阻塞、端点数量四个维度设置陷阱；这相当于竞赛里先判断图是有向边还是无向边、容量是 $+\infty$ 还是有限值，再决定模拟策略。读空/写满是否阻塞，可以看作一个状态机：状态是缓冲区数据量 $x$，操作就是状态转移，条件不满足就进入等待队列，类似于 BFS 中节点不可扩展时先挂起。

**推演**：

（A 错）管道的数据流向是单方向的。设写进程为 $P_w$，读进程为 $P_r$，则

$$P_w \xrightarrow{\text{数据}} P_r$$

它等价于一条有向边，不能反向传数据。若要双向通信，必须构造两条管道：

$$P_A \to P_B,\qquad P_B \to P_A$$

所以“一个管道可实现双向数据传输”不成立。

（B 错）管道容量是内核缓冲区容量，不是磁盘容量。可以把它看成有界队列，容量 $C$ 有限，当前数据量满足 $0\le x\le C$。管道不写磁盘，因此不受磁盘容量限制。

（C 对）这是典型的生产者-消费者模型：

- 读操作：当 $x=0$ 时，管道空，读进程无数据可取，会阻塞，等待写进程写入；
- 写操作：当 $x=C$ 时，管道满，写进程无空间可写，会阻塞，等待读进程取走。

所以读操作和写操作都可能被阻塞。

（D 错）管道有两个独立端：一个读端、一个写端。不是“只能有一个读进程或一个写进程”。“或”把这个模型错误地变成了二选一；正确说法是同时存在读方向和写方向，读端与写端分别供进程使用。

**易错点**：

1. 把管道当成“双向管道”，容易受 Shell 中 `|` 的名字误导；实际上管道是单向数据流。
2. 把“管道文件”当成磁盘文件，误认为容量受磁盘限制；管道缓冲区在内核内存中。
3. 只记“读空阻塞”或“写满阻塞”中的一个；要像判断边界条件一样同时检查空队列和满队列。
4. 混淆“或”和“和”：D 的陷阱在量词，不是一个管道只能有一个读进程或一个写进程，而是有读端和写端两个端点。

**命题规律**：
408 考查管道时，本质是考“有向边 + 有界缓冲区 + 同步等待”的模型。解题时先判断数据流方向，再判断缓冲区是否有界，最后模拟一次空读和满写；这等价于竞赛里先建模、再跑状态转移。类似地，信号量、消息队列、共享内存也常以同样方式命题。遇到 D 类选项要逐个检验量词和逻辑连接词，像构造题一样自己构造反例：若要双向，就多建一条反向管道；若要无限容量，就用磁盘文件，但那不是管道。
