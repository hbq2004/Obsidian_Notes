# MCQ 第 68 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C04-S02-Q068_题目.png|题目]]

下列系统调用的实现中，包含文件按名查找功能的是（ ）
(A) open( )
(B) read( )
(C) write( )
(D) close( )

## DeepSeek V4 Flash Max 解析
**答案**：
$\boxed{\text{A}.\ \text{open}()}$

$\text{open}()$ 接收路径名字符串，需要在目录树中按名查找，解析到对应 inode 后才能建立文件描述符；$\text{read}()/\text{write}()/\text{close}()$ 都只接收文件描述符，不再做按名查找。

**解题切入点**：
把路径名看成 key，目录树看成一张从文件名到 inode 的映射表/Trie；$\text{open}()$ 就是给定 key 做查找（可能还按标志位决定是否新建），返回一个整数编号 fd。之后 $\text{read}()/\text{write}()/\text{close}()$ 都在这个编号上操作，相当于已经离散化完成，不再访问 key。题目问“哪个包含按名查找”，等价于问“哪个调用需要先从字符串 key 映射到对象编号”。

**推演**：
1. 文件按名查找发生在目录系统：目录项记录 $\text{name} \mapsto \text{inode}$，查找时把路径从根目录或当前目录逐级分解，每级在目录项中匹配名字，最后得到目标文件的 inode。
2. $\text{open}(\text{pathname},\text{flags})$ 的实现必须完成上述路径解析；找到 inode 后，再创建打开文件表项并分配 fd 返回。
3. $\text{read}(fd,\text{buf},\text{count})$ 的参数中没有路径名，只有 fd；内核直接通过 fd 找到对应的打开文件表项和 inode，然后读数据。
4. $\text{write}(fd,\text{buf},\text{count})$ 同理，fd 已经确定了目标文件，不需要再查目录。
5. $\text{close}(fd)$ 只是按 fd 释放文件描述符和对应引用，也不涉及文件名的查找。

因此只有 $\text{open}()$ 包含按名查找功能。

**易错点**：
- 不要把库函数参数混淆：$\text{read}()/\text{write}()$ 的第一个参数是 fd，不是文件名；它们已经拥有了“打开文件”的句柄。
- 即使文件在 open 之后被改名/移动，已打开的 fd 仍然有效，这正好说明按名查找只在 open 时做一次，后续 I/O 不再依赖路径名。
- $\text{open}()$ 即使带创建标志，也需要先按名查找以判断文件是否存在；所以“包含按名查找”并不要求文件一定已存在。

**命题规律**：
- 408 喜欢考查“系统调用接口层”和“文件目录系统”之间的分工：谁接收路径名、谁只接收文件描述符。
- 本质是文件系统层次中，目录查询/按名查找是在打开文件阶段完成的，打开后一切操作通过 fd 这个“索引”进行。
- 以后遇到类似题，可先看参数里是否出现 pathname；出现 pathname 且要解析文件对象的系统调用，往往就包含按名查找，如 open、unlink、stat 等；只出现 fd 的调用一般不包含。
