# MCQ 第 69 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C04-S02-Q069_题目.png|题目]]

在下列选项中,文件系统可用于记录外存空闲空间使用的是( )
(A) 目录
(B) 系统打开文件表
(C) 文件分配表($FAT$)
(D) 文件控制块($FCB$)

## DeepSeek V4 Flash Max 解析
**答案**：
C：文件分配表（FAT）。  
FAT 的表项对应磁盘上的簇，$\operatorname{FAT}[i]=0$ 表示第 $i$ 簇空闲，因此可用于记录外存空闲空间。

**解题切入点**：
题目等价于问“哪个结构维护全盘空闲块/簇集合”。目录和 FCB 都是面向单个文件/文件名的元数据；系统打开文件表只是运行期内存表。FAT 则是一个全局数组，既维护文件链，又用 $0$ 作为空闲哨兵——相当于算法竞赛中 `nxt[]` 数组用 `0` 表示空位。

**推演**：
设外存共有 $N$ 个簇，概念上 FAT 第 $i$ 项对应第 $i$ 簇：

$$
\operatorname{FAT}[i]=
\begin{cases}
0, & \text{第 } i \text{ 簇空闲}\\
j, & \text{第 } i \text{ 簇已分配，下一簇为 } j\\
\text{EOF}, & \text{该簇是文件链末尾}
\end{cases}
$$

分配时扫描 $\operatorname{FAT}[i]=0$ 的空闲簇；回收时将该簇对应表项重新置 $0$。这类似维护一个“空闲结点池”：$\operatorname{FAT}[i]==0$ 等价于“第 $i$ 个位置可用”。

其他选项：
- 目录：维护 $\text{文件名}\to\text{FCB/索引结点}$ 的映射，不维护全盘空闲块。
- 系统打开文件表：保存当前打开文件的引用计数、读写位置等，是内存临时结构，不是外存空闲空间记录。
- FCB：仅描述单个文件的属性和物理地址，相当于每个文件的 `struct`，不是全盘空闲块表。

**易错点**：
1. 只把 FAT 理解为“记录文件下一簇”，忽略表项 $0$ 就是空闲簇标记。
2. 误选 FCB：FCB 只能告诉你某个文件占用了哪些块，不能直接回答“全盘还有哪些块空闲”。
3. 误选系统打开文件表：它与进程当前打开文件的操作状态有关，断电即失，不用于外存空闲空间持久记录。
4. 把 FAT 与位示图强行对立：FAT 是链表分配下的“分配/空闲”二合一表；位示图是另一种空闲空间管理方式。

**命题规律**：
408 常把目录、FCB、FAT、打开文件表放在一起考查。关键是区分三项：管辖范围（单文件还是全盘）、存储位置（磁盘持久还是内存临时）、功能（名字映射/属性描述/块分配/打开状态）。FAT 是“全局表 + 磁盘持久 + 块分配与空闲标记”，和算法题中“全局 `nxt[]` 数组”的定位一致；看到要维护全盘空闲块，立刻找全局表而非单个结构体。
