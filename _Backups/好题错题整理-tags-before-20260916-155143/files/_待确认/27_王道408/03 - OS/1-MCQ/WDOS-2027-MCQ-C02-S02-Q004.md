# MCQ 第 4 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S02-Q004_题目.png|题目]]

4. 时间片轮转调度算法是为了（ ）
(A) 多个用户能及时干预系统
(B) 使系统变得高效
(C) 优先级较高的进程得到及时响应
(D) 需要 CPU 时间最少的进程最先做

## DeepSeek V4 Flash Max 解析
**答案**：
A：多个用户能及时干预系统。

**解题切入点**：
考查调度算法与其设计目标/适用场景的对应关系。时间片轮转（Round Robin，简称 RR）是分时系统的代表算法，分时系统的首要目标是“交互式响应”，而不是最大化 CPU 利用率或优待高优先级进程。所以看到“时间片轮转”应立刻联想到“分时 / 多用户 / 及时响应 / 交互”。这就像算法竞赛中多道题同时需要推进时，按某种轮询策略分配精力，是为了让每道题都有反馈，而不是为了某一题最快出解。

**推演**：
1. RR 的机制：就绪队列按 FIFO 排成循环队列；调度器每次取队首进程，给一个时间片 $q$。若进程在 $q$ 内运行完毕则主动让出 CPU，否则由时钟中断强制剥夺，并把它放到队尾。
   可以抽象成：
   $$
   \text{for } r=1,2,\dots;\quad \text{for } i=1,2,\dots,n:\ \text{run}(P_i, q)
   $$
   这保证了每个进程都有机会获得 CPU。

2. 设就绪进程数为 $n$，某进程用完一个时间片被排到队尾后，最多再等约 $(n-1)q$ 就能再次运行。只要 $q$ 合理，多个用户都能在可感知的时间内获得 CPU，因此可以达到“多个用户能及时干预系统”的效果。

3. 排除 B：RR 会引入上下文切换开销。设切换开销为 $c$，CPU 有效利用率约为
   $$
   U=\frac{q}{q+c}
   $$
   $q$ 越小响应越好，但切换开销占比越大。RR 的核心目标不是“让系统变得最高效”，而是获得交互性和公平性。

4. 排除 C：“优先级较高的进程得到及时响应”是优先级调度算法的目标；RR 对所有就绪进程一视同仁，不区分优先级。

5. 排除 D：“需要 CPU 时间最少的进程最先做”是 SJF/SPF 短作业优先调度的思想，和轮转调度无关。

**易错点**：
- 不要把“及时响应”和“高优先级”混在一起。C 中“优先级较高”是明显标志，RR 没有优先级概念；若只说“及时响应”，才和 RR 沾边。
- 不要把“公平轮转”等价于“系统高效”。RR 因时钟中断和上下文切换，通常会降低 CPU 的有效利用率；它的优点是响应快、避免进程饥饿，而不是吞吐量最高。
- 注意时间片 $q$ 的两难：$q$ 过小会使切换开销过大；$q$ $过大$会使 RR 退化成 FCFS，失去交互性。这个设计权衡常常成为后续考点。

**命题规律**：
408 常考调度算法与其目标之间的对应关系：
- 时间片轮转：分时系统、多用户交互、及时响应；
- SJF/SPF：最短 CPU 运行时间优先、最小平均等待时间；
- 优先级调度：高优先级任务及时响应；
- 多级反馈队列：兼顾交互与批处理，动态调整优先级。

看到选项中的“时间片 / 分时 / 及时 / 多用户”就应匹配 RR；看到“优先级”优先匹配优先级调度；看到“需要 CPU 时间最少”匹配短作业优先。后续还常考时间片大小的选择：太小上下文切换开销大，太大退化为 FCFS，核心是“响应时间 vs 系统开销”的权衡。
