# MCQ 第 34 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S02-Q034_题目.png|题目]]

下列调度算法中,系统开销最小的调度算法是 ( \\_ ).

(A) 高响应比优先调度算法

(B) 多级反馈队列调度算法

(C) 先来先服务调度算法

(D) 时间片轮转调度算法

## DeepSeek V4 Flash Max 解析
**答案**：
C（先来先服务调度算法）。

**解题切入点**：
本题问的是“系统开销最小”，而不是“平均周转时间最短”“响应最快”或“最公平”。调度开销主要来自三部分：调度决策本身的计算量、上下文切换次数、定时器/队列维护成本。把调度器看成一个在线算法：FCFS 就是最简单的队列 BFS，入队、出队都是 $O(1)$，而且不抢占；其他算法要么需要扫描计算，要么需要频繁保存/恢复现场，开销都更大。

**推演**：

- FCFS 的就绪队列是 FIFO 队列：新进程从队尾入队，调度时取队首进程运行。每次调度决策只需 $O(1)$ 的队列操作；并且它是非抢占式，不会因为时间片到期而强制切换，所以由调度引起的额外上下文切换最少。
- 高响应比优先（HRRN）在每次调度时，需要计算就绪队列中每个进程的响应比：
  \[
  R_i=\frac{W_i+S_i}{S_i}
  \]
  其中 $W_i$ 是等待时间，$S_i$ 是要求服务时间。每次都要扫描就绪队列找最大值，最坏情况是 $O(n)$，且等待时间动态变化，不能一次排序后永久复用，所以决策开销明显高于 FCFS。
- 时间片轮转（RR）需要时钟中断来检查时间片是否用完。每过一个时间片 $q$，就可能发生一次强制抢占和上下文切换。一个进程若总共需要 CPU 时间 $T_i$，则额外切换次数大致与 $T_i/q$ 成正比；$q$ 越小，系统开销越大。
- 多级反馈队列（MLFQ）维护多条就绪队列，涉及队列选择、时间片控制、进程在队列之间升级/降级等状态迁移。即使每次队列操作是 $O(1)$，其整体状态维护和定时中断开销也比 FCFS 大得多。

因此，四个选项中系统开销最小的是 FCFS。

**易错点**：

- 不要因为 HRRN “兼顾长短作业”或“避免饥饿”就选它；它需要动态计算响应比，调度开销并不小。
- 不要因为 RR “响应时间短”就选它；时间片轮转的代价就是频繁上下文切换，系统开销很大。
- 不要认为 FCFS 完全没有上下文切换；进程阻塞或结束时仍会切换，但它没有时间片到期导致的强制抢占，额外开销最少。
- 注意区分“系统开销”和“调度性能/公平性”：FCFS 虽然开销最小，但可能有护航效应，平均等待时间不一定好。

**命题规律**：

408 中调度算法常以选择题形式考查，问法通常集中在：是否抢占、是否饥饿、系统开销大小、平均周转时间/等待时间、响应时间等。FCFS 常作为“最简单、开销最小、但性能不一定好”的基准算法；RR 则强调响应快但切换开销大；HRRN 和 MLFQ 更复杂但能兼顾部分性能目标。复习时可以按“抢占性、饥饿、系统开销、性能倾向”几个维度对比记忆。
