# MCQ 第 64 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S01-Q064_题目.png|题目]]

下列选项中,可能导致当前进程 $P$ 阻塞的事件是( ).
$I.$ 进程 $P$ 申请临界资源
$II.$ 进程 $P$ 从磁盘读数据
$III.$ 系统将 $CPU$ 分配给高优先权的进程
(A) 仅 $I$
(B) 仅 $II$
(C) 仅 $I$、$II$
(D) $I$、$II$、$III$

## DeepSeek V4 Flash Max 解析
**答案**：
$\boxed{C}$（仅 I、II）

**解题切入点**：
把进程状态看成状态机：当前进程 $P$ 处于运行态，阻塞的本质是运行中的进程等待某个“非 CPU”的事件或资源，事件未到就无法继续执行。而等待 CPU 不是阻塞，而是就绪态。

$$
\text{Running}\xrightarrow{\ \text{等待事件/资源}\ }\text{Blocked},\qquad
\text{Running}\xrightarrow{\ \text{抢占/时间片到}\ }\text{Ready}
$$

类似算法竞赛中的 BFS 队列：就绪态是“在队列里等 CPU 来取”；阻塞态是“暂时不在队列里，等外部事件发生后重新入队”。

**推演**：
- I：$P$ 申请临界资源，相当于请求一把互斥锁。若资源空闲，$P$ 直接进入临界区继续运行；若资源已被其他进程占用，$P$ 会被放到等待队列中，进入阻塞态。题干问“可能”，所以 I 正确。
- II：$P$ 从磁盘读数据，是典型阻塞 I/O。$P$ 发出读请求后，必须等待磁盘数据就绪并产生完成事件，因此会从运行态变为阻塞态。DMA 只减少 CPU 搬运数据的负担，但 $P$ 自身仍要等 I/O 完成。
- III：系统将 CPU 分配给高优先级进程，$P$ 只是被抢占。此时 $P$ 没有等待任何资源或事件，只是暂时没有 CPU，所以从运行态变为就绪态，而不是阻塞态。III 不正确。

综上，可能使 $P$ 阻塞的是 I、II，选 C。

**易错点**：
- 认为“申请临界资源”一定导致阻塞：若资源空闲则不会阻塞；但“可能”导致阻塞，所以 I 仍正确。
- 把“被抢占”看成“阻塞”：高优先级进程抢走 CPU 后，$P$ 在就绪队列中等待 CPU，属于就绪态。
- 把“等待 CPU”与“等待事件”混淆：等待 CPU 是 ready，等待 I/O 完成或等待临界资源是 blocked。
- 把 DMA 理解成读进程不阻塞：DMA 只是让 CPU 不必搬运数据，读进程依然要等数据到达才能继续。

**命题规律**：
408 常考进程状态转换，喜欢把“申请资源、I/O 请求、被高优先级抢占、时间片到、等待信号量”等事件混在一起，让考生判断是否导致阻塞。核心规律是：

$$
\text{被抢占/时间片到}\to\text{就绪},\qquad
\text{等待事件/资源}\to\text{阻塞}
$$

复习时可以把每个事件对应到状态机的一条边，像做状态转移题一样逐一判定，就能避开这类干扰项。
