# MCQ 第 21 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S03-Q021_题目.png|题目]]

下列关于互斥锁的说法中,正确的是( )
(A) 互斥锁只能用于多线程之间,不能用于多进程之间
(B) 互斥锁只能用于多进程之间,不能用于多线程之间
(C) 互斥锁可用于多线程或多进程之间,但只能由创建它的线程或进程来加锁和解锁
(D) 互斥锁可用于多线程或多进程之间,但只能由对它加锁的线程或进程来解锁

## DeepSeek V4 Flash Max 解析
**答案**：
D

**解题切入点**：
互斥锁的核心是“临界区 + 所有权”。判断选项时，只需建立两个预判：
- 使用范围：互斥锁既能保护进程内多线程的临界区，也能通过共享内存或内核对象保护多进程临界区；
- 解锁权限：锁被某个执行流成功加锁后，只有该执行流能解锁，创建者没有额外特权。

这可以类比算法竞赛中的搜索：一个状态被某次 DFS/BFS 扩展后，只有当前位于该状态的搜索分支能决定下一步转移；别的分支不能越权修改它的状态标记。锁的持有者就是“当前状态的主人”。

**推演**：
- A 错：互斥锁可以用于多进程互斥；例如将互斥锁放入共享内存并设置为进程共享属性。
- B 错：互斥锁最典型的使用场景就是多线程共享临界区，不能只说多进程。
- C 错：创建者不是所有者。创建后锁是“无主”的，任何有权限的执行流都可以竞争加锁；创建者若没有成功加锁，也不能解锁。
- D 对：前半句覆盖了进程与线程两种场景；后半句体现互斥锁的“所有权”约束：只有加锁者或持有者可以解锁。若允许非持有者解锁，临界区保护就会被绕过，等价于资源分配图中允许不是占有者的进程释放资源。

**易错点**：
- 不要把互斥锁和二值信号量混为一谈。二值信号量可以用 $V$ 操作由其他进程或线程唤醒；互斥锁的 $\text{unlock}$ 必须由持有者执行。
- 不要把“默认进程私有”理解为“不能跨进程”。互斥锁支持进程共享，只是需要显式构造共享条件。
- 不要把“创建者”当“持有者”。创建者只是初始化锁，持有者随加锁操作动态变化。

**命题规律**：
408 常以概念辨析题考查同步互斥工具，尤其爱考互斥锁与信号量的区别、创建者与持有者的区别、线程与进程的区别。将互斥锁看成状态机：

$$
\text{unlocked} \xrightarrow{\text{lock by } T} \text{locked}(\text{owner}=T) \xrightarrow{\text{unlock by } T} \text{unlocked}
$$

其合法迁移条件就是 $\text{owner}=T$。这和算法竞赛中维护搜索状态的思路一致：谁进入该状态，谁才有权继续操作；判断选项时，只要看是否满足这个状态转移条件即可。
