# MCQ 第 36 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S02-Q036_题目.png|题目]]

与单处理机调度相比,多处理机调度需要额外考虑的调度目标是 $(\quad)$. $I$. 负载平衡 $II$. 处理器亲和性 $III$. 进程周转时间
(A) $I$ 和 $II$
(B) $II$ 和 $III$
(C) $I$ 和 $III$
(D) $I$、$II$ 和 $III$

## DeepSeek V4 Flash Max 解析
**答案**：  
A（$I$ 和 $II$）。

**解题切入点**：  
关键词是“相比单处理机”和“额外”。单处理机调度只回答“下一个运行谁”，多处理机调度还要回答“让它运行在哪一个 CPU 上”。于是“任务如何在多个 CPU 间分配”和“分配后是否值得迁移”成为新问题。这就像从单评测机变成多评测机：原来要优化总完成时间，现在还要考虑题目分给哪台机器，以及评测数据、缓存是否要搬动。

**推演**：  
设单处理机已有的调度目标集合为 $G_{\text{single}}$。进程周转时间定义为  
$$
T_{\text{turn}} = T_{\text{finish}} - T_{\text{arrival}},
$$  
它在单处理机调度中已经是核心指标，因此 $III$ 并不是多处理机“额外”考虑的调度目标。

多处理机新增目标可写成  
$$
G_{\text{multi}} = G_{\text{single}} \cup \{\text{负载平衡}, \text{处理器亲和性}\}.
$$

- 负载平衡：有 $m$ 个处理器时，希望各 CPU 上就绪队列长度或总执行时间尽量均衡。相当于并行算法中不能让某些 worker 空转，而另一些 worker 排队严重。
- 处理器亲和性：进程在某 CPU 上运行后，该 CPU 的 cache/TLB 中可能已有它的热数据；频繁迁移进程会导致缓存失效。好比 DFS/BFS 中反复销毁并重建当前状态，代价比原地继续搜索高得多。

因此额外目标为 $I$ 和 $II$，选 A。

**易错点**：  
- 误选 $D$：把所有调度目标都当作多处理机新增目标；但周转时间是通用指标，单处理机也优化它。
- 认为负载平衡与处理器亲和性只能二选一：二者确实可能冲突，但调度器可以折中，平时保持亲和性，负载严重失衡时再迁移。
- 把处理器亲和性理解成“进程永远只能在某个 CPU 上运行”：实际上它有软亲和性和硬亲和性之分，不是绝对绑定。

**命题规律**：  
408 常以“与……相比”“额外/特有”等措辞考查“单处理机已有目标”和“多处理机新增目标”的差集。多处理机调度的核心新增考点就是负载平衡与处理器亲和性，而周转时间、等待时间、响应时间等都是通用调度指标。算法竞赛视角记忆：单机调度是顺序算法，多机调度是并行算法；并行算法相对顺序算法新增的复杂度就是“任务划分是否均衡”和“任务迁移的缓存/通信代价”，总运行时间本身不是新目标。
