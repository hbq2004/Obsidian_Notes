# MCQ 第 32 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S04-Q032_题目.png|题目]]

假定某计算机系统有 $R_1 和 $R\_2 两类可使用资源 (其中 $R_1 有两个单位, $R\_2 有一个单位), 它们被进程 $P_1 和 $P\_2 所共享, 且已知两个进程均按下列顺序使用两类资源: 申请 $R_1 \rightarrow 申请 $$R_2 \rightarrow$ 申请 $R_1 \rightarrow 释放 $$R_1 \rightarrow$ 释放 $R_2 \rightarrow 释放 $$R_1,$ 则在系统运行过程中, ( )

(A) 不可能产生死锁
(B) 有可能产生死锁, 因为 $R_1 资源不足
(C) 有可能产生死锁, 因为 $R\_2 资源不足
(D) 只有一种进程执行序列可能导致死锁

## DeepSeek V4 Flash Max 解析
**答案**：
B。该系统有可能产生死锁，因为 $R_1$ 资源不足。

**解题切入点**：
把每个进程的资源使用过程看成一个状态机：记进程阶段为 $S_0$ 到 $S_6$ ，每次申请/释放都会迁移到下一阶段。整个系统状态由两个进程当前阶段和剩余资源向量组成。

这就像算法竞赛中的“构造题 + DFS/BFS 状态搜索”：不需要枚举所有调度，只需要构造出一个可达的危险状态，证明“可能死锁”。死锁判定可以转化为等待图判环：进程等待资源时，若等待关系形成环，就说明循环等待已经成立。

**推演**：
资源总量为 $C=(2,1)$ ，初始可用 $A=(2,1)$ 。构造如下调度：

1. $P_1$ 申请 $R_1$ 成功，$A=(1,1)$ ，$P_1$ 持有 $(1,0)$ ；
2. $P_2$ 申请 $R_1$ 成功，$A=(0,1)$ ，$P_2$ 持有 $(1,0)$ ；
3. $P_1$ 申请 $R_2$ 成功，$A=(0,0)$ ，$P_1$ 持有 $(1,1)$ ；
4. $P_2$ 申请 $R_2$ 阻塞，因为 $R_2$ 被 $P_1$ 持有；
5. $P_1$ 申请 $R_1$ 阻塞，因为没有空闲 $R_1$ ：两个 $R_1$ 分别被 $P_1$ 和 $P_2$ 持有。

此时等待关系为：
$$
P_1 \to P_2 \quad (\text{等待 } R_1),\qquad
P_2 \to P_1 \quad (\text{等待 } R_2)
$$

形成环，所以死锁。若 $R_1$ 有 3 个单位，第 5 步 $P_1$ 可以申请到空闲 $R_1$ ，随后释放资源，死锁被打破；若只增加 $R_2$ ，两个进程仍可能各自持有一个 $R_1$ 和一个 $R_2$ 后，同时申请第二个 $R_1$ 而互相等待。因此根因是 $R_1$ 资源不足。

**易错点**：
- 不要以为两个进程按相同顺序申请资源就不会死锁。这里的顺序不是线性一致的：$R_1$ 在 $R_2$ 前后各申请一次，无法用“资源编号递增申请”来避免循环等待。
- 不要把第 3 步“申请 $R_1$ ”理解成重新申请第一个 $R_1$ ；它是在已持有第一个 $R_1$ 和 $R_2$ 的基础上，再申请一个 $R_1$ 单位。
- 不要选 C。$R_2$ 只有 1 个只决定了谁先拿到 $R_2$ ；真正让持有 $R_2$ 的进程也无法推进的原因是 $R_1$ 没有多余单位。
- 不要选 D。到达死锁的进程执行序列不唯一。例如 $P_1R_1, P_1R_2, P_2R_1$ 也能进入同样的死锁状态，所以“只有一种序列”是错的。

**命题规律**：
408 常以“是否可能死锁”设问，本质是让考生在状态空间中构造危险状态，再用等待图判环。对应到算法竞赛，就是构造题 + 图论环检测：先猜一个危险状态，再检查它是否可达；若不可达则需证明所有路径都安全。见到“某类资源有 $m$ 个单位”，优先算每个进程在阻塞前会持有多少、还缺多少，这等价于银行家算法中的安全性检查。
