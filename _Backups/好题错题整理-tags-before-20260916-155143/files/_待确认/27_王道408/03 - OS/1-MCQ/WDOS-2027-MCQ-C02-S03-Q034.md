# MCQ 第 34 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S03-Q034_题目.png|题目]]

并发进程之间的关系是 ( ).
(A) 无关的
(B) 相关的
(C) 可能相关的
(D) 可能是无关的, 也可能是有交往的

## DeepSeek V4 Flash Max 解析
**答案**：
$\boxed{\text{D}}$ 。并发进程之间可能是无关的，也可能是有交往的，不能一概而论。

**解题切入点**：
关键看并发进程之间是否“感知”彼此，即是否共享变量、共享资源或发生通信。这很像算法竞赛中判断两个子问题是否真正独立：如果各自只用自己的局部变量，互不读写全局状态，就是无关；如果都操作同一个全局数组或计数器，就必须考虑同步。题目问“可能是”，所以应构造两个极端样例：一个无关样例，一个有交往样例，然后排除绝对化选项。

**推演**：
设两个并发进程为 $P$ 与 $Q$ ，它们访问的变量/资源集合分别为 $V_P$ 与 $V_Q$ 。

- 若 $V_P \cap V_Q = \varnothing$ ，且二者之间没有消息通信，则 $P$ 与 $Q$ 互不影响，执行结果与调度顺序无关，此时它们是无关的并发进程。
- 若 $V_P \cap V_Q \neq \varnothing$ ，或二者存在通信，则一个进程的执行可能影响另一个进程，此时它们是有交往的并发进程。

用集合语言表示：
$$
\text{无关} \iff V_P \cap V_Q = \varnothing \land \text{无通信},\qquad
\text{有交往} \iff V_P \cap V_Q \neq \varnothing \lor \text{有通信}.
$$

从状态机角度看，无关进程的联合状态转移可以分解为互不影响的 $\delta_P$ 与 $\delta_Q$ ；有交往进程则可能出现 $\delta_P$ 依赖 $Q$ 当前状态的转移，就像 DFS 中两个分支共享同一个 $visited$ 状态。因此并发关系不是固定标签。

**易错点**：
- 误以为“并发”一定“共享资源”：并发只是时间上重叠，若各进程只用局部变量，完全可以无关。
- 误以为“并发”一定“无关”：一旦共享全局变量、文件或设备，执行顺序就可能影响结果。
- 被 C 的“可能相关”迷惑：这个说法不是完全错误，但它漏掉了“也可能无关”的另一半，单选题应选覆盖更完整的 D。
- 把“有交往”等同于“死锁/错误”：有交往只是说明需要同步互斥，并不必然导致死锁。

**命题规律**：
本题是并发控制的基础概念题，命题人常用“绝对化选项 + 半对选项”制造干扰。应对方式类似于算法竞赛中构造反例：先构造无关并发样例排除 A 与 B ，再构造有交往样例排除只保留“相关”这一可能性的 C ，最终锁定 D 。后续真题往往沿这条线继续考临界区、信号量、管程、死锁四个必要条件，本质上都是在处理“有交往”进程之间的同步与互斥问题。
