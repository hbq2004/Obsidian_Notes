# MCQ 第 6 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C01-S01-Q006_题目.png|题目]]

系统调用是由操作系统提供给用户的，它( ).
(A) 直接通过键盘交互方式使用
(B) 只能通过用户程序间接使用
(C) 是命令接口中的命令
(D) 与系统的命令一样

## DeepSeek V4 Flash Max 解析
**答案**：
B。

**解题切入点**：
操作系统给用户提供的接口分两类：

- 命令接口：面向人的“前端”，如 Shell 命令；
- 程序接口：面向用户程序的“内核 API”，即系统调用。

算法竞赛类比：命令接口像 OJ 的提交按钮，系统调用像评测机暴露给提交代码的 $\text{judge::run()}$；你不能在终端靠键盘直接“敲”一个系统调用，只能在用户程序里调用它。

**推演**：
把用户态和内核态看作状态机，系统调用是用户程序主动发起的状态迁移边：

$$ \text{用户程序} \xrightarrow{\text{syscall/trap}} \text{内核} $$

逐项判断：

1. A 错：键盘交互属于命令接口；系统调用需要 CPU 执行陷入指令，不是键盘输入。
2. C 错：系统调用属于程序接口，不是命令接口中的命令。
3. D 错：系统命令是 Shell 解析的字符串命令；系统调用是带编号和参数的陷入请求。命令执行时可能触发系统调用，但命令 $\ne$ 系统调用。
4. B 对：站在最终用户角度，使用路径是

$$ \text{用户} \rightarrow \text{用户程序} \xrightarrow{\text{调用系统调用}} \text{操作系统服务} $$

所以只能通过用户程序间接使用。

若把“用户”理解成“用户程序”，则用户程序是直接调用者；这里的“间接”是相对最终用户而言的。

**易错点**：
- 误以为“命令最终触发系统调用”所以命令就是系统调用。类比：OJ 的提交按钮会触发评测 API，但按钮不是 API。
- 误把库函数（如 $\text{printf}$、$\text{read}$ 的封装）当成系统调用本身；库函数是用户态封装，系统调用是陷入内核的那一层。
- 对 B 的“只能”产生纠结：要看清题目中的“用户”是最终用户，系统调用不是给人直接在键盘上用的。

**命题规律**：
408 常在“操作系统接口”处出概念题，本质是区分命令接口和程序接口。后续可能结合具体系统调用（如 $\text{fork}$、$\text{read}$、$\text{write}$）考查：哪些是库函数、哪些是系统调用、陷入内核时的参数传递方式；复习时按“接口分类 $\rightarrow$ 触发过程 $\rightarrow$ 典型系统调用”这条线记忆。
