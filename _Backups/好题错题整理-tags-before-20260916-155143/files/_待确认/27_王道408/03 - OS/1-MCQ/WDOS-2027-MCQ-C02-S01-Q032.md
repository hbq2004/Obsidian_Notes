# MCQ 第 32 题

![[_Attachments/题目识别/WDOS-2027-MCQ/WDOS-2027-MCQ-C02-S01-Q032_题目.png|题目]]

32. 下列关于信号的处理描述中,错误的是（ ）.
(A) 当进程从内核态转为用户态时,会检查是否有待处理的信号
(B) 当进程从用户态转为内核态时,也会检查是否有待处理的信号
(C) 操作系统对某些信号的处理是可以忽略的
(D) 操作系统允许进程通过系统调用,自定义某些信号的处理程序

## DeepSeek V4 Flash Max 解析
**答案**：
B。

**解题切入点**：
信号投递可以看作“返回用户态前”的一次回调检查。一个完整的模式切换周期是 $S_U \to S_K \to S_U$ ：前半段 $S_U \to S_K$ 是触发入口，后半段 $S_K \to S_U$ 是返回出口。待处理信号只在返回出口检查并分发给用户态处理函数，而不是在入口也检查一次。这就像算法题里“进入递归时只保存状态，回溯时才根据标记决定是否执行某个回调”。

**推演**：
- 当进程发生中断、异常或系统调用时，由 $S_U$ 进入 $S_K$ ，内核保存用户态现场，执行内核逻辑。
- 内核准备返回 $S_U$ 前，检查当前进程的 $\text{pending}$ 信号位图；若存在未屏蔽信号，则构造用户态栈帧，使 CPU 返回到 $S_U$ 后先进入信号处理函数，而不是直接恢复到原断点。
- 所以 $A$ 正确：检查点挂在 $S_K \to S_U$ 这条边上。
- $B$ 把检查点放在 $S_U \to S_K$ 这条边上，错误。刚进入内核时只是保存现场，还没有到“交付信号”的返回出口；且用户自定义 handler 必须在 $S_U$ 中执行，不可能在进入内核的同时执行。
- $C$ 正确：某些信号的默认动作就是忽略，进程也可将多数信号设为忽略；但 $\text{SIGKILL}$ 与 $\text{SIGSTOP}$ 不能被忽略。
- $D$ 正确：进程通过 $\text{signal}()$ 或 $\text{sigaction}()$ 等系统调用注册自定义处理函数，相当于维护一张 $\text{信号编号} \rightarrow \text{回调函数}$ 的分发表。
- 因此错误项为 $B$。

**易错点**：
1. 不要把“信号产生”和“信号处理”混为一谈：产生只是置 $\text{pending}$ 位，真正处理要等 $S_K \to S_U$ 前的检查。这类似“先标记、后统一处理”的懒更新。
2. 不要认为所有模式切换都检查。普通信号的投递检查只在返回用户态路径上，不在用户态进入内核态的路径上。
3. 注意“某些”这个限定词。$\text{SIGKILL}$ 与 $\text{SIGSTOP}$ 是硬规则，不能被忽略、捕获或屏蔽；因此 $C$、$D$ 说“某些”才正确。
4. 信号处理函数在用户态执行，内核只负责保存现场、设置跳转并恢复现场；所以“从用户态转内核态时执行处理函数”在语义上也不成立。

**命题规律**：
408 常把信号放在“进程通信/中断机制”中考查，核心是处理时机和处理方式。可以把它抽象为带回调的状态机：
$$
S_U \xrightarrow{\text{中断/系统调用/异常}} S_K \xrightarrow{\text{返回前检查并投递信号}} S_U
$$
其中 $S_K \to S_U$ 是信号处理触发点。复习时记住：$\text{pending}$ 位图 + 信号屏蔽字 + 回调函数表三者的关系，同时把 $\text{SIGKILL}$、$\text{SIGSTOP}$ 作为不可覆盖的例外项即可。
