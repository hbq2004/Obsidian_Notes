# 选择题 第 18 题

![[_Attachments/题目识别/27_王道408-题目/CN-C06-65-M18_题目.png|题目]]

18.【2022统考真题】假设主机 $H$ 通过 $HTTP/1.1$ 请求浏览某 $Web$ 服务器 $S$ 上的 $Web$ 页 $news408.html$, $news408.html$ 引用了同目录下的 $1$ 幅图像, $news408.html$ 文件大小为 $1MSS$(最大段长), 图像文件大小为 $3MSS$, $H$ 访问 $S$ 的往返时间 $RTT=10ms$, 忽略 $HTTP$ 响应报文的首部开销和 $TCP$ 段传输时延。若 $H$ 已完成域名解析，则从 $H$ 请求与 $S$ 建立 $TCP$ 连接时刻起，到接收到全部内容止，所需的时间至少是 ( )

(A) $30ms$
(B) $40ms$
(C) $50ms$
(D) $60ms$

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C06-65-M18_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：B（40ms）。  
理由：HTTP/1.1 默认使用持久连接，TCP 建链需 1 个 RTT，HTML 响应需 1 个 RTT，3MSS 图像在 TCP 慢启动下还需 2 个 RTT，共 $4$ 个 RTT，即 $40\text{ ms}$。

**解题切入点**：拿到题先不要直接数“HTTP 请求个数”，而要把时间轴按 RTT 切成“轮次”，结合协议分层逐步看：DNS 已省，TCP 建链、HTTP 请求/响应、TCP 慢启动拥塞窗口。这类似算法竞赛中“按轮模拟”的思路：每一轮能传多少数据，取决于当前拥塞窗口大小，而不是只看文件总大小。

**推演**：

按 $RTT$ 作为一轮交互时间，并设初始拥塞窗口为 $1\text{ MSS}$。

1. **TCP 三次握手**：  
   从 H 请求建立 TCP 连接开始，到连接建立，需要 $1$ 个 RTT。第三次 ACK 可捎带后续 HTTP 请求，因此不额外增加一个 RTT。

2. **请求并接收 HTML 文件**：  
   $news408.html$ 大小为 $1\text{ MSS}$，一个 TCP 段即可传完，因此需要 $1$ 个 RTT。  
   收到 HTML 后，H 才能解析出图像 URL，并立即发出图像请求。

3. **请求并接收图像文件**：  
   图像大小为 $3\text{ MSS}$，且此时仍受 TCP 慢启动影响。  
   发送 HTML 后收到 ACK，服务器拥塞窗口由 $1\text{ MSS}$ 增至 $2\text{ MSS}$。因此图像请求到达后，第一个 RTT 最多传 $2\text{ MSS}$，还剩 $1\text{ MSS}$；再经过一个 RTT 传完剩余部分。  
   所以图像阶段需要 $2$ 个 RTT。

总时间为：

$$
T = (1 + 1 + 2) \times RTT
= 4 \times 10\text{ ms}
= 40\text{ ms}
$$

因此选 **B**。

**易错点**：

- 容易误选 A（$30\text{ ms}$）：忽略了 TCP 慢启动，认为 $3\text{ MSS}$ 图像也能在一个 RTT 内全部传完。
- 容易误选 C（$50\text{ ms}$）：误把 HTTP/1.1 当成非持久连接，为图像重新建立 TCP 连接；HTTP/1.1 默认持久连接，不需要重新建链。
- 容易把 HTML 请求和图像请求并行流水线化：图像 URL 必须等收到 HTML 后才能解析，因此二者至少是串行关系。
- 注意第三次握手 ACK 可捎带 HTTP 请求，不要把 TCP 建链时间额外多算一个 RTT。

**命题规律**：本题将应用层 HTTP 与传输层 TCP 拥塞控制结合考查，核心是“持久连接 + 慢启动轮次”。常见变式包括：改为 HTTP/1.0 非持久连接、增加多个图像、加入 DNS 解析时间、设置慢启动阈值或发生超时重传、计算平均吞吐率等。复习时建议画时间轴，标注每个 RTT 内发生的报文和拥塞窗口变化，并牢记 HTTP/1.1 默认持久连接、初始拥塞窗口为 $1\text{ MSS}$。
