# 选择题 第 2 题

![[_Attachments/题目识别/27_王道408-题目/CN-C06-65-M02_题目.png|题目]]

2. 从协议分析的角度，WWW 服务的第一步操作是浏览器对服务器的 (    ).

(A) 请求地址解析  
(B) 传输连接建立  
(C) 请求域名解析  
(D) 会话连接建立

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C06-65-M02_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：B，HTTP 基于 TCP，浏览器在发送 HTTP 请求前必须先与服务器建立 TCP 连接（三次握手），因此第一步是传输连接建立。

**解题切入点**：从协议分层入手，WWW 服务应用层 HTTP 依赖传输层 TCP，故第一步是传输层连接建立；可类比算法竞赛中构造数据结构前先分配内存（建立连接），若先操作未初始化的内存则出错，类似地 HTTP 请求前必须先完成 TCP 连接。

**推演**：浏览器访问 Web 服务器的完整过程如下：
1. 解析 URL，提取域名（如 www.example.com）。
2. 向 DNS 服务器请求域名解析（获得 IP 地址），此操作是对 DNS 服务器，并非对目标服务器。
3. 浏览器获得目标服务器 IP 后，向其发起 TCP 三次握手（SYN、SYN+ACK、ACK），建立传输连接。
4. TCP 连接建立成功后，浏览器在该连接上发送 HTTP 请求（如 GET /index.html）。
5. 服务器响应 HTTP 报文，浏览器渲染页面。

题目限定“浏览器对服务器的”操作，因此第一步为第 3 步的 TCP 连接建立，即选项 (B) 传输连接建立。选项 (C) 请求域名解析指向 DNS 服务器，选项 (A) 请求地址解析（ARP）发生在数据链路层，且需在已有 IP 且需发送数据时触发，非第一步；选项 (D) 会话连接建立通常指 SSL/TLS 握手等，但 HTTP 默认无此步骤，且属于应用层范畴，在 TCP 建立之后。

**易错点**：
- 误选 (C) 请求域名解析：混淆“浏览器对服务器”与“浏览器对 DNS 服务器”，DNS 解析是必要前置步骤，但非对目标服务器的操作。
- 误选 (A) 请求地址解析：ARP 将 IP 解析为 MAC 地址，但发生在局域网内部，且需在 TCP 连接建立后发送数据时才会触发，不是第一步。
- 误选 (D) 会话连接建立：HTTP 本身无会话层概念，若涉及 HTTPS 等安全连接，则 SSL 握手发生在 TCP 建立之后，仍不是第一步。

**命题规律**：考点为 TCP/IP 协议栈的层次依赖关系，考查应用层协议（HTTP）与下层协议（TCP）的先后顺序。常见变式包括“WWW 服务的第一步操作”“HTTP 请求之前必须完成什么”等，也可扩展为“FTP 的第一步操作”类似题目。复习时需牢记各层协议功能及交互顺序，注意区分“对服务器”与“对 DNS 服务器”等细节。
