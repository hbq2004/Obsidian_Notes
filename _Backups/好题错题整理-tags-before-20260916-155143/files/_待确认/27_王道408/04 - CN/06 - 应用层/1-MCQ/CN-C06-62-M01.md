# 选择题 第 1 题

![[_Attachments/题目识别/27_王道408-题目/CN-C06-62-M01_题目.png|题目]]

1. 域名与（\_）具有一一对应的关系.

A. $IP$地址  
B. $MAC$地址  
C. 主机  
D. 以上都不是

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C06-62-M01_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：D。理由：域名与 IP 地址、MAC 地址、主机都不保证一一对应，DNS 的映射关系本质上是多对多的，因此选“以上都不是”。

**解题切入点**：拿到这道题先抓“一一对应”四个字，它对应数学中的“双射”：既不能多对一，也不能一对多。可以把 DNS 类比成算法竞赛里的“分布式哈希表”：域名是 key，IP 地址是 value；看到“有映射关系”不能直接默认是双射，还要检查 key 和 value 是否允许重复。考题就是在考察“域名”和“IP 地址”之间到底是不是单射且满射。

**推演**：设域名集合为 $D$，IP 地址集合为 $I$，DNS 解析关系可表示为
$$R \subseteq D \times I.$$
若 $R$ 是一一对应关系，则必须满足：

- 每个域名只能对应一个 IP 地址；
- 每个 IP 地址也只能对应一个域名。

但实际情况不满足。

1. **一个域名可对应多个 IP 地址**：大型网站常配置多条 A 记录，例如
   $$d \rightarrow i_1,\; d \rightarrow i_2,\; \dots$$
   这属于一对多关系，破坏了单射条件。

2. **一个 IP 地址可对应多个域名**：服务器上用虚拟主机技术，一台服务器的一个 IP 地址可以托管多个域名，例如
   $$i \leftarrow d_1,\; i \leftarrow d_2,\; \dots$$
   这属于多对一关系，也破坏了单射条件。

因此 $R$ 不是一一对应关系。

再看其他选项：

- **MAC 地址**：域名解析发生在网络层之上的应用层，域名最终通过 DNS 解析成 IP 地址，再由 ARP 将 IP 地址映射到 MAC 地址，域名与 MAC 地址没有直接的一一对应关系。
- **主机**：一台主机可以拥有多个域名（如各种别名），一个域名也可以解析到多台主机的 IP 地址，因此也不一一对应。

综上，四个选项中没有一个与域名具有一一对应关系，所以选 D。

**易错点**：

- 易错选 A，认为“域名就是代替 IP 地址给人看的，所以一定一一对应”。实际上 DNS 支持负载均衡和虚拟主机，允许一对多和多对一。
- 易错选 C，认为“一个域名对应一台主机”。实际上一个域名可以解析到多个 IP，对应多台服务器；一台主机也可以绑定多个域名。
- 要区分“映射”和“一一对应”：DNS 提供的是“域名到 IP 的映射”，但映射不一定是双射。

**命题规律**：408 中常考 DNS 的基本概念、域名解析过程和 DNS 使用的端口（TCP/UDP 53）。本题属于基础概念题，一般出现在选择题中。常见变式包括：

- “一个域名对应多个 IP 地址”是为了什么？——负载均衡。
- “一个 IP 地址对应多个域名”是通过什么实现的？——虚拟主机。
- “域名解析采用什么协议？递归查询和迭代查询的区别？”

复习建议：把 DNS 当作一个分布式数据库来理解，不要死记“域名和 IP 一一对应”的错误结论；同时把 DNS、ARP、DHCP、NAT 等协议的分工串起来，考试时才能快速判断。
