# 选择题 第 6 题

![[_Attachments/题目识别/27_王道408-题目/CN-C06-62-M06_题目.png|题目]]

6. 在 DNS 的递归查询中，由（ ）给客户端返回地址.

(A) 最开始连接的服务器
(B) 最后连接的服务器
(C) 目的地址所在服务器
(D) 不确定

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C06-62-M06_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：A。在 DNS 递归查询中，客户端只把请求交给“最开始连接的服务器”（本地 DNS 服务器），由该服务器负责后续查询，并把最终 IP 地址返回给客户端。

**解题切入点**：先抓住题干关键词“递归查询”。递归查询的特点是：客户端只发起一次请求，之后由最开始连接的 DNS 服务器“全权代理”解析过程。这很像算法竞赛中主函数调用一个辅助函数 `solve()`：主函数只调用一次，`solve()` 内部再去调用若干子函数；最终返回结果给主函数的是 `solve()`，而不是最后被调用的那个子函数。DNS 的层次结构又类似分治：根 DNS、顶级域 DNS、权威 DNS 各管一部分，逐层缩小查询范围。

**推演**：

假设客户端要解析 `www.example.com`，它配置的本地 DNS 服务器就是“最开始连接的服务器”。

1. 客户端向本地 DNS 服务器发送递归查询。  
2. 本地 DNS 服务器查看缓存，若没有记录，则继续向其他 DNS 服务器查询。  
3. 本地 DNS 服务器向根 DNS 服务器查询，根 DNS 返回顶级域 `.com` 的服务器地址。  
4. 本地 DNS 服务器向 `.com` 顶级域服务器查询，顶级域服务器返回 `example.com` 的权威 DNS 服务器地址。  
5. 本地 DNS 服务器向 `example.com` 权威 DNS 服务器查询，权威服务器返回 `www.example.com` 的 IP 地址。  
6. 本地 DNS 服务器缓存该结果，并把最终 IP 地址返回给客户端。

用链式表示：

$$
\text{客户端} \to \text{本地DNS服务器（最开始连接的服务器）} \to \text{根DNS} \to \text{顶级域DNS} \to \text{权威DNS}
$$

结果返回时是逆着链路走：

$$
\text{权威DNS} \to \text{本地DNS服务器} \to \text{客户端}
$$

所以，最终给客户端返回地址的是“最开始连接的服务器”，即本地 DNS 服务器。权威 DNS 服务器虽然提供最终记录，但它只是返回给上一级 DNS 服务器，并不直接返回给客户端。

**易错点**：

1. 误选 B“最后连接的服务器”：递归查询中，最后连接的服务器通常是权威 DNS 服务器，它把结果返回给本地 DNS 服务器，而不是直接返回给客户端。  
2. 误选 C“目的地址所在服务器”：权威服务器确实拥有最终地址记录，但在递归查询中它不直接和客户端通信。  
3. 混淆递归查询与迭代查询：递归查询是“一问到底、原路返回”；迭代查询是查询者自己依次询问多个服务器。  
4. 忽略缓存：本地 DNS 服务器有缓存时可以直接返回结果，但仍然是最开始连接的服务器返回，不是“不确定”。

**命题规律**：这是 408 计算机网络应用层 DNS 的常考概念题。重点考查递归查询与迭代查询的区别、DNS 层次结构、缓存机制。常见变式有：给出查询流程问某一步由谁响应；判断递归查询报文数量；或结合 HTTP 访问过程综合考查。复习时应画出 DNS 解析流程图，记住“客户端总是先找本地 DNS 服务器；递归查询由本地 DNS 返回最终答案；迭代查询中本地 DNS 逐级向根/顶级/权威服务器询问”。
