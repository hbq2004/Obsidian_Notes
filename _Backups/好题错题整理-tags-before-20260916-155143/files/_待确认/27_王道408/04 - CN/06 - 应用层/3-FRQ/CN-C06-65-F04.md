# 综合题 第 4 题

![[_Attachments/题目识别/27_王道408-题目/CN-C06-65-F04_题目.png|题目]]

4.【2021统考真题】某网络拓扑如下图所示，以太网交换机 $S$ 通过路由器 $R$ 与 $Internet$ 互联。路由器部分接口、本地域名服务器、$H_1$、$H_2$ 的 IP 地址和 MAC 地址如图中所示。在 $t_0$ 时刻 $H_1$ 的 ARP 表和 $S$ 的交换表均为空，$H_1$ 在此刻利用浏览器通过域名 www.abc.com 请求访问 Web 服务器，在 $t_1$ 时刻 ($t_1>t_0$) $S$ 第一次收到了封装 HTTP 请求报文的以太网帧，假设从 $t_0$ 到 $t_1$ 期间网络未发生任何与此次 Web 访问无关的网络通信。请回答下列问题.

【图：网络拓扑。图中设备连接关系：R 通过 Internet 与 Web 服务器（www.abc.com）相连；R 与交换机 S 端口 1 相连；S 端口 2 连接本地域名服务器；S 端口 3 连接 $H_2$；S 端口 4 连接 $H_1$。图中标注的 IP 地址和 MAC 地址为：R：192.168.1.1/25，00-11-22-33-44-aa；本地域名服务器：192.168.1.126/25，00-11-22-33-44-bb；$H_2$：192.168.1.3/25，00-11-22-33-44-dd；$H_1$：192.168.1.2/25，00-11-22-33-44-cc。】

(1) 从 $t_0$ 到 $t_1$ 期间，$H_1$ 除了 HTTP，还运行了哪个应用层协议？从应用层到数据链路层，该应用层协议报文是通过哪些协议进行逐层封装的？
(2) 若 $S$ 的交换表结构为 <MAC 地址，端口>，则 $t_1$ 时刻 $S$ 交换表的内容是什么？
(3) 从 $t_0$ 到 $t_1$ 期间，$H_2$ 至少接收到几个与此次 Web 访问相关的帧？接收的是什么帧？帧的目的 MAC 地址是什么？

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C06-65-F04_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**  
(1) 还运行了 **DNS**；该应用层协议报文（DNS 查询/响应）的逐层封装顺序为：**DNS → UDP → IP → 以太网**。  
(2) $t_1$ 时刻 $S$ 的交换表内容为：  
$$\langle 00\!-\!11\!-\!22\!-\!33\!-\!44\!-\!cc,\;4\rangle,\quad \langle 00\!-\!11\!-\!22\!-\!33\!-\!44\!-\!bb,\;2\rangle,\quad \langle 00\!-\!11\!-\!22\!-\!33\!-\!44\!-\!aa,\;1\rangle.$$  
(3) $H_2$ 至少接收到 **2** 个帧；接收的是 **ARP 请求帧**（广播帧）；帧的目的 MAC 地址为 **广播地址 $\text{FF-FF-FF-FF-FF-FF}$**。

**解题切入点**  
- 题目描述了一个典型的小型局域网通过路由器访问 Internet 的场景。$H_1$ 首次访问域名，必然先进行 **DNS 解析**，而 DNS 服务器的 IP 在同一子网，因此需要 **ARP** 获取其 MAC；之后 HTTP 请求需发往默认网关，再次触发 **ARP** 获取路由器 MAC。  
- 交换机 $S$ 初始交换表为空，通过 **自学习** 记录源 MAC 与端口的映射，并依据目的 MAC 决定转发或泛洪。  
- 本题可类比算法竞赛中的“缓存”机制：ARP 表≈缓存（IP→MAC），交换表≈缓存（MAC→端口）。DNS 解析相当于“一次远程查询”，而 ARP 广播相当于“全量广播查找”，交换机学习则类似“记录访问过的地址以避免后续广播”。  

**推演**  
1. **$t_0$ 时刻**：$H_1$ 的 ARP 表、$S$ 的交换表均为空。  
2. **DNS 解析阶段**  
   - $H_1$ 需要向本地域名服务器（192.168.1.126）查询 www.abc.com 的 IP。  
   - **步骤 1**：$H_1$ 发送 **ARP 请求**（广播帧，源 MAC=00-11-22-33-44-cc，目的 MAC=FF-FF-FF-FF-FF-FF，询问“192.168.1.126 的 MAC 地址”）。  
     - $S$ 从端口 4 收到该帧，学习源 MAC → 端口 4（$\langle 00\!-\!11\!-\!22\!-\!33\!-\!44\!-\!cc,4\rangle$），因目的为广播，$S$ 将其泛洪至端口 1、2、3。  
     - $H_2$（端口 3）收到该广播帧。  
   - **步骤 2**：DNS 服务器收到 ARP 请求后，发送 **ARP 响应**（单播，源 MAC=00-11-22-33-44-bb，目的 MAC=00-11-22-33-44-cc）。  
     - $S$ 从端口 2 收到，学习源 MAC → 端口 2（$\langle 00\!-\!11\!-\!22\!-\!33\!-\!44\!-\!bb,2\rangle$），查目的 MAC 已对应端口 4，故仅转发至端口 4。  
     - $H_2$ 未收到此帧。  
   - **步骤 3**：$H_1$ 获得 DNS 服务器 MAC 后，发送 **DNS 查询**（UDP 报文，封装在以太网帧中，源 MAC=00-11-22-33-44-cc，目的 MAC=00-11-22-33-44-bb）。  
     - $S$ 从端口 4 收到，查目的 MAC 已在表中学到（端口 2），仅转发至端口 2。  
     - $H_2$ 未收到。  
   - **步骤 4**：DNS 服务器返回 **DNS 响应**（源 MAC=00-11-22-33-44-bb，目的 MAC=00-11-22-33-44-cc）。  
     - $S$ 从端口 2 收到，查目的 MAC 对应端口 4，仅转发至端口 4。  
     - $H_2$ 未收到。  
3. **HTTP 请求阶段**  
   - $H_1$ 得到 Web 服务器 IP，判断其不在本地子网，故需将 HTTP 请求发往默认网关 $R$（192.168.1.1）。  
   - **步骤 5**：$H_1$ 发送 **ARP 请求**（广播，源 MAC=00-11-22-33-44-cc，目的 MAC=FF-FF-FF-FF-FF-FF，询问“192.168.1.1 的 MAC 地址”）。  
     - $S$ 从端口 4 收到，学习源 MAC（已存在，更新计时），因目的为广播，泛洪至端口 1、2、3。  
     - $H_2$（端口 3）再次收到该广播帧。  
   - **步骤 6**：$R$ 发送 **ARP 响应**（单播，源 MAC=00-11-22-33-44-aa，目的 MAC=00-11-22-33-44-cc）。  
     - $S$ 从端口 1 收到，学习源 MAC → 端口 1（$\langle 00\!-\!11\!-\!22\!-\!33\!-\!44\!-\!aa,1\rangle$），查目的 MAC 对应端口 4，仅转发至端口 4。  
     - $H_2$ 未收到。  
   - **步骤 7**（$t_1$ 时刻）：$H_1$ 发送 **HTTP 请求**（TCP 报文，封装在 IP 数据报中，再封装在以太网帧中，源 MAC=00-11-22-33-44-cc，目的 MAC=00-11-22-33-44-aa）。  
     - $S$ 从端口 4 收到，查目的 MAC 已对应端口 1，仅转发至端口 1。  
     - $H_2$ 未收到。  
4. **结论**  
   - 从 $t_0$ 到 $t_1$，$S$ 共学习到三个 MAC 地址：$H_1$（端口 4）、DNS 服务器（端口 2）、$R$（端口 1）。  
   - $H_2$ 仅收到步骤 1 和步骤 5 的两个广播帧，均为 ARP 请求，目的 MAC 为广播地址。  

**易错点**  
- **混淆 ARP 请求与响应**：ARP 请求是广播，响应是单播；响应只发给请求者，其他主机不会收到。  
- **忽略 DNS 过程**：部分考生认为 HTTP 请求直接发送，忘记域名解析必须先进行，从而漏掉 DNS 和对应的 ARP 步骤。  
- **交换机学习时机**：交换机只有在收到帧时才学习源 MAC，且初始时未知 MAC 会导致泛洪；但一旦学习到，后续相同目的 MAC 的帧只转发到对应端口。  
- **IP 地址与 MAC 地址的对应**：需注意路由器 R 的 LAN 口 IP 与 MAC 是图中给出的，不能混淆。  
- **“至少”的含义**：若其他步骤的帧因交换机尚未学习而被泛洪，$H_2$ 可能收到更多帧。但本题中，由于步骤 2 已学习 DNS 服务器 MAC，步骤 3、4 不会泛洪；步骤 6 已学习 R 的 MAC，步骤 7 不会泛洪。因此 $H_2$ 只收到两个广播帧，这是最小值。  

**命题规律**  
- **考点定位**：本题综合考查 **DNS 解析流程**、**ARP 协议**（广播/响应）、**以太网交换机自学习与转发**（泛洪与过滤）。  
- **常见变式**：  
  1. 改变设备位置（如 DNS 服务器与 H1 不在同一子网，则需通过路由器转发 DNS 请求，分析会更复杂）。  
  2. 要求画出 ARP 表或交换表的变化过程。  
  3. 结合 VLAN 配置，考查交换机在不同 VLAN 下的转发行为。  
- **复习建议**：  
  1. 熟练掌握 TCP/IP 协议栈各层封装关系，以及 DNS、HTTP、ARP 等协议的工作流程。  
  2. 理解交换机“学习-转发-泛洪”的完整过程，能手动模拟帧在不同时刻的流向。  
  3. 注意区分广播帧与单播帧，以及不同协议（ARP、DNS、HTTP）的触发顺序。  
  4. 练习时多画时间轴和帧序列，强化对“第一次通信”场景的分析能力。
