# 选择题 第 12 题

12.当TCP在传送大量数据时,是以( )的大小将数据进行分割发送的,进行重发时同样也是以此为单位的.
(A) $MSS$
(B) 字节
(C) 比特
(D) $MTU$

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C05-53-M12_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：A。TCP 将应用层字节流按最大报文段长度 MSS 分割成一个一个 TCP 报文段发送，重传时也以报文段（MSS 大小的数据块）为单位。

**解题切入点**：先抓住题干中“分割发送”和“重发单位”两个关键词，定位到 TCP 传输层与 IP 网络层的层次区别。可以类比算法竞赛中的“分块处理”：你有一个很大的数组，不会一个一个元素地读写，而是按某个块大小 $B$ 分块，整块读入、整块重发。这里的 $B$ 就是 MSS，而“IO 缓冲区总大小”对应 MTU。MSS 是 TCP 层给应用数据设定的最大块长，MTU 是 IP 层/链路层能承载的最大数据报长度，二者不能混用。

**推演**：

TCP 是面向字节流的协议，应用层交下来的数据是一个连续的字节流。TCP 并不能把这串字节无限长地直接交给 IP 层，因为 IP 层又有 MTU 的限制，所以 TCP 需要把字节流“分段”。

设典型以太网 MTU 为 $1500$ 字节，IPv4 首部为 $20$ 字节，TCP 首部为 $20$ 字节，则 MSS 为：

$$
\text{MSS} = \text{MTU} - \text{IP首部} - \text{TCP首部}
= 1500 - 20 - 20 = 1460
$$

即每个 TCP 报文段最多携带 $1460$ 字节应用数据。发送时，TCP 按 MSS 将字节流分割成多个报文段：

$$
\text{字节流} \xrightarrow{\text{按 MSS 分割}} 
\text{TCP 报文段}_1, \text{TCP 报文段}_2, \dots
$$

每个报文段都有自己的序号字段，表示该报文段中第一个字节的序号。发送方发出后，若超时未收到确认，或收到重复 ACK，则重传未确认的报文段。重传的基本单位是“报文段”，而不是某一个字节或比特：

- 若按字节重传，每个 ACK/重传都要精确定位到单字节，开销极大，且不符合 TCP 分段设计的初衷；
- 若按比特重传，则更无意义；
- MTU 是整个 IP 数据报的最大长度，包含 IP 首部，若把 MTU 当作 TCP 数据分割大小，TCP 数据加上 TCP/IP 首部后必然超过 MTU，会导致 IP 分片，降低性能。

因此，TCP 在大量数据传输时，按 MSS 的大小分割发送，重传时也以 MSS 大小的报文段为单位。

**易错点**：

1. **混淆 MSS 和 MTU**：  
   MTU 是网络层/链路层的最大传输单元，包含 IP 首部；MSS 是 TCP 层最大报文段中的数据部分长度，不包含 TCP 首部和 IP 首部。不能直接拿 MTU 作为 TCP 数据分割大小。

2. **误以为 TCP 按字节分割和重发**：  
   TCP 的序号和确认号确实是以字节为单位编号的，但 TCP 的实际传输/重传单位是报文段。序号按字节编号，是为了可靠有序地重组数据流，并不等于发送单位是字节。

3. **忽略“重传单位”与“发送单位”的一致性**：  
   重传通常重发整个未确认的报文段，不是只重发丢失的那一个字节。这道题专门强调“重发时同样以此为单位的”，就是为了提示这一点。

4. **不考虑 IPv6 或路径 MTU 的影响**：  
   若是 IPv6，IP 首部为 $40$ 字节，则相同 MTU 下：
   $$
   \text{MSS} = 1500 - 40 - 20 = 1440
   $$
   但概念不变，仍是 MSS。

**命题规律**：  
本题属于 TCP 可靠传输与报文段分装的经典概念题，重点是 MSS 与 MTU 的区分，以及“TCP 以报文段为传输单位”的层次思想。常见变式有：

- 给出 MTU 和 IP/TCP 首部长度，求 MSS；
- 考察 TCP 建立连接时 MSS 选项的协商机制，通常取双方较小值；
- 对比 UDP 的分片与 TCP 的 MSS 分段，说明 TCP 尽量减少 IP 分片；
- 考察“序号按字节编号”与“报文段按 MSS 分割”之间的联系。

复习时建议把各层的传输单位梳理清楚：TCP 层是报文段（segment），IP 层是数据报（datagram），链路层是帧（frame）。抓住“MSS = MTU − 网络层首部 − 传输层首部”这一换算关系，配合一道计算题即可牢固掌握。
