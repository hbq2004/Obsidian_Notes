# 选择题 第 37 题

![[_Attachments/题目识别/27_王道408-题目/CN-C05-53-M37_题目.png|题目]]

37. 在一个 $TCP$ 连接中, $MSS$ 为 $1KB$, 当拥塞窗口为 $34KB$ 时收到了 $3$ 个冗余 $ACK$ 报文。若在接下来的 $4RTT$ 内报文段传输都是成功的, 则当这些报文段均得到确认后, 拥塞窗口的大小是 ( )

(A) $8KB$

(B) $16KB$

(C) $20KB$

(D) $21KB$

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C05-53-M37_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：C。收到 3 个冗余 ACK 触发快重传/快恢复，$ssthresh$ 降为 17KB；标准 TCP Reno 快恢复中，收到新 ACK 后以 $cwnd=17KB$ 进入拥塞避免，4 个 RTT 中前 1 个用于完成快恢复，后 3 个各加 1KB，因此最终为 20KB。

**解题切入点**：先抓“3 个冗余 ACK”——这不是超时，不能退回到慢开始把窗口置为 1KB，而应走快重传/快恢复。可以类比算法竞赛中的“评测反馈”：收到 3 个冗余 ACK，相当于已经有一部分数据包成功到达，不能清空所有状态推倒重来；快恢复相当于先保留“预算”，等新的 ACK 确认后，再进入稳定的线性增长阶段。

**推演**：

题目已知 $MSS=1KB$，当前拥塞窗口

$$
cwnd = 34KB
$$

收到 3 个冗余 ACK 后，执行快重传和快恢复：

$$
ssthresh = \frac{cwnd}{2} = \frac{34}{2} = 17KB
$$

标准 TCP Reno 快恢复先将拥塞窗口临时置为：

$$
cwnd = ssthresh + 3 \times MSS = 17 + 3 = 20KB
$$

接着传输成功。4 个 RTT 中：

- 第 1 个 RTT 内，重传的丢失报文段收到确认，快恢复结束；
- 收到新 ACK 后，$cwnd$ 回到：

$$
cwnd = ssthresh = 17KB
$$

- 进入拥塞避免阶段，之后每个 RTT 增加 1 个 MSS：

$$
cwnd = 17 + 3 \times 1 = 20KB
$$

因此最终为 20KB，选 C。

**易错点**：

1. **误按超时处理**：若把 3 个冗余 ACK 当成超时，则 $cwnd=1KB$ 进入慢开始，4 个 RTT 后可能得到 16KB，错选 B。
2. **忽略快恢复的临时膨胀**：收到 3 个冗余 ACK 后，标准 Reno 快恢复会先 $+3MSS$，但收到新 ACK 后要回到 $ssthresh$，不能一直保持 20KB 或直接从 17KB 加 4 个 RTT。
3. **RTT 计数错误**：不能简单认为 4 个 RTT 都用于拥塞避免；其中第 1 个 RTT 主要用于完成快恢复，因此后续只有 3 个 RTT 线性加 1，得到 $17+3=20KB$。
4. **忽略单位**：本题 $MSS=1KB$，所以数值上 1 个 MSS 就是 1KB；若 MSS 不为 1KB，应按 MSS 的倍数计算。

**命题规律**：本题核心考点是 TCP 拥塞控制的快重传、快恢复与拥塞避免。常见变式包括：比较“超时”和“3 个冗余 ACK”的不同处理、给出多个连续 RTT 求 $cwnd$、结合 $ssthresh$ 判断处于慢开始还是拥塞避免阶段。复习时应画清状态转移：超时回到 1KB 慢开始，3 个冗余 ACK 进入快重传/快恢复，收到新 ACK 后进入拥塞避免，并注意接收窗口对最终发送窗口的限制。
