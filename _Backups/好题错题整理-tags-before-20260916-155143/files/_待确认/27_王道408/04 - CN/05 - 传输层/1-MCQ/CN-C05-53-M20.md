# 选择题 第 20 题

![[_Attachments/题目识别/27_王道408-题目/CN-C05-53-M20_题目.png|题目]]

20. TCP采用三报文握手建立连接,其中第三个报文是( ).
(A) TCP连接请求
(B) 对TCP连接请求的确认
(C) 对TCP连接请求确认的确认
(D) TCP普通数据

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C05-53-M20_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：C。第三个报文是客户端最后发出的 ACK，用于确认服务器发回的“对 TCP 连接请求的确认”（即 SYN+ACK 报文），因此是“对 TCP 连接请求确认的确认”。

**解题切入点**：先抓三报文握手的时序和标志位：  
第 1 个报文是 SYN，第 2 个报文是 SYN+ACK，第 3 个报文是 ACK。  
从算法竞赛视角看，这很像交互题的状态同步：前两次交互已经交换了“请求”和“确认”，但裁判（服务器）还必须收到“我已收到你的确认”这一最终 ACK，否则双方状态不一致。协议分层则类似分治：把“连接管理”作为传输层的子问题，不关心底层 IP 选路细节。

**推演**：设客户端为 $C$，服务器为 $S$，$C$ 的初始序号为 $x$，$S$ 的初始序号为 $y$。

第 1 个报文：

$$
C \xrightarrow{\mathrm{SYN}=1,\ \mathrm{seq}=x} S
$$

这是 TCP 连接请求，含义是：$C$ 请求建立连接，并告知自己的初始序号 $x$。

第 2 个报文：

$$
S \xrightarrow{\mathrm{SYN}=1,\ \mathrm{ACK}=1,\ \mathrm{seq}=y,\ \mathrm{ack}=x+1} C
$$

这是对 TCP 连接请求的确认，同时 $S$ 也发出自己的连接请求，并告知自己的初始序号 $y$。因为 SYN 报文占用一个序号，所以确认号是 $x+1$。

第 3 个报文：

$$
C \xrightarrow{\mathrm{ACK}=1,\ \mathrm{seq}=x+1,\ \mathrm{ack}=y+1} S
$$

这是对第 2 个报文的确认，也就是对“TCP 连接请求确认”的确认。它让服务器确认：客户端已经收到了服务器的初始序号 $y$。由于第 2 个报文是“对 TCP 连接请求的确认”，所以第 3 个报文就是“对 TCP 连接请求确认的确认”。

TCP 是全双工通信，双方都需要同步对方的初始序号，因此第 3 个 ACK 不能省略。

**易错点**：

- 误选 B：第 2 个报文才是“对 TCP 连接请求的确认”，不是第 3 个。
- 误选 A：第 1 个报文才是 TCP 连接请求。
- 误选 D：第三个报文虽然是 ACK，但若之后有数据，可以捎带在 ACK 中发送；不过从握手语义上看，它不是“普通数据报文”，而是连接建立的最终确认。
- 容易算错序号：SYN 标志占用一个序号，因此第 2 个报文的 $\mathrm{ack}=x+1$，第 3 个报文的 $\mathrm{ack}=y+1$。

**命题规律**：考点是传输层 TCP 连接管理，重点考查三次握手的报文类型、标志位组合以及序号/确认号变化。常见变式包括：给出初始序号求第三个报文的确认号；问第二次握手能否携带数据；问第三次 ACK 丢失后服务器会怎样；结合 TCP 四次挥手考查 FIN/ACK 标志位。复习时建议画完整时序图，熟记三次握手的标志位序列：SYN、SYN+ACK、ACK。
