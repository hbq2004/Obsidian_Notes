# 选择题 第 29 题

![[_Attachments/题目识别/27_王道408-题目/CN-C05-53-M29_题目.png|题目]]

29. 一个 TCP 连接的数据传输阶段,若发送端的发送窗口值由 2000 变为 3000,意味着发送端可以 ( )

A. 在收到一个确认之前可以发送 3000 个 TCP 报文段

B. 在收到一个确认之前可以发送 1000B

C. 在收到一个确认之前可以发送 3000B

D. 在收到一个确认之前可以发送 2000 个 TCP 报文段

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C05-53-M29_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：C。TCP 发送窗口以“字节”为单位，表示发送端在收到确认前最多能发送的未确认数据量；窗口值变为 3000 表示最多可发送 3000B。

**解题切入点**：拿到题目先问：2000 和 3000 是什么单位？TCP 的滑动窗口是“字节窗口”，不是“报文段个数”。这就像算法竞赛中双指针滑动窗口的容量表示能容纳的元素个数，而不是块数或子数组个数；窗口从 2000 变为 3000，是容量上限变成 3000，不是增量 1000，也不是 3000 个“块”。

**推演**：TCP 发送窗口由接收方通告窗口和拥塞窗口共同决定：
$$W = \min(\text{cwnd}, \text{rwnd})$$
其单位是字节。设 $Snd.Una$ 是最近一个未确认字节的序号，$Snd.Nxt$ 是下一个待发送字节的序号，则已发送但未确认的数据量满足：
$$\text{未确认数据量}=Snd.Nxt-Snd.Una \le W$$
所以 $W$ 表示“不需要收到新的确认，最多可以有多少字节在途”。

当 $W$ 由 2000 变为 3000 时，新的上限为：
$$W=3000\text{ B}$$
因此发送端在收到一个确认之前，最多可发送 3000B 数据。

选项逐项看：

- A、D：发送窗口以字节计，不以“TCP 报文段个数”计；3000B 可能只是几个报文段，不是 3000 个报文段。
- B：1000B 只是窗口增量 $\Delta W=3000-2000$，不是变化后的窗口值。
- C：正确。

**易错点**：

- 错把窗口单位看成“报文段个数”，容易误选 A 或 D。TCP 窗口字段表示的是字节数。
- 把“由 2000 变为 3000”理解成“多发送 1000B”。若旧窗口数据已占满，确实只多出 1000B 可用；但窗口值本身的含义是“未确认数据总量上限变为 3000B”。
- 忽略发送窗口是 $\min(\text{cwnd}, \text{rwnd})$ 共同决定的。本题不细分，但要牢记。
- 混淆报文段长度与字节数。TCP 报文段长度由 MSS 等决定，窗口值不能直接换算成固定段数。

**命题规律**：这是 TCP 流量控制/滑动窗口的基础题。408 常见变式有：给出 $\text{rwnd}$ 和 $\text{cwnd}$ 求发送窗口；给出窗口和 MSS 求最多能发送几个报文段；结合 ACK 到达后窗口滑动判断还能发多少字节。复习时应画窗口滑动示意图，熟记 $W=\min(\text{cwnd},\text{rwnd})$，并始终以字节为单位思考。
