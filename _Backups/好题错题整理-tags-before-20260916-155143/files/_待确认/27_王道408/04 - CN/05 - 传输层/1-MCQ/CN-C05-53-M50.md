# 选择题 第 50 题

![[_Attachments/题目识别/27_王道408-题目/CN-C05-53-M50_题目.png|题目]]

50.【2019统考真题】某客户通过一个 TCP 连接向服务器发送数据的部分过程如图所示。客户在 $t_0$ 时刻第一次收到确认序列号 $ack\_seq = 100$ 的段，并发送序列号 $seq = 100$ 的段，但发生丢失。若 TCP 支持快速重传，则客户重新发送 $seq = 100$ 段的时刻是（ ）

A. $t_1$

B. $t_2$

C. $t_3$

D. $t_4$

【图：TCP 连接时序图。左侧为客户，右侧为服务器，时间轴向下。$t_0$ 时刻客户收到 $ack\_seq = 100$，发送 $seq = 100$（丢失），随后发送 $seq = 200$、$seq = 300$、$seq = 400$。$t_1$、$t_2$、$t_3$ 时刻客户分别收到 $ack\_seq = 100$，$t_4$ 时刻 $seq = 100$ 段超时。】

## DeepSeek V4 Flash Max 解析

**答案**：C。客户在 $t_1,t_2,t_3$ 接连收到 3 个重复确认 $ack\_seq=100$，触发快速重传，因此在 $t_3$ 重传 $seq=100$，而不是等到 $t_4$ 超时。

**解题切入点**：先抓住“确认号的含义”和“重复确认的个数”。TCP 的 ACK 是累积确认，$ack\_seq=100$ 表示接收端期望的下一个字节序号是 100，并不表示已经确认了 $seq=100$ 这个段。快速重传的本质是：收到 3 个重复 ACK 就提前判定丢包并重传。  
这可以类比算法竞赛中维护一个计数器/哈希表：每收到一个相同 $ack\_seq$ 的重复 ACK，就对“怀疑丢失”的计数加一；计数到达阈值 3 时立即提前返回，而不是等最坏情况下的超时。也可以理解为分层协议把“可靠传输”这个大问题分治为确认、超时、重传等子问题，本题只需关注 TCP 层的确认与重传机制。

**推演**：

1. TCP 中，$ack\_seq$ 表示“下一个期望接收的字节序号”。  
   因此 $t_0$ 时刻收到 $ack\_seq=100$，说明服务器已经连续收到 100 之前的字节，当前期望收到 $seq=100$。

2. 客户发送 $seq=100$ 的段，但该段丢失。之后客户发送的 $seq=200$、$seq=300$、$seq=400$ 段到达服务器。  
   由于 $seq=100$ 缺失，TCP 累积确认无法前移，服务器对每一个乱序到达的段都回复 $ack\_seq=100$。

3. 重复 ACK 计数如下：

| 时刻 | 客户收到的 ACK | 重复 ACK 计数 |
|---|---|---|
| $t_0$ | $ack\_seq=100$（原始确认） | 0 |
| $t_1$ | $ack\_seq=100$ | 1 |
| $t_2$ | $ack\_seq=100$ | 2 |
| $t_3$ | $ack\_seq=100$ | 3，触发快速重传 |
| $t_4$ | $seq=100$ 段超时 | 已被提前重传，不会走到这里 |

4. 快速重传规定：收到 3 个重复 ACK 时立即重传丢失的报文段，不需要等重传计时器超时。  
   因此在 $t_3$ 时刻，客户重新发送 $seq=100$ 段。

所以正确选项是 **C**。

**易错点**：

- 易把 $t_0$ 也算作 3 个重复 ACK 之一，误选 $t_2$。其实 $t_0$ 是第一次收到 $ack\_seq=100$，不是重复 ACK；$t_1,t_2,t_3$ 才是 3 个重复 ACK。
- 容易误选 $t_4$，即认为一定要等超时重传。快速重传正是为了不等超时，用重复 ACK 提前发现丢包。
- 容易误选 $t_1$ 或 $t_2$，即把快速重传阈值记成 1 个或 2 个重复 ACK。标准阈值是 3 个重复 ACK。
- 容易混淆确认号含义：$ack\_seq=100$ 不是“确认收到了 $seq=100$”，而是“期望收到 $seq=100$”，所以它反而说明 $seq=100$ 未被确认。

**命题规律**：本题属于 TCP 可靠传输中的高频考点，重点考查“累积确认”和“快速重传”。常见变式有：问收到几个重复 ACK 后触发快速重传；对比快速重传与超时重传；结合拥塞控制考查收到 3 个重复 ACK 后 $cwnd$、$ssthresh$ 的变化。复习时应把 TCP 确认机制、滑动窗口、超时重传、快速重传、拥塞控制放在一起理解，并注意画时间轴数清重复 ACK 的个数。
