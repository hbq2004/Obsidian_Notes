# 选择题 第 51 题

![[_Attachments/题目识别/27_王道408-题目/CN-C05-53-M51_题目.png|题目]]

51.【2019统考真题】若主机甲主动发起一个与主机乙的 TCP 连接,甲、乙选择的初始序列号分别为 2018 和 2046，则第三次握手 TCP 段的确认序列号是（ ）

A. 2018

B. 2019

C. 2046

D. 2047

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C05-53-M51_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：D，第三次握手时甲确认乙的 SYN，确认号 = 乙的初始序列号 + 1 = 2046 + 1 = 2047。

**解题切入点**：本题直接考查 TCP 三次握手中序列号与确认号的对应关系。可类比算法竞赛中的“双指针同步”：甲的 SYN 相当于第一次请求，乙的 SYN+ACK 是响应并附带自己的初始值，最后的 ACK 则是确认乙的初始值，形成闭环。抓住“确认号总是对方上次发送的序列号加 1”这一核心规则即可快速定位。

**推演**：
1. 第一次握手（甲 → 乙）：甲发送 SYN 段，初始序列号 $seq_a = 2018$，无确认号。
2. 第二次握手（乙 → 甲）：乙回复 SYN+ACK 段，确认号 $ack = seq_a + 1 = 2019$，同时乙自己的初始序列号 $seq_b = 2046$。
3. 第三次握手（甲 → 乙）：甲发送 ACK 段，确认号 $ack = seq_b + 1 = 2046 + 1 = 2047$，表示正确收到乙的 SYN。

因此第三次握手 TCP 段的确认序列号为 2047。

**易错点**：
- 误将第一次握手的序号（2018）或第二次握手的确认号（2019）当作答案，混淆了不同阶段的含义。
- 忘记了确认号是“对方初始序号加 1”的原则，尤其当题目同时给出两方序号时容易计算错误。
- 第三次握手虽然携带 ACK，但本身不消耗序号（除非带数据），但确认号计算仍按上述规则，与数据无关。

**命题规律**：
- 考点：TCP 三次握手的序列号与确认号机制，是计算机网络必考基础题。
- 常见变式：给出不同初始序号，计算第二次或第三次握手的确认号；或反过来根据确认号推断初始序号。
- 复习建议：牢记三次握手各阶段发送的标记位（SYN、ACK）、序号与确认号的变化规则，并辅以简单的数字例子练习，确保理解“+1”的含义。
