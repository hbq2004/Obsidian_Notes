# 选择题 第 8 题

![[_Attachments/题目识别/27_王道408-题目/CN-C05-52-M08_题目.png|题目]]

8. 下列关于 $UDP$ 检验和的说法中,错误的是( ).

(A) 计算检验和时需按 2 字节对齐,若数据部分不足,则需用一个全 0 字节填充

(B) 若 $UDP$ 检验和计算结果为 0,则在检验和字段填充 0

(C) $UDP$ 检验和字段的计算包括一个伪首部、$UDP$ 首部和携带的用户数据

(D) $UDP$ 检验和的计算方法是二进制反码运算求和再取反

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C05-52-M08_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：B。UDP 检验和若计算结果为 $0$，发送时应在检验和字段填全 1，即 $0\text{xFFFF}$，而不是填 $0$；填 $0$ 会与“未计算检验和”混淆。

**解题切入点**：本题考的是 UDP 检验和的计算细节。可以类比算法竞赛中实现一个自定义哈希/校验函数：先明确“参与计算的数据范围”（伪首部 + UDP 首部 + 数据），再处理“对齐补零”（类似结构体对齐 padding），最后处理“算出来的特殊值”（类似哈希冲突或哨兵值）。本题的关键就是特殊值 $0$ 的发送规则，而不是简单地“结果为 0 就填 0”。

**推演**：

UDP 检验和计算步骤如下：

1. 构造一个不发送的“伪首部”，用于将 IP 层信息纳入校验：
   $$(\text{源 IP 地址},\ \text{目的 IP 地址},\ \text{零 1 字节},\ \text{协议号 17},\ \text{UDP 长度})$$
   其中 UDP 长度为 UDP 首部加数据的总字节数。

2. UDP 首部共 8 字节：
   $$(\text{源端口},\ \text{目的端口},\ \text{长度},\ \text{检验和})$$
   计算检验和时，检验和字段先置为 $0$。

3. 将伪首部、UDP 首部和用户数据全部按 16 bit（2 字节）切分。若数据部分为奇数个字节，则需在末尾补一个全 $0$ 字节，使总长度为偶数；该填充字节不发送，仅参与计算。

4. 对所有 16 位字做“二进制反码求和”，若有进位则回卷相加：
   $$S=\sum_{i=1}^{n} w_i \quad(\text{反码求和，进位加回最低位})$$

5. 对反码和 $S$ 按位取反，得到检验和：
   $$C=\overline{S}$$

6. 关键特殊处理：如果 $C=0$，发送时并不填 $0$，而是填全 1，即：
   $$C_{\text{字段}}=\begin{cases}
   0\text{xFFFF}, & C=0,\\
   C, & C\neq 0
   \end{cases}$$

因为 $0$ 在反码中有全 $0$ 和全 $1$ 两种表示，而 UDP 检验和字段为全 $0$ 时通常表示“未计算检验和”，所以计算得到 $0$ 时必须发送全 $1$，避免歧义。

逐项判断：

- (A) 正确：计算检验和需要按 2 字节对齐，数据部分不足 2 字节时补一个全 0 字节。
- (B) 错误：检验和计算结果为 $0$ 时，应填 $0\text{xFFFF}$，不是 $0$。
- (C) 正确：UDP 检验和包含伪首部、UDP 首部和用户数据。
- (D) 正确：计算方法是二进制反码运算求和后再取反。

因此错误的是 B。

**易错点**：

- 容易把“计算结果为 $0$”与“检验和字段填 $0$”直接对应，忽略了 RFC 768 中“计算结果为 0 时发送全 1”的特殊规定。
- 容易漏掉伪首部。UDP/TCP 的检验和必须包含伪首部，但伪首部不随报文发送。
- 容易忽略奇数字节补 $0$ 的细节，且补的 $0$ 字节不参与实际传输。
- 反码求和不是普通求和，需要在每次产生进位时回卷加到最低位。
- 计算时忘记将 UDP 检验和字段本身置为 $0$，也会导致结果错误。

**命题规律**：这是传输层 UDP 协议的高频细节考点，常与 TCP 检验和、IPv4 首部检验和对比考查。常见变式包括：“UDP 检验和计算范围不包括哪些字段”“伪首部包含哪些内容”“检验和字段为全 0 表示什么含义”“IPv6 下 UDP 检验和是否可选”等。复习时建议记住 IPv4 伪首部的 12 字节结构，对比 TCP 的伪首部，并特别记忆“检验和为 0 时发送全 1”这一特殊规则。
