# 选择题 第 8 题

![[_Attachments/题目识别/27_王道408-题目/CN-C03-34-M08_题目.png|题目]]

8. 下列关于连续 $ARQ$ 的说法中,错误的是（ ）
(A) 发送方可以连续发送若干数据帧, 而不是发完一个数据帧就停下来等待确认帧.
(B) 发送方收到了接收方发来的确认帧, 还可以接着发送数据帧.
(C) 相比停止-等待协议,连续 $ARQ$ 因为减少了等待时间,所以提高了信道利用率.
(D) 接收方可以不按序接收数据帧.

## DeepSeek V4 Flash Max 解析

**答案**：D。连续 ARQ（常规/后退 N 帧式连续 ARQ）的接收窗口大小为 1，接收方必须按序接收；不按序到达的数据帧通常被丢弃，不能把“接收方可以不按序接收”作为连续 ARQ 的一般性质。

**解题切入点**：  
拿到题目先判断考点：这是数据链路层“可靠传输/滑动窗口协议”。连续 ARQ 与停止-等待协议的核心区别是“发送方是否流水线式连续发送”。可以用算法竞赛的思维类比：

- 停止-等待协议 ≈ 单线程同步等待：发一个请求，等一个 RTT，再发下一个。
- 连续 ARQ ≈ 滑动窗口限流：窗口大小内允许多个“在途请求”，收到 ACK 相当于窗口指针后移，释放新空位。
- 后退 N 帧（GBN）的接收端 ≈ 在线处理时只接受“下一个预期的连续值”，遇到乱序输入直接丢弃。
- 选择重传（SR）的接收端则更像用缓存/数据结构暂存乱序数据，等缺口补齐后再按序提交。

本题的关键就是看接收窗口 $W_R$ 是否为 1。

**推演**：  

设一帧的发送时间为 $T_f$，单程传播时延为 $\tau$，确认帧发送时间忽略不计。停止-等待协议中，发送方每发完一帧都要等到确认才能继续，因此一个发送周期约为 $T_f+2\tau$，信道利用率为

$$
U_{\mathrm{SW}}=\frac{T_f}{T_f+2\tau}.
$$

连续 ARQ 允许发送方在收到确认前连续发送若干帧。若发送窗口大小为 $W$，则信道利用率大约为

$$
U_{\mathrm{cont}}=\min\left(1,\frac{W T_f}{T_f+2\tau}\right).
$$

因为 $W>1$，所以 $\dfrac{W T_f}{T_f+2\tau}>\dfrac{T_f}{T_f+2\tau}$，即连续 ARQ 减少了发送方的空闲等待时间，提高了信道利用率。因此 C 正确。

逐项判断：

- A 正确：发送方不必发完一帧就停下来等确认，可以连续发送到发送窗口满为止。
- B 正确：收到确认帧后，发送窗口向前滑动，发送方可以继续发送新数据帧。
- C 正确：相比停止-等待协议，连续 ARQ 减少了等待确认造成的空闲时间，所以提高信道利用率。
- D 错误：连续 ARQ 的常规形态是后退 N 帧，接收窗口 $W_R=1$，接收方只按序接收；若收到不按序的帧，会直接丢弃。  
  例如发送方发送 0、1、2、3 号帧，若 1 号帧丢失，接收方收到 0 号帧后只期待 1 号帧；此时即使 2、3 号帧到达，也会被丢弃。因此接收方不能“不按序接收”。选择重传协议虽然可以用接收缓存暂存乱序帧，但那不是连续 ARQ 的一般结论。

**易错点**：  
1. 混淆 GBN 与 SR：后退 N 帧接收方只按序接收；选择重传接收方可以缓存乱序帧，但仍需按序向上层提交。  
2. 误以为“收到确认帧还能接着发送”是连续 ARQ 独有的；实际上停止-等待协议收到确认后也会发送下一帧，但连续 ARQ 的优点是“未收到确认也能继续发”。  
3. 计算信道利用率时，容易忽略传播时延的往返关系；应抓住一个周期近似为 $T_f+2\tau$。  
4. 若题目没有明确说“选择重传”，不要把“允许不按序接收”当成连续 ARQ 的普遍性质。

**命题规律**：  
本题考查数据链路层可靠传输中的“连续 ARQ/滑动窗口协议”，是 408 计算机网络常考概念点。常见变式包括：

- 比较停止-等待、后退 N 帧、选择重传的窗口大小与接收行为；
- 给定窗口大小、传播时延、帧长，求信道利用率；
- 结合序号比特数，判断发送窗口和接收窗口大小；
- 判断 GBN 和 SR 在某个帧丢失后，分别需要重传哪些帧。

复习时应画图对比三种协议的发送窗口、接收窗口、确认方式和重传范围。重点记住：

- GBN：$W_R=1$，接收方按序接收，发送方超时后从出错帧开始重传；
- SR：$W_R>1$，接收方可缓存乱序帧，发送方只重传出错的帧；
- 连续 ARQ 提升信道利用率的本质是“流水线发送、减少等待”。
