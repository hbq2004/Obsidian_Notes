# 选择题 第 6 题

![[_Attachments/题目识别/27_王道408-题目/CN-C03-34-M06_题目.png|题目]]

6. 主机甲采用停止-等待协议向主机乙发送数据,数据传输速率是 $6\mathrm{kb/s}$,单向传播时延是 $100\mathrm{ms}$,忽略确认帧的发送时延。若信道的利用率为 $40\%$,则数据帧的长度为( )
(A) 240 比特
(B) 320 比特
(C) 600 比特
(D) 800 比特

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C03-34-M06_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：D，数据帧长度为 800 比特。  
理由：根据停止‑等待协议信道利用率公式 \(U = \frac{T_{\text{数据}}}{T_{\text{数据}} + 2T_{\text{传播}}}\)，代入 \(U = 0.4\)、\(T_{\text{传播}} = 100\,\text{ms}=0.1\,\text{s}\)、速率 \(R = 6\,\text{kb/s}=6000\,\text{b/s}\)，解得帧长 \(L = 800\,\text{bit}\)。

**解题切入点**：看到“停止‑等待协议”和“信道利用率”，立即定位到利用率公式，其核心是计算一个发送周期（从开始发送数据帧到收到确认可发下一帧）中有效发送时间占比。类比算法竞赛中“流水线效率”问题，构造周期时间，利用比率反求未知量。本题忽略确认帧发送时延，但必须考虑确认帧的传播时延，故周期为 \(T_{\text{数据}} + 2T_{\text{传播}}\)。

**推演**：  
设数据帧长度为 \(L\) 比特，数据传输速率 \(R = 6\,\text{kb/s} = 6000\,\text{b/s}\)，则发送时延  
$$T_{\text{数据}} = \frac{L}{R} = \frac{L}{6000}\,\text{s}.$$  
单向传播时延 \(T_{\text{prop}} = 100\,\text{ms} = 0.1\,\text{s}\)。  
停止‑等待协议中，忽略确认帧发送时延，一个发送周期为  
$$T = T_{\text{数据}} + 2T_{\text{prop}} = \frac{L}{6000} + 0.2\,\text{s}.$$  
信道利用率定义为有效发送时间占总时间的比例：  
$$U = \frac{T_{\text{数据}}}{T} = \frac{\frac{L}{6000}}{\frac{L}{6000} + 0.2} = 0.4.$$  
解方程：  
$$\frac{L}{6000} = 0.4\left(\frac{L}{6000} + 0.2\right) = \frac{0.4L}{6000} + 0.08,$$  
$$\frac{L}{6000} - \frac{0.4L}{6000} = 0.08 \quad \Rightarrow \quad \frac{0.6L}{6000} = 0.08,$$  
$$0.6L = 6000 \times 0.08 = 480 \quad \Rightarrow \quad L = \frac{480}{0.6} = 800\,\text{bit}.$$  
因此数据帧长度为 800 比特，对应选项 D。

**易错点**：  
1. 单位换算：传播时延 \(100\,\text{ms}\) 要化为 \(0.1\,\text{s}\)，速率 \(6\,\text{kb/s}\) 应视为 \(6000\,\text{b/s}\)（考研中 \(k = 10^3\)）。  
2. 确认帧的传播时延不可忽略，周期为 \(T_{\text{数据}} + 2T_{\text{prop}}\)，而非 \(T_{\text{数据}} + T_{\text{prop}}\)。  
3. 计算时避免代数错误，如将 \(0.4\) 乘到括号内要仔细。  
4. 若题目中给出确认帧长度或发送时延，则周期需相应增加，但本题已明确忽略。

**命题规律**：  
停止‑等待协议的信道利用率是计算机网络基础计算题，常结合数据帧长度、数据传输速率、传播时延等参数，要求考生熟练运用公式 \(U = \frac{T_{\text{数据}}}{T_{\text{数据}} + 2T_{\text{prop}}}\)（忽略确认帧发送时延）或更一般形式。常见变式包括：考虑确认帧发送时延、使用滑动窗口协议（如后退 N 帧、选择重传）时的利用率计算。复习时应吃透基本公式，并注意单位换算和公式推导的灵活性。
