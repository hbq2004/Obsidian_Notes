# 选择题 第 15 题

![[_Attachments/题目识别/27_王道408-题目/CN-C04-44-M15_题目.png|题目]]

15. \textit{OSPF}协议使用（ ）分组来保持与其邻居的连接.

(A) \textit{Hello}
(B) \textit{Keepalive}
(C) \textit{SPF}(最短路径优先)
(D) \textit{LSU}(链路状态更新)

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C04-44-M15_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：A。OSPF 使用 **Hello 分组**发现邻居并周期性地保持邻居关系，从而维持连接。

**解题切入点**：拿到题目先抓住关键词“保持与其邻居的连接”，即邻居关系的建立与维护。这对应 OSPF 协议中“邻居发现/保活”机制，而不是路由计算或链路状态通告。可以类比竞赛中的“心跳检测”：分布式系统里节点之间靠周期心跳（Hello）判断对方是否存活，OSPF 的 Hello 分组就是这种心跳包；SPF 相当于“最短路算法”，LSU 相当于“更新图数据的消息”，它们都不是用来保活的。

**推演**：

OSPF（Open Shortest Path First）是典型的链路状态路由协议，工作过程主要分为：

1. 建立邻居关系：路由器通过接口周期性地发送 **Hello 分组**，用于发现邻居，并协商一些参数（如 Hello 间隔、Dead 间隔等）。
2. 维护邻居关系：Hello 分组继续周期性发送，充当“心跳”，若在 Dead 间隔内未收到邻居的 Hello，则认为邻居失效。
3. 交换链路状态信息：邻居关系建立后，通过 **DD（Database Description，数据库描述）分组**、**LSR（Link-State Request，链路状态请求）分组**、**LSU（Link-State Update，链路状态更新）分组**、**LSAck（Link-State Acknowledgment，链路状态确认）分组**来同步链路状态数据库。
4. 计算路由：每台路由器基于链路状态数据库，运行 **SPF（Shortest Path First）算法**，即 Dijkstra 算法，计算出到各目的地的最短路径树。

题目问的是“保持与邻居的连接”，显然指第 1、2 步，因此选择 **Hello**。

各选项辨析：

- **A. Hello**：用于发现和维护邻居关系，符合题意。
- **B. Keepalive**：这是 TCP 或某些应用层协议（如 RIP 的邻居保活机制）中常见的术语，但 OSPF 中不叫 Keepalive，而是 Hello。注意不要混淆。
- **C. SPF**：是最短路径优先算法，用于计算路由，不是分组类型。
- **D. LSU**：链路状态更新分组，用于通告链路状态信息，发生在邻居关系建立之后，不用于保活。

因此答案为 A。

**易错点**：

1. **混淆 Hello 与 Keepalive**：很多人看到“保持连接”就选 Keepalive，但 OSPF 协议中并不使用 Keepalive 分组。Keepalive 常见于 TCP 连接保活或某些应用层协议，而 OSPF 的邻居保活机制专门称为 Hello 协议。
2. **混淆 LSU 与 Hello**：LSU 是链路状态更新分组，负责发送实际拓扑信息；Hello 只负责邻居发现与维持。题目若问“交换链路状态信息”才选 LSU。
3. **混淆 SPF 与 Hello**：SPF 是算法，不是分组；OSPF 名字里虽然有 SPF，但协议分组类型中不存在名为 SPF 的分组。
4. **忽略 OSPF 的五种分组类型**：Hello、DD、LSR、LSU、LSAck。建议将五种分组与各自职责一一对应记忆。

**命题规律**：本题属于 OSPF 协议基础概念的识记题，考查 OSPF 五种分组类型及其功能。常见变式有：

- “OSPF 建立邻居关系用哪种分组？” → 仍选 Hello。
- “OSPF 邻居失效的检测靠什么？” → 靠 Hello 间隔和 Dead 间隔。
- “OSPF 中哪两种分组用于数据库同步？” → DD 和 LSR。
- “OSPF 中真正携带链路状态信息的分组？” → LSU。
- “OSPF 与 RIP 的区别” → OSPF 用 Hello 保活、用 LSU 更新、基于 SPF 计算；RIP 用 UDP 520 端口、基于距离向量。

复习建议：把 OSPF 的“邻居建立 → 数据库同步 → 路由计算”三个阶段串成一条线记忆，每个阶段对应的分组类型就清晰了。重点记住 Hello 是“邻居关系”的专用机制，这是 408 选择题的高频考点。
