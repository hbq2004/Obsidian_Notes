# 选择题 第 44 题

![[_Attachments/题目识别/27_王道408-题目/CN-C04-42-M44_题目.png|题目]]

44. 下列情况需要启动 $ARP$ 请求的是 (  )

(A) 主机需要接收信息，但 $ARP$ 表中没有源 $IP$ 地址与 $MAC$ 地址的映射关系
(B) 主机需要接收信息，但 $ARP$ 表中已有源 $IP$ 地址与 $MAC$ 地址的映射关系
(C) 主机需要发送信息，但 $ARP$ 表中没有目的 $IP$ 地址与 $MAC$ 地址的映射关系
(D) 主要需要发送信息，但 $ARP$ 表中已有目的 $IP$ 地址与 $MAC$ 地址的映射关系

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C04-42-M44_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：C。主机需要发送 IP 数据报时，若 ARP 缓存中无目的 IP 对应的 MAC 地址，则需广播 ARP 请求以获取该映射。

**解题切入点**：ARP 协议的核心是“需要发送时才请求”。可以将网络层类比为“任务调度”，ARP 缓存相当于“已记录的地址簿”，发送数据时若地址簿查不到目标，则必须发起广播查询（即 ARP 请求）。接收数据时，即使记录缺失，也不会主动发起查询，因为接收方暂无发送需求。

**推演**：  
ARP 协议用于将 IP 地址解析为 MAC 地址，其工作场景如下：  
- 当主机 A 需要向主机 B 发送 IP 数据报时，A 首先检查自己的 ARP 缓存表，查找 B 的 IP 地址对应的 MAC 地址。  
  - 若存在映射，则直接封装帧发送。  
  - 若不存在，则 A 广播 ARP 请求，询问“谁的 IP 地址是 B，请告诉我你的 MAC 地址”。  
- 当主机收到一个 IP 数据报时，它不会主动发起 ARP 请求，而是被动地根据收到的帧中的源 MAC 地址与 IP 地址更新缓存（如果缓存中没有该源 IP 的映射，则可能通过发送 ARP 回复来添加？但实际中，接收方可能通过收到的 ARP 请求或回复来学习，但不会主动发送 ARP 请求）。  

因此，**只有需要发送信息且映射缺失时才会启动 ARP 请求**。  
选项 A、B 描述的是接收信息，无论映射是否存在，都不会主动发起 ARP 请求。选项 D 映射已存在，直接发送即可，无需请求。  

**易错点**：  
1. 混淆“接收”与“发送”场景：误认为接收时也需要解析源 MAC，从而选择 A。实际上，接收方无需主动查询，且 ARP 请求是广播询问，与接收方身份无关。  
2. 忽略“目的”与“源”的区别：ARP 请求针对的是**目的 IP**，而非源 IP。解析源 IP 通常由发送方在收到数据报后通过反向 ARP 或学习 ARP 报文完成，但不会主动发起。  

**命题规律**：  
- 考点定位：ARP 协议的工作触发条件。  
- 常见变式：混合考查 ARP 请求与 ARP 回复的区别、不同网络设备（如路由器）的 ARP 行为、ARP 缓存更新时机等。  
- 复习建议：理解 ARP 协议是“按需解析”，即仅在需要发送数据且缓存缺失时才发起请求；同时区分“学习”与“请求”的被动/主动关系。
