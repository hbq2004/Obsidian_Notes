# 选择题 第 28 题

![[_Attachments/题目识别/27_王道408-题目/CN-C04-42-M28_题目.png|题目]]

28. 路由表错误和软件故障都可能使得网络中的数据形成传输环路而无限转发环路的分组，IPv4 协议解决该问题的方法是 ( )
(A) 报文分片
(B) 设定生命期
(C) 增加检验和
(D) 增加选项字段

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C04-42-M28_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：B（设定生命期）。IPv4 通过首部中的生存时间字段（$\text{TTL}$）限制分组最多经过的路由器跳数，每转发一次减 1，减到 0 即丢弃，从而截断环路中的无限转发。

**解题切入点**：题目描述的是“分组在环路中被无限转发”，这本质上和在算法竞赛中写搜索时担心死循环一样——需要给搜索加一个“最大深度”或“迭代次数上限”。对应到网络层，IPv4 的 $\text{TTL}$（生命周期）就是这个上限。抓关键词“无限转发”，直接锁定“设定生命期”。其他选项分别解决“报文过大”“传输差错”“扩展功能”的问题，与“终止循环”无关。

**推演**：

IPv4 数据报首部中有一个 8 位字段 $\text{TTL}$（Time to Live，生存时间），取值范围为 $0 \sim 255$。源主机生成数据报时设置一个初值（常见如 64、128、255）。数据报每经过一台路由器转发前，路由器先执行：

$$
\text{TTL} \leftarrow \text{TTL} - 1
$$

若减 1 后 $\text{TTL} = 0$，则路由器丢弃该数据报，并可选地向源主机发送 ICMP 超时报文（Type 11, Code 0）。

因此，即使路由表错误或软件故障导致数据报在路由器之间循环转发，数据报也不可能被无限转发，因为每转发一次 $\text{TTL}$ 都会递减，最终必有一次变成 0 而被丢弃。这相当于给每个分组设置了“最大跳数上限”。

其他选项分析：

- **报文分片**：用于解决数据报超过下一跳链路 MTU 的问题，分片后的各个分片仍然受 $\text{TTL}$ 限制。分片不能阻止环路，环路中的分片同样会无限转发。
- **增加检验和**：首部检验和只能检测数据报在传输过程中是否发生比特错误，出错则丢弃，但无法阻止因路由错误导致的循环转发；环路中的分组首部校验和是正确的。
- **增加选项字段**：选项字段提供记录路由、时间戳、源路由等扩展能力，但它不是为环路控制设计的，也不能自动终止循环。

因此 IPv4 解决无限转发环路问题的关键机制就是设定生命期 $\text{TTL}$，选 B。

**易错点**：

1. **误选 A（报文分片）**：分片只处理“报文过大”，与“路由环路”属于不同问题。即使分片后，分片也会在环路里反复转发，真正终止循环的仍是 $\text{TTL}$。
2. **误选 C（增加检验和）**：检验和是差错检测机制，只能保证首部数据在传输中未被破坏；路由错误形成的循环中，分组内容可以完全正确，因此校验和不会拦截它们。
3. **误选 D（增加选项字段）**：选项字段是可选扩展，不会主动丢弃分组。即使有记录路由选项，也只能观察到经过的路径，无法控制循环。
4. **混淆时间单位与跳数**：IPv4 设计时 $\text{TTL}$ 本意是“最大生存时间（秒）”，但实际实现中每经过一台路由器减 1，所以更接近“跳数限制”。IPv6 中已直接更名为“跳数限制”（Hop Limit），含义更加清晰。考试中应说“每跳减 1，为 0 丢弃”。

**命题规律**：

- **考点定位**：IPv4 数据报首部字段功能，尤其是 $\text{TTL}$ 对路由环路/无限转发的抑制作用。本题属于网络层基础概念题，难度较低，但要求熟悉 IP 首部各字段用途。
- **常见变式**：
  - 给出初始 $\text{TTL}$ 值，求经过若干路由器后还能否转发；
  - 问 $\text{TTL}=0$ 时路由器如何处理（丢弃并发送 ICMP 超时）；
  - 问 IPv6 中对应字段名称（Hop Limit）；
  - 利用 $\text{TTL}$ 解释 `traceroute`/`tracert` 原理：逐跳增大 $\text{TTL}$，通过 ICMP 超时报文发现路径上的路由器。
- **复习建议**：把 IPv4 首部 20 字节固定部分画图记忆，逐个字段明确作用；注意区分“差错检测”（校验和）、“差错报告”（ICMP）和“生命周期控制”（$\text{TTL}$）。同时可对比 RIP 协议用跳数 16 表示不可达来限制路由环路，理解“数据平面 TTL 终止转发”与“控制平面路由协议防环”是不同层面的机制。
