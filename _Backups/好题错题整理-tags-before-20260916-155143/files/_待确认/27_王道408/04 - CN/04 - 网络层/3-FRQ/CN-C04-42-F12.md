# 综合题 第 12 题

![[_Attachments/题目识别/27_王道408-题目/CN-C04-42-F12_题目.png|题目]]

12. 某网络拓扑见下图, R1 和 R2 为路由器, R2 实现了 NAT 功能, Switch 为交换机, Hub 为集线器, Web 服务器 S、主机 H1~H4 和路由器各接口的 IP 地址配置见图中标注。回答下列问题:

【图：网络拓扑图。左侧为 Internet 云，内含 Web 服务器 S，IP 地址为 213.48.226.31/24。Internet 云连接到路由器 R1 的 E0 接口，E0 接口 IP 为 203.10.3.2/24。R1 的 E1 接口与路由器 R2 的 E1 接口相连，R1 E1 接口 IP 为 203.10.2.2/30，R2 E1 接口 IP 为 203.10.2.1/30。R2 标注有 NAT 功能，其 E0 接口 IP 为 172.18.1.126/25，连接 Switch；Switch 下接主机 H1（172.18.1.33/25）和 H2（172.18.1.11/25）。R2 的 E2 接口 IP 为 172.18.1.254/25，连接 Hub；Hub 下接主机 H3（172.18.1.211/25）和 H4（172.18.1.233/25）。】

(1) R2 的 E1 接口的 IP 地址是什么? H1 配置的默认网关是什么?
(2) 假设 H1 和 R2 的 ARP 缓存初始均为空, 交换机的交换表初始也为空, H1 向 H3 发送一个 IP 分组 A, H3 收到 A 后向 H1 发送一个响应 IP 分组 B, 则能收到封装 A 的以太网帧的主机有哪些? 能收到封装 B 的以太网帧的主机有哪些?
(3) H1 发出的封装有 HTTP 请求报文的 IP 分组 C, 首部中的源 IP 地址和目的 IP 地址分别是什么? 当 C 从 R2 转发出去时, 首部中的源 IP 地址和目的 IP 地址分别是什么?

## 答案

![[_Attachments/题目识别/27_王道408-答案/CN-C04-42-F12_答案.png|答案]]


## DeepSeek V4 Flash Max 解析

**答案**：  
(1) R2 的 E1 接口 IP 地址为 $203.10.2.1$；H1 配置的默认网关为 $172.18.1.126$。  
(2) 能收到封装 A 的以太网帧的主机：H3、H4；能收到封装 B 的以太网帧的主机：H1、H4。  
(3) H1 发出的 HTTP 请求分组 C 首部中源 IP 地址为 $172.18.1.33$，目的 IP 地址为 $213.48.226.31$；当 C 从 R2 转发出去时，源 IP 地址变为 $203.10.2.1$，目的 IP 地址仍为 $213.48.226.31$。

**解题切入点**：  
拿到题目先根据拓扑图标注 IP 地址与子网掩码，识别各接口所属子网，定位考点：子网划分、默认网关、ARP 与交换机/集线器转发原理、NAT 转换。  
- 将子网划分类比为算法竞赛中的“分块”，路由器 R2 相当于“分治中心”，内部不同子网通过 R2 互连。  
- 交换机与集线器可类比为“数据结构”：交换机（带 MAC 表）类似“哈希表”，可高效定位；集线器（广播）类似“顺序遍历”，无差别转发。  
- ARP 过程类似“缓存失效后的重新查询”，初始为空时需先广播请求，同时更新交换机表项。  
- NAT 功能类似“代理转换”，将内部私有地址映射为外部公网地址。

**推演**：  
(1) 由拓扑标注直接可得：R2 的 E1 接口 IP 为 $203.10.2.1/30$；H1 所在子网为 $172.18.1.0/25$，默认网关应为该子网的路由器接口，即 R2 的 E0 接口 IP $172.18.1.126/25$。  
(2) 初始状态：ARP 缓存与交换表均为空。  
- **H1 发送分组 A 前**：H1 需先获取默认网关（R2 E0）MAC，发送 ARP 请求（广播），交换机泛洪，H2 与 R2 收到；R2 回复 ARP 响应（单播），交换机学习到 H1 和 R2 的 MAC，仅转发给 H1。  
- **H1 发送分组 A 的帧**：源 MAC=H1，目的 MAC=R2 E0。交换机已记录 R2 E0 的端口，只转发给 R2，H2 未收到。R2 收到后解封装，需转发给 H3（属另一个子网）。  
- **R2 转发分组 A 前**：R2 发送 ARP 请求获取 H3 MAC，从 E2 发出，Hub 广播至 H3 和 H4；H3 回复 ARP 响应，Hub 广播至 R2 和 H4，R2 学习到 H3 MAC。  
- **R2 发送分组 A 的帧**：源 MAC=R2 E2，目的 MAC=H3，从 E2 发出，Hub 广播，H3 和 H4 均收到（H3 接收，H4 丢弃）。故能收到封装 A 的帧的主机为 H3 和 H4。  
- **H3 发送响应分组 B**：H3 已知默认网关（R2 E2）MAC，直接发送帧（源 MAC=H3，目的 MAC=R2 E2），Hub 广播，H4 和 R2 收到（H4 丢弃）。  
- **R2 转发分组 B**：R2 已有 H1 的 MAC（从之前 ARP 学习），封装帧（源 MAC=R2 E0，目的 MAC=H1），交换机已记录 H1 端口，只转发给 H1，H2 未收到。故能收到封装 B 的帧的主机为 H4（来自 H3 的帧）和 H1（来自 R2 的帧）。  
(3) H1 发出的 HTTP 请求，源 IP 为 H1 自身私有地址 $172.18.1.33$，目的 IP 为 Web 服务器 S 的公网地址 $213.48.226.31$。R2 具有 NAT 功能，当分组从内部网络转发至外部时，将源 IP 替换为 R2 出接口 E1 的 IP 地址 $203.10.2.1$，目的 IP 不变。故从 R2 转发出去时，源 IP 为 $203.10.2.1$，目的 IP 为 $213.48.226.31$。

**易错点**：  
1. **忽略 ARP 与交换表学习**：认为 H1 直接发送分组 A 且交换机初始为空，导致 H2 被误认为能收到封装 A 的帧。实际上 ARP 过程已更新交换表，H1 的帧仅被转发给 R2。  
2. **默认网关选择错误**：H1 应指向 R2 的 E0 接口（$172.18.1.126$），而非 R2 的 E2 接口（$172.18.1.254$），因为 H1 所在子网为 $172.18.1.0/25$。  
3. **NAT 转换范围**：只转换源 IP 为出接口 IP，未将目的 IP 也转换（NAT 通常不改变目的 IP）。  
4. **集线器与交换机混淆**：集线器无条件广播，交换机根据 MAC 表转发，需区分二者在帧传播中的行为。

**命题规律**：  
- **考点定位**：综合考查子网划分、默认网关、ARP 与交换机/集线器转发、NAT 原理。常见于 408 网络综合题（如 2010 年真题）。  
- **常见变式**：改变拓扑结构（如增加路由器、交换机级联）、调整 NAT 类型（动态/静态）、引入 VLAN 或 ACL 等。  
- **复习建议**：熟练掌握 ARP 与交换机学习过程，能动态分析帧传播路径；理解 NAT 转换的源/目的 IP 变化；区分广播域与冲突域；建议通过画图逐步模拟通信过程，避免遗漏。
