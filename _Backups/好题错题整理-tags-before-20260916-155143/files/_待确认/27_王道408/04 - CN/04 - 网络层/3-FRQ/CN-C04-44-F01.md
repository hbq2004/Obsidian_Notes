# 综合题 第 1 题

![[_Attachments/题目识别/27_王道408-题目/CN-C04-44-F01_题目.png|题目]]

1. RIP 使用 UDP,OSPF 使用 IP,而 BGP 使用 TCP。这样做有何优点?为什么 RIP 周期性地和邻站交换路由信息而 BGP 却不这样做?

## DeepSeek V4 Flash Max 解析

**答案**：  
本题为综合简答题，结论要点如下：  
- RIP 使用 UDP：RIP 报文小、网络规模小，周期广播可容忍个别报文丢失，UDP 开销小、无需建立连接。  
- OSPF 使用 IP：OSPF 需要向链路上所有路由器组播洪泛链路状态，且自己实现确认与重传，使用 IP 协议字段 $89$ 可直接利用 IP 组播并减少传输层开销。  
- BGP 使用 TCP：BGP 在自治系统之间交换大量路由信息，且只发送增量更新，必须可靠传输；TCP 提供可靠字节流、重传和连接管理。  
- RIP 周期性与邻居交换整张路由表，是因为距离向量算法需要周期性刷新“软状态”；BGP 则在 TCP 连接建立后先交换完整路由表，之后只在路由变化时发送增量 UPDATE，平时用 keepalive 维持连接，不周期性传送路由表。

**解题切入点**：  
拿到题目先抓“路由协议 + 传输层承载”这个对应关系，再想每种路由协议的工作方式。  
可以用算法竞赛里的同步方式来类比：RIP 像“每轮全量快照同步”，丢几包没关系，下一轮还会补上，所以用 UDP；OSPF 像“需要组播洪泛全局状态”，要自己实现可靠洪泛，所以直接挂在 IP 上；BGP 像“全国级主从增量同步”，变更不大但绝对不能丢，必须用 TCP 可靠字节流。后半问的实质是“全量轮询 vs 事件驱动增量更新”：RIP 周期全量发送，BGP 只发送 diff。

**推演**：  
1. **RIP 使用 UDP 的优点**  
   RIP 是小型自治系统内部的距离向量协议，使用跳数作为度量，报文内容是路由表条目，报文短小。RIP 每 $30\mathrm{s}$ 向邻居发送一次路由更新，发生路由变化时也可以触发更新。  
   使用 UDP 端口 $520$，优点是避免 TCP 的连接建立、维护和重传开销；即使某个 UDP 报文丢失，下一个周期还会再发送，不会造成严重后果。  
   距离向量更新本质为：
   $$
   d_x(y)=\min_v\{c(x,v)+d_v(y)\}
   $$
   该公式要求邻居不断通告自己的距离向量，RIP 的周期更新正是这种“软状态”的体现。

2. **OSPF 使用 IP 的优点**  
   OSPF 是链路状态协议，需要将 LSA 可靠洪泛到整个区域。它使用 IP 组播地址 $224.0.0.5$（所有 OSPF 路由器）和 $224.0.0.6$（指定路由器与备份指定路由器之间通信）。  
   TCP 是点对点的，不支持组播；UDP 虽然支持组播，但不可靠。OSPF 自己实现了序号、确认、重传等可靠洪泛机制，因此不需要 TCP。直接把 OSPF 报文封装在 IP 数据报中，IP 首部协议字段为 $89$，可不经过 UDP/TCP 层，减少处理开销，并且能利用 IP 组播能力。  
   三者的封装关系可以写作：
   $$
   \text{RIP：UDP 端口 }520,\quad
   \text{OSPF：IP 协议字段 }89,\quad
   \text{BGP：TCP 端口 }179.
   $$

3. **BGP 使用 TCP 的优点**  
   BGP 是自治系统之间的路径向量协议。Internet 路由表规模巨大，路由更新必须可靠交付，否则一条更新丢失会导致全网路径视图不一致。TCP 提供确认、重传、按序到达、流量控制和连接管理，BGP 只需要在 TCP 之上处理 AS 路径和路由策略。  
   另外，BGP 对等体可以不是直连的，使用 TCP 便于建立跨越中间网络的逻辑连接。因此 BGP 使用 TCP 端口 $179$。

4. **为什么 RIP 周期交换而 BGP 不周期交换**  
   - RIP：RIP 的距离向量计算依赖邻居周期通告。若某路由器或链路失效，邻居在接收不到更新的情况下才能判定路由失效。周期更新相当于“心跳”和全网状态刷新；用 UDP 发送时即使丢包，下一轮也能补上。因此 RIP 用周期性全表交换换取实现简单和容错。  
   - BGP：BGP 使用 TCP 可靠连接，连接建立后双方先交换完整路由信息；之后只有某条路由的路径发生变化或需要撤销时，才发送 UPDATE 报文，报文中只包含变化信息。TCP 保证这些增量更新不丢失，所以不需要周期性重传整个路由表。BGP 也有 keepalive 消息（默认每 $60\mathrm{s}$ 发送，保持时间一般 $180\mathrm{s}$），但 keepalive 只用于连接保活，不携带路由信息，不是“交换路由信息”。

**易错点**：  
- 误以为 OSPF 使用 TCP 或 UDP 端口。OSPF 直接封装在 IP 中，IP 协议字段为 $89$。  
- 混淆端口：RIP UDP $520$，OSPF IP $89$，BGP TCP $179$。  
- 认为 BGP 完全没有任何周期性消息。BGP 有 keepalive 保活消息，但它不是路由表交换。  
- 认为 BGP 建立连接后周期性发送完整路由表。实际上只在连接建立时或显式请求全量刷新时发送整表，正常运行中只做增量更新。  
- 认为 RIP 周期更新是因为 UDP 不可靠才要重发。根本原因是距离向量算法的软状态设计；UDP 只是实现载体。

**命题规律**：  
本考点在 408 中常以选择题形式出现，考查路由协议与传输层封装、端口/协议号、更新机制等。常见变式包括：“BGP 为什么使用 TCP”“OSPF 为什么不用 TCP/UDP”“RIP 为什么采用周期更新”“RIP、OSPF、BGP 的适用范围和收敛速度比较”等。  
复习时应建立对比表：协议类型、算法、度量、封装方式、更新方式、适用场景、收敛速度；不仅要记忆端口号，还要理解“距离向量需要周期刷新、链路状态需要可靠洪泛、路径向量需要可靠增量更新”的设计理由。
