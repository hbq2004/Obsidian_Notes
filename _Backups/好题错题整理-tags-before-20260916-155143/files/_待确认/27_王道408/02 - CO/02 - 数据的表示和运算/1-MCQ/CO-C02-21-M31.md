# 选择题 第 31 题

![[_Attachments/题目识别/27_王道408-题目/CO-C02-21-M31_题目.png|题目]]

31.【2019统考真题】考虑以下 C 语言代码：

```c
unsigned short usi = 65535;
short si = usi;
```

执行上述程序段后，$si$ 的值是（ ）

A. - 1
B. - 32767
C. - 32768
D. - 65535

---

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CO-C02-21-M31_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：A. -1。因为 `unsigned short` 类型 65535 的二进制位全 1，转换为 `short` 后按补码解释为 -1。

**解题切入点**：本题直接考察无符号整数与有符号整数之间的类型转换。核心在于转换时位模式不变，但解释方式改变。在二进制补码系统中，全 1 位模式恰好对应 -1，因此可快速锁定答案。

**推演**：  
`unsigned short usi = 65535;` 中，`unsigned short` 为 16 位无符号整数，其最大值为 $2^{16}-1=65535$，二进制表示为 $1111111111111111_2$（16 个 1）。  
`short si = usi;` 执行隐式类型转换，将 `usi` 的位模式直接复制给 `si`（在大多数实现中，位模式不变）。`short` 为 16 位有符号整数，采用二进制补码表示。对于补码，最高位为符号位，全 1 的位模式对应的数值为：  
$$\text{符号位}=1 \Rightarrow \text{负数}，\quad \text{数值部分}=\overline{111111111111111}_2+1=000000000000000_2+1=1，$$  
故该补码表示 $-1$。因此 $si = -1$。

**易错点**：  
- 误以为 `short` 能表示 $-65535$，但 `short` 范围仅为 $-32768 \sim 32767$，无法容纳 $-65535$，从而错误选择 D。  
- 混淆溢出与位模式转换，认为无符号转有符号会进行数值范围截断，实际上在常见实现中仅是位模式重解释。  
- 忽略 C 标准中“实现定义”的细节，但考试通常默认二进制补码平台且位模式不变。

**命题规律**：  
- **考点定位**：整数类型转换（无符号 ↔ 有符号）及补码表示。  
- **常见变式**：将 `unsigned short` 换为 `unsigned int` 与 `int`，或考察有符号转无符号（如 `short` 负数赋给 `unsigned short` 得到大正数）。  
- **复习建议**：深入理解补码的位模式与真值对应关系，以及 C 语言中隐式类型转换的规则（尤其是“值不变”或“位模式不变”两种情形）。可结合真题中类似题目（如 2014 年真题中 `int` 与 `unsigned` 转换）进行对比练习。
