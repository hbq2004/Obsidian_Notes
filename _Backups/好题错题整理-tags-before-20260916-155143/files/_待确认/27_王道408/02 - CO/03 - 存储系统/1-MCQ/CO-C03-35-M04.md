# 选择题 第 4 题

![[_Attachments/题目识别/27_王道408-题目/CO-C03-35-M04_题目.png|题目]]

4. 关于 $Cache$ 的更新策略,下列说法中正确的是( )

A. 读操作时,全写法和回写法在命中时应用

B. 写操作时,回写法和写分配法在命中时应用

C. 读操作时,全写法和写分配法在失效时应用

D. 写操作时,写分配法、非写分配法在失效时应用

---

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CO-C03-35-M04_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：D。写分配法与非写分配法均针对写失效（写操作未命中）时的处理方式，而回写法、全写法是写命中/失效时Cache与主存一致性的策略；读操作不涉及写分配等概念，故D正确。

**解题切入点**：先区分“写策略”中两组概念：一是写命中时“全写法（写直达）”vs“回写法（写回）”，二是写失效时“写分配法”vs“非写分配法”。题目问“更新策略”，实际考查这两组概念与“读/写操作”“命中/失效”的正确搭配。可以类比在线评测系统中的缓存更新：读请求只影响缓存内容，不涉及“写回”策略；写请求时，若缓存未命中，是“先把数据读入缓存再改”还是“直接改磁盘/主存”，这正是写分配与非写分配的差别。

**推演**：

1. 全写法（写直达，write-through）：写命中时，同时更新Cache和主存；写失效时，通常不将主存块调入Cache（即非写分配），直接更新主存。  
2. 回写法（写回，write-back）：写命中时，只更新Cache，不立即写主存，仅在Cache块被替换时才写回主存；写失效时，一般先把主存块调入Cache，再写Cache（即写分配），后续替换时写回。  
3. 写分配法（write-allocate）：当发生写失效时，先把主存中的块调入Cache，然后在Cache中修改。它常与回写法配合。  
4. 非写分配法（no-write-allocate）：当发生写失效时，不把主存块调入Cache，而是直接更新主存。它常与全写法配合。

逐一分析选项：

- A：“读操作时，全写法和回写法在命中时应用”——全写法与回写法是“写”策略，不是“读”策略，读命中时只需从Cache读，不涉及写更新，故A错。  
- B：“写操作时，回写法和写分配法在命中时应用”——回写法确实可用于写命中，但写分配法针对的是写失效，不是写命中，故B错。  
- C：“读操作时，全写法和写分配法在失效时应用”——读失效时只需将主存块调入Cache，与“全写法”“写分配法”无关，故C错。  
- D：“写操作时，写分配法、非写分配法在失效时应用”——正确。写分配法在写失效时调块入Cache并写Cache；非写分配法在写失效时不调块，直接写主存。两者都是写失效时的可选策略，故D正确。

因此正确答案是D。

**易错点**：

1. 混淆“全写法/回写法”与“写分配法/非写分配法”。前者解决“Cache与主存内容何时一致”的问题，后者解决“写未命中时是否把块调入Cache”的问题。  
2. 误认为“写分配法/非写分配法”与读操作有关。实际上它们只针对写操作，读失效只有“读分配”（即正常调块），不会称为写分配。  
3. 误认为“写回法”只用于写命中，而忘记它也有写失效时的处理（通常配写分配）。  
4. 记忆搭配：全写法 ↔ 非写分配；回写法 ↔ 写分配。但这不是绝对的，常见组合，考试常考，需理解原因：全写法写失效时直接写主存即可，不必调块；回写法若不调块则无法在Cache中记录待写数据，故通常调块。

**命题规律**：本题考查Cache写策略的基本概念，属于408中“存储系统”部分的高频基础题。常见变式有：  
- 给出Cache写命中/写失效，问采用某种策略时是否需要写主存；  
- 结合多级Cache、一致性协议（如写无效/写更新）出题；  
- 与“计算平均访问时间”综合，比较全写法和回写法的性能。  
复习时需准确记忆两组策略的定义、使用场合及常见组合，并能画出“命中/失效×读/写”的决策表。建议结合王道或袁春风教材中的Cache写策略表格进行反复对比记忆。
