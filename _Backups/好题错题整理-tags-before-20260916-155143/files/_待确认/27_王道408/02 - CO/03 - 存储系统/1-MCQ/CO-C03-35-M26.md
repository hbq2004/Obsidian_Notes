# 选择题 第 26 题

![[_Attachments/题目识别/27_王道408-题目/CO-C03-35-M26_题目.png|题目]]

26. 下列关于 $Cache$ 大小、主存块大小和 $Cache$ 缺失率之间关系的叙述中，错误的是（  ）

A. 主存块大小和 $Cache$ 容量无直接关系
B. $Cache$ 容量越大，$Cache$ 缺失率越低
C. 主存块大小通常为几十到上百字节
D. 主存块越大，$Cache$ 缺失率越低

---

---

## 答案

![[_Attachments/题目识别/27_王道408-答案/CO-C03-35-M26_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：D。主存块大小并非越大越好，块过大时 Cache 中能存放的块数减少，冲突缺失增加，缺失率可能不降反升。

**解题切入点**：看到“越大……越低”这类绝对化表述时，要警惕它是否忽略了“冲突缺失”和“块内有效数据利用率”的影响。可以把 Cache 比作一个“盒子”：块太大时，盒子里能装的“大件”数量变少，反而容易互相挤占、频繁替换，导致缺失率上升。

**推演**  
设 Cache 总容量为 $C$，主存块大小为 $B$，则 Cache 中可容纳的块数为  
$$
N = \frac{C}{B}
$$
当 $B$ 增大时，$N$ 减小。

- 当 $B$ 较小时，相邻数据往往被分到不同块中，空间局部性利用不足。访问一个地址后，下一次访问它附近的数据可能不在 Cache 中，导致强制缺失较多，缺失率偏高。
- 随着 $B$ 增大，一次缺失会调入包含目标数据和若干相邻数据的较大块，后续访问相邻数据时命中率提高，缺失率下降。
- 但当 $B$ 继续增大时，问题出现：
  1. 块内包含大量暂时用不到的数据，浪费 Cache 空间和主存带宽；
  2. Cache 中的块数 $N$ 变小，能够映射的块更少，冲突缺失明显增加；
  3. 替换一次需要写入/调出更多数据，替换代价增大。

因此，缺失率随 $B$ 的变化是“先降后升”的，存在一个最优块大小，并非“主存块越大，缺失率越低”。故 D 错误。

其他选项：
- A 正确：主存块大小是主存与 Cache 交换数据的粒度，而 Cache 容量由块大小和块数共同决定；在块数或组织方式变化时，容量可以独立设计，二者没有直接决定关系。
- B 正确：Cache 容量增大，能容纳的数据更多，容量缺失减少，通常缺失率降低。
- C 正确：实际系统中主存块大小通常为几十到上百字节，例如 16B、32B、64B、128B。

**易错点**  
- 误将 D 视为正确：只看到块增大能利用空间局部性，忽略块过多导致冲突缺失增加，以及块内有效数据利用率下降。
- 误认为 A 错误：虽然 $C = N \times B$，但块大小和块数可互相调节，容量的设计并不由块大小唯一决定，因此“无直接关系”成立。
- 将缺失率简单等同于“容量缺失率”，忽视强制缺失、容量缺失、冲突缺失三类缺失的不同变化趋势。

**命题规律**  
- 考点定位：Cache 的基本结构、缺失率影响因素、局部性原理。
- 常见变式：
  1. 给定参数计算平均访存时间，判断块大小变化对缺失率的影响；
  2. 给出缺失率曲线，要求解释原因；
  3. 与 Cache 寻址、块内偏移位数等结合考查。
- 复习建议：理解 Cache 容量、块大小、相联度、替换算法之间的关系，牢记缺失率随块大小“先降后升”的曲线，不要记忆绝对化结论。
