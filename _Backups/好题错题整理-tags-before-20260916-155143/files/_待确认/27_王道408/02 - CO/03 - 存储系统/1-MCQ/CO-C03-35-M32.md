# 选择题 第 32 题

![[_Attachments/题目识别/27_王道408-题目/CO-C03-35-M32_题目.png|题目]]

32.【2016统考真题】有如下 C 语言程序段：
```c
for (k = 0; k < 1000; k++)
    a[k] = a[k] + 32;
```
若数组 $a$ 和变量 $k$ 均为 int 型，int 型数据占 4B，数据 $Cache$ 采用直接映射方式，数据区大小为 1KB、块大小为 16B，该程序段执行前 $Cache$ 为空，则该程序段执行过程中访问数组 $a$ 的 $Cache$ 缺失率约为（ ）.
(A) 1.25%
(B) 2.5%
(C) 12.5%
(D) 25%

## 答案

![[_Attachments/题目识别/27_王道408-答案/CO-C03-35-M32_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：C。一句话理由：每个 Cache 块含 4 个 int，每个 int 有读、写两次访问，每个块只在首次被读时缺失一次，故缺失率 $=\frac{250}{2000}=12.5\%$。

**解题切入点**  
拿到题目先明确两件事：一是数组 $a$ 的访问次数（每次循环有读和写各一次）；二是 Cache 块大小与 int 长度的关系，确定每次缺失能“覆盖”多少个数组元素。这就像算法竞赛中看数据规模先算总操作量：先数清总访问次数，再数不可避免的失配次数，二者相除即可。直接映射在这种顺序访问下不会产生额外冲突，重点放在强制缺失上。

**推演**  
1. **参数计算**  
   - int 型占 $4\text{ B}$，Cache 块大小 $16\text{ B}$，因此一个块可容纳的 int 个数为  
     $$
     \frac{16}{4}=4
     $$
   - 数组 $a$ 共 $1000$ 个 int，故数组对应的块数为  
     $$
     \frac{1000}{4}=250
     $$

2. **访问次数统计**  
   循环体为  
   ```c
   a[k] = a[k] + 32;
   ```
   每条循环内对数组 $a$ 有两次访问：
   - 读 $a[k]$；
   - 写 $a[k]$。  
   总循环 $1000$ 次，所以对数组 $a$ 的总访问次数为  
   $$
   1000 \times 2 = 2000
   $$

3. **缺失次数分析**  
   程序执行前 Cache 为空。因为块大小为 $4$ 个 int，所以每当访问到某个块中第一个元素时（如 $a[0], a[4], a[8], \ldots$），该块未调入 Cache，发生一次缺失；随后该块内其他 $3$ 个元素访问时均命中。  
   - 数组中每个块只被顺序访问一次，不会再次访问同一个块，因此没有时间局部性带来的二次缺失。
   - 直接映射的映射冲突可忽略：数组连续映射到 Cache 的 $64$ 个行，虽然有多个块映射到同一行，但都是“用完即走”，不会造成同一数据块的重复缺失。  
   因此缺失次数就是块数：
   $$
   \text{缺失次数} = 250
   $$

4. **缺失率计算**  
   $$
   \text{缺失率} = \frac{\text{缺失次数}}{\text{总访问次数}} = \frac{250}{2000} = 12.5\%
   $$

   故正确选项为 C。

**易错点**  
- **只统计读操作**：如果把写操作忽略，只算读访问 $1000$ 次，缺失 $250$ 次，会得到 $25\%$，对应错误选项 D。题目明确“访问数组 $a$”包含读写，不能漏掉写。  
- **把一次循环的读写合并成一次访问**：若认为每条循环只“访问一次” $a[k]$，则总访问数为 $1000$，缺失率变为 $25\%$，同样是错误理解。  
- **忘记乘以块内可放元素数**：误以为每个元素都缺失，得到 $100\%$ 或 $50\%$ 等，没有利用块的空间局部性。  
- **混淆 Cache 行数与块数**：$1\text{ KB}/16\text{ B}=64$ 行，这是相联度/行数，与本题缺失率无直接关系；缺失率由数组总块数和总访问次数决定。

**命题规律**  
- **考点定位**：Cache 基本工作原理、块大小与命中率的关系、读/写操作对缺失率统计的影响。属于每年必考的“Cache 计算题”基础题型。  
- **常见变式**：  
  1. 修改映射方式，如改为全相联或 $2$/ $4$ 路组相联，冲突缺失变化；  
  2. 修改循环步长或数组访问顺序，如 `a[k+4]`、`for(k=0;k<1000;k+=2)`，影响块内命中次数；  
  3. 加大数组规模至多个块映射同一行，考察替换策略造成的冲突缺失；  
  4. 结合写策略（写回/写直达，写分配/写不分配）考查写缺失的影响。  
- **复习建议**：熟练掌握“时间局部性 + 空间局部性”在 Cache 中的体现。做题时先画时间轴，逐块分析首访缺失和后续命中，再计算总访问次数。尤其注意 C 语言中 `a[k]=a[k]+32` 这类复合运算是读、写各一次。
