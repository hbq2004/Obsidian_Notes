# 选择题 第 12 题

![[_Attachments/题目识别/27_王道408-题目/CO-C04-43-M12_题目.png|题目]]

12. 假设 $P$ 为调用过程，$Q$ 为被调用过程，程序在 32 位 x86 处理器上执行，以下是 C 语言程序中过程调用所涉及的操作：

① 过程 $Q$ 保存 $P$ 的现场，并为非静态局部变量分配空间

② 过程 $P$ 将实参存放到 $Q$ 能访问到的地方

③ 过程 $P$ 将返回地址存放到特定处，并转跳到 $Q$ 执行

④ 过程 $Q$ 取出返回地址，并转跳回到过程 $P$ 执行

⑤ 过程 $Q$ 恢复 $P$ 的现场，并释放局部变量所占空间

⑥ 执行过程 $Q$ 的函数体

过程调用的正确执行步骤是（ ）

A. ② → ③ → ④ → ① → ⑤ → ⑥
B. ② → ③ → ① → ④ → ⑥ → ⑤
C. ② → ③ → ① → ⑥ → ⑤ → ④
D. ② → ③ → ① → ⑤ → ⑥ → ④

## 答案

![[_Attachments/题目识别/27_王道408-答案/CO-C04-43-M12_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：C。正确顺序是：P 先传参 → P 执行 `call` 保存返回地址并跳转 → Q 保存 P 的现场并分配局部变量 → 执行 Q 的函数体 → Q 恢复现场并释放局部变量 → Q 执行 `ret` 取出返回地址返回，即 ②→③→①→⑥→⑤→④。

**解题切入点**：先识别这是“过程调用/函数调用”的栈帧控制流题目，考点是 x86 的 `CALL`/`RET` 和栈帧建立、撤销过程。可以把 `CALL` 看成“压入返回地址 + 跳转”，把 `RET` 看成“弹出返回地址 + 跳回”。被调函数必须“先开场、再干活、后收尾、最后返回”，不要把返回放在函数体之前。

**推演**：

1. **② 传参**：过程 P 先把实参放到 Q 能访问到的地方。在 32 位 x86 中通常是把实参压入栈中，Q 通过 $\text{EBP}$ 加偏移量访问。

2. **③ 保存返回地址并跳转**：P 执行 `call Q`。CPU 把 P 中下一条指令的地址，即返回地址，压入栈中，再把 $\text{EIP}$ 设置为 Q 的入口地址。

3. **① Q 保存 P 的现场并分配局部变量**：Q 执行开场代码，典型操作是：
   - 保存 P 的旧 $\text{EBP}$；
   - 设置自己的 $\text{EBP}$；
   - 用类似 `sub esp, size` 的操作为非静态局部变量分配栈空间。

4. **⑥ 执行 Q 的函数体**：此时 Q 的栈帧已经建立，局部变量可用，函数体开始执行。

5. **⑤ Q 恢复 P 的现场并释放局部变量**：Q 执行收尾代码，释放局部变量空间，恢复原来的 $\text{EBP}$ 等现场信息。

6. **④ 取出返回地址并返回**：Q 执行 `ret`，从栈顶弹出返回地址到 $\text{EIP}$，跳回到 P 中继续执行。

因此得到完整顺序：

$$
② \to ③ \to ① \to ⑥ \to ⑤ \to ④
$$

对应选项 **C**。

**易错点**：

- 不要选 A、B：它们都在 Q 的函数体执行之前就执行了“取出返回地址并返回”，这在逻辑上不可能。
- 不要选 D：它把“恢复现场、释放局部变量”放在了“执行函数体”之前。函数体还没执行就释放栈帧，后续无法正常工作。
- 不要把 ③ 和 ④ 混淆：③ 是进入 Q 前由 `call` 压入返回地址；④ 是离开 Q 时由 `ret` 弹出返回地址。二者必须位于调用过程的两端，且④一定在最后。
- 注意“保存/恢复 P 的现场”不是保存返回地址。返回地址由 `call` 在 ③ 中保存；Q 保存的现场主要是旧 $\text{EBP}$、被调用者保存寄存器等。
- 32 位 x86 栈帧中典型位置：返回地址在 $[\text{EBP}+4]$，旧 $\text{EBP}$ 在 $[\text{EBP}]$，参数在 $[\text{EBP}+8]$ 起，局部变量在 $[\text{EBP}]$ 下方。

**命题规律**：本题考点是“过程调用与返回 / 栈帧管理”，属于指令系统与 CPU 控制流部分的重要内容。常见变式有：给出栈帧布局，问返回地址、旧 EBP、参数、局部变量的位置；考查 `call` 和 `ret` 各自完成的硬件动作；考查不同调用约定下参数压栈顺序和栈平衡；也可换成 MIPS 的 `jal/jr` 进行对比。复习时应画一张栈帧图，把“传参 → call → prologue → 函数体 → epilogue → ret”作为固定流程记忆。
