# 选择题 第 12 题

![[_Attachments/题目识别/27_王道408-题目/DS-C03-32-M12_题目.png|题目]]

12. 下列描述的几种链表中，最适合用作队列的是 ( ).

A. 带队首指针和队尾指针的循环单链表

B. 带队首指针和队尾指针的非循环单链表

C. 只带队首指针的非循环单链表

D. 只带队首指针的循环单链表

## 答案

## DeepSeek V4 Flash Max 解析

**答案**：B（带队首指针和队尾指针的非循环单链表）。

**解题切入点**：拿到题目先明确队列的两个基本操作——入队在队尾，出队在队头。因此存储结构必须能在 $O(1)$ 时间内访问/修改队头和队尾。这就像排队叫号：既要知道队首是谁，又要能在队尾快速加人。所以先排除只带队首指针的 C、D；剩下 A、B 都有队首和队尾指针，都能做到 $O(1)$，但循环链表还要额外维护循环性质，操作更繁琐，非循环单链表才是链队列最直接、最简洁的实现。

**推演**：链队列通常用带头尾指针的单链表实现。以带头结点的非循环单链表为例，设 $front$ 指向头结点（哨兵），$rear$ 指向队尾结点。初始化时 $front=rear$，$rear->next=NULL$。

- 入队：新建结点 $p$，令 $p->next=NULL$，然后执行 $rear->next=p;\; rear=p;$，时间复杂度 $O(1)$。
- 出队：若 $front->next==NULL$ 则队空；否则 $p=front->next$，令 $front->next=p->next$；若 $p==rear$，则 $rear=front$；最后释放 $p$，时间复杂度 $O(1)$。

若采用带头结点的循环单链表（A），入队时 $p->next$ 必须指向 $front$ 以维持循环；出队时若队列不空，还要保证 $rear->next=front$。显然比非循环链表多出了维护“尾结点指向头结点”的操作，边界条件也更复杂，但时间复杂度仍为 $O(1)$，并没有额外好处。

若不带头结点，结论同样成立：设 $front$ 直接指向队头结点，$rear$ 指向队尾结点。非循环链队入队时，若为空则 $front=rear=p$，否则 $rear->next=p;\; rear=p$；出队时 $p=front$，$front=front->next$，若 $front==NULL$ 则 $rear=NULL$。同样 $O(1)$，且操作简洁。

而 C、D 只带队首指针，出队虽为 $O(1)$，但入队必须从队头遍历到队尾，时间复杂度为 $O(n)$，不适合用作队列。

综上，B 是最适合用作队列的链表。A 虽也能实现 $O(1)$ 入队出队，但循环不是队列的必需条件，反而增加了额外维护成本。

**易错点**：
1. 混淆“循环链表”与“循环队列”：循环队列是顺序存储中解决“假溢出”的手段，链表动态分配，不存在“队满”问题，因此循环链表不是链队列的必要选择。
2. 只看到 A、B 时间复杂度都是 $O(1)$ 就随意选，忽略了循环链表需要额外维护 $rear->next$ 指向队头，操作常数更大、更容易出错。
3. 忽略空队列或只剩一个结点时尾指针的处理。无论循环还是非循环，出队后若队列为空，$rear$ 都必须置空（或指向头结点），否则尾指针悬空。
4. 误认为“只带队首指针的循环单链表”入队可以 $O(1)$。实际仍需要从头遍历一圈才能找到队尾，时间复杂度为 $O(n)$。

**命题规律**：本题属于“栈和队列”中“队列的存储结构”基础题，命题点集中在链队列需要队头、队尾两个指针，以及入队/出队能否做到 $O(1)$。常见变式有：
- 给出“只带队尾指针的循环单链表”，问能否用作队列——可以，因为 $rear->next$ 就是队头结点；
- 给出带头结点/不带头结点的链队列，让写出入队、出队操作的指针修改过程；
- 与顺序循环队列的判空/判满条件比较。
复习建议：亲手画一画带头结点和不带头结点两种链队列的指针变化图，特别注意空队列和单结点时的边界处理；理解“循环链表 + 尾指针”可以节省一个头指针，但若已有头指针，循环并非必要。
