11. 与顺序队列相比，链式队列的 ( ).

A. 优点是队列的长度不受限制
B. 优点是入队和出队时间效率更高
C. 缺点是不能进行顺序访问
D. 缺点是不能根据队首指针和队尾指针计算队列的长度

## 答案

![[_Attachments/题目识别/27_王道408-答案/DS-C03-32-M11_答案.png|答案]]

## DeepSeek V4 Flash Max 解析

**答案**：D。链式队列的标准实现没有长度字段，不能像顺序队列那样由队首指针和队尾指针直接算出队列长度，通常需要遍历链表或额外维护计数器。

**解题切入点**：拿到“顺序存储 vs 链式存储”的比较题，先不要逐项背选项，而要抓住几个关键维度：入队/出队时间复杂度、是否会队满、能否顺序访问、如何求队列长度。顺序队列的 `front`、`rear` 本质是数组下标，可以直接做差求长度；链式队列的 `front`、`rear` 是链表结点地址，地址差没有结点数量意义。这就像数组中可以通过下标差求出元素个数，而链表中两个指针相减不能得到链表长度。

**推演**：

设循环顺序队列容量为 $M$，约定 `front` 指向队首元素，`rear` 指向队尾元素的下一个位置，则队列长度为：

$$
L=(rear-front+M)\bmod M
$$

如果采用非循环顺序队列，则直接有：

$$
L=rear-front
$$

所以顺序队列可以在 $O(1)$ 时间内求得队列长度。

而链式队列的结点不是连续存放的，`front` 和 `rear` 是指针，不是下标。两个指针地址的差只是内存地址差，和结点个数没有确定关系。要求链式队列长度，只能从队首沿 `next` 链遍历：

```c
int Length(LinkQueue Q) {
    int len = 0;
    LNode *p = Q.front->next;   // 若 front 直接指向队首元素，则令 p = Q.front
    while (p != NULL) {
        len++;
        p = p->next;
    }
    return len;
}
```

因此，链式队列求长度的时间复杂度是 $O(n)$，不能像顺序队列那样由 `front`、`rear` 直接计算。若希望 $O(1)$ 求长，可以额外维护一个 `len` 字段，入队时 `len++`，出队时 `len--`，但这不是标准链式队列默认具备的能力。

逐项分析：

- A 错：“长度不受限制”说法太绝对，链式队列长度仍受内存总量限制；只能说它不会因为固定容量而“队满”，可以动态增长。
- B 错：顺序循环队列和链式队列的入队、出队时间复杂度都是 $O(1)$；链式队列还要动态分配/释放结点，常数开销不一定更小。
- C 错：链式队列可以沿 `next` 指针从队首向队尾顺序访问，不能说“不能进行顺序访问”；只能说它不便随机访问。
- D 对：链式队列不能仅由 `front` 和 `rear` 两个指针直接算出队列长度。

**易错点**：

1. 容易误选 A。要注意“长度不受限制”不等于“动态增长、不会队满”。考试中更严谨的说法是“链式队列不会因固定容量而溢出，除非内存不足”。
2. 容易误选 B。两种队列的入队、出队时间复杂度都是 $O(1)$，不能说链式队列时间效率更高；链式队列反而有指针存储和动态分配开销。
3. 容易误选 C。链式队列可以顺序访问，不能随机访问。题目说的是“顺序访问”，不是“随机访问”。
4. 要注意“不能根据 `front` 和 `rear` 计算长度”不等于“不能计算长度”。链式队列可以通过遍历或增加长度计数器求长度。

**命题规律**：本题考点是队列的顺序存储与链式存储结构比较。常见变式有：给出循环队列的 `front`、`rear`、`MaxSize`，求队长或判断队空/队满；设计一个支持 $O(1)$ 求长的链式队列；比较顺序栈/链栈、顺序队列/链队列的优缺点。复习时建议画图对比 `front`、`rear` 的变化过程，并记住核心结论：顺序队列适合随机访问和 $O(1)$ 求长，链式队列适合动态增长、不易队满，但求长通常需要遍历或额外维护计数器。
