## DeepSeek V4 Flash Max 解析

**答案**：利用深度优先搜索（DFS）的后序序列（即顶点完成时间的逆序）输出顶点，即可得到有向无环图的拓扑排序；若 DFS 过程中发现回边，则有向图存在环，无法拓扑排序。

**解题切入点**：看到“DFS”和“拓扑排序”，应先建立两者之间的桥梁：拓扑排序要求每条有向边 $u \to v$ 都满足 $u$ 排在 $v$ 之前；而 DFS 中，若从 $u$ 出发访问 $v$，则 $v$ 必先于 $u$ 完成。因此，按“完成时间从晚到早”输出顶点正好满足拓扑序。这类似于竞赛中常用的“DFS 时间戳”思想——用递归栈的返回时刻标记完成顺序，从而将图遍历结果转化为线性次序。

**推演**：

1. **算法设计**  
   采用邻接表存储有向无环图，顶点数为 $n$，边数为 $e$。定义访问状态数组 `visited[]`：
   - `0`：未访问；
   - `1`：正在访问（递归栈中）；
   - `2`：访问完成（已退回）。  

   DFS 函数对顶点 $u$ 进行深度优先遍历，伪代码如下：

   ```
   void DFS(G, u):
       visited[u] = 1
       for v in G.Adj[u]:
           if visited[v] == 0:
               DFS(G, v)
           else if visited[v] == 1:
               存在环，拓扑排序失败
       visited[u] = 2
       push(S, u)       // 顶点 u 完成，入栈
   ```

   主流程对图中每个未访问顶点调用 `DFS`，最后从栈顶到栈底依次输出顶点，即为拓扑序列。

2. **正确性证明**  
   对于任意有向边 $u \to v$，由于 DFS 在访问 $u$ 时会递归访问 $v$，所以 $v$ 的 DFS 调用一定在 $u$ 的调用内部结束，即 $v$ 的完成时间早于 $u$ 的完成时间。因此，$v$ 先入栈，$u$ 后入栈；输出时从栈顶开始，则 $u$ 先于 $v$ 输出，满足拓扑序要求。  
   若图中不存在环，DFS 不会访问到状态为 `1` 的顶点，故算法总能产生包含全部顶点的拓扑序列；反之，若存在环，则必然出现回边，即当前访问顶点 $u$ 有一条边指向正在访问的祖先顶点 $v$，此时状态为 `1`，算法发现并报告“有环”。

3. **复杂度分析**  
   每个顶点和每条边均被访问一次，时间复杂度 $O(n+e)$；递归栈和存储栈的空间均为 $O(n)$，故空间复杂度 $O(n)$。

**易错点**：
- **直接输出 DFS 访问序**：若仅按进入递归的先后顺序输出，从不同起点开始的遍历可能会颠倒 $u$、$v$ 次序，不满足拓扑序。必须使用“后序逆序”。
- **入栈位置错误**：入栈操作必须在遍历完所有邻接点、顶点置为“完成”后进行，而不是在刚访问顶点时。
- **遗漏非连通分量**：主函数需对每个未访问顶点启动 DFS，否则有多个连通分量时会产生遗漏。
- **忽视环检测**：虽然题目限定 DAG，但实现时应加入对状态 `1` 的判断，否则在有环图中会无限递归或产生错误序列。
- **输出顺序混淆**：栈空则序列结束，从栈顶弹出是正拓扑序；若直接按后序数组输出，需反序。

**命题规律**：本题是 408 数据结构“图”章节的高频考点，属于 DFS 与拓扑排序结合的综合应用题。常见变式包括：判断有向图是否有环、利用非递归 DFS 实现、结合关键路径求事件发生时间（逆拓扑排序）、给出具体图要求写出拓扑序列等。复习时应重点掌握 DFS 三色标记法、后序与拓扑排序的关系，并与 Kahn 算法（BFS）对比记忆。建议在纸上手动模拟 DFS 过程，加深对“完成时间”的理解，同时注意代码书写的规范性。
