# 综合题 第 7 题

![[_Attachments/题目识别/27_王道408-题目/DS-C08-84-F07_题目.png|题目]]

7. 优先队列 (PriorityQueue) 是一种数据结构，它类似于普通队列，但每个元素都有一个优先级。元素在入队时会根据其优先级来排序，而不按照先入先出的顺序来排序。每次从优先队列中出队时，出队的是优先级最高的元素，而不是最早进入队列的元素。

队列中的元素的数据结构的定义如下：
```C
typedef struct {
    int value;          // 元素的值
    int priority;       // 元素的优先级，priority 越大，优先级越高
} PriorityQueueElement;
```

请设计一个优先队列，要求满足：①初始时队列为空；②入队时，不允许增加队列的占用空间；③出队后，出队元素所占用的空间可重复使用，即整个队列所占用的空间不变；④入队操作和出队操作的时间复杂度始终保持为 $O(\log_2 n)$。请回答：

1) 该队列是应选择链式存储结构，还是选择顺序存储结构？
2) 给出优先队列的数据结构的定义。
3) 用伪代码给出入队操作和出队操作的基本过程（关键之处可用文字描述）。

## DeepSeek V4 Flash Max 解析

**答案**：采用顺序存储结构，用静态一维数组实现一个最大堆；入队时在堆尾插入并向上调整，出队时取出堆根并用堆尾元素补根后向下调整，入队/出队均为 $O(\log_2 n)$，且总存储空间固定不变。

**解题切入点**：看到“优先队列”且要求每次出队优先级最高的元素，应立刻想到“堆”；要求 $O(\log_2 n)$，也正对应堆的插入/删除调整。堆是完全二叉树，天然适合用顺序存储结构；题目又要求“入队不能增加占用空间、出队空间可复用”，说明应使用静态分配的数组，而不是动态 `malloc` 结点。`priority` 越大优先级越高，所以用**最大堆**。

**推演**：

1. 存储结构选择

优先队列采用最大堆实现。最大堆满足：任一结点的优先级都不小于其孩子结点的优先级，因此堆根 `heap[1]` 就是当前优先级最高的元素。

用一维数组存储堆时，若下标从 1 开始，则：

$$
\text{parent}(i)=\left\lfloor \frac{i}{2}\right\rfloor,\qquad
\text{left}(i)=2i,\qquad
\text{right}(i)=2i+1
$$

若用链式存储结构，入队通常需要新建结点，会增加占用空间；若强行预分配结点池，又需要额外维护指针。顺序存储的数组天然是预分配空间，入队、出队只改变 `size`，不会改变总空间，因此本题应选择**顺序存储结构**。

2. 优先队列的数据结构定义

```c
#define MAXSIZE 1000   // 按实际问题可容纳的最大元素数设定

typedef struct {
    int value;         // 元素的值
    int priority;      // 元素的优先级，priority 越大优先级越高
} PriorityQueueElement;

typedef struct {
    PriorityQueueElement heap[MAXSIZE + 1]; // heap[0] 不用，从 1 开始
    int size;                               // 当前队列中元素个数
} PriorityQueue;
```

初始化：

```c
void InitPriorityQueue(PriorityQueue &Q) {
    Q.size = 0;
}
```

3. 入队操作

入队时，先把新元素放在堆尾，即下标 `size + 1` 处，然后不断与父结点比较：若新元素优先级比父结点高，则与父结点交换，继续向上调整。

```c
void EnQueue(PriorityQueue &Q, PriorityQueueElement x) {
    if (Q.size == MAXSIZE) {
        /* 队满，按题目约定处理，不能增加空间 */
        return;
    }

    int i = ++Q.size;
    Q.heap[i] = x;

    // 向上调整
    while (i > 1 && Q.heap[i].priority > Q.heap[i / 2].priority) {
        swap(Q.heap[i], Q.heap[i / 2]);
        i = i / 2;
    }
}
```

4. 出队操作

出队时，先保存堆根元素，即当前优先级最高的元素；然后将堆尾元素放到堆根，`size--`；再从堆根开始向下调整：比较当前结点与其左右孩子，把优先级最大的结点换到父结点位置，直到满足堆性质。

```c
PriorityQueueElement DeQueue(PriorityQueue &Q) {
    if (Q.size == 0) {
        /* 队空，下溢处理 */
    }

    PriorityQueueElement top = Q.heap[1];

    // 用堆尾元素覆盖堆根
    Q.heap[1] = Q.heap[Q.size];
    Q.size--;

    // 向下调整
    int i = 1;
    while (true) {
        int largest = i;
        int l = 2 * i;
        int r = 2 * i + 1;

        if (l <= Q.size && Q.heap[l].priority > Q.heap[largest].priority)
            largest = l;
        if (r <= Q.size && Q.heap[r].priority > Q.heap[largest].priority)
            largest = r;

        if (largest == i)
            break;

        swap(Q.heap[i], Q.heap[largest]);
        i = largest;
    }

    return top;
}
```

5. 时间复杂度与空间复用

堆是完全二叉树，含有 $n$ 个结点的完全二叉树高度为：

$$
\lfloor \log_2 n \rfloor
$$

入队的向上调整最多经过从堆尾到根的一条路径，出队的向下调整最多经过从根到叶子的一条路径，因此二者最坏时间复杂度均为：

$$
O(\log_2 n)
$$

空间上，数组在初始化时一次性分配，入队、出队都不动态申请或释放内存；出队时用堆尾元素覆盖堆根，原堆根空间被覆盖复用，最后一个位置也因 `size` 的改变可被下一次入队覆盖。因此整个队列占用的空间保持不变。

**易错点**：

- 比较关键字应使用 `priority`，而不是 `value`。
- `priority` 越大优先级越高，应建**最大堆**；若使用 `<` 比较，会建成最小堆，出队元素错误。
- 入队要**向上调整**，出队要**向下调整**，二者不能混淆。
- 向下调整时要同时比较左右两个孩子，不能只比较一个孩子。
- 数组下标必须统一：若从 1 开始，父结点是 `i/2`，左孩子是 `2i`，右孩子是 `2i+1`；不要与从 0 开始的下标公式混用。
- 固定空间实现时必须预定义 `MAXSIZE`，队列满时不能 `realloc` 或 `malloc` 扩容，否则违反“不增加占用空间”的要求。
- 若题目要求同优先级按入队先后出队，则还需要额外增加序号字段作为次级关键字；本题未要求，堆只保证优先级高的元素先出。

**命题规律**：本题属于“堆与优先队列”的综合应用。408 中常以最大堆/最小堆的形式考查堆的插入、删除、建堆过程，以及用堆解决 Top-K、Dijkstra、Huffman 等问题。常见变式包括：求前 $K$ 大元素用小顶堆，求前 $K$ 小元素用大顶堆；给出关键字序列要求画出初始堆、掌握堆排序的每趟结果；或者要求手写堆的上滤/下滤伪代码。复习时应重点掌握堆的数组存储下标关系、插入删除调整过程和时间复杂度分析；同时注意：逐个插入建堆是 $O(n\log n)$，自底向上整体建堆是 $O(n)$。
