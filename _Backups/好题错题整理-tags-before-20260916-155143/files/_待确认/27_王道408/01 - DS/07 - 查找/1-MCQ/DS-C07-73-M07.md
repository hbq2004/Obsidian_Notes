## DeepSeek V4 Flash Max 解析

**答案**：选 **(A) 3**。按给定插入序列构造的二叉排序树中，查找 60 的关键字比较序列为 $52,71,60$，第 3 次比较命中，因此比较次数为 3。

**解题切入点**：  
看到“从空树开始，依次插入”就应立刻定位为“二叉排序树的构造与查找”题。  
二叉排序树的插入规则是：小于当前结点往左走，大于当前结点往右走，遇到空位置就挂上；查找时同样从根开始，每经过一个结点就做一次关键字比较。  
做题时可以先像模拟调试一样把树画出来，再沿查找路径数结点个数。

**推演**：  
按插入规则逐个插入元素，得到的二叉排序树为：

```text
52
├─左：26
│  ├─左：14
│  │  └─右：24
│  └─右：32
│     └─右：41
└─右：71
   ├─左：60
   │  └─左：58
   └─右：93
```

该树中序序列为：

$$
14,24,26,32,41,52,58,60,71,93
$$

中序序列递增，说明树形正确。

现在查找 60：

1. 与根结点 $52$ 比较：$60>52$，进入右子树；
2. 与右子树根 $71$ 比较：$60<71$，进入左子树；
3. 与该左子树根 $60$ 比较：相等，查找成功。

因此查找路径为：

$$
52 \to 71 \to 60
$$

共经过 3 个结点，每次经过一个结点都比较一次，所以比较次数为：

$$
3
$$

对应查找计数代码思路：

```c
cnt = 0;
p = root;
while (p != NULL) {
    cnt++;
    if (key == p->key) return cnt;   // 查找成功
    else if (key < p->key) p = p->left;
    else p = p->right;
}
return -1;  // 查找失败
```

**易错点**：  
- 不要把二叉排序树当作平衡二叉树进行旋转。题目只说“二叉排序树”，树形完全由插入顺序决定。  
- 查找成功时，最后一次“相等”的比较也要计入。只数路径上的边会得到深度 2，从而少算为 2 次。  
- 不要混淆“插入 60 时的比较次数”和“查找 60 的比较次数”。插入 60 时它还不存在，最后一步是放到空位；而查找 60 时还要与已经存在的结点 60 本身比较一次。  
- 若把 58 的位置画错，可能影响其他查找或平均查找长度；本题查找 60 的路径不受影响，但仍应认真建树。

**命题规律**：  
这是 408 数据结构“查找”章节的基础考点，常以选择题形式考查：给插入序列构造二叉排序树，求某关键字的查找比较次数、查找成功/失败的平均查找长度等。  
常见变式有：判断某个查找序列是否为该 BST 的合法查找路径；删除结点后树形变化；与折半查找判定树、平衡二叉树对比。  
复习时要熟练掌握 BST 的插入不旋转、查找路径与比较次数对应关系，并会手算平均查找长度。
