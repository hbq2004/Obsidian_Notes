# 选择题 第 8 题

![[_Attachments/题目识别/27_王道408-题目/DS-C07-73-M08_题目.png|题目]]

8. 在含有 $n$ 个结点的二叉排序树中查找某个关键字的结点时, 最多进行 (\_) 次比较.
(A) $n/2$
(B) $\log_2 n$
(C) $\log_2 n + 1$
(D) $n$

## DeepSeek V4 Flash Max 解析

**答案**：选 **D**，即最多进行 $n$ 次比较。在任意含 $n$ 个结点的二叉排序树中，查找一个结点最多比较 $n$ 次；最坏情况是二叉排序树退化为单支树。

**解题切入点**：  
先抓题目说的是“二叉排序树”而不是“平衡二叉排序树”。二叉排序树只保证中序序列有序，不保证树形平衡。查找过程本质上是从根结点沿某一条路径往下走，最多比较次数等于路径上的结点数，因此问题的核心就是：$n$ 个结点的二叉树最高有多少层？答案是 $n$ 层。不要一看到“排序树”就误以为类似折半查找、比较次数为 $\log_2 n$。

**推演**：

二叉排序树查找算法核心如下：

```c
p = T; // 根结点
while (p != NULL) {
    if (k == p->key)   // 比较当前结点关键字
        return p;
    else if (k < p->key)
        p = p->left;
    else
        p = p->right;
}
return NULL;
```

每次访问一个结点，进行一次关键字比较；因此查找长度等于从根结点到目标结点路径上的结点数。

设二叉排序树的高度为 $H$，这里高度按结点数计，即从根到最深叶结点的结点数。$n$ 个结点的二叉树每层至少有一个结点，所以

$$
H \le n.
$$

因此任意一次查找经过的结点数至多为 $n$，即最多比较 $n$ 次。

更形式化地，设 $W(n)$ 为 $n$ 个结点的二叉排序树中查找的最多比较次数。第一步必与根结点比较：

- 若命中，比较 $1$ 次；
- 若未命中，只能进入左子树或右子树继续查找。

最坏情况下，还需继续查找的子树尽量大，最多为 $n-1$ 个结点，因此

$$
W(n)=1+W(n-1),\qquad W(1)=1.
$$

迭代得

$$
W(n)=1+(n-1)=n.
$$

所以上界可以达到。例如按关键字 $1,2,3,\dots,n$ 的顺序依次插入，得到一棵右单支树：根为 $1$，右孩子为 $2$，再右孩子为 $3$，……，最深的结点为 $n$。查找关键字 $n$ 时，依次与 $1,2,\dots,n$ 比较，共 $n$ 次。

因此最多比较次数为 $n$，选 **D**。

**易错点**：

1. 误选 B 或 C：把二叉排序树当成平衡二叉树或完全二叉树。二叉排序树的形状取决于插入顺序，最坏情况下退化为单支树，此时并不具备“每次排除一半”的性质。
2. 比较次数按“边数”还是“结点数”混淆：深度按边数计可能为 $n-1$，但查找时根结点也要比较，所以最坏比较次数是 $n$，不是 $n-1$。
3. 把平均情况和最坏情况混淆：随机二叉排序树的平均查找长度约为 $O(\log n)$，但最坏情况是 $O(n)$。题目问“最多”，应取最坏情况。
4. 查找失败时不会额外和空指针比较关键；如果查找值大于单支树中所有关键字，仍然最多比较 $n$ 次后结束，而不会多出一次关键字比较。

**命题规律**：  
本题对应 408 查找章节中“二叉排序树的查找性能”这一考点。命题人常把二叉排序树与折半查找、平衡二叉树放在一起考查，要特别注意：

- 二叉排序树最坏查找复杂度为 $O(n)$；
- 平均查找复杂度为 $O(\log n)$；
- 平衡二叉排序树（AVL）的最坏查找复杂度为 $O(\log n)$；
- 折半查找的判定树是一棵平衡二叉树，最坏比较次数约为 $\lfloor \log_2 n \rfloor + 1$。

常见变式有：求 $n$ 个结点的二叉排序树最大/最小高度、求最坏情况下平均查找长度、给出插入序列判断树形是否退化为单支树，以及与 AVL 树性能对比。复习时应紧扣“查找长度 = 路径上结点数 = 树高”这一核心，并熟练区分不同查找结构的最坏情况和平均情况。
