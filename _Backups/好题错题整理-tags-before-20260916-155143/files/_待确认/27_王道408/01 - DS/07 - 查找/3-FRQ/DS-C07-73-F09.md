## 答案

## DeepSeek V4 Flash Max 解析

**答案**：采用二叉排序树的“右子树—根—左子树”逆中序遍历，并在当前关键字小于 $k$ 时只继续搜索右子树、不再处理当前结点和左子树，即可从大到小输出所有值不小于 $k$ 的关键字。

**解题切入点**：看到二叉排序树，首先要想到它的中序遍历结果是有序的：左根右是递增序列，右根左是递减序列。题目要求“从大到小”，所以应走**右子树、根、左子树**的遍历顺序；题目又要求“值不小于 $k$”，因此在遍历过程中需要根据 $k$ 剪枝。注意：当前结点小于 $k$ 时，左子树一定都小于 $k$，但右子树中仍可能有大于等于 $k$ 的结点，不能直接返回。

**推演**：

二叉排序树满足：

$$
\text{左子树所有关键字} < \text{根关键字} < \text{右子树所有关键字}
$$

因此中序遍历“左—根—右”得到递增序列，而“右—根—左”得到递减序列。

算法采用递归，核心代码思路如下：

```c
typedef struct BSTNode {
    int key;
    struct BSTNode *lchild, *rchild;
} BSTNode;

void PrintGE(BSTNode *T, int k) {
    if (T == NULL)
        return;

    if (T->key < k) {
        // 当前结点和左子树都小于 k，不可能输出；
        // 但右子树比当前结点大，仍可能有不小于 k 的结点。
        PrintGE(T->rchild, k);
    } else {
        // 右子树中关键字更大，先递归输出右子树。
        PrintGE(T->rchild, k);
        // 当前关键字不小于 k，输出。
        printf("%d ", T->key);
        // 左子树中仍可能有关键字不小于 k，继续递归输出。
        PrintGE(T->lchild, k);
    }
}
```

正确性证明：

- 对任意结点 $T$，比 $T$ 大的关键字一定都在 $T$ 的右子树中，因此必须先递归右子树，保证“从大到小”。
- 若 $T\to key < k$，则当前结点不满足条件；又因为左子树所有关键字都小于 $T\to key$，所以左子树也不可能有关键字不小于 $k$。但右子树关键字大于 $T\to key$，仍可能满足条件，因此只需继续递归右子树。
- 若 $T\to key \ge k$，则当前结点满足条件。由于右子树已经递归输出完毕，当前结点是剩余未输出结点中最大的，所以输出当前结点；随后左子树中仍可能有满足条件的结点，继续递归左子树。

因此该算法能按从大到小的顺序，无重复、无遗漏地输出二叉排序树中所有值不小于 $k$ 的关键字。

时间复杂度：每个结点最多被访问一次，故最坏时间复杂度为

$$
T(n)=O(n)
$$

其中 $n$ 为二叉排序树的结点数。递归深度取决于树高 $h$，空间复杂度为

$$
S(n)=O(h)
$$

最坏情况下 $h=O(n)$，平衡情况下 $h=O(\log n)$。

**易错点**：

1. **见到“从大到小”却用中序遍历**：中序遍历“左根右”得到的是递增序列，不符合题意；应从右子树开始遍历。
2. **当前结点小于 $k$ 时直接返回**：这是最典型的错误。比如根结点值为 $3$，右孩子值为 $7$，$k=5$，若因为根结点小于 $5$ 就返回，会漏掉 $7$。正确做法是先递归右子树。
3. **当前结点不小于 $k$ 时不递归左子树**：左子树虽然都比当前结点小，但仍可能有值不小于 $k$ 的结点。例如根结点为 $8$，左子树中有结点 $7$，$k=7$ 时，输出 $8$ 后还要继续处理左子树输出 $7$。
4. **忘记判断递归出口**：递归函数开头必须判断 `T == NULL`，否则会出现空指针访问。
5. **输出顺序颠倒**：必须先递归右子树，再输出当前结点，最后递归左子树；否则不能保证从大到小。

**命题规律**：本题是二叉排序树与二叉树遍历结合的典型综合题。核心考点是“二叉排序树中序遍历有序”这一重要性质。常见变式有：从小到大输出不大于 $k$ 的关键字、求二叉排序树中第 $k$ 大的关键字、输出关键字值在区间 $[a,b]$ 内的所有结点、求不小于 $k$ 的结点个数等。复习时应熟练掌握二叉树的三种递归遍历框架，并能针对二叉排序树做剪枝优化；看到“有序输出”首先联想中序遍历，看到“从大到小”就改用“右根左”遍历。
